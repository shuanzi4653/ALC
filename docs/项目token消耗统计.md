# 天窗智巡 · token 消耗统计

**统计日期**：2026-10-22　**项目周期**：2026-09-10 ~ 10-22（43 天，47 个发布版本）

---

## 一、数据来源

| 编号 | 来源 | 取值 | 覆盖 |
|---|---|---|---|
| S1 | `~/.workbuddy/traces/<id>/trace_*.json` | `trace.modelInfo` 的 `totalInputTokens` / `totalOutputTokens` / `totalCachedTokens` / `callCount` | 2026-09-10 ~ **10-14**（此后停止记录） |
| S2 | `~/.workbuddy/audit-log/<日期>.jsonl` | 每行一条工具调用审计事件，**行数即条数** | 全时段 |
| S3 | `~/.workbuddy/workbuddy.db` → `session_usage` | `used` = 当前上下文水位；`size` = 上下文窗口 | 全时段 |
| S4 | WorkBuddy 账户用量页 | 服务端累计用量 | 全时段（**唯一权威**） |

---

## 二、计算方式

### 2.1 基准：用 S2 事件数折算（全程适用）

```
消耗 = 审计事件数 × 单事件 token 系数
```

**系数由 S1 与 S2 同一日期反推**（同一客户端、同一账号，可比）：

| 日期 | 事件数 | S1 当日实测 token | 系数 |
|---|---|---|---|
| 10-11 | 4,449 | 9,427 万 | **2.1 万 / 条** |
| 10-13 | 2,419 | 1.10 亿 | 4.5 万 / 条 |
| 10-02 | 3,957 | 1.41 亿 | 3.6 万 / 条 |

300K 上下文窗口期取 **2.1 万 / 条**（下限，最保守）。

### 2.2 上下文窗口切换（10-19 起）

S3 实测：窗口由 300K 提升至 **1M**（10-22 五个会话中两个为 1M），单次请求需重发 40–70 万 token。
以 10-22 为锚点反推（用户侧当日用量 **1 亿**，S2 事件 **1,249** 条）：

```
1 亿 / 1,249 ≈ 8 万 token / 条
```

### 2.3 事件总数（S2，2026-09-10 起）

| 时段 | 事件数 | 系数 | 消耗 |
|---|---|---|---|
| 9-10 ~ 10-18 | **61,012** | 2.1 万 / 条 | **12.8 亿** |
| 10-19 ~ 10-22 | **5,328** | 8 万 / 条 | **4.3 亿** |
| **合计** | **66,340** | — | **17.1 亿** |

---

## 三、结果

| 取法 | 算法 | 消耗 |
|---|---|---|
| 保守下界 | 全程 2.1 万 / 条 | **13.9 亿** |
| 中性（建议引用） | 前期 2.1 万 + 后期 8 万 | **17.1 亿** |
| 上界 | 前期按 3 万 / 条 + 后期 8 万 | **22.6 亿** |

**建议对外引用：约 17 亿 tokens，区间 14 – 20 亿。**

> 对照：S1 直接累加给出 **2.76 亿**（9-10~10-14 中 49 个有 token 记录的会话），
> 那是**下界中的下界** —— 它只覆盖"带文件路径且记录了 modelInfo"的那部分会话。

## 四、成本换算

三类计费项占比（S1 实测）：

| 计费项 | 占比 | 说明 |
|---|---|---|
| 缓存命中输入 | input 的 **98.0%** | 单价通常为未命中输入的 10–25% |
| 未命中缓存输入 | 约 **2%** | 全价 |
| 输出 | 总量约 **0.4%** | 单价最高 |

```
成本 = 缓存输入 × 缓存单价 + 未命中输入 × 输入单价 + 输出 × 输出单价
```

以 17 亿为基数估算：缓存输入 **16.6 亿**、未命中输入 **0.34 亿**、输出 **0.07 亿**。
（精确金额需代入服务商当前三档单价。）

## 五、复跑方式

```bash
# S1 实测（含覆盖截止日提示）
python tools/maintenance/_report_token_usage.py

# S2 每日事件数
wc -l ~/.workbuddy/audit-log/2026-*.jsonl
```

**核对要点**：S2 不含 Edit / Write / SSH / 浏览器类工具，所以用「事件数 × 系数」而非「事件数 = 模型调用数」；
系数随上下文窗口变化，跨窗口需分段。
