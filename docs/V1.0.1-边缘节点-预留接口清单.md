## 0. 结论先行

1. 现在 **`/api/edge/*` 一条都没有**（后端 43 条路由里零命中，`contracts/` 也没有 edge 契约）。§7 写的三条是"最小闭环"，但**缺一个关键环节：帧从哪来**。
2. 断网演示要成立，节点 NVS 里必须先有 **≥7 条 METAR 实测帧**——§7 只给了 `params / heartbeat / report`，**没有下发帧的接口**。这是最容易在答辩被问穿的一处（"你断网前那份缓存哪来的？"）。本清单把它补成 `GET /api/edge/frames`（P0）。
3. 口径卡 §9 那两条待补规则（数据龄分级、NVS 时间恢复）**必须以字段形式进契约**，否则规则只活在文档里：`dataAgeMin` / `frameTs` / `timeSource` / `monotonicMs`。
4. 版本安排：**1.3.0 不动**；`contracts/edge-v1.openapi.json` 只在 2.0.0 落地；下线开关 `edge.enabled=false` 默认关，不构成既有契约变更。

## 2. 接口清单（12 条，按优先级）

### A. 帧与参数下行（P0 —— 没有这组，断网演示不成立）

| # | 方法 路径 | 作用 | 关键字段（响应） | 判据 |
|---|---|---|---|---|
| A1 | `GET /api/edge/frames` | 下发缓存帧，节点写 NVS | `stationCodes[]`、`frames[{station,ts,source,visM,gustMps,tempC,windMps}]`、`count` | 默认返回**最近 ≥7 条/站**；`?since=ts` 增量；`source` 必须逐帧带 |
| A2 | `GET /api/edge/params` | 规则指纹 + 走廊参数 + 阈值 | `rulesFingerprint`、`paramsVersion`、`thresholds{ban,caution,watch}`、`windowHours:[1,3]`、`stationCodes[]` | 指纹不符 → 节点**拒绝裁决**（不是降级） |
| A3 | `GET /api/edge/time` | 校时（局域网无外网，不能用 NTP） | `serverTimeUtc`、`monotonicMs`、`source:"SERVER_HTTP"` | 节点断网重启必须靠 `monotonicMs` + NVS 恢复时间 |

> A1 是本次盘点新发现的缺口；A2/A3 对应 §7 的 `params` 与口径卡 §4 的"校时 / NVS 恢复"。

### B. 上报与补传（P0）

| # | 方法 路径 | 作用 | 关键字段 | 判据 |
|---|---|---|---|---|
| B1 | `POST /api/edge/report` | 单帧上报（≤1 KB） | 请求：`node,ts,seq,mode,p{vis,gust,unsafe},decision{tier},latencyMs,fw,sig,frameTs,dataAgeMin,timeSource,rulesFingerprint`　响应：`ok,duplicate,pending` | 去重键 `node+seq`；签名 `HMAC-SHA256(node\|ts\|seq\|body)` |
| B2 | `POST /api/edge/report/batch` | 环形补传（≤500 条） | 请求：`node,items[]`　响应：`acceptedSeqs[],duplicateSeqs[],rejected[{seq,reason}]` | 断网 30 min 恢复后**条数一致、零重复** |
| B3 | `POST /api/edge/heartbeat` | 心跳（60 s） | 请求：`node,mode,dataAgeMin,queueDepth,fw,rulesFingerprint`　响应：`ok,serverTimeUtc,backfill:true/false,paramsStale:true/false` | 服务端**连续 10 min** 无成功请求才算 OFFLINE（不由节点自报） |

### C. 接入与节点台账（P1）

| # | 方法 路径 | 作用 | 关键字段 | 判据 |
|---|---|---|---|---|
| C1 | `POST /api/edge/register` | 首次上线、绑定站点 | 请求：`node,hwRev,fw,siteId,stationCodes[]`　响应：`enabled,nodeToken,rulesFingerprint` | 未注册节点上报一律 403，不静默落库 |
| C2 | `GET /api/edge/nodes` | 节点卡列表（云端后台角色） | `[{node,siteId,mode,lastSeenAt,dataAgeMin,tier,pUnsafe,queueDepth}]` | `dataAgeMin` 由**服务端用 `frameTs` 算**，不信节点自报 |
| C3 | `GET /api/edge/nodes/{node}` | 单节点详情 + 最近 N 条曲线 | `node,site,history[{ts,pUnsafe,tier,mode,latencyMs}],coverage{station,ok}` | 只读；不含任何"批准/放行"字段 |

### D. 云端复盘与健康（P1/P2）

| # | 方法 路径 | 作用 | 关键字段 | 判据 |
|---|---|---|---|---|
| D1 | `GET /api/edge/backfill` | 补传台账（复盘/追责） | `node,gapFrom,gapTo,recoveredAt,count,dropped` | 断网区间可逐秒对齐屏上数据龄 |
| D2 | `GET /api/edge/health` | 汇总（验收/巡检） | `online,degraded,offline,oldestDataAgeMin,fingerprintMismatch` | 三种状态计数之和 = 注册节点数 |
| D3 | `GET /api/edge/sites` | **部署三层**的机器可读版 | `[{siteId,name,stage:"demo"\|"planned"\|"future",province,city,stationCode}]` | `stage=demo` 恰好 3 个（沈阳/长春/哈尔滨）；`future` 只放机载/车载，且 `enabled:false` |

## 3. P0 三条的字段级细节（照着写）

### A1 `GET /api/edge/frames?since=&stations=ZYTX,ZYCC,ZYHB&limit=7`

```json
{
  "generatedAt": "2026-11-10T05:30:00Z",
  "rulesFingerprint": "rules-v1:4f2a…",
  "count": 21,
  "frames": [
    {"station": "ZYTX", "ts": "2026-11-10T05:00:00Z",
     "source": "METAR", "raw": "ZYTX 100500Z …",
     "visM": 997.8, "gustMps": 7.0, "tempC": -8.0, "windMps": 4.0}
  ]
}
```
- `source` 只能是 `METAR`（实测）；**不许出现 `SYNTHETIC`** —— 合成帧不进节点缓存，否则"不假装数据新鲜"这条就破了。
- 帧数不足 7 条时返回实际条数 + `shortfall:true`，节点屏上标"缓存不足 N 条"，不许补零。

### B1 `POST /api/edge/report`

```json
{
  "node": "edge-sy-01", "ts": "2026-11-10T05:35:00Z", "seq": 1042,
  "mode": "OFFLINE", "frameTs": "2026-11-10T03:00:00Z", "dataAgeMin": 35,
  "timeSource": "NVS_RESTORE", "rulesFingerprint": "rules-v1:4f2a…",
  "p": {"vis": 0.12, "gust": 0.05, "unsafe": 0.16},
  "decision": {"tier": "WATCH"}, "latencyMs": 18, "fw": "edge-1.0.1",
  "sig": "hmac-sha256:…"
}
```
响应：`{"ok":true,"duplicate":false,"pending":0,"serverTimeUtc":"…"}`

- `mode` 三值只能是 `ONLINE / DEGRADED / OFFLINE`（与口径卡 §3 三状态一一对应）。
- `timeSource` ∈ `SERVER_HTTP / NVS_RESTORE / UNKNOWN`；`UNKNOWN` 时服务端把该记录标 `timeSuspect:true`，**不当正常数据用**。

### A2 `GET /api/edge/params`

```json
{
  "rulesFingerprint": "rules-v1:4f2a…", "paramsVersion": "corridor-2026-11-10",
  "thresholds": {"ban": 0.8, "caution": 0.5, "watch": 0.2},
  "windowHours": [1, 3], "stationCodes": ["ZYTX","ZYCC","ZYHB"],
  "corridorParams": [{"corridorId": "CAR-1-02-1-14", "pMax": 0.31, "verdict": "可飞"}]
}
```
- 阈值必须与后端 `P_PROB_BLOCK/WATCH` 同源，**不许在接口里写第二份常量**。

## 4. "定位 / 使用"怎么映射到接口

| 口径卡的表述 | 落到哪个接口 | 备注 |
|---|---|---|
| 部署三层：示范点 / 扩展 / 演进 | `D3 /api/edge/sites` 的 `stage`；`C1` 的 `siteId` | `demo` = 3 个 vertiport 值班室；`planned` = 216 条城内配送走廊末端；`future` = 机载/车载，`enabled:false` |
| 三类角色：放行员 / 现场操作员 / 云端后台 | 放行员→`C2/C3` 单节点卡；操作员→**节点本地屏，不调接口**；云端→`D1/D2` | 角色差异只在"看哪一屏"，不做细粒度权限系统 |
| 三种状态：ONLINE / DEGRADED / OFFLINE | `B1/B3` 的 `mode` + 服务端算的 `dataAgeMin` | 判 OFFLINE 的口径在**服务端**（连续 10 min 无成功请求），节点自报只作参考 |
| 断网八问 | `A1`(数据哪来) `A3`(时间基准) `A2`(规则过期) `B2`(数据怎么回来) `B1`(新鲜度) | 五个接口各答一问；"航路规划做不做""断网多久判定"在口径文案里，不需要接口 |
| 不做全局重规划 | — | 接口里**故意不提供**任何"重新规划全网"的入口 |

## 5. 必须进契约的两个新字段（口径卡 §9 的缺口）

| 缺口 | 字段 | 落点 | 规则 |
|---|---|---|---|
| 数据龄分级 | `dataAgeMin` + `ageTier` | `B1` 请求、`C2` 响应 | `>90` 标"时效过期"；`>180` 只显示最后一次判决并标"不再更新" |
| NVS 时间恢复 | `timeSource` + `monotonicMs` | `A3` 响应、`B1` 请求 | `timeSource=UNKNOWN` 的记录标 `timeSuspect`，不进任何统计 |

## 7. 明确不做（写进方案，防止被追问时改口）

| 不做 | 理由 |
|---|---|
| MQTT / TLS（节点侧） | 局域网 HTTP；公网由 nginx 终止 TLS，节点不做证书轮换 |
| `POST /api/edge/approve` 之类放行接口 | 节点只给**四档建议 + 数据龄**，放行由人做；有这条接口就等于"自动放行系统" |
| 机载/车载的供电与振动相关接口 | 未验证，`stage=future` 且 `enabled:false` |
| 全网航路重规划入口 | 降的是决策粒度，不是能力 |
| 节点侧模型训练/上传 | 模型离线训练，端侧只推理 |
