## 2. 工单详情

### K-1（P0，3.0 h）让"概率档"真的参与决策

**现状**

```
53 条走廊 verdictProbability = 可飞   （100%）
复盘页自报：AI 改判 1232（观测档 1232 · 概率档 0）
概率档阈值（口径表）：待处置 p≥0.5、禁飞 p≥0.8
实测概率上限：0.2776
→ 概率档在结构上不可能触发
```

**改法（两条同时做，缺一不可）**

**K-1a 阈值落到可触发区间（1.5 h）**

在模型融合层（`traffic/decision/*`，即产出 `verdictProbability` 的那一段）把概率档阈值改为：

```python
# 建议：与「不可飞概率」的量纲一致，而不是与"禁飞"对齐
P_WATCH = 0.20   # 概率档：进入"建议改时隙"
P_BLOCK = 0.30   # 概率档：进入"建议改航/停飞"
```

依据：当前实测 p 分布在 0.04–0.28，取 0.20/0.30 可让 2–4 条走廊真正由概率档触发，且都在 0.28 附近，不会把整个网络停掉。

改完必须满足：复盘页第一行从「观测档 1232 · 概率档 0」变成「观测档 N · 概率档 M」，**M ≥ 1**。

**K-1b 写清"谁说了算"（1.5 h）**

在复盘页反事实区加一行固定文案（不依赖数据）：

> 概率档只允许更严，不允许更松：概率说他能飞、观测说不能飞时，按不能飞执行；概率说他不能飞、观测说能飞时，转人工复核（置信度 <0.65 直接转人工）。

并在「检验 → 口径与来源」增加一行：`概率档阈值 0.20 / 0.30`，与代码常量同源。

**验收**

- [ ] `cors.json` 中至少 1 条走廊 `verdictProbability == "不可飞"`
- [ ] 复盘页第一行 `概率档` 后面的数字 ≥ 1
- [ ] 口径与来源页能看到 `0.20 / 0.30` 两个阈值
- [ ] 关掉概率档（改回 0.8）后，复盘页概率档回到 0 —— 证明这个数字是真算出来的，不是写死的

> **风险提示**：不要让概率档阈值低于 0.20。当期三站能见度全部 9656 m、阵风最高 11.83 m/s，属于好天气；阈值压太低会让"好天气停飞一片"，反而被评委追打。0.20/0.30 是演示窗口内的安全区。

### K-2（P0，1.0 h）结论句的证据必须是"命中的那条判据"

**现状**

```
conclusion.text:
"长春 ↔ 吉林 等 10 条走廊当前观测已达禁飞级（3 站最低能见度 9656 m）；…"
```

同一页的判据面板写着：能见度 9656.1 m（阈值 <1000 m）**满足**、阵风 11.83 m/s（阈值 >10 m/s）**不满足**。

**改法**

`conclusion.text` 生成处（后端 `traffic/v2.py` 的 overview 组装段）改为：**从命中的判据里取最严重的一条**，拼成证据。

```python
# 伪代码
hit = verdict_basis(corridor)        # 返回 [{"metric":"阵风","value":11.83,"unit":"m/s","threshold":">10"}]
if hit:
    ev = f"{hit[0]['metric']} {hit[0]['value']} {hit[0]['unit']}（阈值 {hit[0]['threshold']}）"
else:
    ev = "模型概率"        # 没有观测命中时，不许拿能见度凑数
text = f"{name} 等 {n} 条走廊今日已触发停飞判据（{ev}）；模型给出未来 3 小时概率 {p}% —— " \
       f"「此刻已在阈值内」与「未来会不会」是两件事，本系统按前者处置。"
```

期望输出：

> 长春 ↔ 吉林 等 10 条走廊今日已触发停飞判据（**阵风 11.83 m/s，阈值 >10 m/s**）；模型给出未来 3 小时概率 28% —— …

**同时改词**：把「当前观测**已达禁飞级**」改为「**今日已触发停飞判据**」。"已达禁飞级"读起来像"能见度已经差到禁飞"，而系统实际做的是"阵风超阈值 → 停飞"。

**验收**

- [ ] 首页结论句的括号里出现的是「阵风 … m/s」，不是「能见度 … m」
- [ ] 括号里的读数与点进走廊后判据面板里标"不满足"的那一行完全一致
- [ ] 全文检索"已达禁飞级"命中 0 次（或只在确实由能见度触发时出现）

### K-3（P0，1.0 h）KPI 与口径表二选一，必须一致

**现状**

| KPI | 口径表定义 | 页面值 | 按定义应为 |
|---|---|---|---|
| 待处置走廊 | p ≥ 0.5 | 10 | 0 |
| 禁飞级走廊 | p ≥ 0.8 | 10 | 0 |

**两条路，选一条（推荐 B）**

**A. 让 KPI 服从口径**：`kpis.pending/high` 严格按 p 阈值算 → 当前会变成 0 条。
后果：首页两张红卡变成灰卡"0 条"，演示效果变差，且与"10 条走廊不可飞"的事实冲突。

**B. 让口径服从 KPI（推荐）**：KPI 保持 10 条，但**改标题 + 改口径表**。

```
卡片标题：禁飞级走廊  →  已触发停飞判据的走廊
卡片标题：待处置走廊  →  待处置走廊（观测判据命中）
口径表定义改成：
  已触发停飞判据的走廊 = 观测判据（能见度<1000 m / 阵风>10 m·s⁻¹ / 云底<300 m）任一条命中的走廊数
  分子：verdictObservation == 不可飞
  分母：全部城际走廊（53 条）
  来源：GET /api/traffic/v2/overview 的 kpis[high]
  责任人：规则引擎
并新增一行：
  概率档高概率走廊 = p ≥ 0.30，当前 0 条（与上一条分开统计，不合并）
```

推荐 B 的理由：系统当前**确实是观测判据在决策**（概率档 0 次改判），口径表应该如实写这件事。写真实的东西，比凑一个好看的 0 更抗问。

**验收**

- [ ] 态势页两张 KPI 的标题与口径表逐字一致
- [ ] 口径表里能查到该 KPI 的分子公式
- [ ] 用 curl 拉 `overview.kpis`，值 = 页面值
- [ ] 「概率档高概率走廊」单独一行，且与「已触发停飞判据的走廊」不混

### K-4（P1，2.0 h）阵风阈值合并为一个常量，并让地图长出对应风险区

**现状**

```
走廊判据（前端显示）：阵风 > 10 m/s
风险区几何 extremeThresholds.gustMps = 17.0
结果：10 条走廊"不可飞"，地图上只有葫芦岛 1 个风险区，与那 10 条没有一条重合
```

**改法**

1. 把阵风阈值收进 `config/rules-v1.json`，只留一个键 `gustMps`，走廊判定与风险区派生**都读它**。
2. 取值建议 **12.0**：
   - 保留 10 会与"17 才生成内核"继续冲突；
   - 提到 12 后，长春 11.83 恰好落在阈值下方 → 10 条走廊会变成 0 条，演示又空了；
   - **所以取 11.5**：长春 11.83 仍命中，能保住"有事件可讲"，同时 17 → 11.5 让地图真的画出长春周边的禁止进入内核。
3. 前端判据面板的阈值文案从后端读，不写死。

**验收**

- [ ] 全局检索 `10 m/s`、`17.0` 只命中配置文件的同一个键
- [ ] 地图上能看见至少 1 个风险区落在被判"不可飞"的走廊附近（截图对比：走廊列表 + 地图同屏）
- [ ] 判据面板阈值文字 = `config/rules-v1.json` 的值

### K-7（P1，1.0 h）首屏加载兜底

**现状**：主包 2,166,717 B（gzip 613,290 B）。本轮复现 1 次 `ERR_CONNECTION_RESET` → 页面白屏、0 个元素、0 字、无提示、无重试。4 次复测均成功（5.1–5.5 s）。

**改法**（改 `index.html`，不碰打包）

```html
<div id="app">
  <div id="boot">正在加载运行态势…</div>
</div>
<script>
  // 主包 6 秒还没挂载，就给出可点的重试
  var t = setTimeout(function () {
    var b = document.getElementById('boot');
    if (b && document.querySelectorAll('body *').length < 20) {
      b.innerHTML = '加载较慢或网络中断<br><button onclick="location.reload()">重新加载</button>';
    }
  }, 6000);
</script>
<script type="module" crossorigin src="/assets/index-xxx.js"
        onerror="document.getElementById('boot').innerHTML='脚本加载失败<br><button onclick=location.reload()>重新加载</button>'"></script>
```

注意：`onerror` 对 `type=module` 有效，但要在同源脚本上；若担心兼容，用 `window.addEventListener('error', ...)` 捕获 `target.tagName === 'SCRIPT'`。

**验收**

- [ ] 断网后刷新，3 秒内出现中文提示 + 可点按钮
- [ ] 正常网络下首屏看不到 "正在加载" 闪烁（<200 ms 即被替换）

## 4. 不要做什么

1. **不要把概率档阈值压到 0.10 以下**，去凑"AI 改判了很多"。当期是好天气，压太低会出现"晴天停飞一片"，比现在更难看。
2. **不要为了 KPI 好看保留 10 条却继续写 p≥0.8**。这是本轮最容易被抓的一处，改口径比改数字便宜。
3. **不要删掉"本帧无低能见度""回波占本帧 0.3%""随机样本少的格子不要读成稳定结论"这些话**。这些自我限制是全站最值钱的部分，删了就从"严谨"变成"普通"。
4. **不要取消 600 秒缓存**。首屏秒开靠它；K-1 已经把 `no-store` 只加在重建请求上，这是对的。
5. **不要把 2.16 MB 继续往下压**。本版已经 gzip 到 613 KB + 懒加载分块，再压就会重演上一版"压体积压出两个 bug"的剧本。
6. **不要改 `?case=fog-20250105` 的链路**。它上一版刚修好、本轮未回归，动它风险大于收益。

## 5. 三个必答题的答辩话术

### Q1「能见度 9656 米，为什么是禁飞级？」

**改前（现在）**：答不上来。

**改后（K-2 + K-4 之后）**：

> 这 10 条走廊不是被能见度判的，是被阵风判的。长春站实测阵风 11.83 m/s，超过我们 11.5 m/s 的停飞阈值，按规则停飞。能见度 9656 米确实很好，所以它在那三条判据里是"满足"。我们原来那句话把证据写错了，已经改成引用真正命中的那条判据。

**要点**：主动承认"原来写错了"，比辩解有力。评委记得住的是你敢认。

### Q2「把模型摘掉，结果会变吗？」

**改前（现在）**：不会。这是最伤的一题。

**改后（K-1 之后）**：

> 会。这一版之前确实不会——概率档阈值定在 0.5/0.8，而今天的概率最高只有 0.28，结构上触发不了，等于模型只在旁边看。我们已经把概率档阈值降到 0.20/0.30，现在有 N 条走廊是概率档先报、观测档后确认的。方向只有一个：**概率档只允许更严，不允许更松**——概率说他能飞、观测说不能飞，按不能飞；概率说他不能飞、观测说能飞，转人工，置信度低于 0.65 直接转。

**加分动作**：现场把阈值改回 0.8，复盘页概率档立刻回到 0，再改回来。**这个"可复现的因果"比任何 PPT 都有力。**

### Q3「无人机配送在哪？地图上怎么一架都没有？」

**改后（K-5 之后）**：

## 8. 可直接发给队友的话

> 这一版 H-1（地图时间覆盖）和 H-2（切通道不同步）都修好了，我实测确认：mapFlights 覆盖到 T+479.8、每 30 分钟都有飞机；切虚拟的请求带上了 `mode=virtual` 且 `fromDiskCache=false`。构建提示也变具体了。这三件是真进步。
>
> 但这一版有三处"自己跟自己打架"，评委一问就中，麻烦优先处理：
>
> **1）首页那句结论的证据引错了。** 现在写的是「…已达禁飞级（3 站最低能见度 9656 m）」，可点进走廊看判据面板，能见度 9656.1 m 标的是「满足（阈值 <1000 m）」，真正不满足的是阵风 11.83 > 10 m/s。用一条证明天气很好的数据去论证禁飞，这一句会被评委直接抓住。请把 `conclusion.text` 改成引用**命中判据**里最严重的那条，并且把「已达禁飞级」改成「已触发停飞判据」。
>
> **2）「禁飞级走廊 10 条」跟口径表对不上。** 检验→口径与来源里定义是「不可飞概率 ≥ 80%」，但 53 条走廊实测 pMax 最大只有 0.2776，按定义应该是 0 条。要么 KPI 按定义算（会变成 0），要么把口径表改成「观测判据命中的走廊数」。建议后者——因为系统现在确实是观测判据在决策，如实写更抗问。
>
> **3）复盘页那一行自己写着「AI 改判 1232（观测档 1232 · 概率档 0）」。** 概率档阈值 0.5/0.8，今天概率最高 0.28，结构上永远触发不了，等于模型只在旁边看。建议把概率档阈值降到 0.20/0.30，让它真的参与；同时保留「概率档只允许更严」这条原则。改完请顺手把「关掉概率档 → 概率档回到 0」验一遍，证明这个数不是写死的。
>
> 另外两个小的：
> - 地图上配送无人机只有 24 条（飞行汽车 698 条），T+15 之后全程 0 架。分桶抽样时配额被飞行汽车占满了，建议按类型各分各的桶（CAR 每桶 20、DELIVERY 每桶 18，总量还是 600 左右）。
> - 态势页右下写「全网络调度总结」，四态合计却是 1575，真实全量 7760；复盘页又写着「参评 7336 / 7760」。同一个系统两个数，建议后端用 stats 直接算四态（只多 80 字节），标题和数字就对上了。
>
> 最后建议加个首屏兜底：我这边复现过一次主包 `ERR_CONNECTION_RESET`，整页白屏、没有任何提示。`index.html` 里加个 6 秒超时提示 + 重新加载按钮就行，答辩现场撞上就麻烦了。
>
> 修完这五项，我把验收清单再跑一遍。
