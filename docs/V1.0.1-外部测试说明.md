# 天窗智巡 V1.0.1 · 外部测试说明

> 这份文档是给帮忙找 bug 的同学看的。看完这一页就能跑起来、知道该往哪看、以及哪些**不用报**。

---

## 一、这是个什么系统

低空交通（飞行汽车 / 城际无人机）的**协同运行管理系统**。核心是四件事：

1. **航线网**：全国 319 个城市、30 个省级单元、492 条航线，四级下钻（全国 → 大区 → 省 → 市）；
2. **运行处置**：每架在飞都是独立班次对象，有编号、申请/计划/实际三个时刻、放行许可、高度剖面、风险概率与裁决依据；
3. **气象保障**：逐市实况 + 雷达回波 + 走廊逐公里剖面，回波压线时自动改航；
4. **边境合规**：距国境 50 km 内的城市退出通航，越界监视按航路逐段几何测量。

技术栈：Vue 3 + Vite（前端 5180）、FastAPI（算法服务 8600）、Spring Boot（网关 8085）。

## 三、这一版（V1.0.0 → V1.0.1）改了什么

**V1.0.0 是东北单网**（3 省 36 城 53 走廊）。**V1.0.1 把能力递进到全国四级网**，不是重做：V1.0.0 的 14 个视图、8 个入口、东北那张运行图全部保留。

新增：

| 能力 | 说明 |
| --- | --- |
| 全国四级航线网 | 319 城 / 30 省 / 56 机场城市 / 492 航线（**省内 201、接驳 261、跨省 30**） |
| 边境退出通航 | 距**邻国**不足 50 km 的 11 个城市整体退出，节点与航线一并删除 |
| 越界监视改几何 | 492 条航路按约 8 km 加密逐点求距，10 km 硬限 / 30 km 预警带，实测最近 18.2 km |
| 班次对象化 | 编号、申请-计划-实际、许可、9 点高度剖面、风险与裁决依据、反事实暴露 |
| 全国低能见度模型 | ml-v3（**logistic 28 维，不是树模型**）：319 城 open-meteo 逐小时、22.7 万样本、按时间 8:2 切分，测试 AUC 0.9488 / Brier 0.120 / TS 0.256 / recall 0.959 / precision 0.259（事件基线 6.6%） |
| 雷达回波 | RainViewer 公开瓦片，前后端双端裁到国界内，境外回波不显示 |
| 多源气象 | open-meteo 为主、wttr.in 补缺、落盘快照兜底；每城标注数据来源 |

修掉的主要缺陷（都附了根因，方便你判断有没有修干净）：
地图上的「红色小方框」伪影、后端随机崩溃（shapely 并发）、气象接口限流打满导致整块变空、
同屏两个时间基准、台账横向溢出、全国页误挂东北的建场进度条、雷达瓦片一次拉 140+ 张。
详细版见 [`docs/V1.0.1-发布说明.md`](docs/V1.0.1-发布说明.md)。

## 四、跑起来（三步）

前置：Windows 10/11、Python 3.12+（64 位）、Node.js 20+、JDK 17 或 21（**须含 `javac`**）。

```powershell
# 1) Python 虚拟环境（路径必须是 backend-python/.venv，启动器硬编码）
cd backend-python
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt

# 2) 前端依赖
cd ..\frontend
npm ci

# 3) 回根目录，一键启动（起 Python + Java + 前端）
cd ..
.\start.bat
```

**首次装依赖必须联网**，之后日常运行不用再拉包，但城市底图与雷达瓦片仍需联网。

先跑一次环境自检更省事：双击 **`check-env.bat`**（检查十一类环境与端口占用，会直接告诉你能不能启动）。

浏览器打开 `http://127.0.0.1:5180`，左侧「运行总览」→「全国航线网」就是这一版的主页面。

## 五、请重点看这几块（高价值找茬区）

按"容易出问题、又不容易被发现"排序：

**1. 数字自洽**

- 顶部总数、六个大区卡片、省块、市块，四级的「航线 / 在飞 / 停飞」是否互相矛盾？
- 台账里数出来的在飞行数，和顶部「在飞」是否一致？
- 右栏气象列表的城数，和「气象实况 N 城」是否一致？
- 大区卡片之和**故意大于**全国总数（跨省航线两端各计一次），悬停卡片有说明——这是口径不是 bug。

**2. 层级下钻与返回**

- 全国 → 大区 → 省 → 市 逐级下钻，再逐级返回，选中态、跟随态、地图视野是否残留？
- 下钻过程中切换「态势 / 台账 / 情报 / 处置」四个视图，状态会不会串？
- 在省级点「返回上级」，是否回到正确的父级而不是跳回全国？

**3. 时间轴**

- 拖时间滑块，航班位置是否连续移动、不闪跳？
- 跨零点（滑块拉到接近 24:00 / 00:00）时，班次时刻是否还说得通？
- 切换倍速（15/60/300）再暂停，画面是否停在同一时刻？
- 同屏所有时刻是否都是**北京时间**（曾经出现过 UTC 与本地混排）。

**4. 气象与回波**

- 回波色块的边界是否只在国内（境外应完全没有颜色）？
- 雷达回波里有小到只有几个像素的区域时，是否还画成「空心小方框」（这是上一版修掉的伪影，请重点验）？
- 逐市气象断网或外部接口限流时，界面是否给出**可读提示**（如「补数中」「旧数据」），而不是空白或 0/0？
- 点「定位回波」「定位雾区」，视野是否飞到对应区域？

**5. 班次详情与取证**

- 点地图上的飞机 / 点台账某行，详情是否是**同一架**？
- 「跟随此班次」后地图是否把这一架钉在中心？「复位」「切层级」「改选别的班次」是否能退出跟随？
- 点「取证」，五步证据链的每一行是否都带来源标签（SIM / PUBLIC / DERIVED / OFFICIAL）？
- 取一个**该时刻不在飞**的班次，是否会如实说「不在飞」而不是编一条出来？

**6. 走廊剖面**

- 点任意一条航线，逐公里剖面是否与地图上的绕飞情况对得上？
- 剖面里标「强回波 112–147 km」这一类区间，和地图上那条琥珀色绕飞航迹的起止位置是否吻合？

**7. 窄屏**

- 把浏览器窗口拖到 1366×768、1280×800，工具栏是否折行到挡住地图？右栏是否被压到看不清数字？
- 窗口拉得很大（1920 以上）时，地图两侧是否出现大片空白？

## 六、已知限制（这些**不用报**）

1. **立体是「透视倾斜」不是真三维**。试过用 maplibre 起真三维（俯角 + 建筑体块 + 高程地形），在测试机上两次把浏览器主线程拖死，且公开高程瓦片在本网络不可达，已回退。源码里保留了组件与说明，**当前「立体」按钮=倾斜视角**。
2. **地形高程不叠加**。原因同上，界面与源码都如实标注。
3. **交通数据是模拟（SIM）**，不是真实航班。只有气象、雷达、机场情报来自公开实况源。
4. **大模型取证在未配 api-key 时只走规则链**，界面会标 `NOT_CONFIGURED`。这是设计，不是失败。
5. **气象备源只补 80 个城市**（省会 + 机场城市）。主源被限流时，其余城市没有实况是**预期行为**，界面会写「补数中」。
6. **台湾、西藏、香港、澳门不纳入通航**，地图仍完整绘制（含南海诸岛与九段线小图）。这是需求，不是遗漏。
7. **跨海航线只有大连—烟台一条**。
8. **东北三省那套**（36 城、4 个模型、TS/Brier 三基线、分歧台账、反事实三基线）仍是 V1.0.0 原样，没有并入全国层。
   注意：**全国层的东北大区是 31 城**，因为边境 50 km 规则退出了黑河 0.9 / 丹东 1.2 / 延边 25.6 / 白山 35.6 / 鸡西 44.8 km 五城。
   36 与 31 两个数各自成立，**不要互相对照**。
9. **ml-v3 的三条限制**（主动交代，别当新 bug 报）：
   ① 输入与标签同源（都用 open-meteo 模式能见度），指标衡量的是"模式能见度的演变可不可预测"，不等于实测命中率；
   ② `precision 0.259`——4 次报警有 3 次是假的，低 TS 主要来自**误报多**而非漏报多（recall 0.959）；
   ③ 模型是 **logistic（28 维线性）**，`kind:"logistic"`，不是东北那套森林。

## 七、怎么报 bug

提到 https://github.com/shuanzi4653/ALC/issues ，按这个格式写，我修得快：

```
标题：[页面] 一句话症状

环境：Windows 11 / Edge 版本 / 窗口分辨率 / 是否开了 DevTools
页面：#/situation/national 的「态势」视图
时刻：时间轴 09:00（滑块 60）
步骤：
  1. 点「情报」→ 再点「态势」
  2. 点任意一架飞机
  3. ……
期望：……
实际：……（截图）
控制台：有报错就把那几行贴上来（F12 → Console）
```

**三条提高命中率**：
- 写明**时间轴时刻**。这系统里大量东西随分钟变，「复现不了」十有八九是时刻不同。
- 写明**当前层级**（全国 / 哪个大区 / 哪个省 / 哪个市）。同一个按钮在不同层级行为不同。
- **截图带上顶部那一行总计和右栏**，我能立刻判断是数据算错还是只是显示错。

## 八、口径纪律（报 bug 前先看这一条）

这个项目的数字分四类，混着看会误判：

| 标签 | 含义 | 例子 |
| --- | --- | --- |
| `SIM` | 本系统模拟生成 | 航线、班次、时刻、在飞数 |
| `PUBLIC` | 公开源实况 | 逐市气温/风速/能见度（open-meteo、wttr.in）、雷达回波（RainViewer）、机场 METAR |
| `DERIVED` | 本系统按规则算出 | 风险概率（规则或 ml-v3）、绕飞改航、雾区面、越界距离 |
| `OFFICIAL` | 法规/管制口径 | 边境管制带、净空规则 |

**边境 50 km 与 10 km 管制带都是本项目的保守执行口径**：《无人驾驶航空器飞行管理暂行条例》第十九条第二项只写「一定范围」，**没有写公里数**。所以如果你看到「法律规定 10 km」这种表述，那是错的，欢迎指出来。

## 九、一句话

重点找**自相矛盾**（数字对不上、同屏两个口径、状态残留）和**空态**（没数据时界面说了什么），这两类比样式问题值钱得多。谢谢。
