## 2. 第 1 层：为什么"今天没有橙色"是对的（设计层）

### 2.1 橙色的确切含义

图例 `/api/traffic/weather` 的 `radar` 段与前端 `vt` 提示文案写得很清楚：

```
风险区 ＝ 实测雷达回波（≥35 dBZ）：
  橙黄 ＝ 对流回波，航线须绕飞
  深橙 ＝ 对流内核，禁止进入
35 dBZ 以下层状降水以淡紫画出，可穿越、不构成限制。
```

也就是说，图上"有天气"**不等于"有橙色"**。这是一个**三档分级**：

| 回波档 | 阈值 | 颜色 | 语义 | 会不会拦航路 |
|---|---|---|---|---|
| 层状降水 STRATIFORM | 15–35 dBZ | **淡紫** | 可飞越 | **不会** |
| 对流回波 CONVECTIVE | 35–45 dBZ | **橙黄** | 须绕飞 | 会 |
| 对流内核 STRONG | ≥45 dBZ | **深橙** | 禁止进入 | 会 |

### 2.2 今天的实测回波里，对流是 0

我按后端下发的 relay 协议，手动把 2 个瓦片回传后端，然后再查一次接口：

```json
{
  "available": true,
  "summary": {
    "channel": "CMA_RADAR_TILES",
    "drivesGeometry": true,
    "slot": "2026-10-21T02:42:00Z",
    "slotAgeMinutes": 15.9,
    "echoFraction": 0.003265,
    "components": 0,
    "bands": {
      "STRATIFORM": { "components": 0, "areaKm2": 0.0 },
      "CONVECTIVE": { "components": 0, "areaKm2": 0.0 },
      "STRONG":     { "components": 0, "areaKm2": 0.0 }
    }
  }
}
```

回传那一刻后端返回的原始统计是 `present 31156 / convectiveFraction 0.0007 / strongFraction 0.00003 / maxDbz 46.0`——**全图有回波，但落到东北作业区里，达到 35 dBZ 的成片区域是 0 块。**

> **这是本次诊断最重要的一个事实：即使雷达链路完全正常，今天这片空域也不该有橙色。**
> 换句话说，**你在首页看到的"没有橙色"，在物理上是正确的。**

### 2.3 前端本来就在用文案解释这件事

`index-D2WK8QNK.js` @2034732，地图底部状态条的唯一来源：

```js
o = t === uc.READY ? `风险区：雷达回波已叠加`
  : t === uc.QUIET ? (i ? `雷达：仅层状降水（可飞越，已标出范围）` : `雷达：本作业区当前无回波`)
  : `雷达回波不可用`
```

三态对应：`READY`（有 ≥35 dBZ 几何）/ `QUIET`（有回波但都不到阈值）/ `DOWN`（取不到）。

你 02:50 截图上的那一句 `雷达：仅层状降水（可飞越，已标出范围）`，是 **QUIET 态的正常文案**——**不是降级、不是报错、不是"数据坏了"。**

### 2.4 这一层不要改

**不建议**为了"好看"把层状降水也画成橙色。理由有三条：

1. **口径上撒谎**：图例明写"淡紫可穿越"，画成橙色等于自己推翻自己的判据表；
2. **评委一追问就塌**：只要有懂气象的评委问一句"这 35 dBZ 以下为什么算绕飞"，整套避让几何的可信度就没了；
3. **不是核心叙事**：你的核心叙事是"**天气进判据→进调度→有代价对照**"，不是"图好看"。

**要做的是 W-R3：把"没有"讲成"有理由的没有"**（见 §4.3）。

## 3. 第 2 层：服务端取不到，浏览器能取，但这条链路没跑（链路层）

### 3.1 服务端真的取不到（这是真故障）

```
radar.error = "最近 12 个时次均不可用：
               2026-10-21 10:54Z (6,2) HTTP 403;
               2026-10-21 10:48Z (6,2) HTTP 403;
               2026-10-21 10:42Z (6,2) HTTP 403"
radar.summary.note = "雷达帧不可用时风险几何只来自气象通道，本通道不产出任何几何。"
```

源站 `image.data.cma.cn` **按 IP 把你们的服务器整站拒了**（HTTP 403）。这不是代码问题。

### 3.2 系统对此的处理方式，其实是正确的

- **没有拿模型估算冒充实测**：`qualityFlags` 明确写了 `MODEL_ESTIMATE_NOT_STATION_OBSERVATION`；
- **口径是"不使用"，不是"没风险"**：`RADAR_UNAVAILABLE` 对应的文案是"**本计划不加入回波避让几何**"（`nl` 字典 @104891），
  而不是"本区域无风险"——**这个措辞比大多数商业产品都严谨**，值得保留；
- **主动防陈旧**：`slotAgeMinutes > 90` 时整个雷达图层会被清空（`Ie()` 里 `n = t > J9` 直接 `return`），**宁可画白，也不拿两小时前的回波冒充现在**。

**这三条都是优点，请不要在这次修复里改掉它们。**

### 3.3 设计上留了后门：浏览器代取

后端下发了完整的取图说明（`relay`）：

```json
{
  "needed": true,
  "tileBase": "https://image.data.cma.cn/tiles/China/RADAR_L3_MST_CREF_GISJPG_Tiles_CR",
  "tileUrlTemplate": "…/{YYYYMMDD}/{HH}/{MM}/3/{y}/{x}.bin",
  "zoom": 3,
  "grid": [[6,2],[6,3]],
  "cadenceMinutes": 6,
  "maxLookbackSteps": 12,
  "slotTimezoneOffsetMinutes": 480,
  "tileBytes": 131072,
  "postTo": "/api/traffic/radar/tiles",
  "note": "服务器出口被源站按 IP 拒绝（整站 403），而浏览器在住宅网络上可直取。
           取到后请原样回传字节，不要在浏览器里做任何换算或裁剪。"
}
```

前端也实现了（@2097206）：

```js
async function sue(e, {fetchImpl:t=fetch, nowMs:n=Date.now()}={}) {
  if (!ku(e)) return { ok:false, reason:'NO_INSTRUCTIONS' };
  const steps = Dte(n, e.slotTimezoneOffsetMinutes ?? 480, e.cadenceMinutes ?? 6, e.maxLookbackSteps);
  for (const step of steps) {
    const tiles = await oue(e, step, t);          // 逐个取 .bin，校验 131072 字节
    if (tiles) {
      const stored = await Bo(e.postTo, { method:'POST', body: JSON.stringify({ slot: step.iso, zoom: e.zoom, tiles }) });
      return { ok:true, slot: step.label, stored };
    }
  }
  return { ok:false, reason:'NO_SLOT_AVAILABLE', tried: steps.length };
}
```

### 3.5 失败对用户完全静默

中继状态胶囊只在 `status !== 'idle'` 时才渲染（@2115870）：

```js

  : (… ` 雷达 ` + (status==='ok' ? slot : status==='running' ? '代取中' : '代取失败') …)
```

于是完整的失败链条是：

```

       → 以为是"功能没了"
```

**这就是你这次的体验来源。**

## 4. 第 3 层：首页把两个开关过滤掉了（前端 bug，必须修）

### 4.1 代码

`index-D2WK8QNK.js` @2085648（首页地图组件）：

```js
let o = new Set([`weather`, `risk`, `radar`]),
    s = q(() => hu.filter(e => !o.has(e.key)).map(e => ({ ...e, label: e.key === `radar` && n.radarLabel || e.label })));
```

`hu` 是完整的 **9 项**图例：

```
car · delivery · weather · fog · wind · radar · zones · events · observations
```

去掉 `weather / risk / radar` 后，**首页只剩 7 项**。

### 4.2 DOM 实测：那两个开关不存在

```
飞行汽车 ✓ | 配送无人机 ✓ | 低能见度（雾）✓ | 背景风向 ✓ | 固定管制区 ✓ | 运行事件 ✓ | 观测等级点 ✓
```

**注意：不是"被关掉了"，是"根本没有这个 DOM 节点"。** 各项初始值都是 `z(!0)`（@2101019：`ne=z(!0) … ae=z(!0)` 全是 `true`），所以既不是状态残留、也不是用户误关。

> **为什么会这么写**：推测是上一轮做"首页减法"时，把"气象风险区 / 雷达回波"当成"工业口径"顺手滤掉了（同时把 `weather` 也滤了）。但 `weather` 与 `radar` 是**两个有独立语义、用户唯一能控制天气可见性的开关**，不是冗余项。

### 4.3 顺带的排版隐患：图例条已经溢出了

DOM 实测：

```
.hs-layers   x=21  w=1305  scrollWidth=1532  overflow-x=visible
父 .hs-panel x=21  w=1307  overflow=hidden
```

现在 7 项刚好塞进 1305px；**一旦按 W-R1 把 9 项放回来，最后 1–2 项会被 `overflow:hidden` 切在右边**——不报错、不打折，就是安静地消失。所以 **W-R1 必须同时改 `overflow-x`**。

### 4.4 为什么会变成"能跑但看不见"

这是本次最值得记下来的教训：

> **"隐藏一个控件"在前端是最低风险的动作——不报错、不崩、测试也不会红。**
> 但它对用户是**最高破坏性的动作**：功能还在，路径没了。
> 这类 bug 只有真人上手点才会发现，**而评委就是那个真人。**

| ① | `Lt()` 从未被调用 | 首页 → 天气加载完成 → 无中继触发 | 服务端 403 后就此死掉 |
| ② | 失败只在 `idle → failed` 之间，但 `idle` 不渲染 | `Nt.value.status === 'idle' ? K('') : …` | 全程静默 |
| ③ | 无手动重试入口 | — | 网络恢复后也不会重试 |

#### 改成什么

**① 接上触发点（关键）**

在"天气帧加载成功"和"图层开关被打开"这两个时机调 `Lt(weather)`：

```js
// 天气帧落地后
async function loadWeather() {
  const w = await fetchWeather();
  x.value = w;
  await Lt(w);            // ← 新增：若 w.radar.relay.needed 则尝试代取
}

// 用户打开「雷达回波」开关时
function mt(key) {
  const t = dt[key];
  if (!t) return;
  t.value = !t.value;
  if (key === 'radar' && t.value) Lt(x.value);   // ← 新增
}
```

**② 胶囊四态全渲染（不要漏 idle/failed）**

| 状态 | 显示 | 颜色 | 可点 |
|---|---|---|---|
| `idle` 且 `radar.available === false` 且 `relay.needed` | `雷达 未取到 · 点此代取` | 琥珀 | ✅ 点击 → `Lt()` |
| `running` | `雷达 代取中…` | 中性 | — |
| `ok` | `雷达 10:42` | 绿 | 点击 → 显示 `slotLocal` |
| `failed` | `雷达 代取失败 · 详情` | 红 | ✅ 点击 → 展开 `detail`（人话，见下表） |

`detail` 的人话映射（前端已有 `It()`，直接用）：

| reason | 人话 |
|---|---|
| `NO_SLOT_AVAILABLE` | 本机浏览器也没取到可用的雷达时次（已试 12 档），源站可能对本网络同样拒绝 |
| `POST_FAILED` | 瓦片已取到，但后端未接受：`{message}` |
| `NO_INSTRUCTIONS` | 服务端未下发取图说明，未发起代取 |
| `NO_LAYER_OPEN` | 雷达图层未打开，未发起代取 |

**③ 失败后 60s 自动重试一次，并允许手动点**

前端已有节流变量（`Ft = Date.now() + 60_000`），把 `idle` 也纳入判断即可。

#### 为什么优先级仅次于 W-R1

因为它决定了**"能不能真的拿到回波"**。今天因为没对流，拿不拿到不影响橙色；但**只要哪天有对流，这条链路不通，你依然看不到橙色**。这是"演示那一天会不会翻车"的分水岭。

#### 怎么算改完

```js
// 造一个失败：拦截请求
const realFetch = window.fetch;
window.fetch = (u, o) => String(u).includes('image.data.cma.cn')
  ? Promise.reject(new Error('mock block')) : realFetch(u, o);
location.reload();

// 期望：45 秒内，顶栏出现「雷达 代取失败 · 详情」，且看起来可点
// 而不是一片沉默
```

### 5.4 W-R3 · 把"没有"讲成"有理由的没有"（1h，**投入产出比最高**）

#### 现在的问题

用户（包括你）看到"没橙色"，第一反应是"功能坏了"。因为界面上**没有任何一句话解释"为什么本来就不该有"**。

地图底部那句 `雷达：仅层状降水（可飞越，已标出范围）` 是**结果**，不是**理由**——它没说"没有达到 35 dBZ 的对流，所以按设计不画橙色"。

#### 改成什么

**① 状态条补一句"为什么"**（`M` 计算属性里，`QUIET` 分支）：

```diff
  o = t === uc.READY ? `风险区：雷达回波已叠加`
    : t === uc.QUIET ? (i
-       ? `雷达：仅层状降水（可飞越，已标出范围）`
+       ? `雷达：仅层状降水 ${formatArea(stratiformArea)} km²（15–35 dBZ，可飞越）；本帧无 ≥35 dBZ 对流，橙色按设计不出现`
        : `雷达：本作业区当前无回波（0 块 ≥35 dBZ）`)
    : `雷达回波不可用`
```

**② 图层面板的 `雷达回波` 项后面加一个"当前帧"小注**

| 情形 | 小注 |
|---|---|
| CONVECTIVE + STRONG 都是 0 | `本帧无对流（0 km²）` · 灰字 |
| 有 CONVECTIVE | `对流 12.4 km²` · 橙字 |
| DOWN | `不可用` · 红字 |

**③ 图例说明（`vt` 文案）末尾加一句"本帧口径"**

```
…35 dBZ 以下层状降水以淡紫画出，可穿越、不构成限制。
【本帧】实测雷达 10:42，层状 845.5 km²，对流 0 km² —— 因此本帧不出现橙色。
```

#### 为什么这一条最值

- 它把"看不到"从**缺陷**变成**证据**：评委看到"0 km² 对流，所以不画橙色"，读到的是**系统的克制**，而不是**功能缺失**；
- 它**零风险**：只改文案，不改任何几何或判据；
- 它**正好命中评分细则里"AI 技术应用"的"可解释性"那一栏**。

#### 怎么算改完

```js
// 实时场景
console.assert(/本帧无 ≥35 dBZ 对流/.test(statusBarText), '状态条缺"为什么没有橙色"');
// 有对流时（用雾天案例或虚拟通道验证）
console.assert(/对流回波（35—45 dBZ）\d/.test(statusBarText), '有对流时应显示面积');
```

#### 答辩稿（请原样记住这三句）

**第一句（主动交代，抢在评委问之前）**

> "我们的雷达图层是**实测通道**，回波分三档：**层状（淡紫，可飞越）、对流（橙黄，须绕飞）、强对流内核（深橙，禁止进入）**。
> 今天这片空域实测只有层状降水，**所以图上没有橙色是对的**——我们不会为了画面好看把紫色画成橙色。"

**第二句（如果评委问"那今天这个图有什么意义"）**

> "它的意义是**证明我们没在编**。图上每一块紫色都对应中国气象数据网那一刻的反射率拼图；右上角写着观测时次，超过 90 分钟我们会**主动清空**，宁可画白，也不拿旧回波冒充现在。"

**第三句（把话题拉回核心叙事）**

> "如果评委想看天气真正影响航线的画面，我建议看**雾天案例**——那里不是回波，是能见度：三站实测 998 米，21 条走廊判为禁飞，然后进入反事实对照。"

> ⚠️ **绝对不能说的一句话**："我们有雷达，所以一定会有橙色。"
> 评委只要核一下当天的回波，整段"数据诚实"的叙事就崩了。**你的优势恰恰是"没有就是没有"，别自己丢掉。**
