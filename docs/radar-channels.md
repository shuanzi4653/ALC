## 1. 结论先行（调研快照，未采用）

**推荐双轨，主力换成星图云 Rain-Pulse，中国气象数据网降为备选。**

| 顺序 | 渠道 | 定位 | 是否需要新凭据 |
| --- | --- | --- | --- |
| 主力 | **星图云 Rain-Pulse 全国降水雷达图层** | 直接给 dBZ 回波强度 + 1 km + 6 min + 覆盖黑龙江 | 需要（免费注册 + 实名认证 + 申请 token，可自助办理） |
| 备选 | 中国气象数据网 雷达组网拼图 | 官方权威图像产品，6 min，近 24 h | 需要（已验证可免费取得，路径见 3.1） |
| 付费升级 | 彩云天气 雷达图 / 实况栅格图 | 直接给 PNG + WGS84 边界，含 2 h 外推 25 帧 | 需要（企业套餐，须商务采购） |
| 辅助 | NOAA 上的 Himawari-9 公开桶 | 卫星红外云图，10 min，**无需注册** | 不需要 |
| 仅人工 | 中国天气网 / 中央气象台 雷达拼图网页 | 肉眼核对 | 不需要 |

**最小可行路径**：注册星图云 → 实名认证 → 下单免费体验版 → 控制台建应用取 token →
用 `productCode=sev&meteCode=ste` 取回波强度图层。全程自助，不需要单位资质。

**如果连注册都不想办**：NOAA 的 Himawari-9 公开 S3 桶无需任何凭据即可匿名读取，
10 分钟一帧，但那是**卫星红外反演**，只能派生「对流云团」风险，不能称作雷达回波。

## 2. 渠道核查明细

### 2.1 星图云开放平台 Rain-Pulse 全国降水雷达图层（首选）

| 项目 | 核查结果 |
| --- | --- |
| 服务地址 | `https://api.open.geovisearth.com/v2/rain/pulse/radar`（GET） |
| 鉴权 | 「服务密钥授权，您需要申请 token，将 token 作为必填参数拼接在服务地址中」 |
| 申请路径 | 注册账号 → 完成用户认证 → 下单 → 控制台「我的应用」创建 token |
| 产品类型 `productCode` | `sev` = 3857 可视化产品（返回 png 红黑图 + json）；`mfv` = 墨卡托投影整图（返回 webp 彩图 + json） |
| 要素 `meteCode` | `ste` = **回波强度，单位 dBZ**；`precipint` = 降水强度，单位 mm/h |
| 空间范围 | 中国区 73~135.5°E, 12.15~54.2°N（**含黑龙江全境**） |
| 更新频次 | 6 分钟 |
| 空间分辨率 | 1 km |
| 返回时段 | 查询时间 **过去 1 小时 + 未来 2 小时**，逐 6 分钟 |
| 数据格式 | png / webp + json |
| json 字段 | `min` `max` `width` `height` `lonmin` `latmin` `lonmax` `latmax` |
| 同厂商配套接口 | `https://api.open.geovisearth.com/v2/rain/pulse/nowcast` 逐分钟降水（未来 2 h，121 点，中国区） |
| 免费额度 | 公开材料称免费体验版 **10000 次调用、QPS 10**，覆盖 6 个接口，其中含 RainPulse 降水临近预报 |

**为什么它最合适**：`meteCode=ste` 直接返回 **dBZ 回波强度**，不需要从图片颜色反查；
`json` 里带 `lonmin/latmin/lonmax/latmax` 与 `min/max`，可直接把像素值还原成物理量；
`sev` 红黑图的设计目的就是「黑图配合 json 文件可求解出各像素点气象要素值」。
这与我们需要的「阈值化 → 生成风险多边形」流程天然对齐，省掉整条色彩反演链。

**未核实项（不要当成已知）**：
1. 雷达图层本身是否落在免费体验版范围内。产品价格页与体验专区均为前端渲染，
   静态抓取读不到数字；公开博客只确认免费版含「RainPulse 降水临近预报」（点查询），
   未确认含「全国降水雷达图层」（图层文件）。**注册后须在控制台确认**。
2. 调用量限制的确切条款（`调用限制请点击这里查阅` 指向的是需要登录的页面）。
3. 授权协议对「非商业演示 / 竞赛作品」的措辞。

### 2.2 中国气象数据网（现有实现，凭据可免费取得）

**关键新发现：凭据不是拿不到，是之前没走对页面。**

公开的接入教程显示完整路径为：

1. `https://data.cma.cn` 注册并邮箱激活；
2. 首页 → **服务接口** (`https://data.cma.cn/market/index.html`)；
3. 进入产品详情页（例：`https://data.cma.cn/Market/Detail/code/A.0012.0001/type/0.html`）；
4. 选择台站 / 要素 / **服务时长「免费试用 7 天」** → 完成选购；
5. 在 **我是买家 → 我的订单 → 套餐 → 接口详情** 中查看生成的 **API 密钥（userId / pwd）**；
6. 调用 `http://api.data.cma.cn:8090/api?...&userId=...&pwd=...`

另一条不依赖订单页的路径（官网注册类型说明）：

- **个人实名注册用户**「可在中国气象数据网浏览、查询和下载中国气象局最新公布的
  《基本气象资料和产品开放清单》内的气象数据和产品」；
- 即 **实名注册 + 签署《气象资料用户使用协议》** 即可走 **网页数据检索/下载**，
  不必持有 API 密钥。2015 年《基本气象资料和产品共享目录》开放了地面、高空、
  气象卫星、天气雷达、数值天气预报 5 类 17 种产品，雷达图像产品的共享级别标注为
  「个人实名、单位实名注册用户访问」。

**雷达产品清单**：雷达资料共 9 类，本系统关心的是天气雷达组网系列，均为**图像产品**：

| 产品 | 时间分辨率 | 说明 |
| --- | --- | --- |
| 天气雷达组网组合反射率图像产品 | 6 min | 资源登记编号 `1.2.156.416.CMA.D3.J002.L3.OT.TX.CHN.CR.DAY.0P01.1` |
| 天气雷达组网基本反射率图像产品 | 6 min | |
| 天气雷达组网回波顶高图像产品 | 6 min | |
| 天气雷达组网液态垂直累积含水量图像产品 | 6 min | |
| 天气雷达组网 24 小时降水估测图像产品 | 1 h | |

空间范围 0.01°×0.01°，数据窗口**近 24 h**，数据源中国气象局气象探测中心。
（`cma_radar.py` 里写的 7 天窗口是按 API 的 `getRadaFileByTimeRange` 限制写的，
与产品页「近 24 h」的口径不同，两者需要在使用中确认，不要假定一致。）

**局限**：
1. 全部是 **PNG 图像产品**，没有数值化的 dBZ 字段 → 必须自己做
   **颜色 → dBZ 反查表**，这一步属于「本系统推断」，必须单独标注（见第 5 节）。
2. API 走 **明文 HTTP，凭据写在查询串里**（`cma_radar.py` 已对此做了完整防护：
   `safe_url()` 打码、`STRICT_TRANSPORT` 可拒绝明文传输）。
3. 「免费试用 7 天」不是长期方案；长期要靠实名注册的网页下载或单位资质。

### 2.3 彩云天气 雷达图 / 实况栅格图（付费升级位）

| 项目 | 核查结果 |
| --- | --- |
| 实况接口 | `GET http://api.caiyunapp.com/v1/radar/images?lon=&lat=&level=1|2&world_map=true&token=` |
| 预报接口 | `GET http://api.caiyunapp.com/v1/radar/forecast_images?...` 最新一帧实况 + 未来 2 h 共 25 帧 |
| `level=1` | 单站雷达，过去 20 帧，4~6 分钟一帧 |
| `level=2` | 雷达拼图，5 分钟一帧；`world_map=true` 切新版拼图（EPSG:3857） |
| 返回 | `images[][0]` 图片 URL + `images[][1]` 时间戳 + `images[][2]` **边界 `[南纬, 西经, 北纬, 东经]`（WGS84）** |
| 访问限制 | **「本部分 API 属于增值服务，仅提供给企业套餐开发者，如需采购请联系彩云商务」** |

**价值**：接口形态与我们需要的完全一致——**直接给图片 + WGS84 边界 + 时间戳**，
前端叠加不需要任何坐标换算猜测；且自带 2 小时外推帧，正好补上「未来时隙风险」。
另有「实况栅格图」（降水强度图 / 可用区域 mask / 雨雪类型 mask，最近 10 帧）。

**成本**：必须走商务采购，没有自助免费路径。作为**中期升级位**保留，
竞赛作品阶段不建议优先。

### 2.4 华风爱科（weathercn.com）——确认不可用

`apidoc.weathercn.com` 确有**国内雷达拼图**：

- `{api|apidev}.weathercn.com/china_radar_mosaic/v1/image_list?apikey=&requestDate=&accessKey=`
- **`china_radar_mosaic/v3/`** 为「国内雷达拼图 V3（含外推）」
- 图片 URL 形如 `China_Mosaic_20220412_091200.png`，须在返回 URL 上再拼 `apikey` + `accessKey`

但**每个请求都要 `apikey` 和 `accessKey` 两把钥匙**，且平台注明
「只适用于中国大陆地区访问，非大陆访问可能返回 403」。手头只有一把标准 Key、
没有 secret，因此**维持原判：雷达不可用**。若将来能拿到第二把钥匙，这是一条
权威性很高的路径（含外推的组网拼图）。

## 3. 落地路径（推荐）

### 3.1 三步走

**第一步（今天就能做，零成本）**：注册星图云 → 实名认证 → 下单（选免费体验版）→
控制台建应用取 token。下来后立刻做两件事：
1. 用 `productCode=mfv&meteCode=ste` 取一帧 webp 彩图，确认能覆盖黑龙江；
2. 用 `productCode=sev&meteCode=ste` 取同一时次的 png 红黑图 + json，
   核对 `lonmin/latmin/lonmax/latmax` 是否落在 126°E / 46°N 附近，验证像素→dBZ 还原。

**第二步（并行，零成本）**：注册中国气象数据网个人实名账号，走网页数据检索下载
一帧组合反射率图像产品，与星图云同帧做**交叉比对**。两条独立来源能互相验证，
也是「不把未验证写成已验证」的必要动作。

**第三步（按需）**：若星图云雷达图层收费或配额不足，转向彩云商务报价
（企业套餐，含 WGS84 边界与外推帧）。

### 3.2 接入位置（对应现有文件，不新建架构）

现有抽象已经够用，新增源应当**沿用同一套契约**：

| 落点 | 现有参照 | 新增内容 |
| --- | --- | --- |
| `backend-python/traffic/weather_sources.py` | `PROVIDER` 开关、`weather_snapshot()` 单一归一入口、`qualityFlags` 显式降级、`provider_status()` | 新增 `radar_snapshot()` 与雷达源开关；降级必须走 `PROVIDER_FALLBACK_*` 同款标注 |
| 新模块 `traffic/geovis_radar.py` | `cma_radar.py` 三原则：凭据不进日志（`safe_url`）、不产出半成品、`provenance` 随结果返回 | token 同样只从加密存储读，绝不写进 `application.yml` |
| `backend-python/traffic/secret_store.py` | 已有 `CMA_API_USER_ID` / `CMA_API_PASSWORD` | 新增 `GEOVIS_TOKEN`（复用现有加密存储与指纹机制） |
| 前端 `frontend/src/traffic/runtime.js` | `classifyMapError`、`staticZoneSurfaces` 等纯函数集中处 | 新增雷达图层标签/降级说明纯函数，便于 `node --test` 覆盖 |
| 前端 `CityTrafficMap.vue` | 冷色 = 固定管制空域，暖色 = 气象风险 | 雷达派生风险区**走暖色**，与禁飞区冷色严格分开 |

### 3.3 反演链的三个必答问题

若走图像产品（中国气象数据网）而非 dBZ 接口：

1. **色标从哪来**？必须取到官方图例配色，不能凭肉眼看图定阈值。
2. **反查表如何记录**？`provenance` 里必须区分
   `OBSERVED_DBZ_FIELD`（接口直接给 dBZ）与 `IMAGE_COLOUR_REVERSE_LOOKUP`（本系统推断）。
3. **反演误差如何暴露**？给不出置信区间就必须标 `DERIVED_FROM_IMAGE_PRODUCT`，
   不允许在界面上呈现为「实测回波」。

## 5. 纪律约束（不得省略）

1. **雷达回波 ≠ 空域管制。** 派生风险区是「建议规避区」，不得渲染成禁飞区，
   不得与 `fixed-zones.json` 的固定管制区共用配色与图例。
   现有前端已确立：冷色 = 固定管制空域，暖色 = 气象风险。雷达派生区归暖色。
2. **不把未验证写成已验证。** 未做交叉比对前，状态只能是
   `SIMULATION_ASSUMPTION_UNVERIFIED` 或 `DERIVED_FROM_IMAGE_PRODUCT`。
3. **数据来源必须可溯。** 每个雷达快照要带 `provider` / `dataset` / `retrievedAt` /
   `validAt` / `qualityFlags`，沿用 `weather_sources.py` 的既有字段命名。
4. **凭据不进版本库、不进日志、不进聊天记录。**
   API 密钥一律走 `secret_store` 加密存储；URL 输出前过 `safe_url()`。
5. **禁止抓取未授权网页。** 中国天气网 / 中央气象台雷达图只作人工核对。
6. **词汇纪律（硬）**：**亮温 → dBZ 禁止换算**（两者不是同一物理量）；
   `nowcast_cn` 单位未验证 → **只暴露原始编码，不换算不解释**。
7. **合成帧必须在上游打标记**（2026-09-18 增）。见下方 §7。

## 6. 运行时实测 / 虚拟通道（2026-09-18 落地）

雷达通道现在可在**实测**与**虚拟**之间**运行时切换，无需重启**，由 `weather_control.py` 控制。

| 模式 | 数据来源 | 关键字段 |
| --- | --- | --- |
| `measured`（**默认**） | CMA 公开组网组合反射率瓦片 | `provider='CMA_DATA_NET'`；失败即 `available:false` |
| `virtual` | `weather_sim.py` 生成（离散对流单体 + 尾随层状降水盾 + 生命史 + 平均风平移） | `provider='SYNTHETIC_RADAR'`、`synthetic:true`、`source='SYNTHETIC_RADAR_CREF'` |

- 虚拟帧与实测帧**逐字段同构**（字节级兼容 `cma_tiles.frame()`），强度分档沿用同一条阈值
  （15/35/45/60 dBZ），因此**下游几何代码无需任何分支**。
- 同一 `seed` + 同一时次可**逐字节复现**。
- 接口：`GET/POST /traffic/weather/mode`；界面上是 `实测气象` / `虚拟气象` 两个并列按钮。

**两条硬判据（由单测锁定）：**

1. **实测模式下真实源失败必须如实返回失败**，**绝不用合成帧顶替**。
2. **合成帧必须处处显式标注**。

---

## 7. 为什么标记必须在上游打（踩坑记录）

`radar_field.derive()` 会在**自己的输出里硬编码** `provider: 'CMA_DATA_NET'`。
这意味着：

> 一个在下游才补标记的方案是行不通的 —— 下游不但不会补，还会**覆盖**成实测口径，
> 于是生成的合成帧被读成**国家组网实测**。而前端文案写的正是「实测雷达」。

因此标记必须在 `weather_control.radar_frame()` **打在上游**，且在四个地方同时生效：
`provider` / `synthetic` / `source` / `sourceNote`，外加前端图例与警示条。

> **记一笔**：用户曾口头要求「不带标记」，**没有照做**。理由是上述硬编码会让
> 不带标记的合成帧在下游被当成实测数据流通 —— 标注是这条通道唯一的意义所在。
