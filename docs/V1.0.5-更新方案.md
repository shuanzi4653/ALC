## 1. 页面结构：删掉页内 tab，一个分节只放一个视图

### 现象
首页正文顶部有一条 `态势 | 台账 105 | 情报 56 | 处置 11`（图 1、图 2），
和左侧导航的第 3 项「处置」重复；`运行总览` 打开后又是同一张地图，
`气象监测` 打开的地图也和首页一模一样。

### 病根（已核对代码）
`NationPanel.vue:792` 的 `nrn-tabs` 用四个按钮切换 `view`，
而 `TrafficWorkbench.vue` 已经在 `nationViewOf()` 里把分节映射到视图：

| 分节 | 现在渲染 | 视图 |
|---|---|---|
| 态势 / 运行首页 | NationPanel | `map`（同时暴露 4 个 tab） |
| 运行总览 | NationPanel | `ledger`（**同一组件，只是初始视图不同**） |
| 气象监测 | NationPanel | `map` + `mode=weather` |
| 处置 | NationPanel | `alerts`（又从首页 tab 能进一次） |

也就是说：**四个视图早就各有归属，tab 条是第二套入口**。两套入口同时存在，
于是"首页里有个处置、左边还有个处置"。

另外 `运行情报` 页顶还有一条 `运行情报 [全国][东北] 东北三省·V1.0.0 原页`（图 4），
是第三套作用域切换（`scope=nation/ne`）。

### 改法
1. **删除 `nrn-tabs` 整条**（四个按钮一起删），`hideTabs` 这类开关一并下线。
   视图仍由分节决定，不再让用户在同一页切四个视图。
2. 分节 ↔ 视图固定成一对一：

   | 左侧导航 | 内容 | 数据 |
   |---|---|---|
   | 态势 · 运行首页 | 地图态势（`map`） | 全国 |
   | 态势 · 运行总览 | 台账（`ledger`，逐班表） | 全国 |
   | 态势 · 气象监测 | 情报（`intel`，班次/空域两张表） | 全国 |
   | 处置 · 事件处置台 | 处置（`alerts`） | 全国 |
   | 走廊 · 走廊剖面 / 运行情报 | 不变 | 全国 |
   | 推演 · 推演 | 六段链路 + 走廊浏览器 | 全国 |
   | 日志 | 运行日志 | 全国 |

3. **删除两处 `scope-bar`**（`TrafficWorkbench.vue:649` 运行总览、`:699` 情报/台账），
   即图 4 那块。理由：全国已经是默认且唯一的运行范围，东北那套只在
   「算法机理」作为**历史版本**保留（那一页本来就写着"非当前在跑的"）。
4. 删掉因 tab 删除而变成死代码的：`.nrn-tabs` 样式、`view` 的 tab 分支、
   `intelTab`（如果情报页改成一次显示两张表）。

**验收**：首页正文不再出现 4 个 tab；`处置`、`台账`、`情报` 各只有一个入口；
13 个分节仍逐个可打开，无空页。

## 2. 城市名与航班标签：全显 + 可拖动 + 按缩放分级

### 现象
现在标签按"密度档"藏，用户看到的是"有的城市有名字、有的没有"，且拿不准为什么。

### 病根
`NationMap.vue` 的 `labels` 计算里有两道闸：
`limit = density==='slim' ? 18 : (level==='nation' ? 44 : 40)`；
以及 `ordered` 只收"省会 + 跨省端点 + rank≤2"。
全国层标签池实测 **80 个**（30 省会 + 57 跨省端点，有重叠），
1366×768 下地图只有 712 px 宽，80 个 10 px 的胶囊必然互相压。

### 改法
1. **取消数量闸与密度闸**：标签池里 80 个全部参与排布（下钻时仍只显示本省/本市，
   跨省的端点城市在下钻层隐藏——这条按你说的"不影响"保留）。
2. **用"分级"代替"隐藏"**：同一批城市，按缩放级别换形态，不是换集合。

   | 缩放 | 城市名 | 航班标签 |
   |---|---|---|
   | < 1.6（概览） | 只写名字，无胶囊底、9 px | 只写编号 |
   | 1.6–3（中） | 胶囊底 + 名字，10 px | 编号 + 高度 |
   | > 3（近） | 胶囊底 + 名字，11 px | 编号 + 高度 + 速度 |

3. **允许长按拖动**：按住标签 400 ms 进入拖动，松手后把偏移量写进
   `localStorage['alc.labelOffset.v1']`（按城市名 / 呼号记），刷新仍生效；
   提供"复位标签"按钮清空。
4. 重叠取舍：全显之后重叠不可避免，采用"**先放省会与端点，再放其余；
   重叠时降一级形态**（有底→无底）"而不是直接丢弃。

**验收**：全国层 80 个城市名全部出现；1366 下无"两个名字叠成一坨"（允许边缘相接）；
拖动一个城市名 → 刷新后仍在原位置；缩放到 3 倍 → 航班标签出现高度与速度。

## 3. 大模型 Key：读不到，但根因不是"没配"

### 现象
图 3：「大模型未配置（config 里没有 api-key）：这里给的是**规则证据链**…」
取证页整块变成降级说明。

### 病根（已核对）
`main.py:32` 的 `load_deepseek_cfg()` 只认两个来源：
1. 环境变量 `DEEPSEEK_API_KEY`；
2. `config/application.yml` 的 `deepseek.api-key`。
而 `config/application.yml:31` 现在写的是占位符 `"${DEEPSEEK_API_KEY:}"`，
`load_deepseek_cfg()` 见到以 `${` 开头就**直接当空**（第 39 行）。
后端是我用脚本起的进程，环境里没有这个变量 —— 所以"你配了"和"它读到"不是一回事。

### 改法
1. 增加第三个来源，并且**按顺序覆盖**：
   `环境变量` > `config/secrets.env`（gitignore，单行 `DEEPSEEK_API_KEY=sk-…`） >
   `application.yml` 的明文值 > 占位符（视为未配置）。
2. `/health` 与取证接口都回传 `keySource`（`env|file|yml|none`），
   前端未配置时把**该改哪个文件**写清楚，而不是只说"没有"。
3. 取证页在未配置时**不整块降级**：规则证据链照常显示（它本来就不依赖模型），
   只把"模型结论"那一栏标成"未启用"。
4. 配好之后跑一次真调用（`/agent/ask`）验证鉴权通，而不只看 `configured:true`。

**验收**：把 Key 写进 `config/secrets.env` 后重启，`/health` 的 `keySource=file`；
取证页显示"模型可用"；发起一次提问能拿到真实回复；Key 不出现在任何被跟踪文件里。

## 4. 点航班 / 处置 / 推演时自动暂停

### 现象
点开一架飞机或一条事件后，时间继续跑，飞机一边看一边飘，推演结论也跟着变。

### 病根
`NationPanel.vue:76` `playing` 默认 `true`，只有用户自己点「Ⅱ 暂停」才停；
`chooseFlight / openCorridor / openAlert` 都没有碰它。

### 改法
在"打开对象"的三个入口统一置 `playing=false`（并停 rAF 推进、把 `frameMinute`
对齐回 `minute`），右上角北京时间（`nav-timebase`）继续走真实时间，两者互不影响。
恢复播放仍由用户点按钮，不自动恢复。

**验收**：播放中点任意飞机 → 时间轴停住、飞机不再移动；点「▶」继续；
等待 30 秒，右上角北京时间仍然在变。

## 5. 走廊跳转偏移：算视野用的是旧尺寸

### 现象
从处置事件点进走廊，地图停在一片没有航线的空白处；航线跑到可视区外。

### 病根（实测，不是猜）
进入走廊页后测量：地图容器 **940×462**，航线包围盒在容器内 **top=509**（已经超出 462），
世界层 transform `matrix(4.2,0,0,4.2,-1734.79,-324.38)`。
`focusPts()` 的算法本身是对的（`pan = {x: VIEW.w/2 - cx*zoom, y: VIEW.h/2 - cy*zoom}`），
问题在 **`VIEW`**：它初值是 `{w:1000,h:640}`，由 `ResizeObserver` 在挂载后才写入真实尺寸。
走廊页从列表切过来时容器高度会二次变化，`focusPts` 用的是那之前的值，
于是整体偏下约 280 px；而且尺寸变化后**不会重新 fit**。

### 改法
1. `VIEW` 尺寸变化时（`ResizeObserver` 回调里），若当前处于"单条走廊/选中班次"
   状态，重新执行一次 `focusPts`（用 requestAnimationFrame 合并，避免每帧重排）。
2. `focusPts` 增加 `padding` 参数：留出容器内边距与底部图例高度，不把线贴到边缘。
3. 走廊页的 `lockView` 保持（禁缩放），但 fit 必须发生在尺寸稳定之后。

**验收**：从处置、日志、推演三个入口各跳一次走廊，航线包围盒完整落在容器内
（左/上/右/下均留 ≥ 24 px），中心偏差 ≤ 12 px。

## 7. 删掉地形 / 倾斜 / 三维；核实"实测 vs 虚拟"；密度三档重定义

### 7.1 删三维系
按钮在 `NationPanel.vue` 的 `.nrn-tools` 里（地形/倾斜/三维）。
连带删除：
- 前端 `NationGlobe.vue`（783 行）、`maplibre-gl` 依赖、DEM 相关 props 与 `?worker` 引入；
- 后端 `terrain_tiles.py` 路由（`/terrain/{z}/{x}/{y}.png` 那套 DEM 代理）与它的缓存目录；
- 三维相关的验收用例（`check102.mjs` 里 4 条）、`gpu.js` 的 `probeGPU` 降级链
  （若仍被"软件渲染"提示使用则保留，否则一并删）。

预计包体：`dist` 3.7 MB → 约 2.8 MB（maplibre 及其 worker 约 900 KB）。

### 7.2 「实测 / 虚拟气象」到底实现了没有
**实现了，但只做了一半**。实测对比（同一分钟、同一档）：

| 指标 | 实测通道 | 虚拟通道 |
|---|---|---|
| 回波环数 | 196（50 / 63 / 83） | **18（6 / 6 / 6）** |
| 放行 / 停飞 | 90 / 14 | **71 / 34** |
| 雾区 | 8 片 | **8 片（一模一样）** |
| 低能见度城市 | 10 | 10（未变） |
| `radar.stats` | 有 | **null（缺字段）** |

所以差距看着小，是因为：**虚拟只换了回波、且只有 6 个粗多边形，雾区完全没换**，
视觉上就"两坨差不多的色块"。而裁决侧的差别其实很大（停飞 14 → 34）。

### 7.3 虚拟气象按你说的口径重做
- 只替换**雷达回波**与**雾区**两样；气温、风、能见度实况**一律沿用真实**。
- 回波改成"一个像样的对流系统"：多单体 + 强弱嵌套（红⊂黄⊂绿）+ 随分钟缓慢移动，
  而不是每档 6 个孤立多边形。
- 雾区也走虚拟通道生成（现状完全没变，这是"差距不大"的主因之一）。
- payload 补齐 `stats` / `coverage`，右上角"回波 N"计数在两种通道下都成立。
- 页头角标从"虚拟气象 · 合成回波，非实况"改为
  "**虚拟气象 · 仅替换回波与雾，气温/风/能见度仍为实况**"，把边界写在脸上。

**验收**：虚拟通道下回波环数 ≥ 60、雾区片数与实测不同、气温序列逐值相同；
切换通道后裁决结果必然变化（停飞数不同）。

### 7.4 信息密度三档重定义
现在下拉是 `标准 / 精简 / 极简`（图 6），语义含糊。改为三档，与 §2 的分级联动：

| 档位 | 城市 | 航线 | 航班标签 | 备注 |
|---|---|---|---|---|
| **精简** | 只标点 + 名字（无胶囊） | 只画线，无端点标记 | 不显示 | 只看骨架 |
| **标准** | 定标胶囊 + 名字 | 线 + 端点 | 编号 + 高度 | 默认 |
| **详细** | 胶囊 + 名字 + 机场标记 | 线 + 端点 + 方向箭头 | 编号 + 高度 + 速度 + 状态 | 逐架看 |

顺序改为「精简 / 标准 / 详细」（从少到多），默认落"标准"。

**验收**：三档切换后标签元素数量单调递增；"精简"下没有任何航班标签与端点圆点。

## 8. 推演里的「口径与来源」：紧凑、完整、数据换全国口径

### 病根
这一页现在渲染的是 `OperationsConsole` + `caliberBlocks(session, weather, network)`，
参数全是**东北那套**（`session` 是 36 城计划）。所以页面上会出现
"36 城 / 53 条走廊"这种与全国 319 市并列的数字，既是重复也是口径错位。

### 改法
1. `/traffic/v2/nation` 增加一个轻量 `caliber` 段（复用已有字段，不重算）：
   来源、有效时刻、逐站观测数、回波环数、覆盖、城市/机场/走廊计数、净空计数。
2. 口径页改由 NationPanel 渲染（`mode='caliber'`），数据取全国口径。
3. 排版从"每块一个大卡片 + 长句"改成**两列紧凑表**：左列标签、右列值 + 一行注，
   每块最多 6 行；边界说明收进块尾一行小字。
4. 保留 `SOURCE_BADGES` 六个徽标的说明（这类"术语表"是加分项），但压成一行一个。

**验收**：页面上出现的城市/机场/走廊数与首页一致（319 / 56 / 492）；
整页在 1366×768 下不超过 2 屏；不再出现"36 城"。

## 9. 页头那行数字：换成指标块

### 现象
图 7：`492 条航线 · 在飞 111 架 · 绕飞 2 架 · 延期 37 架 · 低能见度 10 城`
——五个数用间隔号串成一句，哪个数对应哪个指标要靠位置猜；而且和右侧
`492 / 103 / 2 / 0 / 3` 那五个竖排数字是同一批数据的两套写法。

### 改法
删掉这句长串，改为**一横排指标块**（与右栏口径统一，但只留首页必需的 4 个）：

```
航线 492 │ 在飞 111 │ 绕飞 2 │ 停飞 0 │ 延期 37
          （每个数字下面一行小字：占全国 x% / 较上一时刻 +n）
```

- 变动量用 `▲/▼ + 数字`，涨用琥珀、跌用青（不用红绿，避免与"告警红"混）；
- 数字与右侧竖排统计**共用一个 computed**，避免两处各算一遍。

**验收**：首页页头不再出现间隔号长串；指标块数字与右栏同源；
有变动时出现 `▲2` 这类标记且颜色正确。
