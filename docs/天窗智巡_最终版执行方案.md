## 1. E-1　把"保守"策略改成真的更保守（P0，0.2h）

### 1.1 现在错在哪

反事实页给了三档策略。我三档都打了，在 T+00 / T+03 / T+06 三帧上做全字段 diff：

```
conservative  params={"incident": 20000, ...}  处置 2856 · 绕飞 2848 · 延误 8 · 暴露 2613→0
balanced      params={"incident": 10000, ...}  处置 2856 · 绕飞 2848 · 延误 8 · 暴露 2613→0
efficiency    params={"incident":  4000, ...}  处置 2664 · 绕飞 2656 · 延误 8 · 暴露 2613→0
                      ↑ 三档分得清          ↑ 后两档分不清（少 192 架次）
```

**`conservative` 与 `balanced` 的返回结果逐字节相同**，三帧都是。参数确实变了（20000 / 10000），但结果没变。

### 1.2 为什么变了参数却没变结果

雾案例里，绝大多数航班的**损失量远超 20000**——也就是说，不管门槛设在 10000 还是 20000，被跨过的都是同一批航班。逻辑上没有错，但展示上等于"这个按钮没接上"。

一句话根因：**门槛设在了"已经有差异"的位置之上。**

### 1.3 改法

把 `conservative` 的 `incident` 从 **20000 降到 15000**。

```python
# 找到策略参数表（三档 incident 应该在一起）
POLICY_PARAMS = {
    "conservative": {"incident": 15000.0, "delay": 1.0, "reroute": 25.0, "cancel": 180.0},  # ← 20000 改 15000
    "balanced":     {"incident": 10000.0, "delay": 1.0, "reroute": 25.0, "cancel": 180.0},
    "efficiency":   {"incident":  4000.0, "delay": 1.0, "reroute": 25.0, "cancel": 180.0},
}
```

**为什么是 15000 而不是别的数**：三档的间距现在是 20000/10000/4000（1:0.5:0.2）。改成 15000/10000/4000 后间距是 1.5:1:0.4，仍然是"越保守拦得越多"，而且 15000 落在"确实有航班分布"的区间里——大概率能让 conservative 真的多拦几十到几百架次。

**如果 15000 还是撞上同一个数**（保险起见先试一次），往下调到 **12000**。判据只有一条：**三档的 `rerouted` 必须互不相等。**

### 1.4 验收（三条，缺一不算过）

```
curl -H "X-ALC-Workspace: X" ".../v2/counterfactual?case=fog-20250105&minute=0&policy=conservative"
curl -H "X-ALC-Workspace: X" ".../v2/counterfactual?case=fog-20250105&minute=0&policy=balanced"
curl -H "X-ALC-Workspace: X" ".../v2/counterfactual?case=fog-20250105&minute=0&policy=efficiency"
```

1. 三条返回的 `b.rerouted` **两两不相等**，且 `conservative > balanced > efficiency`；
2. `a.exposure` 三档都是 **2613**（A 组不受策略影响，这是对的）；
3. `b.exposure` 三档都是 **0**（暴露都清零，这是卖点，不能变）。

界面上：进「5 复盘 → 复盘对照」，切三档策略，**绕飞架次必须跟着变**。

## 2. E-2　实时态别让人拖一个不动的滑块（P0，0.6h）

### 2.1 现在错在哪

评委不点案例、直接打开首页（**这是默认路径**），这时：

| 现象 | 实际 |
|---|---|
| 滑块可拖，范围 **0–480** | 案例只到 T+06，拖到 T+08 什么都没发生 |
| 拖到 T+06，时间基准显示 `T+06:00:00` | 表盘走了 |
| 结论、需复核、已触发、站况 | **一动不动** |
| 结论仍是「未来 3 小时内…」 | 时间已经不是"未来 3 小时" |

接口确认这是数据限制不是 bug：实时通道只有一份 METAR 观测，`timeBase` 恒为当前整点，六次请求同一个值。

### 2.2 改法：实时态不显示可拖的滑块，改成一句引导

**只改前端，一个 `v-if` + 一句文案。**

```vue
<!-- 时间轴区域 -->
<template v-if="hasCase">
  <input type="range" v-model="minute" min="0" :max="caseFrames * 60" />
  <span>时间基准 {{ timeLabel }}</span>
</template>

<template v-else>
  <div class="axis-live-note">
    <b>实时通道只有当前观测（{{ obsTime }}），没有分钟级预报。</b>
    要看雾从生成到消散的完整改判过程，请
    <button class="link" @click="enterCase">切到 2025-01-05 沈阳大雾案例 →</button>
  </div>
</template>
```

**这一段文案同时干三件事**：
1. 说清"为什么不能拖"（实时只有一份观测）——**这本身是加分项，是诚实**；
2. 把评委直接引到你想给他看的那条路（案例回放）；
3. 消掉 480 那个越界刻度（滑块不出现了，问题自动消失）。

### 2.3 如果只能改一行（极端情况）

那就在实时态给滑块加 `disabled`，并把 `max` 从 480 改成 **360**。最省事，但要牺牲那句引导文案——而那句文案是我们最想说的。

### 2.4 验收

1. 打开 `https://tianchuang.shuanzi.site/`（不带参数）：**看不到可拖的滑块**，能看到"实时通道只有当前观测…"这句；
2. 点「切到 2025-01-05 沈阳大雾案例」→ 跳到案例态，滑块出现、范围 0–360、能拖；
3. 案例态下拖滑块，KPI / 结论 / 处置按钮 / 地图站况**全部跟着变**（这版已验证正常，**别改坏**）；
4. 全站不应再出现"时间基准 T+06:00:00 但数据不变"的组合。

## 4. 明确不做（2 条，附理由）

**E-4　`fields=slim` 真瘦身 —— 不做。**
现在三种参数都返回 140,855 B，`slim` 参数被接收但没被消费。改它要动后端序列化出口，**这是全站 13 页共用的数据源**，改错一次全站白屏。而收益是首屏省 100 KB（0.2 秒）。**风险收益比不划算，最后一版不碰。**

**E-5　实时分钟级预报 —— 不做。**
实时源是每小时一份 METAR，要做出分钟级只能插值编造或套案例数据。**在"数据显示哪来的"这一问上，编出来的东西是负分。** 用 E-2 的文案说清"没有"，反而体现工程诚实。

## 5. 答辩现场：三步走 + 三个避坑

### 5.1 三步走（这套已经全部验证过，可放心用）

**第一步 · 首屏（30 秒）**
> 「这是 2025 年 1 月 5 日沈阳大雾的案例回放。T+00 的时候，28 条走廊需复核、19 条已触发停飞判据，最差的一条 31%。我把时间轴拖到 T+06——雾散了，0 条需复核、0 条触发。这 12 小时里，系统是逐帧给出改判的。」

（T+06 时手指口径小字：「这行在解释 28 和 34 差在哪——不是算错，是两个口径。」）

**第二步 · 一条走廊的改判（40 秒）**
> 「拖到 T+00，沈阳↔本溪不可飞概率 31%，四个判据三个命中停飞档。拖到 T+06，同一条走廊 7%，只剩观测判据命中谨慎档，判定从不可飞变成需谨慎。**同一条走廊，雾散了就该放开，系统自己改的。**」

**第三步 · 反事实（60 秒）**
> 「同一份运行计划、同一份气象快照，只改最后一层裁决规则。关掉 AI，**2613 架次**飞进不可飞走廊；开启 AI，**0 架次**，−100%。代价是绕飞 2848 架次、延误 8 班、320 分钟，占计划总时长 **0.1%**。AI 一共改判 3044 架次，其中观测判据 2640、概率档 404，三个数闭合。」

### 5.2 三个避坑（E-1 / E-2 没修的情况下必须遵守）

**坑 1：不要点三档策略按钮。** 现在保守和均衡答案一样。如果评委自己点了——话术：
> 「这个案例里，保守档和均衡档拦下的是同一批航班——因为雾最重那段，绝大多数航班的损失量都远超两个门槛。要看策略真的拉开差别，请看效率档：少绕 192 架次。」（**这是实情，不算狡辩。但最好还是修掉。**）

**坑 2：不要在默认（实时）态拖滑块。** 拖了就会发现数不动。正确做法：**开场第一句就说"我切到雾案例"，然后点横幅上的"回到案例"**，全程在案例态演示。

**坑 3：不要从深链直接进"复盘对照"。** 新浏览器首次进入要等 23 秒。正确做法：**先进首页，停 3–5 秒**（后台会把计划建好），再点导航进复盘对照，秒开。

### 5.3 如果被问到"为什么这个案例是 2025 年 1 月的"

> 「因为我们用的是**真实 METAR 实测**，不是仿真。2025-01-05 那天沈阳出现过 997.8 m 的浓雾，四个机场站都有实测报文，可以逐小时核。用真实数据的好处是：评委可以自己去 Iowa State ASOS 上查同一天的报文。」
