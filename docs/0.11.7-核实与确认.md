## 2. 三处要改方案

### 2.1 F-1 的"30 分钟回落豁免"应该改成**永久豁免**

方案 §1.5 写：

> 虚拟气象模式在切换后的 **30 分钟内**，允许任何人切回实测。

**理由不成立。** 方案自己给的话术是：

> 进虚拟态需要管理员，但退出虚拟态不需要 —— 我们不允许系统停留在虚拟状态而无人能恢复。

**这句话本身要求的是"永久可恢复"，不是"30 分钟内可恢复"。** 加上时限，就变成了"30 分钟后同样无人能恢复"—— 和现在这个死锁一模一样，只是把触发条件换成了"隔着开了个会"。

**改成**：

```python
ACTION_MIN_ROLE = {
    ...
    'weather-mode-to-virtual': 'admin',   # 进虚拟态要管理员
    'weather-mode-to-measured': 'observer',  # 回实测：任何人都可以
}
```

规则一句话：**往"更不可信"的方向要权限，往"更可信"的方向不要。** 这比时间窗更容易讲，也更容易验（判据：observer 能把 virtual 切回 measured，但切不过去）。

> 附带好处：这条规则本身就是答辩素材 —— "安全侧默认永远可恢复"。

### 2.2 F-2 的验收第 4 条，现有数据**做不到**

方案 §2.5 验收：

> - [ ] 地图上能看到沈阳周边的**雾区**（深灰 = 禁飞档 / 浅灰 = 偏低档）

**这条做不到。** 核实 `data/traffic/cases/fog-20250105.json`：

```
顶层键：caseId label kind timeBase displayTz window stations history frames source note
frames：7 条，每条 { t, ZYTX, ZYCC, ZYHB }   ← 只有 3 个机场站的值
history：是 dict（按站索引），也是 3 个站
```

**案例只有 3 个点的实测能见度，没有任何格点场或面。** 而 `lowVisibility.regions` 是**面**（由 open-meteo 的 36 城市格点聚类生成）。所以：

| 能做到 | 做不到 |
|---|---|
| `?case=` 带下去 → `validAt` 变 2025-01-05 | 地图上出现"沈阳周边的雾区面" |
| 状态条从「本帧无」改成「3 站实测 998 / 1593 / 2993 m」 | 深灰/浅灰两档雾区几何 |
| 右侧 21 条禁飞与左侧结论同一时间基准 | 面与"21 条走廊"在图上对应 |

**可选的第三条路（我建议做，但要如实标注）**：用 3 站实测能见度**派生影响圈**（≤6 km 深灰 / ≤12 km 浅灰，取 `config/rules-v1.json::visibilityM`），画成以站点为圆心的多边形，并在图例/状态条写明：

> 本案例只有 3 个机场站的实测能见度。图上雾区是**由这 3 个实测点派生**的影响范围（半径取判据阈值），**不是实测雾区面** —— 实测面需要格点场，本案例数据没有。

这条不违反"不合成气象"：**从实测点派生影响域**是插值/判据，不是编造观测值；前提是**必须标注它不是实测面**。

**工时：3h → 4.5h**（多出来的是"派生圈 + 标注 + 一致性断言"）。

### 2.3 `/metrics` 的 404 是路径测错

方案 §1.2（E-2 那节）说 `/metrics` 404。实测：

| 路径 | 状态 |
|---|---|
| `/api/traffic/metrics` | **200**（Prometheus 文本，8 条 `alc_*`） |
| `/metrics` | 404（顶层没这一条） |
| `/health` | 200（结构化，nginx 新增的 location） |

所以**不是没做，是顶层没挂**。

**要不要加顶层 `/metrics`？** 我倾向**加**：运维习惯就是 `curl host/metrics`，而 `/api/traffic/metrics` 需要人先知道前缀。成本是 nginx 加一条 location（10 分钟）。

## 4. 顺序：F-1 → F-3 → F-2 → F-5 → F-4

**与方案不同的一处：F-3 提到 F-2 之前。**

理由：F-3 只有 2h，而且是**纯减法**（改文案 + 接两个探针 + 升版本号），风险最低、收益确定（评委点开 `/health` 就能看见）。F-2 要动 weather 契约（前端 + 后端 + 派生几何），是这一轮**唯一有回归风险**的一张。**先把确定收益拿到，再动契约** —— 这与上一轮"E-1⑤ 先于 E-1①②③"是同一个道理。

F-5 提到 F-4 之前：F-5 是"把半成品收口"（`slim:true` 却说自己是胖的，这是**字段在撒谎**），比 F-4 的文案优先级高。

## 5. 我完全认同方案的三条判断

1. **"F-1 必须第一，因为它对着 25 分的创新性"** —— 双气象通道是全项目最硬的主张，按不动等于没有。我把它做成死锁，这是我的错。
2. **"后端静默忽略 `case` 比前端忘了传更坏"** —— 完全正确。前端至少有个"忘了传"的理由，后端这是"传了也不认还不吭声"。
3. **"`slim: true` 却说自己是胖的"** —— 字段名与内容不一致，是最难发现的一类错：它不报错，只让读代码的人相信一件假事。
