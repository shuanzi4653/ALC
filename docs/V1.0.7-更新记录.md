## 1. 为什么不是"照收 PR"

大佬的诊断是对的，两个真 bug 确实存在：

- 原 `_band_of` 把**云边米色晕**判成强回波。同一帧真实瓦片复算：国界内被标成 STRONG 的像素里
  **99.4% 是云晕和云顶泛白，真正的黄红核心只有 98 px（0.12%）**。
- 原实现把**最深的降水核**（`(0,71,104)` ≈ 34 dBZ、深红 51–54 dBZ）当成杂波整档丢弃，
  50 dBZ 反而被放大成 60 —— 冰雹核消失，而且非单调。

但 PR 交付的实现有三处不能再往下走：

| 问题 | 实测 |
|---|---|
| dBZ 是**手调分段拟合**，不是查表 | 对官方 Universal Blue 色表，15–50 dBZ 段平均 **+9.96 dBZ**、最大 **+13.80**；真 23 被算成 32（进"对流"）、真 28 被算成 41（进"强回波"），门线整体前移 12–16 dBZ |
| 阈值 5 份副本，其中雷达侧两份都漂了 | `cells` 活码 32/41、`_band_of` 死码 32/41、`cma_tiles` 权威 35/45、`NEXRAD_LUT` 断点 34/46、前端字面量 35/45 |
| 图像塞进主载荷 | 覆盖率 2% 就撞 820 KB 门槛；且 `upscale=2.0` 被截断成 1.498，纯插值白付 49% 字节 |

第一条的后果最重：同帧 **STRONG 面积 2.2253 vs 真值 0.0038 平方度（586×）**、CONVECTIVE 41×，
回波像素只有 24.9% 与真值同档 —— 一场 20–30 dBZ 的层状小雨被画成大片橙红强对流。
第二、三条让"图上的颜色"与"绕飞几何"第一次来自不同阈值：实测 **7.1% 的回波格子已判对流、
会让航线绕开，图上却是深绿；4.6% 已判"禁止进入"，图上根本没变红**。

## 2. 后端改了什么

### 2.1 反查层：拟合 → 官方色表（阻断项）

- 新增 `COLOUR_TO_DBZ`（RainViewer `rainviewer_api_colors_table.csv` 的 Universal Blue 列，
  15–74 dBZ 每 1 dBZ 一色，共 51 项）与 `REACHABLE_DBZ`（51 个代表值）。
  精确 RGB 一次命中；查不到的抗锯齿混合色走最近色回退，**距离超过 40 就判无回波**（不硬塞）。
- 65–74 dBZ 同为白色，代表值取 **70**（与源图观感一致，14 级色板最顶格终于用上）；
  **75 dBZ 以上是纯绿溢出标记色，不入表**。
- 删除 `_pixel_dbz` / `_band_of` / `_tile_range`（约 46 行）。这三个函数**零调用**：
  `fetch()` 走的是 `_tile_dbz_array`，PR 描述里说的"换成 `_pixel_dbz`"那条路从来没跑过，
  两条实现对紫色 `(168,64,220)` 还给不同答案（15.00 vs 62.00）。删掉死的那份，
  不一致就不存在了 —— 留着它，将来谁接回去，32/41 会以"新写的代码"身份复活。
- 瓦片 URL 由 `/4/1_1.png` 改 `/4/1_0.png`：`1_1` 会让降雪区走**雪色标**
  （实测本帧 6.76% 的回波像素是 `(195,255,255)` 系），单表反查对它们全给 0 —— 冬季 30+ dBZ 的雪带会被低估。

### 2.2 阈值：收敛成一份，且断点落在判据上

- 新增 `weather/dbz.py`（零 import 的纯常量模块）：`ECHO_FLOOR_DBZ=15 / CONVECTIVE_DBZ=35 /
  STRONG_DBZ=45 / SEVERE_DBZ=60` + `BAND_EDGES` + `band_of()` + `THRESHOLDS_DBZ`（四键）。
- `traffic/cma_tiles.py` 改为**再导出**这几个同名常量：名字与取值一字未变，
  `radar_field.py` 与三个雷达测试文件一行没动，但全仓只剩一个赋值点。
  （`weather/` 依赖 `traffic/` 实测三序皆通，不成环；仍然把常量放在 `weather/dbz.py`，
  理由是单一事实源 + 不让 `weather` 沾上 `cma_tiles` 的 urllib opener。）
- `radar_public.fetch()` 的三档门限改读常量，恢复 15/35/45。
- `NEXRAD_LUT` 断点 `34→35`、`46→45`：这两个数原来落在色块**中间**，
  于是 35 dBZ（绕飞线）与 45 dBZ（禁入线）根本画不成边界。实测只动 4,624/10,866,688 = **0.04%** 像素。

### 2.3 色阶：由「可达档位」推导，不是数出来的

`nexrad_scale()` 遍历 LUT，某档区间里没有任何可达代表值就丢弃 —— 得到 **12 条**：

```
10 档丢弃（反查下限是 15）；65 档丢弃（65–74 同色白，代表值 70）
15/20/25/30/35/38/42/45/50/55/60/70，60 的 until = 70
```

色板仍是 14 级（那是**编码**），图例 12 条（那是**刻度尺**），两者由同一条规则连接，不是拷贝关系。
`scale` 没有硬编码条数，改色板或改可达集合都会自动跟着变。

### 2.4 图像契约

| 字段 | 值 | 为什么 |
|---|---|---|
| `imageSize` | `[w,h]` | 前端据此判断"这张图是下采样还是上采样"，不再靠猜 |
| `imageScope` | `'nation'` | 贴图只用于全国视图；省/市层放大 6–8 倍后插值颜色不在色阶里，回退矢量环 |
| `scale` | 12 条 `{dbz, until, color}` | 图例不再手抄 |
| `thresholdsDbz` | 四键 `{echo, convective, strong, severe}` | 与 `cma_tiles`/`weather_control`/`weather_sim` 同形 |
| `provenance` | `method: IMAGE_COLOUR_REVERSE_LOOKUP` 等 9 项 | 纪律条款：颜色反算不许当实测 dBZ 外流 |
| `coverageBasis` / `maskApplied` | `LAND` / `true` | 掩膜后分母必须跟着换，否则覆盖率莫名掉到三分之一 |

`upscale` 默认改 **1.0**：原来 2.0 被 `4096/max(h,w)` 截断成 1.498，纯插值零信息、白付 49% 字节
（PNG 32.2 → 48.0 KB）。同时**去掉高斯模糊**：它在量化域、放大之前做，把 10–15 dBZ 从 6,714 像素抬到
16,417（+145%，图上凭空多一圈青晕），又把 55/60/65 三档共 39 像素抹成 0（冰雹核被吃掉）。
`transparency` 由 `bytes([0,255]*14)` 改 `0`（LUT 的 alpha 全是 255，那 14 字节是冗余）。

### 2.5 超时与失败路径

- 单瓦片超时 20 s → **6 s**；线程 24 → **32**；加 **45 s 全局 deadline**。
  原来最坏 `ceil(130/24) × 20 s = 120 s`，而前端三处 `timeoutMs: 90000` —— 上游一抖就白屏。
- **缺块闸门**：`fetched < 90%` 直接返回 `_empty` 且不落盘。
  以前 `fetched == 0` 仍返回 `available: true` / `cells: 0`，界面显示"全国无回波" ——
  假阴比报错危险：绕飞判定会据此全放行。
- 失败冷却 15 s → **60 s**（上游挂了时，15 s 窗口 × 130 张 × 串行锁会把三个接口一起拖住）。
- 缓存写盘改 `tmp + os.replace`（半截文件会让下一个进程 `json.loads` 失败），并只保留最近 6 帧
  （每帧约 230 KB、每天 144 帧 = 33 MB/天，原来无清理）。
- `nation._VIRTUAL_CACHE` 的失败结果不再永久缓存（`(None,None)` 写进去就一直到重启）。
  这个坑 PR 刚在 `_radar()` 上修掉，自己在虚拟气象上又踩了一次。

### 2.6 掩膜与去噪顺序

- 新增 `weather/china_geo.py`：`china.json` 的**唯一解析点**，同时供矢量并集与栅格掩膜；
  路径按 `backend-python/data/china.json` → `frontend/src/assets/china.json` 回退，
  两者都缺时抛 `ChinaGeoMissing`（而不是让 `except` 把异常吞掉、掩膜静默跳过）。
- 栅格掩膜去掉 `outline/width`：实测"逐省独立填充"与"一次画全 + 3px 描边"在 8,499,968 个栅格上
  差异为 **0**（省界严格共边），76 ms → 27 ms。
- **先掩膜再去噪**：去噪只看 8 邻域，在境外那 70% 上算是白算；邻域累加改 `uint8`
  （原来 int32 在 8.5 M 像素上峰值 144.9 MB）。

## 5. 这一轮没做的（有意留）

1. **`imageUrl` 独立端点**（ETag + immutable，PNG 单独落盘）：前端 `/api` 走 Java 网关（8085），
   新端点要 Java 侧一起改；本轮的 `upscale=1.0` 已把 image 从 71 KB 降到 30 KB、
   载荷 763 → 614 KB，820 KB 门槛余量从 7% 回到 25%。**V1.0.8 第一件事**，并须绕开
   `nation.py` 的 `_NATION_LOCK`（否则冷启动 15 s 期间图片请求被锁死）。
2. **虚拟气象图文同源**：`virtual_nexrad_image()` 用解析式（含 9 次谐波）出场，
   `_virtual_bands()` 用 6 个偏心椭圆 —— 图上红核可能落在矢量绿区之外。改法是把场生成抽成
   `virtual_dbz_field()` 供两边消费，代价是 `_virtual_bands` 从 ~0.3 ms 涨到 ~1.2 s（有 bucket 缓存兜）。
3. **`bands` 的 z6 采样步长**：忙帧（6% 覆盖）三档各 200 环上限会先打满（600 环 / 1,145 KB），
   载荷仍会破 820 KB —— 与 `ROUND_PIXELS` 一起评估，属采样精度权衡，不是本轮的渲染问题。

## 7. 独立检测与修复（同日，仍属 V1.0.7）

改完之后又做了一轮**分开的**自检：前端只靠眼睛（1366/1920 双分辨率、深浅双主题、运行首页/走廊页/省级下钻/虚拟气象五个场景 + 2 倍放大截取细节），后端只读代码加实测。查出三个真问题和一个观感问题，都已修，版本不变。

### 7.1 三处 P1

**① 全局止损永不触发（本轮自己引入的）**
`fetch()` 里 `started = time.time()` 是 epoch（1.79e9），`deadline = started + 45`，而 `grab()` 判的是 `time.monotonic() > deadline`（开机秒数，实测 12105）。两者差三个数量级，判据恒为 False —— 45 s 止损等于没写。改成 `started_mono = time.monotonic()` 与比较方同一时钟，并加了一条静态用例钉死（`deadline = started + ...` 一旦回来就红）。

**② 底图缺失时两条裁剪链都静默降级**
`china_geo.load()` 会抛 `ChinaGeoMissing`，但两个消费方各自 `except` 掉：栅格掩膜返回 None、矢量并集返回 None，一条日志都没有。后果是境外回波直接进绕飞判定，而载荷里原本只有栅格那条路径有标记。
现在：`nation.mask_status()` 统一报 `{vectorClipped, maskError}`，随载荷下发；`_china_mask` 去掉 `lru_cache`（缓存住 None 等于"一次读不到、整进程都不裁国界"），恢复后自动清空错误。实测模拟删除底图：`vectorClipped:false` + `maskError:"ChinaGeoMissing: …"`；恢复后自动回到 true。

**③ 走廊页把全国贴图放大平铺**
`:radar-on="true"` 固定开着，门控只看 `level`（走廊页也是 nation），于是那张全国图被铺到锁定的单走廊视野里：实测 `<image>` 元素宽 **2438 CSS px** 铺在 864 px 画布上，回波呈明显阶梯、95% 不透明把底图压死。门控补上 `props.lockView || props.soloCorridor`，回退矢量环。修复后该页 `hasImg:false`，观感回到 V1.0.6。

### 7.2 图例：量不到的尺不如不摆

上一版图例只看 `radarOn`，但省/市层与走廊页回退的是矢量环，那三层用的是 `.echo-weak/.echo-convective/.echo-strong` 一套柔色，一个都对不上 12 格 NEXRAD 色。中间试过"把矢量三色改成色阶里的 15/35/45"，视觉上绿得刺眼（纯 `#00ec00`），而且这套柔色当初是按"三档叠加不压成橄榄绿"调过的，不该为对齐图例推翻。
最终：**图例的显示条件从 `radarOn` 改成 `radarImage`** —— 这张尺量的是贴图的 12 档颜色，贴图不在就不摆。

### 7.3 新增可观测：反查失配

色表一旦被上游改掉，全部像素会静默走进最近色回退，图上要么全 0 要么全强，界面看不出区别。现在每帧统计 `reverseLookup = {hitPixels, missPixels, resolvedFromNearest, missRatio, degraded}` 随载荷下发。
实测本帧：`hit 136,368 / miss 181,323（57.1%）/ resolvedFromNearest **0**` —— 说明"查不到"的那些像素（半透明边缘、米色云晕）全部被距离上限正确地判成无回波，没有凭空造出回波。`degraded` 的判据是"总像素 >5 万且 hit 为 0"，即色表已经不是我们认识的那张。

### 7.4 顺带

- 掩膜加回缓存，但**只缓存成功结果**（失败不缓存，避免老坑）。实测二次命中同一对象，省掉每帧 8.5 M 像素的重算。
- 来源文案改成"先判有没有数据、再判虚实"：虚拟气象 + 取数失败时原来会写成「模拟回波（演示包）」，可屏幕上根本没回波。
- 浅色下 70 dBZ 的纯白块与白面板同色，给色条加了内阴影边框。
- 模块 docstring 的产物字段清单补全（原来还停在只有 bands/coverage 的年代）。
