### 1.1 规划期发现的一条既有缺陷（本轮不修主线，但必须先说）

规则阈值有**两份文件**：`config/rules-v1.json`（外部，2 512 B）与 `backend-java/src/main/resources/rules-v1.json`（打进 jar 的 classpath 副本，2 316 B）。`RuleProperties` 的优先级是 **外部 → classpath → 内置默认**。实测两份**内容不等**：

| 差异 | 后果 |
| --- | --- |
| classpath 副本里 `thunderProb` **没写 `required:false`** | Java 的 `required` **默认 true**。一旦回落到 classpath 副本，雷暴概率变成"必需字段"，而 open-meteo 不发布该字段 → **每轮都以"缺字段"被拒** |

交付包带 `config/`，所以正常路径没事；**但只要换个 cwd 启动 jar，就静默回落到旧副本**。
它不是本轮主线，但它决定了本轮校准怎么写：**改阈值必须同时改两份，并加一条"两份语义等价"的判据**（§8 A5），否则"改完没生效"只会发生在别人的机器上。

## 4. 技术内核

### 4.1 三层分工（口径纪律，报告与答辩统一）

| 层 | 是什么 | 参赛材料里怎么表述 | 不许怎么表述 |
| --- | --- | --- | --- |
| **标注** | DeepSeek 按公开运行下限辅助打标 + 人工仲裁 | "辅助标注，用于构造训练标签；已用人工仲裁计算一致性 κ" | "专家标注""观测真值" |
| **算法主体** | **ExtraTrees / RandomForest 轻量集成模型** | 指标、特征重要性、危险漏报下降**全部归它** | 把 DeepSeek 说成算法核心 |
| **解释** | DeepSeek 走既有 `/traffic/explain` | "把模型结果翻译成自然语言研判" | "用大模型做风险分级" |

一句话版本：**模型判几档，大模型负责怎么说，标注只是造训练集。**

### 4.2 任务定义

输入单小时气象特征 → 输出 `level`（四档，与 `FlightLevel` 同词）、`confidence`（森林叶投票比例，**不是常数**）、`top3`（因子 + 取值 + 单位 + 方向）、`modelVersion` / `labelsVersion` / `provenance`。

### 4.3 特征（含冬季，按实测字段名）

| 类别 | 字段 | 说明 |
| --- | --- | --- |
| 风 | `windSpeed` / `windGust` | 10 m 平均风与阵风，m/s |
| 降水 | `precipMmh` / `rain` / `snowfall` | `snowfall` 是**真实字段**（cm/h） |
| 派生 | **precipType**（待建） | 由 `rain`、`snowfall`、`weather_code` 派生：雨 / 雪 / 雨夹雪 / 无。**不是接口字段** |
| 能见度 | `visibilityM` | 历史预报存档全量可得（实测） |
| 热力 | `tempC` / `rhPct` | 低温 + 高湿 = 结冰风险 |
| 其它 | `cloudPct` / `pressureHpa` | |
| 时间 | `hourSin` / `hourCos` / `month` | 周期编码，不要裸 `hour` |
| 缺失 | 三个缺失指示列 | 缺席要能被模型看见，不能当 0 |

字段名与 `backend-python/traffic/weather_sources.py` 的输出**保持一致**，训练与推理共用一套名字。

### 4.4 训练与评估

- 模型：**ExtraTrees**（关键路径唯一模型）；对照 RandomForest / 逻辑回归 / HistGB **默认参数**，只做一张表，**不调参**。
- 切分：**按时间**（暖季训练 → 冬季验证 → 冬季测试，或按月分块），禁止随机打乱；`TimeSeriesSplit` 做 CV。
- 不平衡：`class_weight='balanced'`，**不做上采样**（重采样改变先验，线上概率就不可解释）。
- 必交：逐档 precision / recall / F1、混淆矩阵、macro-F1、**危险档（DANGER+BAN）漏报数**、与规则逐条对比。
- **准确率只作参考**：这一分布下"恒判 BAN"就有 65%。

### 4.5 导出与推理

- 导出（待建）：**models/ml-v1.json** —— 每棵树 `feature / threshold / left / right / leaf` + 版本串。
- 推理（待建）：**backend-python/ml/forest.py** —— 纯标准库，约 120 行；逐树遍历、叶投票取众数得档位、票数比例得置信度。
- **判据**：同一测试集上 sklearn `predict` 与纯 Python 打分**逐条 100% 一致**，不一致即闸门 FAIL。
- 预算：单次推理 ≤ 5 ms；接口 p95 ≤ 200 ms（含特征组装）。

## 5. 数据标注与阈值校准

### 5.1 试点已完成（这就是"流水线钉死"的证据）

| 项 | 读数 |
| --- | --- |
| 样本 | 3 城 × 2026-09 逐小时 = **2 160 行**，能见度 0 缺失；按规则档平衡抽 **33 条** |
| DeepSeek | `deepseek-chat` / temperature 0 / seed 固定 / `json_object`；**33/33 成功**，0 重试 |
| 开销 | 输入 **20 130** + 输出 **3 796** token（≈610 / 115 per 条）；单条中位 **1.29 s**（0.96–2.01） |
| 三方一致性 | 规则 vs DS **κ 0.592**（加权 0.845）；规则 vs 人工 **0.384**（0.783）；DS vs 人工 **0.595**（0.845） |
| 危险漏报 | 规则 **11** 条 / DeepSeek **8** 条 |
| 产物 | `docs/0.10.1-标注试点/`（samples / ds_labels / human_labels / metrics）—— **试点 33 条，作为"流水线钉死"的历史证据保留**；全量样本与训练产物在 `data/training/`（`samples-v1.jsonl` **1133 条**、`label-agreement.json`、`model-v1-metrics.json`）与 `models/ml-v1.json` |

三条可用结论：**加权 κ 都在 0.78–0.85，Cohen κ 只有 0.38–0.60 ⇒ 分歧集中在相邻档**；**规则把 10 条人判 DANGER 全压成 CAUTION ⇒ 这就是 DANGER 只剩 0.14% 的机制**；**DeepSeek 比现行规则更接近人工**。

### 5.2 全量跑批的触发条件（不是日期，是条件）

**触发条件**：**labels-v1.json 定稿 且 阈值出处核对完成** → 才启动 1 200 条。理由：阈值一动标签全废，先跑后改等于付两次钱。

跑批契约（定稿后照此执行）：

| 环节 | 契约 |
| --- | --- |
| 采样 | 按**气象情景**分层（静稳 / 有风无雨 / 有雨无风 / 低能见 / 雨+风 / 极端风 / **降雪**），每情景 200 条；**不按规则档抽样**（否则把规则偏差写进标签分布） |
| 输入 | 11 个要素 + 城市 + 本地时刻；**只给公开下限，不给惩罚权重、不给 SFI、不给规则结论** |
| 输出 | 严格 JSON：`level` / `confidence` / `top3Factors` / `rationale`（须引用数值）/ `needsHuman` |
| 幂等 | 缓存键 `sha256(sampleId + promptVersion + model + temperature)`；断点续跑 |
| 失败 | 重试 3 次（指数退避）；仍失败写 `ANNOTATE_FAILED` **单列计数**，不静默丢 |
| 自查 | 10% 样本用**改写过的 rubric** 复跑（不给阈值、只给运行后果），不一致的进人工队列 |
| 人工仲裁 | **120 条**（每情景 20），优先取"模型与规则分歧 + 自查不一致 + needsHuman" |
| 放行门槛 | **κ(DeepSeek, 人工) ≥ 0.60** 才允许训练；< 0.60 先改 rubric 重跑 |
| 冻结 | 结果 + 全量 `sha256` + 模型名/日期/prompt 哈希/token 用量/κ，一次写死；此后只增不改（新版叫 v2） |

### 5.3 阈值校准（已定：先出处、后分布）

| 步 | 做什么 | 产出 |
| --- | --- | --- |
| 1 | 给 `config/rules-v1.json` 每条阈值**找出处**（能见度 / 风 / 降水的运行下限）。现行值**在仓里没有任何出处记录**（该文件只有 `version` 与语义说明） | 出处表：阈值 → 文件/条款 → 摘录 |
| 2 | 查不到出处的，**如实标"工程经验值"**，不冒充公开标准 | 同一张表 |
| 3 | 判据分离：**运行放行**阈值留在 `config/rules-v1.json`；**标注判据**落到待建的 **config/labels-v1.json**。两者允许不同，要写的是**关系声明** | 两份文件 + 关系声明 |
| 4 | 校准后重算四档分布，**前后对照表**入报告 | 分布表 |
| 5 | 若动 `config/rules-v1.json`：**升 `version` 字段 + 同步 classpath 副本 + 全量复跑** | 见 §8 A5 |

> **分布是结果，不是目标。** 校准后若 DANGER 仍 < 1%，说明"聚合方式"（现行是累减扣分 + 一票封顶）本身把中档挤掉了 —— 那是**换聚合方式**的问题，不是调数字的问题。这条要写进报告：它比"我们调好了"诚实，也更能说明团队理解自己的系统。

### 5.4 负向对照（证明我们不是在凑分布）

把某条阈值人为放松 10%（如阵风禁飞 18 → 20 m/s），四档分布会明显变"好看"，但危险漏报会上升。**把这张对照表放进报告**："若为凑分布而放松阈值，漏报将上升 N 条 —— 因此我们保留出处决定的阈值。"

## 9. 风险与红线

**风险（按影响排序）**

1. **阈值无出处**（实测现行 `config/rules-v1.json` 没有任何阈值出处记录）—— 答辩最容易被问倒的一处，也是 W1 存在的理由。
2. **分布极端**：65% BAN、0.14% DANGER。不校准，模型与成效页同时失效。
3. **两份规则文件已不等**（§1.1）：校准只改一份，"没生效"会发生在别人机器上。
4. **`precipType` 是幽灵字段**：接口没有，必须派生；写成原始列 = 训练有列、线上恒 0。
5. **标注不是真值**：报告写"大模型判断 + 人工仲裁"，不写"专家标注/观测真值"。
6. **季节漂移**：只训 9 月、11 月演示 = 分布外；扩样本比加特征更根本。

**红线（沿用）**：不编造、不夸大、不掩盖天气事实；模型不改写航线、不把禁飞改成可飞；可复现三件套（快照编号 / 算法指纹 / 气象通道）随结果返回；下钻只导航不重算；密钥不打印、不落日志、不进交付包；参赛材料不出现学校、指导教师、联系方式。
