# 数据卡 v1 —— 轨1 训练与标注数据集

> 版本：`v1`（2026-10-17）· 对应产品版本 `0.10.1（Beta）`
> 这份卡片的用途：让任何一个读者（包括几个月后的我们）能在**不读代码**的前提下，
> 判断"这批数据能支持什么结论、不能支持什么结论"。
> 凡是"能不能这么写"存疑的地方，这里的答案优先于任何汇报材料。

---

## 1. 一句话定位

**这不是天气数据集，是「判据在历史天气上的分布样本」。** 标签由 `config/labels-v1.json`
的判据算出，不是观测真值。所以它能支持的结论只有一类：**模型复现判据的能力**；
它**不能**支持任何"模型预测天气更准"的说法 —— 那需要独立观测真值，本仓没有。

## 2. 来源与时间窗

| 项 | 值 |

| 数据源 | `historical-forecast-api.open-meteo.com`（历史**预报**产品，非 ERA5 再分析） |
| 城市 | 沈阳 `SHE`、长春 `CGQ`、哈尔滨 `HRB`（3 座） |
| 月份 | 2025-11 / 2025-12 / 2026-01 / 2026-02 / 2026-03（冬）＋ 2026-06 / 2026-07 / 2026-09（暖） |
| 可用小时 | 17 424（3 城 × 8 月 × 逐时） |
| 抽样后样本 | **1 133**（每情景上限 200，按情景分层抽样） |
| 季节占比 | 冬季 **58.5%** / 暖季 **41.5%** |
| 文件 | `data/training/samples-v1.jsonl` |
| SHA-256 | `735b199752d82f9c99e6619f0d55e77ca3b36c4879c3152a1293806562e86d08` |

**为什么用 `historical-forecast-api` 而不是 `archive-api`**：实测 archive（ERA5）对沈阳
2026-09 的 `visibility` **整列全 `None`**；historical-forecast-api 同时段 **240/240 非空**，
且与线上（取的就是预报产品）**同口径**。换成 archive 会让"能见度"这个关键要素整列缺席，
而缺席会被缺测填充悄悄吃掉 —— 训练照跑、指标照出，只是模型从没看过能见度。

## 3. 字段与单位（**这张表是防静默错配的唯一依据**）

运行时快照（`/track1/ml` 收到的）与训练样本**同名不同量**，写反不会报错：

| 训练列 | 单位 | 运行时来源键 | 运行时单位 | 差异 |
| --- | --- | --- | --- | --- |
| `windMps` | m/s | `windSpeed` | m/s | 一致 |
| `gustMps` | m/s | `windGust` | m/s | 一致（口径问题见 §6.1） |
| `precipMmh` | mm/h | `precipMmh` | mm/h | 一致 |
| `visibilityM` | m | `visibilityM` | m | 一致 |
| `temperatureC` | ℃ | `tempC` | ℃ | 一致 |
| `rhPct` | **0–100** | `humidity` | **0–1** | **×100** |
| `cloudPct` | **0–100** | `cloudCover` | **0–1** | **×100** |
| `pressureHpa` | **海平面** | `pressureHpa` | **地面** | 同名不同量，见 §6.2 |

换算只在一个地方：`backend-python/ml/features.py::_scale_percent()`（`≤1.5` 才 ×100，
双向兼容）。它同时在 docstring 里抄了这张表。

缺测率：上表九个要素在 v1 样本里**全部为 0 缺测**（因为按月取的是连续序列，
逐时都有值）。线上运行时会有缺测 —— 那时走"训练中位数填充 + `miss_*` 标志点亮"，
并由 `service.predict()` 在缺测 ≥3 时给 `degraded.flag=true`。

## 4. 情景分布（分层抽样）

| 情景 | 判定规则（按优先级） | 条数 |
| --- | --- | --- |
| `snow` | `snowCmh > 0` | 200 |

| `gusty` | `wind >= 3` 且 `gust/wind > 2.6` | 200 |
| `windy` | `wind >= 8` | 200 |

**`lowvis` 只有 133 条，是抽样上限之外的真实稀缺**：从 4 个月扩到 8 个月之后，低能见度
小时从 19 涨到 133 —— 稀有情景**靠抽样救不回来，只能扩时间窗**。这条要如实写进报告：
"低能见度样本 133 条"是一个**样本量事实**，不是"充足"。

## 5. 标签怎么来的

### 5.1 主标签：判据（`config/labels-v1.json`）

- 聚合方式：**逐要素分段 + 取最坏档**（`aggregation.method = worst-band`）。
- 与运行规则（`config/rules-v1.json`，累减扣分 + 一票封顶）**是两份文件**，
  关系声明为 `DISTINCT_BY_DESIGN`。合并会让其中一方接受另一方的偏差：
  实测同一批 2 160 小时，累减扣分给出 **BAN 65.0% / DANGER 0.14%**（中档被两侧挤掉），
  分段取最坏档给出四档 **23.8 / 25.8 / 26.2 / 24.2**。
- 阈值出处：`provenance.kind = ENGINEERING`。**仓库内没有任何一条阈值记录着公开出处**，
  卡上就写"工程经验值"，不硬凑引用。

### 5.2 独立第二标注员：DeepSeek

| 项 | 值 |
| --- | --- |
| 条数 | 1 133（成功 1 133、失败 **0**、缓存命中 6） |
| 提示词版本 | `labels-v1-2026-10-17`，由判据文件**生成**（单一来源） |
| 温度 | 0 |
| 与判据一致率 | **0.6867** |
| 二次加权 κ | **0.7946** |
| 分歧集中在 | 相邻档（FIT→CAUTION 104、CAUTION→DANGER 210、BAN→DANGER 2） |
| 人工仲裁表 | **42 条**（每档 12 条 = 分歧 8 + 一致 4），`adjudication-sheet.jsonl`，`needLabel` 待填 |

**为什么不用 DeepSeek 当训练标签**：它 1 133 条里只给了 **27 条 FIT（2.4%）**，
而 FIT 恰恰是最常出现的档。逐条读 rationale 确认这不是随机噪声，而是**系统性的一档偏移**
（把「7.5 m/s，接近 8 m/s 阈值」判成 CAUTION，而判据里 7.5 < 8 就是 FIT）。
随机噪声能靠多标抵消，系统偏移不能。

**但这 1 133 条没白跑**：它量的是"同一份判据换一个人按同样读法能否复现"（κ = 0.7946）。
这条数比"模型准确率"更能说明判据本身没写歪 —— 而它同时说明**判据有一定的解释空间**
（一致率 0.6867 并不高）。

## 6. 已知局限（**引用这批数据时必须一并说明**）

### 6.1 阵风字段口径无法从接口自证

`wind_gusts_10m` 实测 **p50 = 22.0 m/s、p90 = 38.2、max 59.0**，而同批 `wind_speed_10m`
**p50 = 8.7**；**阵风/平均风比值 p50 = 2.49、p90 = 3.41**，而陆地常规阵风因子约 **1.3–1.8**。

⇒ 照 18 m/s 判禁飞会把 **64%** 的小时判成 BAN。**量的不是天气，是字段口径。**
所以 v1 判据给阵风 `direction: "none"`（不设绝对阈值），只在组合规则里用**阵风因子**
（无量纲，与口径无关）。运行规则那套本轮未改，属独立一轮。

### 6.2 气压：两个不同的量

训练取海平面气压（`pressure_msl`），运行时快照给地面气压（`surface_pressure`）。
差值主要取决于测站海拔，同一城市内近似常量。模型**不拿气压做阈值判断**，只作弱特征，
故不做订正 —— 但这条口径写进了模型 JSON 的 `provenance.pressureNote`。

### 6.3 标签是自产的（循环性）

模型学的是我们的判据，所以"macroF1 = 0.977"衡量的是**复现能力**，不是正确性。
它与运行规则（另一套阈值与聚合方式）**不可直接比优劣** —— 两列回答的不是同一个问题。
`data/training/model-v1-metrics.json::metricsNote` 与界面成效页都写死了这句话。

### 6.4 时间切分而非随机切分

按 `timeLocal` 升序 **70/15/15**（793 / 170 / 170），**不打乱**。理由：打乱会让"未来小时"
进训练集，指标虚高。代价是测试段只覆盖时间上的最后一段，季节分布与训练段不同。

### 6.5 抽样偏差

情景是**按规则选的**，不是随机抽样。所以样本里"恶劣天气"的占比远高于真实时间占比
（`lowvis` 133/1133 = 11.7%，而真实小时占比远低于此）。**不能拿样本占比推"一年有多少
小时不能飞"** —— 那是另一个问题，需要全量小时统计。

## 7. 可复现步骤

```bash
# 1) 取历史 + 分层抽样（需外网；结果已缓存在 data/training/raw/）
D:/Anaconda3/python.exe tools/ml/build_dataset.py

# 2) 标注（需 DEEPSEEK_API_KEY；幂等缓存，断点续跑）
D:/Anaconda3/python.exe tools/ml/annotate.py

# 3) 判据档位 + 一致性 + 人工仲裁抽样
D:/Anaconda3/python.exe tools/ml/label_report.py

# 4) 训练与导出（sklearn 只在 D 盘 Anaconda；backend-python/.venv 故意不装）
D:/Anaconda3/python.exe tools/ml/train_model.py
#   → models/ml-v1.json + parity 170/170 + data/training/model-v1-metrics.json
```

运行时**不需要** sklearn / scipy / pandas：`ml/forest.py` 是纯标准库打分器，
`models/ml-v1.json` 是人能读、能 diff 的 `alc-forest-v1` 格式。

## 8. 这张卡自身怎么维护

- 数据集重跑 ⇒ §2 的 SHA-256、§4 的条数必须一起改，并跑 `pytest tests/test_ml_core.py`。
- 判据改阈值 ⇒ `config/labels-v1.json` 的 `version` 必须变，模型必须重训，
  否则模型文件里 `labelsVersion` 与页面印的判据版本会对不上。
- 想加"准确率 0.98"这类话 ⇒ 先回来读 §6.3。**
