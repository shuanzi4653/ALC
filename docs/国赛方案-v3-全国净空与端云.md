## 1. 三条技术红线（全局确认过，不是推测）

### 红线 1：投影是单点 AEQD，全国范围会畸变
`weather/geometry.py` 用 `+proj=aeqd +lat_0=45 +lon_0=126`。东北精确，全国边缘畸变 >20%。
**处置**：全国/大区层用 WGS84 + 大圆距离；省/市层继续 AEQD；**跨层只传比率与计数，不传长度**。

### 红线 2：3 省 / 36 城是硬编码
`catalog.py` 的 `PROVINCES` 元组、`len(rows)!=36` 校验、`boundary()` 只认 `northeast.geojson`；
`connections()` = 省内 MST + 每城最近 2 边 + 2 条跨省边，全国跑会生成上万走廊。
**处置**：全国层**不生成走廊**，只聚合。

### 红线 3：载荷
现网 `session` 24.4 MB（53 条走廊的全量明细，gzip 3.95 MB）。全国同法 30–50 倍 → 崩。
**处置**：聚合端点 <30 KB，下钻才懒加载。

## 3. 新增主线：机场净空避让与禁飞

### 3.1 现在有什么（不用重写）

| 已有 | 位置 | 状态 |
|---|---|---|
| 三段强制等级 `PROHIBITED / APPROVAL_REQUIRED / REGISTERED` | `zones.py` | ✅ |
| 穿越台账（逐班记录、按等级排序、分 prohibited/approval 计数） | `zones.crossings()` | ✅ |
| 静态障碍包络 `envelope(policy)` | `zones.py` | ✅ |
| **绕飞求解**：`routing.route(..., obstacles=)`，凸包剪枝 + 切线绕飞 | `routing.py` | ✅ |
| 机场政策开关 `airportFootprintPolicy`（默认 APPROVAL_REQUIRED） | `operations` | ✅ |
| 覆盖范围 | 东北 **69 站点**法定空域 | ⚠️ 仅东北 |

**结论**：算法和判据都在，本轮是**扩数据 + 抬层级 + 补纪律**，不是重做。

### 3.2 扩到 240 个机场：几何怎么来（这一节关系到"能不能讲"）

| 层 | 几何 | 半径/尺寸 | 来源标注 |
|---|---|---|---|
| 机场限制区（运输） | 圆 | R = 8 km | **DERIVED**（按公开跑道方位与机场等级规则化） |
| 机场限制区（通用/支线） | 圆 | R = 5 km | DERIVED |
| 跑道净空区 | 跑道两端延长梯形 | 长 10 km、半宽 1.5→3 km | DERIVED |
| 机场巡视区（严格口径才启用） | 圆 | R = 2 km | DERIVED |
| 法定管制区（已公布） | 原始几何 | 原样 | **OFFICIAL**（仅东北 69 站点） |

**纪律（硬）**：
- 官方公布的几何 → `source: OFFICIAL`，可以染红、可以说"法定"
- 规则化生成的 → `source: DERIVED`，**必须**在图上与材料里写"按公开跑道方位与机场等级规则化生成，非官方公布"，且**不得与 OFFICIAL 合并计数**
- 现有纪律「只画有公开定量依据的几何」不变 —— **派生几何不违反它，但必须自报家门**

### 3.3 判据与绕飞（沿用现有三段等级）

| 等级 | 含义 | 规划器行为 | 台账 |
|---|---|---|---|
| `PROHIBITED` | 穿即不可飞（严格口径下机场巡视区、法定禁飞） | 强制绕飞；绕不开 → `NO_GEOMETRIC_PATH` → 停飞 | 记 1 条 + 原因 |
| `APPROVAL_REQUIRED`（默认） | 可申请穿越 | **优先绕飞**；绕飞代价 > 阈值则记为"待审批穿越" | 记 1 条 + 绕飞增量 |
| `REGISTERED` | 仅登记 | 直飞 | 记 1 条 |

**绕飞的代价必须同时出**（这是"应用成效 15 分"的要害）：

```
穿净空走廊  N 条 → 绕飞后 0 条
新增里程    Δ km（逐走廊求和）
新增时长    Δ min（逐班求和）
新增架次    绕飞 M 架 / 待审批 K 架
```

### 3.4 全国/大区层看什么（不生成走廊也能算）

| 指标 | 算法 | 为什么可信 |
|---|---|---|
| 净空受限机场数 | 240 机场中，限制区与"已有机场/城市点"重叠或距省界 <5 km 的计数 | 纯几何计数，可复算 |
| 净空覆盖面积占比 | Σ限制区面积 / 省面积（球面近似） | 可复算；标注 DERIVED |
| 待审穿越数 | **仅东北**有走廊，其他省为空 | 空就写"未接入"，不编 |

> 全国层**不假装**有全国走廊。净空这层恰好能在没有走廊的省也给出真实指标（机场数 × 覆盖占比），这就是"全国层不至于空"的第二个支柱。

### 3.5 双受众各自看什么（同一套几何）

| | 民航局（运行） | 工信部（无人机） |
|---|---|---|
| 看这张图问什么 | 这条走廊穿不穿机场净空、绕飞代价多少 | 这片空域哪些点禁飞、边界在哪 |
| 我们给什么 | 穿越台账 + 绕飞增量 + 待审批清单 | 净空区边界 + 禁飞等级 + 可申请通道 |
| 一句台词 | "**绕开机场，代价是清楚的**" | "**禁飞边界是可查的**" |

## 4. 硬件 v3：边缘自治节点（去掉 4G，走热点/局域网）

### 4.1 为什么去掉 4G（这个判断是对的）

- 会场蜂窝信号不可控，**手机热点反而更稳**（自己带的路由）
- 演示链路缩短：ESP32 → 手机热点 → 笔记本（同网段直连）
- 省钱省事：不用买 SIM、不用管流量、不用担心欠费
- **答辩口径更硬**：不是"我们有云"，而是"**这套东西完全在本地也能跑**"

### 4.3 三种运行模式（都无外网）

| 模式 | 条件 | 端侧行为 | 屏上 |
|---|---|---|---|
| **ONLINE（局域网）** | 连上手机热点 | 拉本机服务的参数帧 → 本地推理 → 上报 → 本机网页出节点卡 | 绿点 · 数据龄 <5 min |
| **DEGRADED** | 热点在但丢包 | 用上次帧推理，标数据龄 | 黄点 · 数据龄 xx min |
| **OFFLINE** | 热点关闭 | 读 NVS 里最近 6 h METAR 帧 → 26 维齐全 → 100 棵树推理 → 走廊 2 h 推演 | 红点 · "离线自治" |

**演示就演 OFFLINE**：关热点 → 屏幕给未来 2 h 可飞性曲线 + 标注"本帧来自 03:00Z 缓存"→ 开热点 → 10 秒内补传，网页出现这 30 分钟的记录。

### 4.4 端侧模型（绕开"69% 特征端侧拿不到"）

`alc-forest-v1` · 100 棵树 · 26 维；重要性前三 `visM` 35.8% / `visMin3h` 18.9% / `visMin6h` 14.4%，**传感器给不出**。
→ **用缓存帧喂**：NVS 里存最近 6 h 的 `visM` 序列，26 维全齐，与云端同源。

| 步 | 判据 |
|---|---|
| S1 100 棵树导出 C 数组 | flash 增量 ≤ 120 KB |
| S2 同 1000 组特征，端 vs 云 | `max\|Δp\| < 1e-6`（树展开是确定性等价） |
| S3 规则侧（`rules-v1.json` 阈值 + 走廊参数表） | 裁决一致率 **100%** |
| S4 本地 2 h 推演（5 min 步长，持续性假设） | 与云端同帧差 ≤1 档 |
| S5 补传 | 断网 30 min 恢复后条数一致、零重复 |

摄像头通道标 `EXPERIMENTAL`，只做能见度趋势，不参与 p 与裁决。

### 4.5 端云链路（局域网版）

```
ESP32 ──WiFi──▶ 手机热点 ──▶ 笔记本（同网段）
                              ├─ FastAPI  127.0.0.1:28083   ← 节点上报到这里
                              ├─ Java     127.0.0.1:28082
                              └─ 前端      http://<LAN-IP>:5173 或打包后的 8080
```

- 节点按 `http://192.168.x.x:28083/api/edge/report` 上报（地址写在 NVS，可重配）
- 心跳 60 s；90 s 判离线；`node+seq` 去重；**每节点 HMAC 签名**
- 参数下发 `GET /api/edge/params`（rules 指纹 + 走廊参数版本）
- 补传：NVS 环形 500 条，重连后按 seq 顺序补

> **答辩口径**：现场跑的是**同一套 jar + 同一套 FastAPI** 的本地副本；线上另有公网实例（`tianchuang.shuanzi.site`）。这句话必须能脱口而出，否则"你们云端呢"会变成减分点。

## 7. 还差你一句话的一件事

净空几何的**默认等级**：机场限制区默认 `APPROVAL_REQUIRED`（现在就是这个），还是国赛演示时切到 `PROHIBITED` 给评委看"严口径下有多少班停飞"？

- 选 `APPROVAL_REQUIRED`：数据温和、绕飞代价小、看起来"可运行"
- 选 `PROHIBITED`：冲击力强（停飞数会跳），但要能解释"为什么平时不这么严"

我建议**默认 APPROVAL_REQUIRED，演示时现切一次**——切换本身就是个演示动作，还顺手证明"政策是可配置的、不是写死的"。
