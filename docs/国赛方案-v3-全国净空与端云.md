## 1. 三条技术红线（全局确认过，不是推测）

### 红线 1：投影是单点 AEQD，全国范围会畸变
`weather/geometry.py` 用 `+proj=aeqd +lat_0=45 +lon_0=126`。东北精确，全国边缘畸变 >20%。
**处置**：全国/大区层用 WGS84 + 大圆距离；省/市层继续 AEQD；**跨层只传比率与计数，不传长度**。

### 红线 2：3 省 / 36 城是硬编码
`catalog.py` 的 `PROVINCES` 元组、`len(rows)!=36` 校验、`boundary()` 只认 `northeast.geojson`；
`connections()` = 省内 MST + 每城最近 2 边 + 2 条跨省边，全国跑会生成上万走廊。
**处置**：全国层**不生成走廊**，只聚合。

### 红线 3：载荷
现网 `session` 24.4 MB（53 条走廊的全量明细，gzip 3.95 MB）。全国同法 30–50 倍 → 崩。
**处置**：聚合端点 <30 KB，下钻才懒加载。

## 2. 四级递进：全国 → 大区 → 省 → 市

主界面是**全国航线网**，四级逐级加载、返回即释放（换层重新请求，不在内存里留整棵树）：

| 层级 | 数据 | 屏上 | 下钻 |
|---|---|---|---|
| **L1 全国** | 30 省级单元 / 330 个地级节点 / 514 条航线 | 省数、市数、机场城市数、无机场市数、航线数（省内 / 接驳 / 跨省）、逐市气象覆盖数 | 点大区 |
| **L2 大区**（六大区） | 区内聚合 | 各省市数、机场数、气象覆盖数、航线数 | 点省 |
| **L3 省** | 本省全部地级单元 + 跨省航线的**对端城市** | 城市清单（有机场标机场代码，无机场标"接驳 → 某市"）+ 逐市气象（温度/风速/能见度，能见度 <3 km 标红） | 点市 |
| **L4 市** | 该市 + 直接相邻 | 是否有机场、接驳目标、航线数与逐条里程 | 到底 |

**范围口径**：华北 5 + 东北 3 + 华东 7 + 中南 6 + 西南 4 + 西北 5（新疆并入西北）= **30 个省级单元**。
**台湾、西藏不纳入航线网**——两地不通航，网络里没有节点、也没有航线；港澳同样不纳入。这不是"没做完"，是明确的范围决定。

但**地图本身必须完整**：34 个省级单元（含台湾、西藏、港澳）与南海诸岛界线一律按国标实线绘制，
不做虚线、不做"未通航"特殊标注；南海诸岛放在右下角小图（inset）里，主图取大陆外包框，
既不把大陆压成一条缝，也不会漏掉南海。

**三条数据口径必须分开写**：

- **节点 = 真实**：民政部区划目录（地级单元名称与 adcode）+ Wikidata P625 坐标；缺坐标的不编，标注后剔出。
- **机场 = 真实**：`aviationweather.gov` 的站点总表（与此刻是否发报无关），按 60 km 挂到最近地级市；
  省会机场落在邻市境内的（太原武宿在晋中、西宁曹家堡在海东、兰州中川在白银）按省会归属。
- **气象 = 真实、公开、免密钥**：逐市取 `open-meteo` 的 `current`（温度 / 风速 / 能见度 / 降水 / 天气码），
  330 城分 6 批并发取，缓存 10 分钟；**取不到的城市就不显示气象，不插值**。
  机场 METAR 只作为"机场实测"的交叉校验，不替代逐市数据。
- **航线 = 模拟派生**：`source: SIM`，只做全国屏聚合与示意，**不参与运行计划与裁决**；
  东北那 53 条城际走廊仍是实际跑出来的航路，`2848 / 8 班 / 320 min` 由它产生。

**航线怎么拉（2026-11-10 定稿）**：

1. **省内 MST**：每省节点连成树，保证市市相连（无孤立点）；
2. **机场接驳**：**没有机场的市，必须有一条直连最近机场城市的专用航线**——是"多一条"，不是"替代"，
   它照样在省内网里跑；
3. **跨省收窄**：省级 MST（保证 30 省连通）+ 每省再补一条最近邻，合计 29 条跨省通道，
   枢纽省最多 4 条。不做全国全互联。
4. **跨海通道单列**：渤海海峡补一条**大连—烟台**（160 km，轮渡/摆渡的现实走向，标 `SEA`）——
   绕山海关要 1200 km 以上，这条是唯一一条不是由 A\* 生成的跨省通道。

**为什么跨省只留这么少**：飞行汽车解决的是**城市间**交通；跨省长距离仍靠飞机与火车。
这套网络是**分担**，不是**取代**——所以跨省只保留少量通道，把长距离留给民航与铁路。

**定位一句话**（对外表述统一用这句）：飞行汽车分担城际出行，不取代干线航空与铁路。

## 3. 新增主线：机场净空避让与禁飞

### 3.1 现在有什么（不用重写）

| 已有 | 位置 | 状态 |
|---|---|---|
| 三段强制等级 `PROHIBITED / APPROVAL_REQUIRED / REGISTERED` | `zones.py` | ✅ |
| 穿越台账（逐班记录、按等级排序、分 prohibited/approval 计数） | `zones.crossings()` | ✅ |
| 静态障碍包络 `envelope(policy)` | `zones.py` | ✅ |
| **绕飞求解**：`routing.route(..., obstacles=)`，凸包剪枝 + 切线绕飞 | `routing.py` | ✅ |
| 机场政策开关 `airportFootprintPolicy`（默认 APPROVAL_REQUIRED） | `operations` | ✅ |
| 覆盖范围 | 东北 **69 站点**法定空域 | ⚠️ 仅东北 |

**结论**：算法和判据都在，本轮是**扩数据 + 抬层级 + 补纪律**，不是重做。

### 3.2 扩到 240 个机场：几何怎么来（这一节关系到"能不能讲"）

| 层 | 几何 | 半径/尺寸 | 来源标注 |
|---|---|---|---|
| 机场限制区（运输） | 圆 | R = 8 km | **DERIVED**（按公开跑道方位与机场等级规则化） |
| 机场限制区（通用/支线） | 圆 | R = 5 km | DERIVED |
| 跑道净空区 | 跑道两端延长梯形 | 长 10 km、半宽 1.5→3 km | DERIVED |
| 机场巡视区（严格口径才启用） | 圆 | R = 2 km | DERIVED |
| 法定管制区（已公布） | 原始几何 | 原样 | **OFFICIAL**（仅东北 69 站点） |

**纪律（硬）**：
- 官方公布的几何 → `source: OFFICIAL`，可以染红、可以说"法定"
- 规则化生成的 → `source: DERIVED`，**必须**在图上与材料里写"按公开跑道方位与机场等级规则化生成，非官方公布"，且**不得与 OFFICIAL 合并计数**
- 现有纪律「只画有公开定量依据的几何」不变 —— **派生几何不违反它，但必须自报家门**

### 3.3 判据与绕飞（沿用现有三段等级）

| 等级 | 含义 | 规划器行为 | 台账 |
|---|---|---|---|
| `PROHIBITED` | 穿即不可飞（严格口径下机场巡视区、法定禁飞） | 强制绕飞；绕不开 → `NO_GEOMETRIC_PATH` → 停飞 | 记 1 条 + 原因 |
| `APPROVAL_REQUIRED`（默认） | 可申请穿越 | **优先绕飞**；绕飞代价 > 阈值则记为"待审批穿越" | 记 1 条 + 绕飞增量 |
| `REGISTERED` | 仅登记 | 直飞 | 记 1 条 |

**绕飞的代价必须同时出**（这是"应用成效 15 分"的要害）：

```
穿净空走廊  N 条 → 绕飞后 0 条
新增里程    Δ km（逐走廊求和）
新增时长    Δ min（逐班求和）
新增架次    绕飞 M 架 / 待审批 K 架
```

### 3.4 全国/大区层看什么（不生成走廊也能算）

| 指标 | 算法 | 为什么可信 |
|---|---|---|
| 净空受限机场数 | 240 机场中，限制区与"已有机场/城市点"重叠或距省界 <5 km 的计数 | 纯几何计数，可复算 |
| 净空覆盖面积占比 | Σ限制区面积 / 省面积（球面近似） | 可复算；标注 DERIVED |
| 待审穿越数 | **仅东北**有走廊，其他省为空 | 空就写"未接入"，不编 |

> 全国层**不假装**有全国走廊。净空这层恰好能在没有走廊的省也给出真实指标（机场数 × 覆盖占比），这就是"全国层不至于空"的第二个支柱。

### 3.5 双受众各自看什么（同一套几何）

| | 民航局（运行） | 工信部（无人机） |
|---|---|---|
| 看这张图问什么 | 这条走廊穿不穿机场净空、绕飞代价多少 | 这片空域哪些点禁飞、边界在哪 |

- 会场蜂窝信号不可控，**手机热点反而更稳**（自己带的路由）
- 演示链路缩短：ESP32 → 手机热点 → 笔记本（同网段直连）
- 省钱省事：不用买 SIM、不用管流量、不用担心欠费
- **答辩口径更硬**：不是"我们有云"，而是"**这套东西完全在本地也能跑**"

### 4.3 三种运行模式（都无外网）

| 模式 | 条件 | 端侧行为 | 屏上 |
|---|---|---|---|
| **ONLINE（局域网）** | 连上手机热点 | 拉本机服务的参数帧 → 本地推理 → 上报 → 本机网页出节点卡 | 绿点 · 数据龄 <5 min |
| **DEGRADED** | 热点在但丢包 | 用上次帧推理，标数据龄 | 黄点 · 数据龄 xx min |
| **OFFLINE** | 热点关闭 | 读 NVS 里最近 **≥7 条 METAR 实测帧** → 26 维齐全 → 100 棵树推理 → 走廊 2 h 推演 | 红点 · "离线自治" |

**演示就演 OFFLINE**：关热点 → 屏幕给未来 2 h 可飞性曲线 + 标注"本帧来自 03:00Z 缓存"→ 开热点 → 10 秒内补传，网页出现这 30 分钟的记录。

### 4.4 端侧模型（绕开"69% 特征端侧拿不到"）

`alc-forest-v1` · 100 棵树 · 26 维；重要性前三 `visM` 35.8% / `visMin3h` 18.9% / `visMin6h` 14.4%，**传感器给不出**。
→ **用缓存帧喂**：NVS 里存最近 6 h 的 `visM` 序列，26 维全齐，与云端同源。

| 步 | 判据 |
|---|---|
| S1 100 棵树导出 C 数组 | flash 增量 ≤ 120 KB |
| S2 同 1000 组特征，端 vs 云 | `max\|Δp\| < 1e-6`（树展开是确定性等价） |
| S3 规则侧（`rules-v1.json` 阈值 + 走廊参数表） | 裁决一致率 **100%** |
| S4 本地 2 h 推演（5 min 步长，持续性假设） | 与云端同帧差 ≤1 档 |
| S5 补传 | 断网 30 min 恢复后条数一致、零重复 |

摄像头通道标 `EXPERIMENTAL`，只做能见度趋势，不参与 p 与裁决。

### 4.5 端云链路（局域网版）

```
ESP32 ──WiFi──▶ 手机热点 ──▶ 笔记本（同网段）
                              ├─ FastAPI  127.0.0.1:28083   ← 节点上报到这里
                              ├─ Java     127.0.0.1:28082
                              └─ 前端      http://<LAN-IP>:5173 或打包后的 8080
```

- 节点按 `http://192.168.x.x:28083/api/edge/report` 上报（地址写在 NVS，可重配）
- 心跳 60 s；**连续 10 min 无成功请求判 OFFLINE**；`node+seq` 去重；**每节点 HMAC 签名**
- 参数下发 `GET /api/edge/params`（rules 指纹 + 走廊参数版本）
- 补传：NVS 环形 500 条，重连后按 seq 顺序补

> **答辩口径**：现场跑的是**同一套 jar + 同一套 FastAPI** 的本地副本；线上另有公网实例（`tianchuang.shuanzi.site`）。这句话必须能脱口而出，否则"你们云端呢"会变成减分点。

### 4.6 边缘节点的定位与使用

> 本节口径与 `docs/V1.0.1-边缘节点-定位与表述口径.md` 一致；只同步表述，不改任何数字与结论。

**一句话定位**

> 它是一个**低成本、可密集布点的边缘决策节点**：把机场 METAR 实测帧缓存在本地，断网时用端侧模型自己做"能不能飞"的四档判决，并外推未来 1–3 小时的风险概率；判决链路不经过任何服务器，**20 毫秒级**。

**它存在的唯一理由是**：把"断网也能决策"从**说法**变成**可当场验证的事实**。软件本身一个功能都不少——硬件不补功能缺口，只补"凭什么信"。

**是什么 / 不是什么**

| 是 | 不是 |
|---|---|
| 地面**固定节点**（起降点值班室） | 机载设备（未做供电/振动/电磁/适航验证） |
| **离线决策**子节点 | **气象观测站**（自带 BME280 只做开机自检） |
| 云平台的**降级兜底** | 取代云平台 |
| 给出**四档建议** | **自动放行系统**（放行仍由人决定） |
| 单点可用性判断 | 全网航路重规划 |

**部署位置（三层，别混着讲）**

| 层级 | 位置 | 依据 |
|---|---|---|
| **示范点**（现在做） | 沈阳 / 长春 / 哈尔滨三地**城市起降点（vertiport）值班室** | 模型只覆盖 ZYTX/ZYCC/ZYHB 三站；这三地正是三个**运行态省份**，走廊与节点对得上 |
| 扩展（讲规划） | 216 条**城内配送走廊**末端起降点 | 这些点没有气象席位、没有专线，断网即失明，是真实痛点 |
| 演进（只放展望） | 机载 / 车载 | 需先过供电与振动验证，**当前不做** |

**为什么不放机场塔台**：塔台已有气象席、备份通信与 UPS，再放一个"断网兜底"是重复建设，兜底无意义。痛点在最末端——那里没人看得懂 METAR 原文。

**物理安装**：放桌上即可。**不立杆、不布线、不改市电、不做防雷**（电池供电、USB 充电、透明盖直接看屏）。这是 372 元能密集布点的前提。

**给谁用、怎么用**

| 角色 | 看什么 | 做什么决定 | 要懂模型吗 |
|---|---|---|---|
| **放行员**（值班调度） | 屏上四档 + 数据龄 | 放行 / 等待 / 转人工复核 | 不需要，只看颜色 |
| **现场操作员**（操控、地勤） | 按键切"未来 1–3 小时风险概率" | 现在起飞还是等这波过去 | 不需要 |
| **云端后台** | 恢复后看补传台账 | 复盘、追责、调走廊参数 | 需要 |

**三种状态（30 秒能讲完）**

| 状态 | 屏上 | 行为 |
|---|---|---|
| **ONLINE** | 绿点 | 每 5 min 上报；取参数指纹、校时 |
| **DEGRADED** | 黄点 + 数据龄 | 用上次帧继续算；上报进队列等重试 |
| **OFFLINE** | 红点·离线自治 | 本地判决照出；按键看推演；恢复后补传 |

**断网时到底发生什么（评委必问，逐条对应）**

| 问题 | 答案 |
|---|---|
| 气象数据哪来？ | **断网前缓存的 METAR 实测帧，按原始时序存 ≥7 条**，掉电不丢，每帧带 `ts` + `source`。**不是自己采的** |
| 断网多久判定？ | 连续 **10 min** 无成功请求 → OFFLINE |
| 未来 1–3 小时怎么算？ | 模型本身是 nowcast（`t+1h..t+3h`，leadTime 中位 120 min），**从当前帧往后外推，不需要新数据** |
| 时间基准哪来？ | 断网前校时（**UTC**）；断网重启必须从 **NVS 恢复最后已知时间**，否则 `hourSin/hourCos` 整体偏 |
| 规则会不会过期？ | `rules-v1.json` **指纹校验**，不符即拒绝裁决 |
| 航路规划做不做？ | **不做全局重规划**。降的是决策**粒度**（全网最优 → 单点可用性），不是能力 |
| 数据怎么回来？ | 环形 **500 条**，去重键 `node+seq`，退避 5s→30s→120s，**时间戳原样保留** |
| 数据新鲜度怎么交代？ | 屏上永远显示**帧来源 + 数据龄**；没有来源的数字不许上屏 |

> 与 §4.3 / §4.4 既有描述的差异（缓存时长写法、局域网参数地址）以本节与口径卡为准，数字一个不改。

## 7. 还差你一句话的一件事

净空几何的**默认等级**：机场限制区默认 `APPROVAL_REQUIRED`（现在就是这个），还是国赛演示时切到 `PROHIBITED` 给评委看"严口径下有多少班停飞"？

- 选 `APPROVAL_REQUIRED`：数据温和、绕飞代价小、看起来"可运行"
- 选 `PROHIBITED`：冲击力强（停飞数会跳），但要能解释"为什么平时不这么严"

我建议**默认 APPROVAL_REQUIRED，演示时现切一次**——切换本身就是个演示动作，还顺手证明"政策是可配置的、不是写死的"。
