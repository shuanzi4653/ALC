# AIC 国赛方案 v2 · 全国递进视图 + 端云协同

> 编制：2026-11-09 18:10　|　基线 V1.0.0
> 本版回应三件事：① 三省份 → 全国/大区/省/市 递进；② 端侧推演 + 云端连接；③ 受众改为民航局（运行）与工信部（无人机）
> 预算：无上限（但仍按"钱花在冗余与可复现上"配置）

---

## 0. 结论：可行，但必须把两件事分开

| 事 | 判断 | 理由 |
|---|---|---|
| **视图递进**（全国→大区→省→市） | ✅ **可行，2–3 周能落地** | 骨架已在仓库：`frontend/src/assets/china.json` 就是全国 **35 个省级单元**（含 adcode/center），底图不用求人 |
| **数据全国化**（每城都有走廊、航班、裁决） | ❌ **不可行，也不必做** | 现网 53 走廊 × 1614 班已经 24.4 MB 载荷；全国同法生成 ≈ 30–50 倍，浏览器直接崩 |

**所以正确的做法是**：全国层做**监管看板**（聚合指标，KB 级载荷），省/市层做**运行决策**（现有引擎，东北三省样板）。
这不是妥协——民航局最认的就是"**试点—推广**"这个句式：一个省跑通、可复制、给全国看板。

> 一句话对外说法：**"全国看态势，大区看差距，省里做决策，市里做处置。"**

## 1. 三条技术红线（先看这个，否则后面全是空中楼阁）

### 红线 1：投影是单点 AEQD，全国范围会失真

`weather/geometry.py` 用的是 `+proj=aeqd +lat_0=45 +lon_0=126`（东北中心）。这个投影在东北精确，但全国范围（哈尔滨↔三亚 3000+ km）边缘畸变可超 20%，走廊长度、判据半径、风险区面积全部失真。

**处置**：
- **全国层 / 大区层**：直接用 WGS84 经纬度 + 大圆距离（`haversine`），不投影
- **省 / 市层（东北）**：继续用 AEQD，不动现有引擎
- **禁止混算**：两套坐标各自算各自的指标，跨层只传"比率、计数、结论"，不传长度

### 红线 2：36 城 / 3 省是硬编码

`traffic/catalog.py` 里三处锁死：
```python
PROVINCES = ('辽宁省', '吉林省', '黑龙江省')      # 省列表
if len(rows) != 36 ...: raise ValueError          # 城市数校验
boundary(province)  # 只认 data/northeast.geojson
```
且 `connections()` 是"省内最小生成树 + 每城最近 2 边 + 2 条跨省边"，全国跑这套算法会生成上万条走廊。

**处置**：全国层**不生成走廊**（只做聚合），省层用到时才生成。这样不用改动 `connections()` 的核心，只加一层"数据成熟度"判断。

### 红线 3：载荷体积决定架构

现网 `session` 24.4 MB（gzip 后 3.95 MB）= 53 走廊 × 1614 班。若全国同法生成，单页 100 MB+。

**处置**：全国层新端点只返回**聚合**（每省/每区 8–12 个数字），单个响应 < 30 KB；点进某省才懒加载明细。

## 2. 递进式信息架构（四级）

| 层级 | 数据来源 | 屏上给什么 | 下钻 |
|---|---|---|---|
| **L1 全国** | 35 省级单元（已有）+ 全国机场 METAR | 机场数 / 可飞率 / 低能见度站数 / 风险走廊数 / 受影响班次；一屏一张中国地图 + 大区色块 | 点大区 |
| **L2 大区** | 同上聚合 | 区内各省排序（按可飞率/受影响班次）、区内外对比、异常省高亮 | 点省 |
| **L3 省** | 东北三省=运行态明细；其他省=观测态 | 有走廊的：走廊清单 + 判据 + 处置；无走廊的：机场站表 + 状态灯 + "待接入"标注 | 点市 |
| **L4 市** | 东北 36 城 | 现有城市网络视图（枢纽/配送节点/走廊/处置） | 到底 |

### 2.1 关键设计：数据成熟度三态（这一条解决"全国看上去是空的"）

| 态 | 标识 | 含义 | 覆盖 |
|---|---|---|---|
| ● **运行态** | 实心绿 | 走廊 + 航班 + 裁决全齐 | 辽宁 / 吉林 / 黑龙江（36 城 / 53 走廊 / 1614 班） |
| ◐ **观测态** | 半实心蓝 | 有 METAR 实测 + 风险判据，无走廊推演 | 全国其余省份主要机场 |
| ○ **待接入** | 空心灰 | 仅行政区划 | 其余 |

**为什么必须有这三态**：评委一定会问"你说全国，那别的省是真的吗"。
答"三态标注"= 诚实且专业；答"都接了"= 现场被打穿。而且三态本身就是**推广路线图**（民航局最熟的话术：试点省 → 观测铺开 → 运行推广）。

## 3. 大区口径：建议用民航局七大区，不是五大区

受众是民航局，民航局的行政架构是 **7 个地区管理局**：华北、东北、华东、中南、西南、西北、新疆。
"五大区"不是民航口径，评委（尤其民航系统出身）会问"你这五个区怎么划的、依据是什么"——一句话答不上就掉分。

**建议**：做成**配置驱动**，一份 `regions.json` 两种口径：

| 口径 | 划分 | 用在哪 |
|---|---|---|
| **七大区（默认）** | 华北 / 东北 / 华东 / 中南 / 西南 / 西北 / 新疆 | 正式材料、答辩主视图（对齐民航局） |
| 五大区（可切） | 华北 / 东北 / 华东 / 中南 / **西部**（西南+西北+新疆） | 宏观叙事页、工信部视角（西部空域广阔、无人机试验需求集中） |

UI 上一个下拉切换，同一份数据两种聚合。**这样你不用在"我说五个还是七个"上纠结**，两个都能讲，而且切换本身就是个演示动作。

## 4. 两个受众，两套视图（这是本次改版最大的加分点）

| | **民航局（运行）** | **工信部（无人机）** |
|---|---|---|
| 关心什么 | 航班正常性、放行率、区域容量、跨区协调 | 隔离空域、飞行计划、试验区、UOM 监管 |
| 我们哪一屏回答 | 运行首页 KPI · 走廊剖面 · 事件处置台 · 反事实对照 | 空域与风险区图层 · 计划/审批状态 · 边缘节点网络 |
| 新增的全国层 | 大区可飞率对比、异常省排序 | 低空节点覆盖图、待接入省份清单 |
| 一句对口台词 | "把气象概率翻译成**这一班放不放**" | "把空域风险翻译成**这一片能不能飞**" |

**叙事结构**（PPT 与方案共用）：
> 一个引擎（概率校准 + 走廊判据 + 反事实回算），两套监管视图（运行 / 空域），三级数据成熟度（运行 / 观测 / 待接入）。

## 5. 全国层的数据从哪来（不能编）

| 数据 | 来源 | 现状 |
|---|---|---|
| 省级行政区划 + 中心点 | 仓库已有 `china.json`（35 feature，含 adcode/center） | ✅ 现成 |
| 机场清单（运输 + 通用） | 民航局年度公报 / 公开机场列表 | 需整理一次（约 1 天） |
| 机场 METAR | open-meteo（现网在用，全球覆盖） | ✅ 现成通道 |
| 大区映射 | `regions.json`（7 或 5，含每省归属） | 需新建（1 小时） |
| 城市清单（全国） | 公开行政区划 | 只做展示用，不生成走廊 |
| 走廊 / 航班 | **只在东北生成** | 现有引擎不动 |

**纪律**：全国层每一个数字都必须能追到"哪个机场、哪一帧 METAR、哪个时间"。聚合不是估算，是**求和 / 计数 / 比率**，三样都可复算。

### 6.2 三种运行模式（这是端侧推演的主体）

| 模式 | 触发 | 端侧做什么 | 屏上 |
|---|---|---|---|
| **ONLINE** | 有 4G/WiFi | 拉云端最新观测帧 + 规则参数 → 本地推理 → 上报 | 绿点 · 数据龄 <5 min |
| **DEGRADED** | 网络抖动 | 用上次帧 + 本地模型，标注数据龄 | 黄点 · 数据龄 xx min |
| **OFFLINE** | 断网 ≥10 min | **读本地缓存的最近 6 h METAR 帧 → 26 维齐全 → 100 棵树推理 → 走廊 2 h 推演 → 出可飞性曲线** | 红点 · "离线自治" |

**演示就演 OFFLINE**：拔掉 4G 与 WiFi，屏幕给出未来 2 h 的走廊可飞性曲线，并写明"本帧数据来自 03:00Z 缓存"。

### 6.3 端侧模型怎么落地（关键：绕开特征缺失）

模型实测：`alc-forest-v1` · **100 棵树** · 26 维 · 重要性前三 = `visM` 35.8% / `visMin3h` 18.9% / `visMin6h` 14.4%，端侧传感器**给不出这三项**（合计 69%）。

**所以端侧只用"缓存帧"喂模型**：缓存里本来就存着最近 6 h 的 `visM` 序列，26 维**全部可得**。

| 步 | 做什么 | 判据 |
|---|---|---|
| S1 | 导出 100 棵树为 C 数组（脚本生成，不手写） | 编译后 flash 增量 ≤ 120 KB |
| S2 | 同 1000 组特征，端侧 vs 云端 | `max\|Δp\| < 1e-6`（树展开应完全一致） |
| S3 | 规则侧：`rules-v1.json` 阈值 + 走廊参数表存 NVS | 同输入裁决一致率 **100%** |
| S4 | 推演：本地按 5 min 步长外推 2 h（只用最后帧 + 持续性假设） | 与云端同帧推演差异 ≤1 档 |
| S5 | 上报与补传 | 断网 30 min 后恢复，服务端条数 = 端侧缓存条数，无重复 |

> 摄像头那条通道单独标 `EXPERIMENTAL`，只做"能见度估计趋势"，**不参与 p 与裁决**。红线：不说"我们的传感器能进业务"。

### 6.4 端云协议

```
端側                                   云侧
────                                   ────
POST /api/edge/report (HTTPS, 兜底)     FastAPI: 校验 HMAC + seq 去重 + 落 SQLite
MQTT aic/{ws}/{node}/report (8883/TLS)  EMQX/mosquitto: 转发到同一处理器
POST /api/edge/heartbeat (60 s)         标记 online/offline（90 s 判离线）
GET  /api/edge/params                   下发 rules 指纹 + 走廊参数（版本化）
```

载荷（JSON，≤1.5 KB/条）：
```json
{"node":"ZYTX-01","ts":"2026-11-09T10:00:00Z","seq":10231,"mode":"OFFLINE",
 "obs":{"visM":800,"gustMs":7.2,"tempC":-8.1,"dewC":-9.4,"qnhHpa":1021.3},
 "p":{"vis":0.72,"model":"ml-v2-vis3k","fp":"alc-forest-v1"},
 "decision":{"tier":"CAUTION","corridors":[{"id":"CAR-1-01-1-02","verdict":"HOLD"}]},
 "latencyMs":18,"fw":"1.2.0","sig":"<hmac-sha256>"}
```

**安全**：每节点一把密钥（只在 `.env.secrets` 与端侧 NVS），签名覆盖 `node+ts+seq+payload`；限频 10 条/min；沿用现有 workspace 隔离。

**云端新增**（不破现有契约）：
- `POST /api/edge/report`（批量 ≤50，去重键 `node+seq`）
- `GET /api/edge/nodes`（节点清单 + 在线态 + 最近帧）
- 前端：首页一张"边缘节点"卡（在线 1 / 离线 0 / 最近 20 条）；全国层叠一层"节点分布点"

## 8. 风险与止损

| # | 风险 | 对策 |
|---|---|---|
| 1 | 全国层指标是编的 | 每个数字给 `source`（station/frame/时间），页面上可点开看"这批数怎么算的" |
| 2 | 两套坐标混算 | 全国层代码**不允许 import** `weather.geometry.project`；CR 时 grep 一次 |
| 3 | 全国聚合拖慢首屏 | 聚合端点独立缓存 60 s；下钻才拉明细 |
| 4 | 4G 在会场无信号 | 演示走 OFFLINE（本来就要演断网）；4G 只做"恢复补传"的 10 秒 |
| 5 | 端侧 p 与云端不一致 | S2 判据卡死（1e-6），不一致就不许上"一致性"这句话 |
| 6 | 时间不够 | 砍顺序：节点分布点 → 五大区切换 → 摄像头 → 风杯；**全国聚合层与端云补传不砍** |
