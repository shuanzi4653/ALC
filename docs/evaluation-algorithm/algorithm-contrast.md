## 二、五组分别读出了什么

### A 连续移动 vs 静态单时刻 —— **时间维不能冻结**

把 `weather_sim._advection` 换成恒零偏移，回波整场不动，等于只用一个静止时刻的场。

- 受理 **6929 → 6753（-176）**，关闭 **831 → 1007（+176）**，气象阻断关闭 683 → 861。
- 气象改航 **28 → 16**；平均绕行 1.76 分 → 2.36 分。
- **本轮的越核内核是 0**（本算法也是 0）：这一次快照没有把差异落在硬约束上。
  照实写 —— 把"这一轮没量出来"说成"它其实没什么问题"，就是拿一轮读数当结论；
  A 的代价本轮体现在关闭数与平均延误上。

> **一处必须如实写的数字**：A 组的**外场**越核是 **23**，本算法是 **39**。
> 外场停留本身不是缺陷：本算法的 39 机分钟**全部落在声明允许的擦入深度（250 m）之内**，
> 是设计允许量。两个数谁大谁小都不能单独说明安全性，**判据是内核，不是外场**。

### B 按预计经过时刻扫掠 vs 当前时刻单帧 —— **本组是五组里最硬的一条**

把 `service.RADAR_SWEEP_STRIDE_MINUTES` 拉到大于时间轴，`sweepSlots` 由 **49 → 1**，
即只用 `t=0` 那一帧规划全部 480 分钟。

| | 本算法 | B（单帧） |
| --- | ---: | ---: |
| 放行率 | 89.3% | **75.6%** |
| 关闭 | 831 | **1895** |
| 气象阻断关闭 | 683 | **1789** |
| 气象改航 | 28 | **0** |
| 地面等待 / 均值 | 3666 / 19.46 分 | 2664 / 6.46 分 |
| **越核内核** | **0 机分钟 / 0 班** | **449 机分钟 / 233 班** |

- 单帧规划**关闭得更多**（1895 vs 831），因为 `t=0` 的场一旦压住某条走廊，这条走廊在整条
  时间轴上都被判死；而**改航数直接归零**（0）—— 一个只看当前时刻的规划器，没有任何
  "前方会怎样"的信息可用，只能关闭。
- **233 个班次在各自经过的时刻切进了 ≥45 dBZ 内核**，累计 449 机分钟。
- 附带观察到一件事：B 的构建只要 **13.5 s**，而本算法 64.7 s —— 差的就是那 48 次扫掠推导。
  **这条不能当收益读**：它省下的是把气象读进来的那部分工作。

### C 单阈值**从严**（35 dBZ 全硬）—— **一个诚实的零结果**

把内核请求改回外场几何（内核 = 外场向内收缩 `radar_field.CORE_INSET_M`），软障碍并进硬障碍，
等价于 0.9.22 之前的行为：整个 ≥35 dBZ 场都是硬障碍，**没有"可以擦边"的那一档**。

| | 本算法 | C（从严） |
| --- | ---: | ---: |
| 受理 | 6929 | 6926 |
| 关闭 | 831 | **834** |
| 气象阻断关闭 | 683 | 684 |
| 气象改航 | 28 | **27** |
| 越核内核 | 0 / 0 | **0 / 0** |
| 越核外场 | 39 机分钟 | 38 机分钟 |

**结论：收紧到"零容忍"，只多关 3 班（831 → 834），却把 39 机分钟的外场擦边权白收掉了。**
也就是说，本网络规模下两级两规则与单阈值从严**几乎不可分**。

这条零结果**照实写**，理由与 `docs/algorithm-spec.md` §4.7 里那个 `0.74×` 相同：
只报对自己有利的那一侧，报告就不再是测量。它的正确读法见 §三。

### D 单阈值**从宽**（只保护 45 dBZ 内核）—— **去掉外场这一档要付什么代价**

反过来把唯一的阈值抬到 45 dBZ：外场那条带子完全不再进入避让集合。

- 受理 **6929 → 7163（+234）**，关闭 831 → 597。**看起来是净收益。**
- 但代价是：**10 个班次穿进 ≥45 dBZ 内核**（10 机分钟），外场越核 **39 → 522 机分钟**。

> **这两条必须一起看。** 只引用"受理增加"会把一个破坏硬约束的实现说成一次优化。
> 判据是**越核**，不是受理数 —— 受理数只回答"安排了多少"，越核回答"安排得对不对"。

### E 做气象决策 vs **完全不做气象决策** —— **放行率最高的那一组，也是最不安全的那一组**

气象照常读取、照常逐档判定，但**两条通往几何的出口同时置空**：
`PublicWeather.envelope`（点观测派生的禁止进入区）与 `_radar_window_union`（雷达派生的
避让几何）。固定管制区、机场周边等**法定**障碍保持不动 —— E 的语义是"不做气象决策"，
不是"不做任何约束"。

- 放行率 **89.3% → 98.4%**，关闭 **831 → 123**，气象阻断关闭 **683 → None**。
- 平均延误 **19.46 分 → 6.59 分**，气象改航 **28 → 0**。
- **越核内核 0 → 1077 机分钟 / 541 班**，外场 **39 → 926 机分钟**。

> **E 的读法最容易读反。** 它是五组里放行率最高、平均延误最低的一组 —— 如果只报
> 这两个数，"不做气象决策"看起来像一次性能优化。它的真实内容是：**把 541 个班次
> 送进了 ≥45 dBZ 内核**。绕行代价为零，是因为绕行根本没发生。
>
> E 与 A/B 也不是同一件事：A/B 改的是"气象读得准不准"，E 改的是"读准了之后用不用"。

## 三、结论：这套气象决策替代了什么

C 与 D 是同一个问题的两个方向，**缺一不可**：

- 只报 D → "两级两规则当然更好"（但它没说好在哪）；
- 只报 C → "两级两规则没有用"（而它恰恰说明了这条规则**不是**一个用安全性换吞吐的妥协）。

两个方向合起来才能说出这句话：

> **35 dBZ 这一档既不是可有可无（D：去掉它 → 10 个班次直接切进内核、
> 外场越核从 39 涨到 522 机分钟），也不是越严越好（C：收紧到零容忍，只多关 3 班，
> 等于把可用的擦边权白收掉了、不给任何回报）。**

换句话说：**两级两规则在"多放行"上一分钱没赚（C 证明），在"不越核"上是必需的（D 证明）。**
它的价值不是吞吐，而是**让"内核不可触碰"与"外场可有界擦边"这两条不同强度的规则同时成立**。

本轮量出的**代价排序**（按越核内核机分钟）：

| 组 | 不做它会怎样 | 越核内核（机分钟 / 班） |
| --- | --- | ---: |
| E | 做气象决策 vs 完全不做气象决策（两条几何出口同时置空） | 1077 / 541 |
| B | 按预计经过时刻扫掠 vs 当前时刻单帧 | 449 / 233 |
| D | 两级两规则 vs 单阈值从宽（只保护 45 dBZ 内核） | 10 / 10 |
| A | 连续移动 vs 静态单时刻（回波整场冻结） | 0 / 0 |
| C | 两级两规则 vs 单阈值从严（35 dBZ 全硬、不许擦边） | 0 / 0 |

本轮越核最严重的两组是 E 与 B —— 它们说明的**不是同一件事**：B 是"气象没读全"，
E 是"读了但不用"。两种失败在界面上长得完全不同，代价却落在同一个地方（≥45 dBZ 内核）。
而 E 说明的是另一件事：**读进来之后还必须用它**，否则那些回波只会出现在图上。

## 四、量具自证（M27 / M58）

一组"量不出差异"的对照不能用来说明任何事，而**计划层的数字区分不了两种解释**：
"C 组量不出差异"既可能是算法的结论，也可能是**补丁根本没生效**。两种解释的下一步动作
完全相反。

因此带几何补丁的组各额外量一次**几何本身**（`witness_tiers()` / `witness_no_weather()`，
同一个 300 分钟窗口）：

| | core 面积（m²） | field 面积（m²） | envelope 探针 |
| --- | ---: | ---: | --- |
| 本算法 | 261,588,023,859 | 342,335,401,918 | — |
| C | 342,335,401,918 | 342,335,401,918 | — |
| D | 261,588,023,859 | 261,588,023,859 | — |
| E | 0 | 0 | PATCHED_EMPTY |

C / D 组把内核那一档的几何换掉了（面积在 2.62e11 与 3.42e11 之间切换，两个值都取自真实
求值），**所以"C 的差异很小"是算法的结论，不是量具坏了**。

E 组的 `envelope 探针` 是第二个出口的自证：雷达那条用真几何问（被换成恒空 → 量到 0），
包络那条**不能**用真快照问（那要有网），所以用一个不读属性的替身对象问 ——
补丁装上了就返回空几何，没装上就抛 `AttributeError`，**没有第三条路**。
少了这一步，`PublicWeather.envelope` 这个名字一旦写错，补丁会安静地不生效，而量出来的
差异会被归因到一个没被改过的东西上。

脚本另有一道闸门：任何一组，如果既没改变计划层数字、也没改变几何，就 `[STOP]` 退出并
**不产出报告**（`_bench_algorithm_contrast.py::main`）—— 宁可没有报告，也不产出一行
"看起来算法没优势"的数字。判据集合含**全部四个结果指标**：只看受理与关闭的话，
一组只改变延误或只改变绕行量的对照会被误判成"量不出差异"并中止。

### 4.1 过程记录：C 组被写错过一次（已修，照实记）

C 组的第一版把方向写反了 —— `naive_union` 让**外场请求返回内核几何**（保护得更少），
于是朴素版受理更高、关闭更低：一个"更宽松"的变体被贴上了"单阈值禁飞（35 dBZ 全硬）"的
标签。**量出来的数字方向与标签方向相反，就是它写错了的信号。**

第二版改对方向后，量出来的是 §二·C 的零结果。**两次都跑通了、都没有报错** ——
唯一把它们区分开的是"朴素做法到底应该是更严还是更松"这个**语义**问题，
而这正是脚本里 `naive_union` 那段注释现在专门记下来的东西。

### 4.2 过程记录：报告是生成的（本轮改动）

上一版这份文档是**手抄**的，于是它与 JSON 可以无声地分叉。本轮改成由脚本整份生成：
抬头写版本、计划指纹与快照时刻，正文数字全部取自同一次运行。**这不是排版改动** ——
它把"报告里的数字"变成了一条能被重新生成、因而能被核对的东西。

## 五、本报告**不**主张的事

| # | 不主张 | 理由 |
| --- | --- | --- |
| 1 | 不主张"本算法比 X 快 N 倍" | B/E 的构建耗时更低是**省掉工作换来的**（B 少 48 次
扫掠、E 少两层几何），不是算法效率优势 |
| 2 | 不主张外场越核 39 机分钟是缺陷 | 它全部落在声明允许的擦入深度（250 m）内，是设计允许量 |
| 3 | 不主张 C 组的零结果说明两级两规则无用 | C 只说明"收紧"这一侧无收益；D 从另一侧证明了它是必需的（见 §三） |
| 4 | 不主张 E 组的"高放行率 / 低延误"是优化 | 那两个数正是"什么都没做"的直接后果；判据是越核（§二·E） |
| 5 | 不把本报告的收益外推到其它网络规模，也不跨快照比较 | 全部数字标注了规模与**快照身份**；`README.md` 的引用纪律要求写版本与规模 |
