### 0.2 两条要修（我核过原文，结论与终审略有出入）

**① A4「METAR visib 是英里，会整屏染红」——严重性下调**

现有链路**已经转换过**：`weather_sources.py:365` 明确声明 `sourceUnits.visibility = statute_mile`，且 `test_weather_sources_extra.py:138` 有自证用例（报文 6000 m，JSON `visib=3.73` ⇒ 6003 m）。

所以不是"现存 bug"，而是：**全国屏新代码如果自己 parse raw METAR，才会犯这个错**。
→ 处置不变（必须复用 `weather_sources` 的转换，禁止自己解析），但不必当成救火项。

**② C2「scale 应是 0.711」——0.5028 不是 bug，是容器高度**

`stageBox` 的 `scale = min(容器宽/舞台宽, 容器高/1080)`。1366×768 是**视口**尺寸，浏览器客户区高度通常只剩 543–620 px：

| 容器高 | scale |
|---|---|
| 768（全屏无 chrome） | 0.711 |
| 620 | 0.574 |
| 543 | **0.503** ← 实测值 |

所以"最小字 17 px"是按 0.711 反推的，**实际 0.50 时要 24 px 才够 12 px**。
→ **判据必须用容器实测高度**，不能用 `window.innerHeight`。这也说明"整站缩放"在 1366 上本来就不该是主方案（见 §3）。

## 2. W2 净空：55 km 是法定几何，不是我们画的圈

### 2.1 仓库里已经有什么（比我原方案强，别改）

| 项 | 实际 | 状态 |
|---|---|---|
| 运输机场净空保护区域 | **圆 R = 55 000 m**（24 个机场） | `PUBLISHED_STANDARD` |
| 净空巡视检查区域 | **跑道两侧各 10 km、端外 20 km 矩形**（24 条） | `PUBLISHED_STANDARD` |
| 记录数 | **69 条 = 24 个运输机场（48 条几何）+ 21 个非机场固定设施**（10 导航台站 / 6 革命纪念地 / 2 核电厂 / 2 文物 / 1 天气雷达站） | 不是"69 个机场" |
| 强制等级 | 12 `PROHIBITED` / 48 `APPROVAL_REQUIRED` / 9 `REGISTERED_REVIEW_REQUIRED` | 现成结构 |
| 垂直范围 | `floorAglM: 120`（真高 120 m 以上属管制空域；以下仍受条例第四十九条限制） | 现成 |
| 法条 | 每条带 `citation`（《运输机场净空保护管理办法》《民用机场管理条例》第四十九条） | 现成 |
| 生成器 | `tools/generators/_gen_fixed_zones.py`（28 KB） | 扩 240 走它，不手写 JSON |

**所以扩到 240 = 补 240 个机场基准点坐标 + 套同一条规则**，`geometryStatus` 继续 `PUBLISHED_STANDARD`，**不引入 DERIVED、不做双栏分栏、不画"我们自己生成的圈"**。

### 2.2 55 km 到底管什么（这决定了大连能不能起飞）

**用户的问题问对了**：如果把 55 km 当水平禁飞圈，大连周水子 55 km 覆盖主城 + 金州 + 旅顺，**大连全市无法起降**——这显然是荒谬的。

正确理解（也是数据里写的）：

> 55 km 净空保护区管的是**障碍物限高**与**飞行需批准**，不是"水平方向一律禁止"。
> 判据是「水平范围 × 垂直下限 120 m × 审批等级」三者共同作用。

所以系统的正确建模是**三层**：

| 层 | 几何 | 判据 | 规划器 | 屏上 |
|---|---|---|---|---|
| **L-A 起降审核层** | 55 km 圆（法定） | `APPROVAL_REQUIRED`：**可飞，需批准** | **不进障碍集**（进了就无解） | 台账记"待审批穿越" |
| **L-B 核心禁飞层** | 12 条法定 `PROHIBITED` + 严口径下的巡视矩形 | `PROHIBITED`：不可穿 | **进障碍集**，走现有绕飞 | 停飞/绕飞，逐班可查 |
| **L-C 航路软避让层**（新增） | 55 km 圆内的**巡航段** | 软约束：**代价惩罚**，尽量绕开 | A* 成本 = 长度 + `k`×圈内航段长度 | "净空内穿越 xx km，已优化至 xx" |

**L-C 就是"起飞后的航线尽可能规避"**：
- `k = 0` 时行为与今天完全一致 ⇒ **2848 / 8 班 / 320 min / 94% 全部不变**
- 演示时把 `k` 调到 >0，路径会主动避开机场净空区，屏上显示"净空内航段 3.2 km → 0.8 km"
- 明确标注：**该模式改变路径选择，代价数字另计**，不与默认口径混用

> 成本 1.5 人日（比扩 240 更值）：距离场 + A* 代价项 + 一个开关 + 屏上一行提示。

### 2.3 台账模板（替换原"绕飞后 0 条"的错误写法）

```
净空保护区域穿越      N 条（涉及 M 个机场）   ← 默认口径：待审批
核心禁飞区穿越        0 条（严口径下 K 条停飞）
航路规避（可选）      净空内航段 3.2 km → 0.8 km，绕飞代价 +Δ km / +Δ min
```

原写法"穿净空走廊 N 条 → 绕飞后 0 条"在 55 km 下**做不到**，已删。
新写法最后一行不是露怯，是**这套系统最懂行业的一句话：知道什么时候不该绕**。

### 2.4 演示纪律（对应终审 D1）

1. 切严口径**只在净空台账页**做，不回首页
2. 切之前先存一张 94% 的截图备用
3. 口播把它叫"**口径敏感性**"，不说"改成严口径"：

> "默认口径下，净空区里飞行要批准，我们记待审批。切严口径、把巡视区一律视为禁止：同一张网，停飞从 0 变成 K 班，放行率从 94% 掉到 9x%。**我们不改口径，但要知道口径值多少钱。**"

## 3. W3 1366：判据必须用容器实测高度

| 步骤 | 做法 |
|---|---|
| 1 | 用 `getBoundingClientRect()` 量**舞台容器**高度，`scale = min(w/1920, h/1080)` |
| 2 | 1366 视口下实测 scale 约 **0.50–0.57**（不是 0.711） |
| 3 | 因此需要 **24 px** 设计字号才能渲染到 12 px；全局最小字号提到 24 px 不现实 |
| 4 | 正解：**1366 走关键页断点**（首页/走廊/处置/反事实四页压缩列宽、去留白），其余页保持缩放并接受 10–11 px |
| 5 | 判据：`实测字号 = fontSize × scale ≥ 12 px`，用**容器**算，不用 `window.innerHeight` |

> 历史坑：曾量 `body zoom` 恒 1 得出"已修"的假结论。这次量 `.hstage` 的 `transform` 矩阵 + 最终字号，两个都留截图。
