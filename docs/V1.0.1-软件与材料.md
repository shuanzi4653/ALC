## 1. W1 全国屏（这是"递进"的落地形态）

### 1.1 为什么不是四级连跳

决策板判"8 人日"，是因为把"全国/大区/省/市"做成了四个独立页面。实际不需要：

| 层级 | 怎么实现 | 谁提供 |
|---|---|---|
| 全国 | **新增一屏**（地图 + 七大区着色 + 三态点） | 新做（2 人日） |
| 大区 | **不是页面，是筛选器**（顶部 chips：全部/华北/东北/…） | 包含在上面 |
| 省 | 点地图上的省 → **东北三省进运行态页面，其他省出观测态抽屉** | 复用现有 + 抽屉 ~0.5 人日 |
| 市 | **完全复用现有城市网络视图**，不新增 | 0 |

**这样"全国→省→市"这条递进是真的存在的**，大区作为着色与筛选维度。省下的 6 人日拿去做净空和材料。

### 1.2 屏上内容（一屏讲完，别做第二页）

```
┌─────────────────────────────────────────────────────────┐
│ 全国低空运行态势     [七大区 chips]      [T+00 实时/回放] │
├──────────────────────────────┬──────────────────────────┤
│                              │ 异常省 Top5（按受影响排序）│
│      中国地图（china.json）   │ 1 辽宁  走廊 12 · 停飞 3 │
│      · 省按可飞率着色         │ 2 黑龙江 走廊 9 · 停飞 2 │
│      · ● 运行态 ◐ 观测态 ○ 待接入│ …                     │
│      · 机场限制区（DERIVED）  ├──────────────────────────┤
│                              │ 口径条：机场 240 · 运行态 │
│                              │ 3 省 · 数据源 METAR 实测  │
└──────────────────────────────┴──────────────────────────┘
```

**四个数字（都能追到源头）**：
1. 机场总数 **240**（清单可下载）
2. 运行态省份 **3**（东北三省）
3. 低能见度站数（当前帧 METAR 实测 <3000 m 的站数）
4. 净空受限机场数（限制区与省界/城市点重叠的机场计数，DERIVED）

> **纪律**：没有走廊的省，不显示"受影响班次"。空着就写"未接入"，不编。

### 1.3 判据

- 首屏响应 **< 30 KB**（聚合接口，不含几何；几何走现有 `china.json` 静态资源）
- 点省 → 东北进运行态、其他出抽屉，**1 次交互**
- 1366 下不破版（与 W3 同批验收）
- 地图上 `DERIVED` 几何与 `OFFICIAL` 几何**图例分开**

## 2. W2 机场净空避让与禁飞（扩到 240）

### 2.1 现在有什么（不用重写）

| 已有 | 位置 |
|---|---|
| 三段等级 `PROHIBITED / APPROVAL_REQUIRED / REGISTERED` | `zones.py` |
| 逐班穿越台账（按等级排序、分档计数） | `zones.crossings()` |
| 静态障碍包络 `envelope(policy)` | `zones.py` |
| **绕飞求解**（凸包剪枝 + 切线绕飞） | `routing.route(…, obstacles=)` |
| 机场政策开关（默认 `APPROVAL_REQUIRED`） | `airportFootprintPolicy` |
| 覆盖 | 东北 **69 站点** |

### 2.2 扩到 240 个机场：几何怎么来

| 层 | 几何 | 尺寸 | 标注 |
|---|---|---|---|
| 运输机场限制区 | 圆 | R = 8 km | **DERIVED** |
| 通用/支线机场限制区 | 圆 | R = 5 km | **DERIVED** |
| 跑道净空区 | 两端延长梯形 | 长 10 km，半宽 1.5→3 km | **DERIVED** |
| 机场巡视区（严口径启用） | 圆 | R = 2 km | **DERIVED** |
| 法定管制区（已公布） | 原几何 | 原样 | **OFFICIAL**（仅东北 69 站点） |

**两条硬纪律**：
1. `DERIVED` 必须带 `source` 字段并在图例/材料/口播三处写"按公开跑道方位与机场等级规则化生成，**非官方公布**"
2. **`DERIVED` 不得与 `OFFICIAL` 合并计数**（台账分两栏）

### 2.3 判据与绕飞代价（必须同时出）

| 等级 | 规划器行为 | 台账 |
|---|---|---|
| `PROHIBITED` | 强制绕飞；绕不开 → `NO_GEOMETRIC_PATH` → 停飞 | 记原因 |
| `APPROVAL_REQUIRED`（默认） | 优先绕飞；代价超阈值记"待审批穿越" | 记绕飞增量 |
| `REGISTERED` | 直飞 | 记 1 条 |

**输出模板**（这一块直接进"应用成效"）：
```
穿净空走廊  N 条 → 绕飞后 0 条
新增里程    Δ km   （逐走廊求和）
新增时长    Δ min  （逐班求和）
绕飞 M 架 / 待审批 K 架 / 停飞 0 架
```

### 2.4 演示动作（一个动作讲两个受众）

默认 `APPROVAL_REQUIRED` → 讲"可运行"；现场**切到 `PROHIBITED`** → 停飞数跳起来 → 讲"严口径下的代价"。
切换本身就是"政策可配置、不是写死的"的证据。**同一个动作，民航局看绕飞代价，工信部看禁飞边界。**

## 3. W3 1366 适配：分级缩放，不推翻舞台

决策板与我的意见一致：**别重写布局**。13 个分节全按 1920×1080 坐标系排版，推翻 = 全站回归。

| 视口 | 策略 |
|---|---|
| ≥1600 | 基准（现状） |
| 1280–1600 | `transform: scale(vw/1920)`，但**最小字补偿**：`--base-font` 反向放大，保证渲染 ≥12 px |
| <1280 | 仅对 4 个演示页（首页/走廊/处置/反事实）启用 CSS 断点压缩列宽，其余页保持缩放 |

**判据**：1366×768 下用 `getComputedStyle` 量**实际渲染字号**（`fontSize × scale`）≥12 px；截图与 1920 对比无错位。
（历史坑：曾量 `body zoom` 恒 1 得出"已修"的假结论——**必须量 `.hstage` 的 transform 与最终字号**。）

### 5.1 决策板 D8 有一处要改

D8 写"改判写 **3 048 = 2 640 + 408**"。查证结果：**3 048 是"B 组处置架次"，不是"改判架次"**；而 2 640+408 只是算术上凑得出 3 048，语义上无出处。真正的改判是 3 044（=2 640+404）或 3 030（=2 640+390）。

**处置建议（三选一，我推荐 A）**：
- **A（推荐）**：正文只讲 `2 640 → 0`。它是最强证据（单变量对照），且不依赖会话漂移
- B：讲 `3 044 = 2 640 + 404`，但必须**当天开系统录屏复现**，三处材料用同一张截图
- C：什么都不讲，只在附录放"口径说明"

**无论选哪个，`3 048 = 2 640 + 408` 这个写法必须撤掉**——它是把两个不同域的数焊在一起，评委一追就断。

## 6. W6 代价—工作点表（补一列就变成护身符）

数据全部来自 `data/training/metar/model-v2-metrics.json`（我逐项核过）：

| 目标 | 用途 | 工作点 | POD 命中 | FAR 误报 | **阈值 0.5 时 POD / FAR** | 误报的价格 | 漏报的价格 |
|---|---|---|---|---|---|---|---|
| 能见度 <3 000 m | 预警 | 0.30 | 67.4% | 35.2% | **55.5% / 19.3%** | 提前备运力 | 临场改航，时隙乱 |
| 能见度 <1 000 m | 停飞/熔断 | 0.23 | 46.5% | 63.6% | **25.7% / 44.7%** | **2 848 班绕飞 + 320 min** | **暴露，不可接受** |
| 阵风 >10 m/s | 机型限飞 | 0.21 | 44.6% | 56.0% | **20.5% / 39.7%** | 少飞几班 | 机体风险 |

> 补的最后一列是关键：**FAR 63.6% 不是模型上限，是为保 POD 主动选的代价**。
> 评委问"误报六成怎么用"，答："把阈值从 0.23 抬到 0.5，FAR 能降到 44.7%，但 POD 从 46.5% 掉到 25.7%——等于漏掉四分之三的停飞事件。我们按代价选的工作点。"

**答辩原话（背）**：
> "我们的阈值不是调 AUC 调出来的，是按代价选的。漏报的代价是暴露，不可接受；误报的代价可核算——2 848 班绕飞、320 分钟，占计划总时长 0.1%。所以压在 0.23，宁可多停。**这套取舍只在载物场景成立**：载人时六成误停就是运营停摆。"

## 7. W7 创新层级 + 定性对比 + 删减必替代

**创新层级（官方"须"标注）**：**系统级 + 应用级**
- 系统级：概率校准 → 走廊判据 → 航班处置 → 反事实回算，四段闭环且每段可独立关停
- 应用级：把"气象概率"翻译成"这一班放不放 + 代价多少"

**定性对比（四行表，直接用）**

| 方案 | 给什么 | 决策依据 | 代价可算 | 断网可用 | 差距 |
|---|---|---|---|---|---|
| 传统签派 | 报文 + 经验 | 人读 METAR/TAF | ✗ | ✗ | 逐班人工，无法批量 |
| 商业气象 API | 数据/概率 | 用户自建判据 | ✗ | ✗ | 给原料不给菜 |
| 端到端预测模型 | 气象场/概率 | 不落到处置 | ✗ | ✗ | 精度竞赛，不落地 |
| **本作品** | **可执行裁决 + 代价** | 概率校准 + 走廊判据 + 反事实 | ✓ 每层可核算 | ✓ 边缘节点 | — |

**删减必替代（主动写）**：
> 本作品不做端到端气象预测，采用"概率校准 + 规则裁决"组合路径。替代等价性由消融证明：观测判据档贡献 2 640 架次改判、概率档贡献 404 架次，每层可单独核算。
