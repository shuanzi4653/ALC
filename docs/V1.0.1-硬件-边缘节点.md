> 版本：产品 V1.0.1 配套硬件（固件 `edge-1.0.1`）　|　编制 2026-11-09 18:50
> 对齐决策板：**D6 端侧离线自治**（砍 4G / 摄像头 / 风杯 / 太阳能）、**D7 端云只留 HTTP report + 心跳 + 补传**
> 用户已定：**不用 4G，走手机热点/局域网**
> 预算：≈ **350–450 元**（无上限，但只买"能在答辩里加分或能救场"的东西）

---

## 0. 一句话定位

> 不是"气象站"，是**断网后仍能出裁决的推理盒**。
> 它不采信自己的传感器，它读**本地缓存的 METAR 帧**——所以它敢说"和云端同一个模型、同一组特征"。

**这条定位决定了三件事**：传感器不进裁决、不需要 4G、不怕现场没网。

## 3. 固件分层（5 个模块，别写成一坨）

| 层 | 职责 | 关键点 |
|---|---|---|
| `boot` | 上电、读 NVS 配置（WiFi SSID、服务端 IP、node_id） | 配置写坏要能回落默认值，不能起不来 |
| `frame_cache` | 最近 **6 h METAR 帧**环形缓存（5 min/帧 = 72 帧 × 26 float ≈ 7.5 KB） | 掉电不丢（NVS），带 `ts` 与 `source` |
| `infer` | 100 棵树 → C 数组 → `p_vis` / `p_gust` | 纯函数，无动态内存 |
| `rules` | `rules-v1.json` 阈值 + 走廊参数表 | 与云端同版本，指纹不一致则拒绝裁决并报警 |
| `net` | 局域网 HTTP 上报 / 心跳 / 补传队列 | 断线不阻塞主循环（非阻塞状态机） |

> **一条铁律**：`infer` 与 `rules` 不许依赖网络与传感器。断网、探头坏了，裁决照出。

## 4. 模型移植（这是唯一的技术风险点，先做）

`models/ml-v2-vis3k.json` 实测：`format=alc-forest-v1`，**100 棵树**，26 维特征，`operatingThreshold=0.3`。

| 步 | 做什么 | 判据 |
|---|---|---|
| 4.1 | 写 `tools/ml/_export_forest_c.py`：读 JSON → 生成 `forest_vis3k.h`（节点数组 + 索引） | 生成文件 < 120 KB；节点数、树数与 JSON 对得上 |
| 4.2 | 端侧前向：`p = sigmoid(Σ tree_leaf/100)`（按 JSON 里的聚合方式实现，先照抄 `v2.py` 的推理函数） | 同 1000 组特征，`max\|Δp\| < 1e-6` |
| 4.3 | 量化取舍：**不做 INT8**（树模型不需要），保持 float32 | flash 增量 ≤ 120 KB |
| 4.4 | 单次推理耗时 | ≤ 20 ms @ 240 MHz（含 26 维拼装） |

> **特征怎么来**：全部从 `frame_cache` 里那 72 帧算——`visM/visMin3h/visMin6h/visChange3h/gustMax3h/…` 都在缓存里，26 维齐全。
> 这是本方案能成立的根本：**不靠传感器，靠缓存**。

## 5. 三种运行模式

| 模式 | 触发 | 行为 | 屏上 |
|---|---|---|---|
| **ONLINE** | 连上手机热点，`GET /api/edge/params` 成功 | 校时、取参数指纹、正常上报 | 绿点 · 数据龄 <5 min |
| **DEGRADED** | 热点在但请求失败/丢包 | 用上次帧推理，标数据龄；上报进队列 | 黄点 · 数据龄 xx min |
| **OFFLINE** | 连续 10 min 无成功请求 | 纯本地：缓存帧 → 推理 → 规则 → **2 h 走廊推演** | 红点 · 「离线自治」 |

**屏上四个字段**（一屏讲完，别做多页）：`站名 · 时刻 · p_vis · 裁决（GO/CAUTION/BLOCK）`，右上角模式点。

## 6. 端云交互（最小闭环，D7）

```
POST http://<笔记本LAN-IP>:28083/api/edge/report     每 5 min 或按键触发
POST http://<笔记本LAN-IP>:28083/api/edge/heartbeat   每 60 s
GET  http://<笔记本LAN-IP>:28083/api/edge/params      启动时 + 每小时
```

载荷（≤1 KB）：
```json
{"node":"EDGE-01","ts":"2026-11-09T10:00:00Z","seq":10231,"mode":"OFFLINE",
 "p":{"vis":0.72,"gust":0.11,"model":"ml-v2-vis3k","fp":"alc-forest-v1"},
 "decision":{"tier":"CAUTION","reasons":["VIS<3000m"]},
 "corridors":[{"id":"CAR-1-01-1-02","verdict":"HOLD"}],
 "latencyMs":18,"fw":"edge-1.0.1","sig":"<hmac>"}
```

- 去重键 `node + seq`；`seq` 单调递增，掉电从 NVS 续
- 补传：环形队列 500 条，重连后按 seq 顺序发，失败退避 5s→30s→120s
- 签名：HMAC-SHA256(`node|ts|seq|body`)，密钥烧在 NVS，服务端 `.env.secrets` 有同值
- **不做 MQTT / 不做 TLS**（局域网内 HTTP，D7 已定）；公网部署时由 nginx 终止 TLS

**云端最小改动**（不破现有契约）：
| 改动 | 规模 |
|---|---|
| `POST /api/edge/report`（含去重、限频 10/min、签名校验） | ~80 行 |
| `POST /api/edge/heartbeat` + 在线态表（90 s 判离线） | ~40 行 |
| `GET /api/edge/params`（下发 rules 指纹 + 走廊参数） | ~30 行 |
| 前端首页一张卡「边缘节点 · 在线 1/离线 0 · 最近 20 条」 | ~60 行 |

> 默认 `edge.enabled=false`，演示时开。**因为默认关，所以不构成契约变更——版本停在 1.0.1，不进 `contracts/`。**

## 7. 验收（5 条，全过才算完成）

| # | 判据 | 怎么测 |
|---|---|---|
| 1 | 冷启动到出第一屏裁决 ≤ 5 s | 拔电重上，秒表 |
| 2 | 同 1000 组特征，端 vs 云 `max\|Δp\| < 1e-6` | 脚本对拍，出 CSV |
| 3 | 同输入裁决一致率 100% | 同上，比对 tier |
| 4 | 关热点 30 min 后开热点，服务端条数与端侧队列数一致、零重复 | 查库 `count(distinct seq)` |
| 5 | 90 秒演示连跑 **5/5 成功** | 排练记录 |

**止损线（D6）：11/15 若第 2 条不过，立即砍硬件，回 L0（纯软件演示 + 录屏）。**
砍了不丢人——`max|Δp|<1e-6` 过不了还硬上，答辩现场会被问穿。

## 8. 90 秒演示脚本（现场版）

| 时间 | 动作 | 台词 |
|---|---|---|
| 0:00 | 装上电池，屏亮 | "这是我们的边缘节点，成本 280 块。" |

## 9. 风险

| # | 风险 | 对策 |
|---|---|---|
| 1 | 热点把节点与笔记本分到不同网段 | 演示前固定 IP 写 NVS；备用方案＝笔记本自建热点 |
| 2 | 手机热点休眠断流 | 关省电、锁屏常亮；或用备用手机 |
| 3 | 焊接/烧板 | 两块板；先面包板后洞洞板；不焊芯片只焊排针 |
| 4 | 缓存帧过期（会场缓存是几天前的） | 演示前用笔记本推一帧进节点（提供 `--seed` 命令） |
| 5 | 屏刷新拖慢主循环 | SPI 用 DMA；UI 只刷变化的字段 |
| 6 | 时间不够 | 砍序：2 h 推演 → 按键交互 → 外壳；**缓存推理与上报不砍** |

## 11. 红线（写在纸上贴桌上）

1. **不说**"我们的传感器能进业务运行"——BME280 是消费级，只作自采通道展示。
2. **不说**"模型是我们现场训练的"——模型是离线训练的，端侧只做推理。
3. **不说**"边缘节点替代云端"——它是**降级兜底**，不是替代。
4. 屏上永远显示**帧来源与数据龄**；没有来源的数字不许上屏。
