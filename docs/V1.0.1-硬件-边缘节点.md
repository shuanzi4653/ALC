### 1.1 三条改单理由

**① 电池换一体套件——不是省钱，是不烧板**
TP4056 只充电不升压。原方案"TP4056 + MT3608 升压"意味着 MT3608 出厂电位器位置不定，**输出常 >12 V**，没先调到 5.0 V 就接主板 5V 脚 → 板当场报废。而且原 BOM 没有电源开关（演示第一句是"装电池，屏亮"，只能拔线）。一体套件三样全有，免焊，只有一个 5V 输出口。

**② 面包板是必需项**
D1 判据要反复插拔调试；洞洞板一焊死，改线要拆焊。两个没焊过东西的人第一天就焊，大概率第一天就废一块板。

**③ 删 USB-TTL / 三脚架 / 百叶罩，省 43 元也省三个麻烦**
DevKitC-1 板载 USB-UART，Type-C 直烧；三脚架+百叶罩会让评委默认"你们又做了个气象站"，要多花一分钟解释"它不是"。

## 2. 装配与接线

```
┌──────────────────────────┐
│ 1.9" IPS（盒盖开窗）      │
│ ┌──────────┐             │
│ │ ESP32-S3 │ ← M2.5 铜柱抬高 3 mm
│ └──────────┘             │
│  18650 套件（与主板隔 5 mm）│
└──────────┬───────────────┘
           │ 硅胶线穿防水接头
     ┌─────┴─────┐
     │ BME280    │  ← 盒内即可（不装百叶罩；它不进裁决）
     └───────────┘
```

| 信号 | 引脚 | 备注 |
|---|---|---|
| BME280 SCL / SDA | GPIO10 / GPIO11 | 3V3 供电；地址 0x76 |
| 屏 DIN / CLK / CS / DC / RST | GPIO12 / 13 / 14 / 15 / 16 | SPI2 |
| **屏 BL（背光）** | **GPIO17，或直接并 3V3 常亮** | **漏了它屏不亮，而 D1 全部判据挂在"屏亮"上** |
| **按键** | **GPIO4** | **不要用 GPIO0**：那是 BOOT 拉低进下载模式，开机误触直接进烧录态 |

**禁区**：N16R8 是 Octal PSRAM，**GPIO33–37 被内部占用**；GPIO26–32 归 flash。上表的 10–17 全部安全。

**电源纪律**：绝不直接给 18650 焊线（封不住、局部过热、有起火风险），用电池盒或带焊片电芯；充电时把盒盖打开（TP4056 会发热）。

## 3. 固件分层

| 层 | 职责 | 关键点 |
|---|---|---|
| `boot` | 读 NVS 配置（SSID、服务端 IP、node_id） | 配置写坏要回落默认，不能起不来 |
| `frame_cache` | **按 METAR 原时序存最近 ≥7 条观测**（不是 5 min 插值帧，见 §4.2 坑 1） | 掉电不丢，带 `ts` + `source` |
| `infer` | 100 棵树 → `p_raw` → 等渗校准 → `p_cal` | 纯函数，无动态内存 |
| `rules` | 阈值 + 四档 + `p_unsafe` 合成 | 与 `rules-v1.json` 同版本，指纹不符拒绝裁决 |
| `net` | 局域网 HTTP 上报 / 心跳 / 补传 | 非阻塞状态机 |

**铁律**：`infer` 与 `rules` 不许依赖网络与传感器。断网、探头坏了，裁决照出。

## 4. 模型移植（唯一技术风险点，先做）

`ml-v2-vis3k.json`：`format=alc-forest-v1`，**100 棵树**，26 维，`operatingThreshold=0.3`。

### 4.1 真实推理是三段，不是一段（原公式作废）

**原册子写的 `p = sigmoid(Σ tree_leaf/100)` 是错的**——链路里**一步 sigmoid 都没有**。真实链路（`ml/forest.py` + `ml/nowcast.py`）：

**① 叶子不是标量，是一对概率**：`[p_neg, p_pos]`（和为 1）；树是嵌套数组 `[特征下标, 阈值, 左, 右]`。

**② 聚合 = 每棵树归一后取平均**：
```python
for tree in trees:
    counts = leaf                 # [neg, pos]
    total  = sum(counts)
    for i in range(2): totals[i] += counts[i] / total
grand = sum(totals) or 1.0
probs = [t / grand for t in totals]   # p_raw = probs[1]
```

**③ 还有一步 92 点等渗校准**（`numpy.interp` 语义：越界取端点，中间线性）：
```python
raw = forest.predict(v)['probabilities']['POS']
p   = _interp(raw, calibration['x'], calibration['y'])
```

> 按原公式写，`Δp` 会是 **0.1–0.4** 量级，11/15 必挂，而且会被误判成"ESP32 浮点精度不够"——真实原因只是漏了一次校准查表。

### 4.2 可直接照写的 C 骨架（约 30 行）

```c
/* 1. 单棵树：迭代下降，不递归，免栈 */
static float tree_pos(const node_t *n, const float *x) {
    while (n->feature != 0xFF) {
        n = (x[n->feature] <= n->threshold) ? (n + n->left) : (n + n->right);
    }
    return n->p_pos;              /* 叶子已归一，直接取 pos 分量 */
}

/* 2. 森林平均 = p_raw */
float p_raw = 0.f;
for (int t = 0; t < N_TREES; t++) p_raw += tree_pos(&forest[t], x);
p_raw /= N_TREES;

/* 3. 等渗校准（numpy.interp 语义） */
float p_cal;
if (p_raw <= CAL_X[0])            p_cal = CAL_Y[0];
else if (p_raw >= CAL_X[CAL_N-1]) p_cal = CAL_Y[CAL_N-1];
else {
    int i = 1;
    while (i < CAL_N && p_raw > CAL_X[i]) i++;
    float span = CAL_X[i] - CAL_X[i-1];
    p_cal = (span <= 0) ? CAL_Y[i]
          : CAL_Y[i-1] + (p_raw - CAL_X[i-1]) / span * (CAL_Y[i] - CAL_Y[i-1]);
}
```

**导出脚本必须做的一件事**：**阈值在导出时就 round 到 float32**。用 `double` 读阈值去和 `float` 特征比，边界样本会走错分支，`Δp` 跳 1e-2。

### 4.3 判据（只有两条，别再加载荷）

| 判据 | 值 |
|---|---|
| 同 1000 组特征，端 vs 云 `max\|Δp\|` | **< 1e-6** |
| 单次完整裁决链（读缓存 → 26 维 → 推理 → 判决） | **≤ 20 ms @ 240 MHz** |

> 这道门已被走通过一次：三个目标都带 `exportParity = {checked: 202, maxAbsDiff: 0.0, tolerance: 1e-06}`（float32 口径）。**不做体积判据**——16 MB flash，120 KB 还是 400 KB 对功能与答辩都无影响。

## 5. 六个"照抄就会错"的口径

| # | 坑 | 服务端真实行为 | 照错的后果 |
|---|---|---|---|
| 1 | **采样步长** | `past = reversed(history)[:6]`；`visMin3h = min(pv[:3])`、`visMin6h = min(pv[:6])` | 按 5 min/帧存 72 帧再取前 6 条 → `visMin6h` 变成"30 分钟窗口" → Δp 必挂。**缓存要按 METAR 原时序存 ≥7 条** |
| 2 | **校时基准** | `ts = fromtimestamp(epoch, UTC)`；`hour_rad = ts.hour*2π/24` | 用北京时间算 `hourSin/hourCos` → 整体偏 8 小时 |
| 3 | **四档不是三档** | `BAN ≥0.8 / CAUTION ≥0.5 / WATCH ≥0.2 / FIT`；`p_unsafe = 1-(1-p_vis)(1-p_gust)`；观测档 `vis<1000 或 gust>11.5 → BAN`，`vis<3000 → CAUTION` | 屏上写 GO/CAUTION/BLOCK → **"裁决一致率 100%"必然失败** |
| 4 | **stationCode 只有 3 个值** | `{ZYTX:0, ZYCC:1, ZYHB:2}`，其他站 `-1.0` | 第 4 个站不报错、只静默给错概率。**这个模型只覆盖三站；全国屏 240 站不能拿它算"可飞率"** |
| 5 | **26 维里 4 维是缺失标记** | `miss_vis/miss_gust/miss_cloud/miss_temp`，在填默认值**之前**按原字段是否 None 置 0/1 | 只填 `defaults` 不置标记 → 缺测样本概率整体偏移 |
| 6 | **要移两个模型** | 裁决用 `p_vis`（<1000 m）+ `p_gust`（>10 m/s）合成 `p_unsafe`；`vis3k` 只用于展示 3 km 概率 | 只移 vis3k → 算不出 `p_unsafe` → 判不出四档。**每个模型各有 92 点校准表** |

> 口径提醒：模型目标是**阵风 >10 m/s**，业务限飞阈值是 **11.5 m/s**（`rules-v1.json::gustMps`）——两个数不要混着讲。

## 6. 三种运行模式

| 模式 | 触发 | 行为 | 屏上 |
|---|---|---|---|
| **ONLINE** | 热点连上，`GET /api/edge/params` 成功 | 校时、取参数指纹、正常上报 | 绿点 · 数据龄 <5 min |
| **DEGRADED** | 热点在但请求失败 | 用上次帧推理，标数据龄；上报进队列 | 黄点 · 数据龄 xx min |
| **OFFLINE** | 连续 10 min 无成功请求 | 纯本地：缓存帧 → 推理 → 四档 → 2 h 推演 | 红点 · 「离线自治」 |

**屏上五个字段**：`站名 · 时刻(UTC) · p_vis · 四档 · 数据龄`，右上角模式点。

> **推演窗口怎么讲**：模型 `provenance.window = future 3h (t+1h..t+3h)`，`leadTime` 中位 120 min。
> 所以口播说 **"未来 1–3 小时"** 是安全的；说"30 分钟"反而越界（模型不含 t+1h 内的即时外推）。
> 屏上打 `推演 2 h（模型视野 1–3 h）`，别说"未来 3 小时"。

## 7. 端云交互（局域网，最小闭环）

```
POST http://<笔记本LAN-IP>:28083/api/edge/report     每 5 min 或按键
POST http://<笔记本LAN-IP>:28083/api/edge/heartbeat  每 60 s
GET  http://<笔记本LAN-IP>:28083/api/edge/params     启动 + 每小时
```

载荷（≤1 KB）：`{"node","ts","seq","mode","p":{"vis","gust","unsafe"},"decision":{"tier"},"latencyMs","fw","sig"}`

- 去重键 `node+seq`；补传环形 500 条，退避 5s→30s→120s

**云端最小改动**：`/api/edge/report`（去重+限频+签名，~80 行）、`/heartbeat`（~40 行）、`/params`（~30 行）、首页节点卡（~60 行）。默认 `edge.enabled=false`，**不构成契约变更**。

## 11. 四个会烧板/不亮的陷阱

1. **屏背光 BL 漏接** → 屏不亮，而 D1 全部判据挂在"屏亮"上（接 GPIO17 或并 3V3）
2. **按键用 GPIO0** → 开机误触进烧录态（改 GPIO4）
3. **直接给 18650 焊线** → 封不住、局部过热、有起火风险（用电池盒/带焊片）
4. **12 V 进 3.3 V 板** → 若仍用 MT3608，接板前先用万用表调到 5.0 V

## 12. 红线

1. 不说"我们的传感器能进业务运行"——BME280 是消费级，只作自检。
2. 不说"模型现场训练"——模型离线训练，端侧只做推理。
3. 不说"边缘节点替代云端"——它是**降级兜底**。
4. 屏上永远显示**帧来源与数据龄**；没有来源的数字不许上屏。
5. **不说"这个模型覆盖全国"**——`stationCode` 只有 ZYTX/ZYCC/ZYHB 三个值，其他站返回 -1。
