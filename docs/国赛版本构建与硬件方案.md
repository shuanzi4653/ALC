## 0. 三句话结论

1. **国赛不是"再加功能"，是"把五个二档推成一档"。** 省赛的 74→86 分里，只有 3 分靠技术深度，9 分靠材料。国赛排名取前 15% 一等奖，边际收益最高的是**需求调研、第三方佐证、创新点提法**这三件非代码的事。
2. **硬件不是必要条件，规则里没有这一项。** 六个评分维度中没有任何"实物/硬件"栏。**为硬件而硬件会直接拖累"项目实施"。**
3. **但硬件有一条值得做的路子**：自建一个 200–350 元的边缘观测节点，把"数据从哪来"这件事从"用公开数据"变成"我们采的数据 + 公开数据融合"。它补的是我们最薄的一环（需求分析 + AI 技术应用），不是当道具。

## 1. 先把规则摊开：国赛比的是什么

复赛（=省赛）与总决赛**用同一套评分表**，100 分：

| 维度 | 分值 | 一档门槛（原文） | 我们省赛的落点（估） |
|---|---|---|---|
| 创新性 | 25 | 全新 AI 应用模式，**具有开创性** 18–25 | 16（二档偏上） |
| 需求分析 | 15 | 剖析深入、**调研方法科学** 10–15 | 10（一档下限） |
| AI 技术应用 | 20 | 选择合理、融合紧密、**难度高且效果好** 14–20 | 15（二档偏上） |
| 项目实施 | 15 | 方案完整、计划合理、关键技术实现良好 10–15 | 13（一档） |
| 应用成效 | 15 | 成果显著、效益突出、**数据详实** 10–15 | 12（一档下限） |
| 总结与展望 | 10 | 全面准确、展望前瞻 7–10 | 8（二档偏上） |

**读法**：五个"二档偏上/下限"是当前最大的隐性损失——档位是取整的，二档再高也只算二档。
国赛要进 15%，目标应该是 **3 个一档 + 其余一档下限**（按 §2.3 的六条动作估算约 **86–90**；要摸到 90 以上，靠的是赛场表达与佐证真伪）。

### 1.1 复赛已知的三处失分（来自 10-27 复核）

| 失分点 | 现状 | 国赛怎么办 |
|---|---|---|
| 无需求调研过程 | 只有"问题真实存在"，缺"问过谁、怎么问" | **补 5 份可追溯调研**（通航/气象/机场/物流/校内导师），做成附录表 |
| 第三方佐证几乎为零 | 软著仅"受理"（流水号 2026R11.3476201） | 争取 1 份合作意向书或试点证明 + 软著受理函 + 公开数据核验记录 |
| 材料数字会漂 | A 组 2613→2402、改判 3044→3030 跨天重建就变 | 国赛一律只引**同会话录屏**抄下的数，或只用稳定组 |

## 2. 国赛版本构建思路（软件）

### 2.1 一条主线、三个里程碑

```
V1.0.0（已上线）
   │
   ├─ M1  V1.1.0  「可信版」      工程修复 + 现场演示不死
   │      4–6 人日   （不含硬件）
   │
   ├─ M2  V1.2.0  「可核查版」   调研 + 佐证 + 模型卡 + 消融表
   │      6–8 人日
   │
   └─ M3  V2.0.0  「国赛版」      仅在接入硬件/新契约时启用，否则交付 1.2.0
          5–10 人日（含硬件联调）
```

**版本号口径**（`docs/NAMING.md` §7）：正式版按 `x.y.z` 递增。`1.1.0/1.2.0` 是功能增量；只有新增对外契约（边缘节点接入、新数据源）才升 `2.0.0`。**不要为了好看跳到 2.0.0 却没有任何契约变化**——评审问"2.0 比 1.0 多了什么"，答不上来比不升更糟。

### 2.2 M1「可信版」V1.1.0 —— 七件必修

全部来自 11-09 盘点的遗留，都是**评审能看到**的问题：

| # | 项 | 判据 |
|---|---|---|
| 1 | **1366×768 整站缩放**（`.hstage transform: scale(0.5028)`，最小字 9.5 px） | 1366 下最小字 ≥ 12 px；评委笔记本 90% 是 1366/1440 |
| 2 | **冷启动建场时长**（0.34 s 已优化过，但首访仍有 16–23 s 空窗） | 首访 ≤ 8 s，或给明确进度语义（不显示"已开始"） |
| 3 | **离线/弱网演示模式** | 断网仍能跑完 5 分钟主流程，有降级横幅 |
| 4 | **演示脚本固化** | 一条命令进入 `?case=fog-20250105` 指定状态，KPI 固定可复现 |
| 5 | 材料数字「同会话」口径 | 录屏脚本内置取数页，数字从页面抄而不是从旧文档抄 |
| 6 | `.run/traffic` 无界（8 计划 200 MB） | 同代次设上限 + 定时清理；线上磁盘 23% 不是问题，但"工程纪律"是加分项 |
| 7 | 文档与实机不一致（`-Xmx384m` vs 文档 512m；CHANGELOG 缺 13 行） | 一处口径，发版前自动核对 |

### 2.3 M2「可核查版」V1.2.0 —— 四个上档动作

**动作 A：需求调研（需求分析 10 → 13，性价比最高）**

- 5 份可追溯材料，每份含：对象角色 / 时间 / 3 个原话问题 / 对应改了哪个功能
- 建议对象：① 通航或无人机运行公司值班员 ② 气象局预报/服务岗 ③ 机场气象观测 ④ 低空物流运营 ⑤ 校内做过空域课题的老师
- 做法：30 分钟访谈 + 一张表。**必须有"因为这次访谈改了 X"的闭环**，否则是走过场
- 产出：`docs/需求调研记录.md` + 方案第二章改写 + 附录原件

**动作 B：AI 技术应用 15 → 17（不训大模型也能上档）**

现有资产：METAR 标签、`ml-v2-vis3k`（AUC 0.947）、`ml-v2-gust`（0.9358）、TS/Brier + 三条基线、概率档 + 置信门。缺的是**把它写成方法而不是功能**：

1. **模型卡（Model Card）**：训练样本量、特征 26 维清单、标签定义、时间划分防泄漏、AUC/Brier/TS 与三条基线对比、失效条件
2. **消融表**：三层各自贡献（观测判据 2640 架次改判 / 概率档 404 / 端到端 0 架次入不可飞走廊）——**每层可单独核算**，这是"难度高"的证据
3. **一次真正的对照实验**：同快照、同计划，只关一层，跑 5 个 case 出表（现在只有 1 个 case，国赛建议 3–5 个）
4. **主动写"等效替代论证"**（官方"删减必替代"条款）：不做端到端气象预测，用"概率校准 + 规则裁决"，等价性由消融证明

**动作 C：应用成效 12 → 14（补第三方佐证）**

按可获得性排序，能拿几个算几个：

| 佐证 | 现状 | 国赛动作 | 权重 |
|---|---|---|---|
| 软著 | 已受理（2026R11.3476201） | 拿受理通知书扫描件入佐证 PDF | 高 |
| 试点/试用证明 | 无 | 找 1 家通航/无人机/物流企业出 1 页盖章说明（哪怕"内部试用两周"） | 最高 |
| 用户反馈 | 无 | 调研访谈的 5 位对象，请 2 位写一段书面评价（可匿名单位） | 高 |
| 论文/专利 | 无 | 时间不够就不追；有 `docs/paper-innovations.md` 可投会议短文 | 中 |
| 公开数据核验 | 有 | 附"评委可自行核验"的一页：ASOS 档案链接 + 日期时刻 + 数值 | 中 |

**动作 D：创新性 16 → 19（提法升级）**

- 明确标注创新层级：**系统级 + 应用级**（原文要求必须标）
- 把"反事实闭环裁决"提成一个**可命名的范式**：气象概率 → 走廊判据 → 航班处置 → 反事实回算，四段闭环、每段可单独关停
- 做一张「与主流方案定性对比表」：传统签派（人读报文）/ 商业气象 API（只给数据）/ 端到端预测模型（给概率不给处置）/ 本作品（给可执行裁决 + 代价量化）

### 2.4 M3「国赛版」V2.0.0 —— 只在接硬件时启用

新增契约：`POST /observations/ingest`（边缘节点上报）、`source=EDGE` 来源标签、`/v2/overview` 增加"自采/公开"分栏。
**这三条一动，就是契约变更**，必须同步更新 `contracts/` 与 `verify-remote.sh`。

### 2.5 现场/线上答辩的"不死"清单

用户提到可能是**线上半决赛**。线上答辩最怕三件事，都要提前做：

1. **网络断了**：本地 `start.bat` 起全套（Python + Java + 前端），离线模式跑同一 case，5 分钟内可切
2. **共享屏幕卡**：录一段 3–5 分钟成品视频兜底，卡住就放视频（官方视频本来就是必交件）
3. **时间失控**：5 分钟演示脚本精确到秒（0:00 首页结论 → 1:00 走廊判据 → 2:30 处置与代价 → 4:00 反事实 → 4:40 收口）

## 3. 硬件：有没有必要？怎么做？

### 3.1 先回答"有没有必要"

**规则层面：不必要。** 六个评分维度没有一项要求实物；官方原文是"不限定成果形态"。

**竞争层面：别人有硬件，不等于硬件加分。** 评委按同一张表打分，硬件只在三个地方间接起作用：

| 间接受益的维度 | 硬件能补什么 | 不做的代价 |
|---|---|---|
| 需求分析 15 | 证明"我们知道现场要什么"（自采观测点） | 可用调研访谈替代 |
| AI 技术应用 20 | 证明"模型能在端侧跑"（延迟/量化/离线） | 这一栏本来就有 15 分底子 |
| 应用成效 15 | 实物 = 可感知的完成度 | 可用试用证明替代 |

**风险层面：** 时间未定（可能只有 3–4 周）、零预算、线上答辩硬件无法运输。**硬件是"锦上添花且必须一次成功"的项。**

**结论**：**不做重硬件（沙盘/无人机/机场模型），做就只做"能改变结论"的轻硬件。**

### 3.2 判据：硬件必须回答一个软件回答不了的问题

| 问题 | 只有硬件能答 | 硬件形态 |
|---|---|---|
| 数据是你自己采的吗？ | ✅ 自建观测节点 | L1 |
| 模型在断网、算力受限的现场还能跑吗？ | ✅ 端侧推理盒 | L2 |
| 界面好看吗？ | ❌ 软件就能答 | 不做 |

**凡是落在第三行的硬件，一律不做。**

### 3.3 三档方案（成本/工时/风险）

#### L0 不做硬件（基线方案，推荐先按这个准备）
- 用「真实 METAR + 公开数据核验页 + 5 份调研 + 1 份试用证明」顶上
- 成本 0，工时 0，风险 0
- **必须做**：这是保底，任何硬件方案失败都回到这里

#### L1 边缘观测节点（推荐，≈250 元 / 2–3 人日）

```
[BME280 温压湿] ┐
[风杯/超声波风速] ├→ ESP32-S3 ──WiFi/MQTT──→ 本机 FastAPI /observations/ingest
[ESP32-CAM 图像] ┘        │                        │
                      [2.9" 墨水屏]            source=EDGE 标注
                     显示"当前放行结论"        与 METAR 同屏对照
```

| 件 | 型号 | 估价 |
|---|---|---|
| 主控 | ESP32-S3-DevKitC（8MB PSRAM） | 45 |
| 温压湿 | BME280 | 15 |
| 风速风向 | 风杯式（脉冲计数）或超声波 RS485 | 60 / 200 |
| 图像（能见度） | ESP32-CAM（OV2640） | 35 |
| 显示 | 2.9" 三色墨水屏 | 65 |
| 电源/线材/外壳 | Type-C 5V2A + 3D 打印或亚克力 | 60 |
| **合计** | | **≈280** |

- **演示脚本（90 秒）**：加湿器对着传感器 → 湿度/能见度下降 → 屏幕 3 s 内变"谨慎" → 网页走廊判据同步变化 → 处置台出现新增停飞。**这是"物理世界改变决策"的闭环，比任何 PPT 都有说服力。**
- 软件侧改动：`/observations/ingest`（新端点，签名 + 限频）、`source=EDGE` 标签、`/v2/overview` 分栏、`rules-v1.json` 增加"自采通道可用性"开关（默认关，答辩时开）
- 风险：现场 Wi-Fi 不稳 → 走**本机热点**，不依赖会场网络；传感器漂移 → 答辩前 30 分钟标定一次，脚本里写"未标定不判级别"

#### L2 端侧推理盒（可选，≈1 200–1 800 元 / 4–6 人日）

- 硬件：树莓派 5（8 GB）或二手 Jetson Orin Nano
- 软件：`ml-v2-vis3k.json` → ONNX → INT8 量化 → 端侧推理；输入 26 维特征，输出 p
- **可量化指标**（这一栏最能上档）：
  - 模型体积 1.2 MB → ≤ 400 KB（量化后）
  - 单次推理 ≤ 5 ms（CPU），与云端 Python 结果差 < 1e-4（同一组特征逐条比对）
  - **拔网线**仍出结论：端侧算 p → 本机规则裁决 → 页面出结果
- 讲故事的角度：**"不是能不能上云，而是断网时能不能活"**——低空现场恰恰是弱网环境
- 风险：量化掉点要用同一个测试集复核（AUC 掉幅 ≤ 0.01 才敢讲）

#### L3 重硬件（不做）
无人机、机场沙盘、跑道模型：成本 3 000+、运输风险高、与算法无关、答辩 5 分钟讲不完。**明确放弃。**

### 3.4 推荐组合

| 时间余量 | 建议 |
|---|---|
| ≥ 4 周 | **L1 + L2**，版本升 2.0.0，材料里加"端侧部署"一节 |
| 2–3 周 | **只做 L1**，版本 1.2.0 不变（`source=EDGE` 走可选扩展，不破契约） |
| < 2 周 或 线上答辩 | **只做 L0**，把力气全投调研 + 佐证 + 视频 |

### 3.5 不做硬件也能拿"应用成效"的替代路径（同等重要）

1. **试用证明**：1 页盖章，写"于 X 年 X 月对 Y 场景试用，覆盖 Z 条走廊，结论可用" —— 比硬件便宜，比硬件有效
2. **公开可核验页**：把 2025-01-05 沈阳大雾的 4 站报文、时刻、数值列成表，注明"评审可自行在 ASOS 档案核到"
3. **用户原话**：调研访谈里最锋利的 3 句原话直接放进方案第四章

## 5. 需要你拍板的三件事

1. **预算**：L1 ≈ 280 元 / L1+L2 ≈ 1 500–2 000 元。要不要投？
2. **人力**：L1 需 2–3 人日（含焊接/外壳），L2 需 4–6 人日。你手上还有 WisDiet、HongSight、课程，能挤出几天？
3. **形态**：决赛若线下，硬件要不要带实物？带就要考虑运输与"现场没网"（L1 自带热点方案已覆盖）。

**我的建议**：先按 L0 把所有材料做扎实（这部分无论有没有硬件都要做），同时花 280 元把 L1 打出来当"面试作品"——它最大的价值不是加分，是**答辩时手里有东西**。
