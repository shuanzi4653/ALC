## 1. 三处判断修正（与执行方案不同）

### 1.1 「叶子节点 908」不能当验收指标

报告自己给了两档数据：1680 宽 **908**，1366 宽 **99**。**同一页面、同一份代码，差 9.17 倍** —— 它量的是渲染结果，不是信息结构。拿它当判据会出现"改成 1366 就通过"的假通过，而评委用他们自己的屏幕。

冲奖版改用三条**与视口无关**的判据（全部可断言）：

| 判据 | 断言 | 为什么抗视口 |
|---|---|---|
| 顶层信息块数 | `document.querySelectorAll('.hs-panel').length <= 4` | 结构，CSS 折叠不改变 DOM 数量 |
| 结论条字数 | `.hs-brief` 的 `innerText.length < 160` | 文本，与宽度无关 |
| 主按钮唯一 | 首屏可见 `button.primary` 恰好 1 个 | 交互元素 |

> "更乱"这个**方向我认同**。上一轮我为修"首页没回波"把 `show-radar/fog/weather` 接上了，KPI 基线也写得更长——每一条单独都对，合起来就是更密。**这是"一条一条修"的必然结果。**

### 1.2 W-25b 的路径要换：不是"重跑建场"，是"把已经算出来的结论搬上处置台"

执行方案写 `b（6h）动建场管线，让雾天案例真的产出 weather_flights > 0`。

**这条路走不通**，缺的不是时间而是数据：案例文件只有 `history`（7h×3 站 METAR）与 `frames`，**没有雷达瓦片**；而 `service.session()` 的链里是 `_radar_avoidance → weather_control.radar_frame → cma_tiles`。真跑只能跳雷达层（案例处置口径与实时不同源）或造雷达帧（造假）。

**但报告的方向是对的：那 123 班与 21 条禁飞必须同源。** 换一条路就能做到，而且更省：

> **`counterfactual(case)` 已经把"天气进决策"算出来了**：A 3016 → B 0，改判 3048 班（观测档 3048）。它只是待在「复盘 » 反事实」页，没进「处置台」。
>
> 把它搬到处置台，首页那 21 条禁飞就从"孤立的判据"变成"有下文的判据"。

**具体做法（3h）**：
- 后端：`counterfactual` 已返回 `detail`/`delta`，补一个 `casePanels` 摘要（21 条走廊 / 3048 班 / 3016 应改航 / 32 应延误），**不新增计算**；
- 前端：处置台在 `caseMode` 下顶部加一张「本案例判据」卡，与下方「实时推演事件」用分隔线明确分区，各自带来源角标。

结果：首页"21 条禁飞" ↔ 处置台"21 条、3048 班该处置"——**同源、可点、有下文**。评委问"那这 21 条上的飞机呢"，答案是"3048 班，按观测档该改航 3016、延误 32，见反事实"。

### 1.3 消融的修法不是"标注不可比"，是让 A 组恒定

W-30 原写"表格里标出该组 A 组已无暴露，差值不可比"。**这会让一张错的表变得看起来更严谨，但仍然是错的。**

A 组的定义是"现行做法"（只看当前观测、按人工值班逻辑），**它必须恒定**；消融只能改 B 组。现在 `use_obs/use_prob` 同时作用在两组上，等于把对照组和被测对象一起改了。

修法（3 行）：

```python
# A 组：现行做法，不受消融影响
current_obs_ban = _nearest_observation_level(route, field_payload) == 'BAN'
current_ban = current_obs_ban or p_unsafe >= 0.8
if rule_level < 2 and current_ban: exposure_a += 1

# B 组：本系统，被消融影响
obs_ban = use_obs and current_obs_ban
ban_hit = obs_ban or (use_prob and p_unsafe >= 0.8)
```

改完四组立刻可比，且「去观测档 → B 组暴露回到 3016」是一句**能讲的结论**，比"不可比"强得多。

## 3. 逐张施工说明

每张四段：**现在是什么 → 改成什么 → 为什么 → 怎么算改完（可断言）**。

### W-25a · 处置台那句"与天气无关"（1h）

**现在**（雾天，第一屏）：

```
停止放行 123 班，其中气象成因 0 班 —— 不要把这一屏读成天气造成的
气象成因 0        非气象成因 361
当前窗口内的 361 个事件里没有气象成因的：停止放行 123 班全部来自排程越界
（超出推演时段），与天气无关。切到「排程冲突」可查看这些事件。
```

三处问题：①「与天气无关」直接否定首页 21 条禁飞；②「切到『排程冲突』」——**全站没有这个 tab**（"排程冲突"是卡片上的二分类标签）；③ 没给"那天气去哪了"的出口。

**改成**：

```
本案例只回放观测与判据，不重跑调度。
下方 123 班的停止放行来自实时推演（超出规划视界），与本次回放的气象无关 ——
要看气象进入决策后的差别，见「复盘对照 » 反事实」。
```

**为什么**：同一个事实两种读法。「与天气无关」读者听到"你的天气没用"；「本案例不重跑调度」读者听到"这一页不负责那件事"。

**改完**：
- 处置台紧邻文案不含「与天气无关」「排程冲突」
- 含「不重跑调度」，且含一个跳 `counterfactual` 的按钮

### W-27 · markdown 归零 + 扫描面扩展（1h）

**现在**：`_scan_markdown_leak.py` 只扫 `.vue` 的 `<template>`，共 0 处。而 `runtime.js` 的 `boundary` 字段有 20 处，模板 `{{}}` 直渲 → 泄漏。

**改成**：
1. `boundary` / `definition` / `source` 等文案字段里的 `**x**` → `<b>x</b>`，反引号 → `<code>x</code>`（20 处）；

**为什么**：不扩面必复发——病因是扫描器的**射程**，不是那 20 处字面量。

**改完**：输出 `合计 0 处`，且 `--self-test` 两条负向用例通过。
