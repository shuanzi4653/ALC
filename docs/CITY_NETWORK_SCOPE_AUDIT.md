# 东三省城际交通监测：现状核查与改造边界

本文为改造前核查记录。用户已确定低空飞行汽车、城区外卖无人机和模拟运行数据；跨省仅省会相连。本轮按 36 个地级行政区实施，具体实现见 [0.9.4（Beta） 更新说明](CITY_NETWORK_V1.1.md)。下表描述的是改造前状态。

## 当前系统的不足

| 当前实现 | 对全域城际监测的影响 | 必须改造 |
|---|---|---|
| 主界面只有沈阳、长春、哈尔滨附近三个演示任务 | 无完整城市目录，不能覆盖东三省各城市 | 独立城市目录，稳定行政区标识与来源台账 |
| 旧渲染器只有10个固定节点、9条固定连线 | 不是城市交通网络，也不是完整线路数据 | 线路目录与拓扑由服务端管理，界面不硬编码城市连线 |
| 规划器要求端点与路径均在同一省内 | 正常跨省路线会被拒绝 | 城际模式采用三省联合边界，按所经区域检查气象 |
| 天气单体集中在三个演示中心周边 | 其他城市缺少有空间代表性的情景验证 | 覆盖网络的区域天气分区、沿线采样和来源/缺测状态 |
| 一次评估一项任务 | 无多线路调度、批量更新或全网运行指标 | 城市、线路、运行班次、运行事件分层建模 |
| 候选轨迹动画依赖单项任务时间轴 | 不能区分线路配置与真正运行中的运输实例 | 每个班次独立身份、方向、出发时刻、进度和状态 |
| 只有历史点观测和模拟空间场 | 不能声称已掌握真实交通流或真实在途目标 | 数据适配器、事件时间、数据更新时间、过期与中断处理 |

## 不依赖交通选型的设计原则

1. 城市主数据与真实站点、运行枢纽分开。城市中心坐标不自动等于机场、收费站或车站位置。
2. 线路和班次分开：线路表达连接关系，班次表达某个运输实例的实际或模拟运行。
3. 不默认任意两城之间都存在直达线路；连接来源、运营属性和模拟生成规则必须可查。
4. 省内和跨省线路统一归属全域网络；原单任务评估保留为线路详情中的分析能力。
5. 网络状态至少区分正常、受影响、中断和数据未知；具体延误、绕行、停运规则由交通类型决定。
6. 总览指标可以下钻到线路、班次和事件；不得用动画数量冒充真实运力或交通流量。
7. 实时流、历史回放和模拟运行严格标记；缺测不补造为正常。
8. 批量气象评估应复用时空查询、缓存和增量更新，不能简单串行调用当前8秒单任务规划器。
9. 保留既有本地交付、密钥忽略、Windows PowerShell 5.1兼容要求。本轮仍不上传、不打包，除非用户另行修改要求。

## 本轮已确定边界

低空飞行汽车与城区外卖无人机，模拟运行数据，跨省仅省会。城市范围按已说明默认值覆盖 36 个地级行政区，县级城市尚未纳入。
