## 3. 改了什么

### 3.1 模型文件随发布走（本版的核心）

`models/ml-v3-national-vis.json`（2 543 B，md5 `e49c58528c1263401bfac05c8371cbfd`）此前从未随部署上传 —— 部署脚本只发 jar、Python 文件与 `VERSION`，`models/` 与 `data/` 不在范围内，于是线上 `nationalModel.available` 一直是 `false`，319 城全走规则派生，模型卡那一栏在屏幕上是空的。

本版把它手工补到 `/opt/apps/AIC-tianchuang/models/`（注意是项目根，不是 `backend-python/models` —— `national_model.py` 的 `ROOT = parents[2]`），重启 Python 单元后生效。

**这一步的副作用比修复本身更重要**，见 §4。

### 3.2 净空「一律禁飞」不再自相矛盾（`traffic/nation_zones.py`）

切到 `PROHIBITED` 后，`crossings()` 的 note 仍写「默认等级 APPROVAL_REQUIRED 表示可申请穿越，**不是禁飞**」。实测两档 note 逐字相同、`counts` 与 `hit = 113 / 492` 也完全相同。

改为按 `policy` 分叉，`PROHIBITED` 时写：

> 按规则化限制区（DERIVED）与航路求交；当前为演示态：**一律禁止进入**。穿越条数不变（113 / 492）—— 变的是这 113 条穿越从"可申请"变成"禁止"，不是几何变了。

**该说的是"等级变了、几何没变"，不是"什么都没变"。** 同时把 `payload()` docstring 里「计数与等级一起变」改成「等级变、计数不变」—— 这句话本来就是错的。

### 3.3 城市层分级切片不再说自己是全国（`OperationsConsole.vue`）

`nationRollup` 只有 `province` 与 `region` 两个分支，城市层落到「全国」兜底：下潜到沈阳市时，表头写「全国」、城市一栏写 **13**（那是辽宁省全量市数）。

补 `city` 分支后：表头是「沈阳市」，行是「本级合计 · 辽宁省 · 有机场 ZYTX」，四列与省层同量纲。

**刻意不输出 `total.cities`** —— 市层的这个值是省聚合，列出来等于撒谎。

### 3.4 「绕飞」「停飞」写清量纲（`traffic/NationPanel.vue`）

指标块绑的是 `total.delayed` / `total.hold`（按班次），口径表另有「绕飞航线」（按条）。同屏出现过 **0 / 1 / 3** 三个数被当成 bug。

标签改为「绕飞架次」「停飞架次」，各加 `title` 说明「另有『绕飞航线』按条计，口径不同」。**数字一个不动** —— 改数字才是错，改标签只是把载荷里已有的事实说出来。

### 3.5 补掉一个从未跑过的测试

`tests/render-offline-basemap.mjs` 有三重问题叠在一起：

1. 不叫 `*.test.mjs`，`npm test`（`node --test` 默认收集）**从来没收集过它**
2. 断言的两个类名 `city-map-offline-note` 与 `city-map-status` **从未在模板里存在**（实际是 `city-map-info-status`，也没有说明带），全仓只有这个测试文件里出现过这两个字符串
3. 脚本没有 `process.exit`，即使断言失败退出码也是 0

于是它从加进仓库那天起，既没跑过、也不可能红。改为：重命名 `render-offline-basemap.test.mjs`、断言改成「离线徽标 + 重试在线底图按钮」、补退出码。

现在它真的在断言实现：三态渲染互异、badge 与重试按钮只在 offline 出现、状态条文案三态不同。

### 3.6 版本号

四类落点全改到 `1.0.9`：`VERSION` / `pom.xml` / `package.json` / `package-lock.json`（两处）/ `weather_sources.py::USER_AGENT` / `radar_public.py::USER_AGENT` / `README.md` 标题与版本行 / `docs/NAMING.md` §7 正文。

## 4. 传模型文件的副作用：首页数字变了

这是本版最需要对外说清的一点。本地与线上实测同一接口（20:50–21:03 之间多帧）：

```
nationalModel.available = true    v3.20261110
test.auc = 0.9488   brier 0.12014   ts 0.2559   samples 45490
liveCoverage = {cities: 319, medianP: 0.0668, maxP: 0.9781}
fallback.probSource = MODEL       flights[*].probSource 全 MODEL
modelAxis = {applicable: true, changedCount: 30}
   withModel:    hold 30 / detour 1 / release  93
   withoutModel: hold  0 / detour 1 / release 123
```

**首页从「停飞 0、全放行」变成「停飞 23–30 架」。**

这不是缺陷，是模型真的参与了判定：`pModel` 中位数 0.20、p75 0.64，端点任一侧超 0.6 就停飞。但它直接推翻了材料里「放行率 100%」「停飞 0」的说法。

演示口径应改为：**不用模型 123 架全放行 → 用模型拦下 30 架**，这一屏比原来的"0 停飞"有信息量得多。若被问"今天天气好为什么停 30 架"，答：ml-v3 是**前瞻 1 小时**的低能见度概率，端点两城按独立事件合并取任一端点，拦的是"一小时后可能掉到 3 km 以下"的航段，不是当前实况。

## 8. 留存的一条教训

两份外部文档的错误是同一类：**把"看起来像"当成了"实测是"**。

- 文件在不在 → 看了目录名就下结论，没 ssh
- AUC 为 null → 看见 null 就归因「文件没传」，没打开文件看字段
- 507 全过 → 数了通过的用例，没数**没被收集的文件**

所以本版的验收全部写成「字段路径 + 期望值」，每一条后面都能追到一条命令。反过来也一样：**"没报错"不等于"跑过了"** —— 那个测试既没被收集，也没有退出码，两条都缺，于是它永远绿。

## 9. 界面叙述文案全量改写（同日追加，同属 1.0.9）

### 9.1 为什么改

用户指出界面上的说明段落"很 AI 感"：句子长、破折号插话、第二人称、以及大量"不要把它读成…""否则会被当成…"这类**对自己写作的辩解**。要求改成言简意赅、书面、官方口径。

典型三条（改前 → 改后）：

| 改前 | 改后 |
|---|---|
| 这张表跟着当前作用域走：全国看六大区…**航线数不能跨级相加** —— 跨省航线在两端的容器里各出现一次，**那是"本区涉及"，不是重复计数**；合计一律回原始列表数。 | 本表随当前作用域切换：全国列六大区，大区列所辖省，省列地市，市列相邻航线；字段与①层同源。航线数不可跨级相加，跨省航线在两端各计一次，合计取原始列表数。 |
| 两个文件都没上传这件事先不说了——**一个落在几内亚湾的点比少一个点更糟：它看起来像那里有雷暴**。 | 坐标缺失时少一点，优于错一点。 |
| 点列头排序。数值列默认降序（点「阵风」要的是最大的那一站排最前）… **一个没报阵风的站既不是"阵风 0"，也不该在降序时顶到最前面冒充最大值**。 | 点击列头排序。数值列默认降序、文字列默认升序。缺值恒排末尾，不受排序方向影响。 |

### 9.2 改法与范围

- **改写规则**：陈述句、主谓宾完整；一句说完一件事；不用第二人称与"读者""我们"；不用破折号插入语；去掉解释写作动机的从句；保留全部数字、字段名、来源标注与 `{{ }}` 绑定。
- **覆盖**：97 条 ≥30 字且带叙述标记的界面文案，实际改写 **~130 处**（含同块内的多处短句），涉及 15 个组件 + `runtime.js` 的 12 条说明常量。界面中文总字数由 **14 5xx → 14 232**（去变量计），长句（≥70 字）由 40+ 条降至 21 条，其中 12 条属未挂载组件。
- **不动**：所有数字、口径、判据、来源标注、`{{ }}` 表达式与条件分支；术语表的 `plain`（通俗一行）保留，它是刻意的双轨。
- **跳过**：`ModelCardPanel.vue`（`9aafd7f` 后已无 import，界面不可见）。

### 9.3 测试随之调整（5 处断言）

文案是契约的一部分。5 条断言锚在旧措辞上，改文案后必须同步，且**约束不能放松**：

| 测试 | 旧锚点 | 新锚点 |
|---|---|---|
| `casePanels` W-25b | 「与这段判据不同源」 | 「不同源」（整句收窄为关键词，避免改一个量词就红） |
| `casePanels` W-26 | 「两段不可合并读」 | 「不计入改判架次」（更具体：既说分两段，也说后段不进总数） |
| `diagnosisGaps` | `/取不到走廊几何/` | `/无走廊几何/` |
| `diagnosisGaps` | `/请勿把它读成回放时刻的天气/` | `/不代表回放时刻天气/` |
| `mechanismChain` | `includes('倒推出一个成因')` | `includes('无可用成因判据')` |

每条改动处都留了注释说明"约束不变、只换措辞"，避免下次有人以为是放宽判据。
