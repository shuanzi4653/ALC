# 红外云图推演通道：算法与架构设计

> 背景：中国气象数据网雷达凭据未取得，彩云雷达图属企业套餐需付费。
> 用户决定 **走免费路线**，约束是 **不得违规窃取、不得侵犯他人知识产权**，
> 并提出若雷达不可行则以 **实时红外云图** 做推演，单独完善其算法与架构。
>
> 本文的结论与设计均以 **实测字节** 为依据（探针脚本 `_probe_himawari.py`），
> 不采用记忆中的接口参数。第 6 节逐条区分「已验证」与「未验证」。

---

## 1. 结论

**免费且合规的路线是存在的，不需要走灰色地带。** 并且：

**红外通道应当是「基线源」，而不是「实在不行的退路」。** 理由是它唯一同时满足
四条硬条件：**零凭据、零成本、永久可用、无需注册**。雷达两条免费路线都要求先完成
实名注册，且都有未核实项（星图云免费额度是否含雷达图层；数据网是图像产品需自建色标反演）。

因此建议的形态是：

| 层 | 源 | 角色 |
| --- | --- | --- |
| 基线 | NOAA 公开桶 Himawari-9 红外通道 | 先跑通整条管线，随时可验证，无人可挡 |
| 增强 | 中国气象数据网雷达图像产品 | 实名注册后作为第二源，与红外交叉比对 |
| 可选 | 星图云 Rain-Pulse | 免费额度内若是含雷达图层则最省事 |

**三条路共用同一条「栅格场 → 风险区」管线**，源可插拔。这就是把这件事做成
「单独一个子系统」而不是散落的取数代码的原因。

## 3. 物理量谱系（最硬的一条纪律）

红外通道与雷达通道**物理量不同，不可互换**。必须建立独立谱系并在数据结构上体现：

| 层 | 量 | 单位 | 性质 |
| --- | --- | --- | --- |
| L0 | 计数 `count` | 无量纲 | 观测（原始） |
| L1 | **亮温 `brightnessTemperature`** | K | 观测反演（Planck 反演，含本系统推断成分） |
| L2 | 冷云掩膜 / 云顶温度 `cloudTopTemperature` | K | **派生** |
| L3 | 云顶高度 `cloudTopHeightAglM` | m | **派生**（需温度廓线，无探空时用标准大气近似） |
| L4 | 对流强度代理 `convectiveIntensity` | 分级 | **派生**（经验阈值） |
| L5 | 派生飞行风险区 `derivedConvectiveRisk` | 多边形 + 分级 | **本系统推断** |

**明确禁止**：亮温 → dBZ 的任何换算。二者物理机制不同，换算得出的数字没有意义，
且会让界面出现「回波强度」这种失实措辞。

界面与文档措辞固定为「**对流云团 / 云顶亮温 / 对流风险区**」，
**不得**出现「雷达回波」「回波强度」「禁飞区」。雷达通道接入后，
它自己才用 dBZ 与「回波」措辞，两套词汇在 `provenance` 与图例上不可混。

## 4. 推演算法

### 4.1 取帧

- 源：`AHI-L1b-FLDK/{YYYY}/{MM}/{DD}/{HHMM}/HS_H09_{YYYYMMDD}_{HHMM}_B13_FLDK_R20_S0110..S1010.DAT.bz2`
- 波段：**B13（10.4 µm）红外窗区**。选它的理由：对云顶温度最敏感、几乎不受水汽吸收影响、
  且是判识深对流的常规窗区通道。
- 一帧 = 10 个段，实测合计 **约 22.6 MB**（各段 1.13–3.00 MB）。10 分钟一帧。
- 延迟实测 **约 10 分钟**（观测 10:00:20 → 对象写入 10:10:27）。

**不取 L2 云高产品**：`AHI-CHGT` 单帧 **736.5 MB**（CMSK 316.3 MB、CPHS 81.0 MB），
10 分钟一帧不可下载。

### 4.2 解码

实测得到的容器事实：

- 对象是 bz2，解压后 6,051,523 字节（**奇数长度** → 头部必为奇数长度或存在奇数尾部）
- 载荷是 **uint16 原始计数**，**小端**，填充值 **65534**
  （依据：填充游程字节为 `fe ff`，小端读作 0xFFFE）
- 以 **5500 为行宽** 折叠时，填充掩膜呈**对称的地球边缘圆弧**：
  上方为真空（填充），圆弧向下逐渐变宽 —— 这是 `550 行 × 5500 列` 的特征
- 头部候选长度 **1523**（另一候选 1604 与总长奇偶性冲突）

**解码链路**：`bz2 → 头部(定位 gain/offset 与带中心波数) → uint16 counts → 亮温`。

Planck 反演（IR 窗区标准形式）：

```
radiance = gain * count + offset
BT = (c2 * nu) / ln( (c1 * nu^3) / radiance + 1 )
c1 = 1.191042972e-16 W·m^2·sr^-1    c2 = 1.4387752e-2 m·K
nu = 带中心波数（cm^-1，B13 约 925.6）
```

> **这一步未完成标定**：gain/offset 的确切字节位置尚未定位，行宽 5500 尚未用
> 第二个段交叉验证。见第 6 节。**在标定完成前，不得声称红外链路可用。**

### 4.3 地理配准

- 全圆盘是**固定网格**：先由头部导航参数（四角经纬度）建立
  `(row, col) → (lat, lon)` 仿射/椭球映射，再用项目既有的
  `weather.geometry.project()` 投到本地 aeqd 平面（`+proj=aeqd +lat_0=45 +lon_0=126`）。
- **不复用** `boundary()` 裁剪以外的任何气象几何代码——固定网格与极坐标环是两套东西。

### 4.4 冷云掩膜与对流判识

B13 亮温初值阈值（**经验初值，须与雷达或实况比对后再定稿**）：

| 判据 | 阈值 | 含义 |
| --- | --- | --- |
| 冷云上界 | BT ≤ 273 K (0 °C) | 进入掩膜 |
| 深对流候选 | BT ≤ 235 K (−38 °C) | 强上升气流、云顶已冻结 |
| 强对流 | BT ≤ 210 K (−63 °C) | 显著对流，可能伴短时强降水／雷暴大风 |
| 过冲云顶 | BT ≤ 193 K (−80 °C) | 极端，标记最高等级 |

**不使用单一阈值**：同时要求**云顶亮温梯度**（局部空间梯度大 = 云顶起伏剧烈）与
**亮温时间变化率**（相邻帧快速降温 = 对流发展）作为交叉条件，降低薄卷云的误判
（卷云冷但不是对流）。

### 4.5 连通域与形态

1. 二值掩膜 → 连通域标记（8 邻域）
2. **面积过滤**：丢弃小于设定面积（建议 ≥ 200 km²）的孤立斑块，去掉噪声与单像素冷点
3. 形态学闭运算填补小孔，开运算去毛刺
4. 边界简化：与项目既有口径一致，`SIMPLIFY_TOLERANCE = 120 m`
5. **顶点数上限**：单环顶点受控（参考 `RING_VERTICES=64` 的思路），避免把整幅云图顶点直接塞进渲染层

### 4.6 外推（未来时隙）

两条路，优先第一条：

1. **帧间交叉相关**：取 `T` 与 `T−10 min` 两帧，对每个连通域做块匹配求位移矢量，
   得到该云团的移速/移向，线性外推到未来时隙。**优点：不依赖外部数据。**
2. **L2 云导风**：`AHI-L2-FLDK-Winds` 提供云顶运动矢量
   （`NDMW-AHI-C14CT`、`C08CT` 等，实测 5.5–13.8 MB/帧，延迟约 23 min）。
   作为**背景环流约束**，限制块匹配的搜索范围，避免匹配到错误回波。

外推结果必须标注 `EXTRAPOLATED_NOT_OBSERVED`，与实况帧在结构上区分开。

### 4.7 风险区生成

每个连通域产出：

```
{
  polygon,                       # 本地投影坐标环
  level,                         # DEEP_CONVECTION / SEVERE / OVERSHOOTING
  minBrightnessTemperatureK,     # 该云团最低亮温（强度代理）
  cloudTopTemperatureK,
  cloudTopHeightAglM,            # 标准大气近似，标注为推断
  validFrom, validTo,            # 含外推时段
  motionVector,                  # 移速移向
  provenance: {...},
  qualityFlags: [...]
}
```

### 4.8 与固定管制区严格分离

沿用项目既有配色纪律：**冷色 = 官方固定管制空域，暖色 = 气象派生风险**。
红外派生风险区归**暖色**，与 `fixed-zones.json` 的固定管制区**不共用配色、不共绘图例**。
侧壁高度可取 `cloudTopHeightAglM`，从而比现有固定的 `RISK_TOP_AGL_M = 620` 更有物理依据。

## 5. 架构与落点

**原则：新增源复用既有抽象，不新建架构。**

| 落点 | 参照的现有实现 | 新增内容 |
| --- | --- | --- |
| `backend-python/traffic/himawari.py`（新） | `cma_radar.py` 三原则：**凭据不进日志**、**失败不产出半成品**、**`provenance` 随结果返回** | 匿名取帧、缓存、`status()` |
| `backend-python/traffic/ir_cloud.py`（新） | `weather.py` / `runtime.js` 的做法：纯算法与 IO 分离 | HSD 解码、亮温反演、掩膜、连通域、形态、外推、风险区生成 |
| `backend-python/traffic/weather_sources.py` | `PROVIDER` 开关、`weather_snapshot()` 单一归一入口、`qualityFlags`、`provider_status()` | 新增对流风险源开关与 `convective_snapshot()` |
| `backend-python/traffic/weather.py` | `NetworkWeather.shapes()` 是气象几何的**唯一来源** | 派生风险几何**必须只有一个来源函数**（见下） |
| `backend-python/traffic/service.py` | `stats` / 飞行记录结构 | 把对流风险并入班次记录与统计 |
| `frontend/src/traffic/runtime.js` | `classifyMapError` 等纯函数集中处 | 新增纯函数：风险分级标签、外推标注、降级说明 |
| `frontend/src/components/CityTrafficMap.vue` | 暖色风险层已就位 | 复用暖色层，接入对流风险几何 |

### 必须吸取的上一轮教训

上一轮「轨迹跑到禁飞区」的真根因是：**风险单体的位置有两份实现**，`shapes()` 里
另写了一份只存在于局部变量的雨带，导致避让包络整条漏掉最大风险区。

**所以：红外派生风险区的几何只能有一个来源函数**，
`shapes()`（渲染）与 `swept()`（避让包络）都必须调它。这条要写进代码注释并加测试锁定。

### 未验证（在完成前不得写成「已通过」）

1. **头部确切长度**：候选 1523；另一候选 1604 与总长奇偶性冲突，但未用第二个段交叉验证。
2. **行宽 5500 未交叉验证**：只测了一个段（S0110）。必须用 S1010 或另一时次复测，
   并验证 10 段拼接后是完整圆盘。
3. **gain / offset 的字节位置**：未定位 → **亮温反演尚未跑通**。
   在跑通并与独立来源比对之前，红外链路状态为 `UNVERIFIED`。
4. **导航参数**：四角经纬度字段位置未确认 → 地理配准未完成。
5. **对流阈值**：235 / 210 / 193 K 是气象常规经验值，**未针对东北做过比对检验**。
6. **许可措辞**：JMA/NOAA 的署名与再分发条款需逐条确认后写入项目文档。

**这三条是下一步唯一该做的事**（标定 → 反演 → 配准），做完才谈推演算法。

## 7. 测试策略

沿用项目既有做法：**纯算法抽到可被 `node --test` 或 pytest 覆盖的位置，不在 `.vue` 里写私有实现。**

| 测试 | 断言内容 |
| --- | --- |
| `tests/test_himawari_hsd.py` | 解码器对**固定的本地样本**（缓存在 `.run/`）解出 550×5500；填充占比约 44%；小端不与大端混淆（故意用错误字节序解出的填充占比应为 0%，即 **可失败**） |
| 同上 | 亮温反演：已知计数的亮温落在物理区间（190–320 K）；填充像素必须返回 `None` 而非数字 |
| `tests/test_ir_cloud.py` | 掩膜阈值边界；面积过滤去掉小斑块；连通域计数；形态学不产生自交环；简化后最大外角达标（沿用上一轮「外角 > 45° 即锯齿」的判据） |
| 同上 | 外推帧带 `EXTRAPOLATED_NOT_OBSERVED`；**几何唯一来源**：渲染与避让包络取到同一组多边形（防上一轮那份局部变量事故） |
| `tests/test_weather_sources.py` | 源缺失时显式降级并带 `SOURCE_UNAVAILABLE`，绝不静默返回空 |
| `frontend/tests/irCloud.test.mjs` | 词汇纪律：输出文案中不得出现「回波」「禁飞区」；冷/暖配色不共用 |

**性能口径**：解码与反演必须在**冷进程**与**热进程**下分别计时并记录，
不可混用（这是上一轮踩过的坑）。
