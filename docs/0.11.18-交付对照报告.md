## 二、本轮另查明的一件事：那条「P3、可停」的路由缺陷

上一轮我判定：「页面内容是对的，只有地址栏不对，P3 可以停」。**这个判断是错的，方向正好相反**——地址栏是对的，内容是错的。

复查后的因果链是一条：

1. 源码里写的是 `location.hash`，但**打包产物里它被编译成了另一个变量**（`Me.hash`），而那个变量在产物里是一个**数组**；
2. 于是程序每次读到的都是「空地址」，它认为「没有指定页面」，就停在首页；
3. 因此：直达失败、刷新回首页、手动改地址无效、未知地址也不纠正——**四个现象一个原因**。

修法是把所有全局对象写全（`window.location.hash`），打包器就不会再误认。

**为什么上一轮没修好**：源码改对了，但**没有重新构建前端**（只更新了后端包），线上跑的一直是旧逻辑。本轮补上了这一步，并新增一条工序：**改完前端必须确认产物里确实有那段代码**，不再只看源码。

修正后的实测（干净浏览器、无缓存）：

| 入口 | 结果 |
|---|---|
| 直接打开某页地址 | 正确落页 |
| 在该页按 F5 | 仍在原页 |
| 站内点击切换 | 正确 |
| 打开一个不存在的地址 | 页面回首页，地址栏同步纠正 |

## 六、可以对外说的两句话（实测支撑）

**问：这些链接能转发给别人吗？**
> 能。13 个页面各有独立地址，转发、收藏、刷新都落在同一页。

**问：判据全绿为什么判"需谨慎"？**
