## 二、推演页：7 个模块，每块一张图

地址仍是 `#/model/card`（没有改 slug —— 现有深链、测试、命令面板都按它走，改键是纯风险）。
默认对象是**当前最差的那条走廊**（读者第一眼该看到最该被解释的那条），可下拉切换，随��间轴联动。

| 模块 | 讲什么 | 图 | 数据来源 |
|---|---|---|---|
| **1 输入观测** | 4 站 METAR，各站能见度与档位 | 水平条 + 档位色 | `observation.stations` |
| **2 空间插值** | 谁在给这条走廊加权 | 走廊折线 + 3 站 + 连线粗细=权重 | `path` + `deduction.stations` |
| **3 概率合成** | 低能见度 × 阵风 → 不可飞概率 | 4 条横向进度条 | `deduction.midpointProbs` |
| **4 判据** | 四条判据逐条对阈值 | 表格（值 / 阈值 / 命中档） | `criteria` |
| **5 裁决** | 四种处置的期望损失 | 4 根条形，被排除的灰化 | `deduction.decision` |
| **6 对照** | 规则裁决 vs AI 裁决 + 全局 A/B | 两行对比 + 数字 | `corridor` + `counterfactual` |
| **7 七帧** | 00–06 Z 逐时概率 | 折线 + 7 个点 | `hourly`（真实帧） |

**关键取舍：所有数都由后端算，前端一个都不重算。** 权重 `1/d²`、合成式、期望损失都是算法本身；
前端重算等于把算法复制第二份，而这一页存在的意义恰恰是"给你看算法怎么算的"。
`tests/deduction.test.mjs` 里有一条断言专门盯这个（出现 `Math.pow` 就红）。

模块 5 有一个很好的展示点：**取消的损失只有 180，数字上最便宜，但被排除**（有可绕飞走廊时取消会丢掉整班任务）。
页面把这条原因原样印出来 —— "看起来最省的那个不是可执行的"，这是算法的判断，不是文案修辞。

## 三、4 秒的真因：不是算得慢，是**在拉今天的天气预报**

`corridor()` 里有一段 `_extension_curve()`（"3–6 h 模式延伸"），它无条件调用
`om_forecast.station_hours()` → **3 个站出来回 HTTP 到 Open-Meteo，各约 1.1 s** = 3.48 s。

profile 实测（`cProfile`，冷）：

```
3.480s  _extension_curve
3.480s    om_forecast.station_hours → forecast → _fetch_station ×3 → httpx.get   ← 3.356s 在这里
```

**而且它不只是慢：** 回放的是 2025-01-05 的案例，那段"模式延伸"取的却是**今天的预报**。
所以旧版走廊页的 3–6 h 曲线，是拿今天的天气画 2025 年的雾。

修法一举两得：

1. **案例模式不再拉 Open-Meteo**，改用案例自己的 7 帧观测逐帧计算（`frameObserved: true`）；
2. 案例观测场缓存**永久化**（案例文件是静态的，原来 600 s TTL 只会让它反复重建）。

效果（线上）：

| | 改前 | 改后 |
|---|---|---|
| 首次请求 | **3.96 s** | **1.12 s** |
| 第二次 | 0.25 s | 0.33 s（多算 7 帧真曲线） |
| 曲线数据 | 当前值复制 4 次 + 今天 OM 延伸 | **7 帧真实观测**：15.7% → 15.7% → 2.8% → 0.9% → 0.9% → 0.9% → 0.4% |

热请求慢 0.08 s 是**买来的**：那 0.08 s 换来一条真实的"雾散"曲线，而不是四个同样的数。

## 四、导航：检验 → 推演，复盘只剩日志

```
1 态势   首页 / 总览 / 气象
2 走廊   剖面 / 民航情报
3 处置   事件处置台（台账 / 取证）
4 推演   ← 原「检验」，改名 + 合并（推演 / 口径与来源 / 算法机理）
5 日志   ← 原「复盘」，只剩运行日志
```

- 「复盘对照」「分歧台账」进 `HIDDEN_SECTIONS`：**不进导航、不进命令面板、tab 条不出现**，
  但**深链仍然可达**（`#/compare/counterfactual`、`#/compare/ledger`）—— 旧链接有人存着，断了就是 404。
- 归属仍写进 `members`：`navCoverageGap()` 要求"每个分节都能反查到入口"，少了就是"这页永远打不开"。
- 同步改了 5 处测试（可导航页 13 → 11、入口名只剩 `card`、tab 条等），
  每处都注明**判据没变，是被守的对象少了两个页面**。

## 五、双击航线

链路：`CityTrafficMap`(dblclick → raycast 命中载具) → `emit('open-corridor', {from,to,mode})`
→ `HomeStage` 透传 → `TrafficWorkbench.onOpenCorridor` → `activeSection='profile'` + `corridorPair`
→ `CorridorPanel` 用起降对在 53 条里反查（同一起降对分两个方向，取更差的那条）并选中。

两个注意点：

1. **单击语义没动**：单击仍是"选中这架看一眼"，双击才是跳转。把单击改成跳页会让"只想看一眼"变成误操作。
2. **`open-corridor` 现在有两种载荷**：字符串（结论条「查看 CAR-…」）与对象（双击）。
   `onOpenCorridor` 按类型分流 —— 不区分的话对象会被当 id 用，`corridorFocus` 变成 `[object Object]`，
   走廊页什么都选不中，**而且不报错**。

`tests/deduction.test.mjs` 用源码契约钉住整条链（3D 场景在 headless 里用坐标命中不稳定，
点不中会得出"没接线"的假结论）。
