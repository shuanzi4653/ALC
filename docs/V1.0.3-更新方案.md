## 1. 逐条方案

### 1.1 航向与运动（#1）

**病根**

```python
# nation_ops.py:206  数学角：0=东，正=北（atan2(dy, dx)）
heading = degrees(atan2(ahead_lat - lat, ahead_lon - lon))
```

```js
// NationMap.vue 两处都按屏幕角用（0=东，正=顺时针/向南）
rotate(${f.heading})                    // 少了负号
lat -= dKm * Math.sin(h) / 110.574      // 纬度方向反了
```

结果：图标歪一个镜像角，位置每次快照被推反再拉回，肉眼就是「在一个区间里抖」。

**改法**

1. 后端在 `flights` 里**同时给两种角**，避免前端再猜：
   - `heading`：保持数学角（其他调用方已在用，不改语义）
   - 新增 `headingScreen`：屏幕角（`-heading`），仅供 SVG 用
   > 也可以只在前端取负。我倾向**后端显式给两种**——这类"角度约定"靠前端注释约定迟早还会错第二次。
2. `rotate(headingScreen)`，外推改用 `lat += dKm*sin(h)/110.574`。
3. 加一条守卫用例：取一个 `heading` 已知的班次，断言「沿 headingScreen 走 1 分钟后，与终点距离变小」。

**验收**：盯住一架放大地看 30 秒，位置单调逼近终点，不回头。

### 1.2 箭头放大 + 飞行数据（#2）

**改法**

| 项 | 值 |
|---|---|
| 图标 | 全国层 0.6 → **1.0**；大区 0.92 → 1.1；省/市 1.15 |
| 文字 | 一行三段：`TC02709 · 411m · 200km/h`，字号 8.5，带描边（屏幕尺寸恒定，随 zoom 反向缩放） |
| 编号 | 用 **`callsign`**（台账「班次」列的主号），与走廊班次号完全一致 |
| 密度 | 「标准」全国层只标**选中 / 绕飞 / 高风险 / 延期恢复**；「精简」「极简」只标选中。下钻到大区及以下全标 |
| 悬停 | **不点击也能看**：鼠标停在任意箭头上 200 ms，浮出该班次卡片（编号 / 高度 / 速度 / 起讫 / 裁决 / 风险） |

> 全国 106 架如果全标文字，地图会被 106 行小字糊住 —— 这是上一轮刚清理过的问题，不能再回来。
> 所以：**值得看的几架常显，其余靠悬停**。悬停卡片用自绘的 HTML 浮层（跟随鼠标、自动避让边界），
> 不用 SVG `<title>` —— 后者有 1 秒延迟、样式不可控、手机上没有。

**验收**：全国层默认文字标签 ≤ 12 个；点任意一架后这一架的文字必出现；文字不压住其它飞机（横向偏移 8px、上下避让）。

### 1.3 删除投影模式（#3）

删四处，一个不留：

1. 顶栏按钮 `[data-present-toggle]`（`toggleFullscreen`）；
2. `fullscreen` / `presentFallback` / `presenting` 状态与 `document.requestFullscreen` 调用；
3. CSS：`main.is-fullscreen`、演示字号覆盖、`first-visit` 里"按 P 切投影模式"；
4. 首次引导 `TOUR_STEPS` 里的 `present` 一条、快捷键 `P`。

数据与布局不动 —— 它本来就没改数据，删掉不影响任何口径。

**验收**：`grep -rn "投影模式\|presenting\|data-present-toggle" frontend/src` 为空；全站无全屏按钮；`P` 键无反应。

### 1.4 运行情报可二次归类（#4）

**现状**：`NationBriefing` 只有 `variant==='briefing'` 时按 `riskP` 降序，其余固定按后端顺序。

**改法**：表头可点排序 + 一组筛选片。

| 交互 | 行为 |
|---|---|
| 点表头 | 升/降序切换，右上角显示当前排序（`风险 ↓`）；同时只保留一个主排序 |
| 筛选片 | 裁决（全部 / 直飞 / 绕飞 / 延期）、风险（全部 / 高 / 中 / 低）、类型（省内 / 接驳 / 跨省）、城市 |
| 组合 | 筛选先、排序后；筛选结果条数写在标题旁 `12 / 108 架` |
| 记忆 | 写在 URL 查询串（`?sort=risk&dir=desc&hold=0`），刷新/分享保持 |

**默认排序**：班次情报 = 风险降序；调度台账 = 起飞时刻升序（保持现有语义）。

**验收**：同一时刻、同一作用域下，按风险与按时刻排出来的第一行不同；筛选后条数 = 手数。

### 1.5 处置事件可点（#5）

**改法**：一行事件 = 一个可点对象（`button` 语义，键盘可达）。

点下去做三件事，按代价从小到大：

1. **定位**：把作用域切到事件所属城市（`city` 级），地图 `focus` 到该点；
2. **选中**：若事件关联班次（`flightId`），同时选中该架，右栏展开详情；
3. **处置**：卡片展开一段「处置建议 + 依据 + 影响面（同判据还有几班）」，带「跳到该班次」「查看判据链」两个入口。

聚合事件（一条覆盖多个城市）点开后先展开成员列表（`places` / `memberIds`），再选一个具体城市进去。

**验收**：点任意一条，面包屑变成该市、地图定位、右栏出现班次或城市详情；`Tab` 能逐条走完。

### 1.6 推演页要有"可不可飞"（#6）

**病根**：`NATION_VIEWS` 含 `card` → 全国模式渲染 `NationPanel(mode='card')`，只画地图+右栏+详情卡；
1.0.0 的 `DeductionPanel`（四站 METAR → 插值 → 概率 → 四判据 → 期望损失 → 对照）根本没有被挂载。

**1.0.0 那套不能直接搬**：它绑定的是东北四站 METAR 与固定走廊；全国网是 319 城逐市实况，没有"四站插值"这一步。

**改法**：推演页 = **立题行 + 判据链面板**，数据直接吃已有的 `/traffic/v2/nation/evidence`（五步证据链），不新造模型。

**每架班次独立生成**：链路里的每个数都来自该班次自己的记录（观测取它自己的起讫两端、判据用它的阈值、
反事实用它的 `exposure`、期望损失用它的时长与绕飞距离），**不允许用一套模板套所有航班**。
换一架，五段全部换数；没有的那一项写"该班次无此项"，不拿默认值凑。

面板六段，逐段带来源标签：

| 段 | 内容 | 来源 |
|---|---|---|
| ① 立题 | 选城市 120 项 / 选班次 80 项（已有） | SIM |
| ② 观测 | 起讫两端实况：能见度、风、温度、观测时刻、数据源 | PUBLIC |
| ③ 判据 | 逐条 `通过 / 不通过`：能见度门槛、侧风门槛、回波压线、净空穿越、延期规则 —— 每条写阈值与实测值 | DERIVED |
| ④ 概率与裁决 | 规则分、模型分（ml-v3）、`probSource`、裁决标签 | DERIVED / MODEL |
| ⑤ 反事实 | 不绕飞暴露 N 分钟 / 绕飞后 0；若延期，写"等到几点可恢复" | DERIVED |
| ⑥ 期望损失 | 直飞 / 绕飞 / 延期三个方案的代价对比，推荐项高亮 | DERIVED |

**期望损失怎么算**（三项加权，权重写在界面上，可复算）：

```
代价(方案) = 风险损失 + 时间成本 + 能耗成本
风险损失  = riskP × 1.0          该方案下的风险概率（直飞用现值，绕飞用 detour 后的，延期用落地后）
时间成本  = 延误分钟 / 60 × 0.6   每小时延误计 0.6 个当量
能耗成本  = 航程增量 km × 0.02     每公里多耗 0.02 个当量（绕飞才不为 0）
```

三个方案画成横向条形对比（同一比例尺、推荐项描边高亮），旁边一行小字写清用了哪三个系数。

右侧保留地图与班次详情，但**净空块移走**（见 1.7），只留"这条链路"。

> 与 1.0.0 的差别要说清：那套是"一条走廊的气象链路"，这套是"一个班次的裁决链路"；
> 数字不可互比，界面文案里写明。

**验收**：推演页与态势页在 1366×768 下**首屏内容完全不同**（推演有 5 段链路且默认展开一段）；换班次整链跟随；未配 api-key 时模型分显示 `NOT_CONFIGURED` 而不是 0。

### 1.7 空域净空归位 + 首页显示禁飞区（#7）

**病根两条**：
- `NationPanel` 侧栏的 `.nrn-zone` 无条件渲染，`mode='card'` 也跟着出现 → 跑到推演页；
- 净空几何（`zoneGeom`）只在 `audience==='airspace'` 时才拉，首页默认看不到。

**改法**

1. 净空块从 `NationPanel` 侧栏**移出**，改为「处置 · 空域」入口（与"事件处置台 / 调度台账 / 大模型取证"并列第四项）；
2. 首页地图**默认画净空圈**（`zoneOn` 默认 true），图层开关放工具栏「净空」；
3. 所有层级都画：全国画 287 个限制区（缩放下会自动聚成点状，需按屏幕尺寸分流，同雷达环的做法）；下钻到大区/省/市画限制区 + 跑道梯形；
4. 净空只保留一种视觉：琥珀描边 + 极淡填充；`可申请穿越 / 一律禁飞` 一键切仍留在空域页，不带到首页。

**验收**：首页默认能看到净空圈；推演页没有净空块；空域入口点进去是独立页面而不是侧栏一小块。

### 1.8 日志页要有内容（#8）

**病根**：`loadJournal()` 首行 `const id=props.session?.sessionId; if(!id){journal=[];return}` ——
全国模式没有东北推演会话，直接被判空。

**改法**：日志分两本账，一个页面两栏。

| 账 | 来源 | 内容 |
|---|---|---|
| **系统事件**（后端） | 新增 `GET /traffic/v2/nation/journal?minute=&level=&id=` | 裁决变化（直飞→绕飞→延期）、气象快照刷新、模型分越阈值、净空穿越新增、聚合事件新增/解除。每条带 `at / minute / kind / place / detail / source` |
| **人工操作**（本地） | 前端 localStorage（每工作区一份，上限 500 条） | 切作用域、选中班次、导出 CSV、取证、切主题、深浅色、播放/暂停 |

页面结构沿用现有 `OperationsConsole` 的日志样式（类型筛选片 + 搜索 + 导出 CSV），只换数据源：
`scope==='nation'` 走 `nation/journal`，`scope==='ne'` 仍走原 `sessionId` 那套。

**系统事件怎么产生（不改后端模型）**：在 `nation.py` 的 `flights_payload()` 里按需比对"上一分钟 vs 这一分钟"的裁决差异，
落一份 6 小时的环形缓冲（内存，不落库）。这不需要新数据，只是把已经算出来的东西记下来。

**验收**：全国模式打开日志页至少有 20 条真实记录；切作用域/点班次/导出后立刻多出对应条目；导出的 CSV 与页面一致。

## 1.9 ~ 1.16 · 第二轮实测反馈（2026-11-11 15:25）

### 1.9 浅色主题下雷达回波不可用（#9）

**病根**：回波主体是**瓦片位图**（`radarTiles`），它的红色/黄色透明度是按深色底调的；
浅色主题的地图几乎白底，同样的 42% 红叠上去只剩一层极淡的粉，等于没有。

**改法**：与 1.14 合并 —— 删掉瓦片位图，回波统一走矢量轮廓，轮廓色按主题两套：

| 档 | 深色底 | 浅色底 |
|---|---|---|
| STRONG | `#ff6a4d` 描边 | `#c0392b` 描边 |
| CONVECTIVE | `#ffc857` 描边 | `#b8860b` 描边 |
| WEAK | `#7fd6ff` 极淡填充 | `#9db8cc` 极淡填充 |

**验收**：浅色下能一眼看出回波范围与档位；深浅两套截图对照，回波形状一致。

### 1.10 回波判定漏大片（#10）

**病根**：`_radar_clipped()` 里 `out[band] = kept[:45]` —— 每档最多留 45 个环；
再加上 `part.area < 0.02`（约 20×20 km）被直接丢弃。
于是"图上有回波、判定里没有"，绕飞算法也看不见那些片。

**改法**：
1. 面积阈值 `0.02 → 0.004`（约 6×6 km，一块积雨云的合理下限）；
2. 上限 45 → **不设上限，改为按面积降序保留前 200**（全国极端天气也够用）；
3. 返回里带 `truncated: true/false` 与 `totalRings`，截断时界面明写"回波过多，已按面积取前 200 片"——
   不能悄悄丢。
4. 加一条用例：构造 60 个小环，断言全部保留（不是 45）。

**验收**：图上有几片强回波，判定里就有几片；`/zones` 的穿越数随回波面积单调不减。

### 1.11 首页恢复航线 + 数量由人决定（#11，**推翻 V1.0.2 的决定**）

**病根**：上一轮为去噪把全国层的航线整层 `v-if` 关掉了；但图例里"航线"这一项还在（只是跟着隐藏），
读者看到的是"有图例、没图形"。

**改法**：恢复显示，并把"显示多少"交给人 —— 工具栏一个「航线」按钮，点开三个开关 + 一个数量滑块。

| 档 | 判据 | 条数 | 默认 |
|---|---|---|---|
| 跨省主干 | `kind==='CROSS'` | 30 | 开 |
| 机场接驳 | `kind==='FEED'` | 261 | 开 |
| 省内短途 | `kind==='INTRA'` | 201 | **关** |

- 三个开关任意勾选，按钮上实时写 `航线 291/492`；
- 下面是数量滑块（0–492），拖动时按"面积/长度从长到短"截取，**先画长的**——
  这样即使只开 50 条，看到的也是最主要的骨架，而不是随机 50 条；
- 「全关」一键（滑块拖到 0 与它等价）；
- 选择写进 localStorage，下次打开保持。

**视觉分档**（按当前显示条数自适应，避免"开全部就糊"）：

| 显示条数 | 线宽 | 不透明度 | 箭头 |
|---|---|---|---|
| ≤ 60 | 1.2 px | 0.95 | 全部 |
| 61–300 | 0.8 px | 0.7 | 只主干 |
| > 300 | 0.55 px | 0.45 | 只主干，且每 3 条标 1 个 |

**验收**：滑块从 0 拖到 492，地图从"只有城市"渐变到"完整航线网"，任何一档都不糊；
按钮上的数字与实际画出的条数一致；重开页面保持上次设置。

### 1.12 禁飞区统一成红框 + 首都红星 + 绕飞（#12）

**病根**：三套图层各画各的 —— 机场净空画琥珀圈（`zonePolys`）、气象禁飞只有回波框、
绕飞航段只存在走廊详情里。首页既没有"这是禁飞区"的统一标记，也没有"因此绕了哪条路"。
另外省会用"大点 + 浅环"表示，与普通城市只差一个环，缩放下分不出来。

**标记口径（2026-11-11 15:2x 用户确定，别再改）**

| 对象 | 标记 | 说明 |
|---|---|---|
| **首都 / 省会** | **红色五角星**（实心，边长 10–13 px 按层级） | 全国层只标 31 个省会；这是唯一用星的元素 |
| 普通城市 | 圆点（三级大小） | 省会不再用点+环 |
| **禁飞区** | **红色多边形框**（描边 1.6 px + 6% 极淡填充） | 气象（回波 STRONG/CONVECTIVE）与非气象（287 机场限制区）**同一套框** |
| 绕飞航段 | 琥珀虚线 | 压线且已改航 |
| 无可绕方案 | 红色断线 + 悬停"停飞" | 压线且改不了 |

> 星只给首都，框只给禁飞区。二者不混用 —— 上一版把"禁飞区中心标星"是错的，已作废。

**改法**

1. **禁飞区合层**：新增 `nmap-no-fly` 组，气象与非气象都进；统一红框 `#e03131`，
   填充只用 `rgba(224,49,49,.06)`（够看出范围、又不把底图盖住）。
   两类用一个 5 px 的角标区分：气象在框的东北角画一道短斜线（斜线=天气），非气象不画。
2. **首都改星**：省会/首府用五角星路径（`M0,-6 L1.8,-1.9 L6.2,-1.9 L2.6,0.9 L4,5.6 L0,2.6 L-4,5.6 L-2.6,0.9 L-6.2,-1.9 L-1.8,-1.9 Z`），
   红色 `#e03131` + 深色描边保证在浅色底也可读；普通城市沿用圆点。
3. **绕飞**：被禁飞区压线的航段画琥珀虚线（几何来自后端 `detour.path`）；
   没有绕飞方案的画红色断线，悬停写"无可绕方案，停飞"。
4. 首页全部层级都画，工具栏「禁飞」一键开关；关掉时框与绕飞一起消失。

**图例（改成 6 项，一行放得下）**

```
★ 首都   ● 城市   — 航线   -- 绕飞   ▭ 禁飞区   ▲ 应急
```

（"应急"仍是航班状态色，不是区域；右下角红框才是区域。）

**验收**：首页能同时看清"红星=首都、红框=禁飞区、琥珀虚线=绕飞"三层；
点一个红框能定位并列出受影响航线；浅色下红星与红框都还认得出。

### 1.13 跨省航线端点城市显示名字（#13）

**病根**：`labels` 只取 `rank<=2`（省会 + 机场城市），且按 `12/40` 个截断，
跨省航线的端点若是一般城市（如南通、锦州）就被挤掉，图上只有线没有名字。

**改法**：
1. 端点提权：所有**有航线连到本级之外**的城市，与省会同级参与排版；
2. 全国层也标（只标跨省主干的端点，约 40 个）；
3. 避让盒从 `54×12` 收到 `48×10`，多留几个位置；
4. 选中/悬停一条航线时，两端的名字**强制显示**（不吃密度限制）。

**验收**：图2 那种场景（济南—青岛—上海—南通一带）每条可见航线的两端都能读到名字。

### 1.14 回波统一为轮廓线（#14）

**病根**：同时存在两套画法 —— `radarTiles`（瓦片位图，彩色块）与 `radarRings`（矢量环，轮廓线）。
图3 那种纯轮廓才是要的，但只在部分时候出现。

**改法**：
1. **删掉瓦片位图这一层**（连同 `radarRelay` 的前端取图逻辑，保留后端 relay 接口以免破坏其他调用）；
2. 全部走 `bands` 轮廓：`fill=none`，描边 1.6 px（STRONG 加 `drop-shadow` 一点点辉光），
   档位配色见 1.9；弱回波（`WEAK`）保留极淡填充，用来表达"有回波但不禁飞"；
3. 逐分钟重算：`bands` 随 `minute` 变，前端按 1.14 的推进量做 200 ms 淡入淡出，避免整片闪跳；
4. 小到只有几个像素的区域（屏幕上 <6 px）直接画点，不画轮廓 —— 否则又回到"小方框伪影"。

**验收**：全站任何一页都不再出现彩色瓦片块；回波随时间轴变化有连续感；1366 下不糊。

### 1.15 虚拟气象要真的造出禁飞区（#15）

**病根**：`virtualMode` 只把回波和绕飞**加亮**（改透明度/线宽），没有生成任何新几何，
所以"全国恶劣天气"这个演示场景根本不存在。

**改法**：把 `virtual` 做成一个**后端开关**（`?virtual=1`），而不是前端的一层滤镜：

1. 固定种子的"恶劣天气包"：在全国 6 个大区各生成 1–2 片强回波（椭圆 + 扰动，面积 2–6 万 km²），
   覆盖东部沿海与长江中游两条主廊道；
2. 这些片与航路求交 → 生成气象禁飞区（`kind:'WEATHER'`）→ 走同一套绕飞/停飞逻辑；
3. 前端：与真实回波用同一套轮廓渲染，但加一个「虚拟」角标，图例里写明"演示用，非实况"；
4. 关掉虚拟开关，几何立刻回真实值（不缓存）。

**验收**：开虚拟后禁飞区从 0/个位数增到 20+ 片、受影响航线 100+ 条，事件页出现对应气象事件；
关掉后全部复原，且两条路径的数据互不污染。

### 1.16 自查出的前端 bug（#16）

| bug | 现状 | 修法 |
|---|---|---|
| 底部浮层的 `:hover` 是死代码 | `.nrn-mapfoot{pointer-events:none}` 使 `.dim:hover{opacity:1}` 永远不触发；选中班次后图例永久压到 26%，鼠标移上去没反应 | 去掉这条 hover，改为"选中时折叠成一行极简图例"，或给容器 `pointer-events:auto` 但子项 `none` |
