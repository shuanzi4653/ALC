## 1. 逐条方案

### 1.1 左导航"点完不灭"（#1）

**病根**

模板里入口按钮的类名是"当前入口 + 合并入口"两个条件，与"当前页"无关：

```html
<!-- TrafficWorkbench.vue:618 -->
<button :data-section="sub.key"
        :class="{active:entryKey===sub.key,'group-active':entryKey===sub.key&&sub.merged}">
```

`entryKey` 是**入口**，不是当前页。于是 `#/model/reference`（口径与来源）下：

```
推演       class="active group-active"   bg rgba(89,223,252,.13)  border rgba(89,223,252,.26)
口径与来源  class="nav-entry-tab active"  bg rgba(89,223,252,.13)  border rgba(89,223,252,.26)
```

两行像素级同款，实测截图见 `.run/shots104/rail-_model_reference.png`。
样式表里本来有一条"合并入口不点亮"的兜底（`.nav-subs button.active.group-active{background:transparent}`），
但它写在前面，被后面同选择器族、更高顺序的 `.nav-subs button.active` 覆盖 —— 特异性赢了也白搭。

处置页同理：`处置`（入口）与 `调度台账`（tab）同时亮。

**改法**

1. 入口按钮的 active **只认当前页**：`active: entryKey===sub.key && activeSection===sub.key`，删掉 `group-active` 这个半吊子类。
2. 合并入口在"当前页是它的兄弟 tab"时，改为一种**弱标识**（左侧竖线保留、底色去掉），让人知道"我在这个入口里"，但绝不与 tab 抢焦点。
3. 把两条冲突规则合并成一条，避免以后再加样式又把它盖掉；顺带给底色加 `transition:background .16s`，点击时是"这一盏灭、那一盏亮"，不是硬切。

**验收**：`#/model/reference`、`#/dispatch/ledger` 两页断言"亮着的导航按钮恰好 1 个"。

### 1.2 飞行参数不再压住箭头（#2）

**病根**

```js
// NationMap.vue:939
:y="row.y-7*inv"                      // 基线只比机位高 7
```

机身 `M6 0 L-3.4 3.2 L-1.7 0 L-3.4 -3.2 Z` 旋转后外接半径 ≈ 6，标签字号 7.6 + 2.2 px 描边，
基线 7 个单位意味着**文字下沿正好压在机头**。实测 3 条常显标签，3 条都与本机重叠。

**改法**

1. 标签改成"胶囊块"（见 1.3），块高固定，底边离机位 **≥ 11 个单位**（机半径 6 + 3 间隙 + 块内边距 2）。
2. 默认放**右上方**（`x+9`，`text-anchor:start`），因为机头朝前、右上比正上更少遮挡航向；
   靠近右边界（`row.x > VIEW.w-90`）时自动翻到左上，与现有城市名的翻边规则一致。
3. 保留既有互相避让：标签之间、标签与城市名之间仍是"先到先得"。

**验收**：截图检查 + 一条用例断言"每条标签的包围盒与任一机身外接圆不相交"。

### 1.3 地图文字统一成"椭圆底 + 直角字"（#2 / #3 合并）

**病根**

地图上所有文字（城市名 8.6 px、航班参数 7.6 px、起终点名 9.6 px）都用同一套"描边做底"：

```css
.nmap .city{stroke:rgba(4,12,20,.85);stroke-width:2.4px;paint-order:stroke}
```

描边比字还宽（缩放 4 倍时字号实测 2.05 px、描边 2.4 px），字被自己糊成一坨，
笔画末端伸出两个尖角 —— 用户看到的"箭头气泡"就是它。

**改法**

1. 新增一个纯函数 `tagBox(text,fontSize)`：按 CJK≈1.0 em、拉丁/数字≈0.56 em 估算宽度，
   产出 `{w,h}`；调用方给 `<rect rx="h/2">`（半高圆角＝标准胶囊，短名看起来就是椭圆）。
2. 三类文字共用一套渲染：`<g class="map-tag"><rect class="tag-bg"/><text/></g>`，
   底色 `rgba(6,18,28,.72)`、字色 `#dff3ff`、**无描边、无阴影、无边框**。
3. 取消 `paint-order:stroke` 的那套晕（保留 `text-shadow` 也不需要）；
   浅色主题换成 `rgba(255,255,255,.86)` + `#12314a`。
4. 起终点名（`.end-lbl`）同样处理，`end-sub` 那行小字不进胶囊（信息量大、会过长）。

**取舍**：SVG 里量文字宽度要 `getBBox()`（每帧几十次，会掉帧），所以用**估算宽度 + 左右各 6 px 内边距**，
中文名不会溢出、英文缩写略宽 1–2 px，肉眼无感。若以后要精确，再换成 HTML 覆盖层（见 §3 备选）。

**验收**：截图对比（深/浅两色）；断言所有标签矩形与文字包围盒的左右留白 ∈ [4,10] px。

### 1.4 红圈要有说法，市级只讲本市（#4）

**病根 A（红圈）**

```html
<!-- NationMap.vue:893 -->
<circle v-if="node.weather&&node.weather.low" :r="4.8*inv"
        fill="none" stroke="rgba(226,75,74,.92)" stroke-width="1"/>
```

这是"低能见概率 ≥ 0.35 的城市"圈，与图例里任何一个符号都不是同一件事，图例也没写。

**改法 A**：图例补一项「红圈 · 低能见城市」，并把它挂到已有的"低能见"叙事上
（顶部结论条里就有"低能见 N 城"）。同时该圈的悬停浮层补一行 `低能见概率 xx%`，
让"圈—数—图例"三处对得上。

**病根 B（层级与右栏）**

面包屑是**点击历史**，不是层级链：

```js
// NationPanel.vue:336
const cut=trail.value.findIndex(item=>item.level===nextLevel)
```

从市级「返回上一级」再点省份、或在市级点地图空白（`clickShape` → `drill('province',…)`），
`trail` 就会追加成 `全国›临沧市›云南省`。此时页面标题与五个大数字取的是**省**的口径（22 航线 / 7 在飞），
右栏是"本省城市 13 个节点" —— 用户读到的就是"我点了临沧，右边在讲云南别的机场"。

市级本身是好的（实测点列表里的临沧：`3 航线 / 1 在飞`，右栏出"城市节点 临沧市：省/机场/航线/在飞/相邻"），
**坏的是走到市级之后还能被打回省级、而面包屑不回退**。

**改法 B**

1. `go()` 改成按**层级链**构造：`nation → region → province → city` 恒为一条链，
   跨级时用父级补链（点城市但链上没有省 → 用 `data.city.province` 补上），不再 append 任意目标。
2. 面包屑与五个大数字、右栏一律以**服务端返回的 `level`/`id`** 为准，不认请求参数；
   两者不一致时以服务端为准并清掉链尾多余项（服务端把 city 兜底成 province 时，界面必须跟着回落）。
3. 市级（本项目最低一级）右栏固定为"本市卡片"，且**永不出现省级城市列表**：
   指标换成该市自己的（在飞 / 停飞 / 低能见概率 / 能见度 / 与其相连的 3 条走廊），
   走廊可点，直接落到走廊页。
4. 市级不再响应"点地图空白跳省" —— 底图多边形在市级是背景，点了应该什么都不发生（或提示"已是最低级"）。

**验收**：脚本走"全国 → 西南 → 云南省 → 临沧市"，断言 ①面包屑恰为这 4 段；②`航线` 数字 = 3；
③右栏不含"本省城市"字样；④在市级点空白后面包屑不变。

### 1.5 换分钟不再抖（#5）

**病根**

```js
// NationMap.vue:457
const base = frameMinute>=0 ? frameMinute : minute
const adv  = base - minute            // ← 分母是"请求的分钟"，不是"数据自己的分钟"
```

```js
// NationPanel.vue:398
if(m!==minute.value){ minute.value=m; loadFlights() }   // 异步，几十毫秒后才回来
```

分钟一翻：`adv` 从 0.99 掉到 0.00，而 `flights` 还是上一分钟的快照 → 飞机瞬间**倒退**约一分钟的航程；
新快照到了再**弹回**前方。实测（4 倍缩放、25 ms 采样）：

```
换分钟 09:04  x: 308.9 → 309.0 → 308.7(退) → 309.0(回) → 309.0
```

9 倍缩放下这一退一回约 2.7 px，加上标签一起跳，就是录屏里那种"一秒钟抖一下"。

**改法**

1. **以数据自己的时刻为基准**：`loadFlights` 收到 `payload.minute` 就记 `flightsMinute`，
   推进量改成 `adv = frameMinute - flightsMinute`（夹在 `[0, 1.6]`）。
   分钟翻的时候 `adv` 只是从 1.00 继续涨到 1.08，不再归零；新快照到达时 `flightsMinute+1`、
   `progress+1/duration`，两边正好抵消 —— 数学上连续，不需要任何缓动补丁。
2. **位置改参数化**：不再用"沿 heading 直线外推 4 km"，改成沿**这条走廊自己的折线**取点。
   后端 `nation_ops.flight_objects` 的规则是"按顶点均分进度"（`pos=progress*(n-1)`），
   前端照抄同一条规则，误差 = 0，也不会在转弯处漂出去（漂出去再被拉回，本身就是第二种抖）。
3. 机头角度也取自折线当前段的方位角，段与段之间做**最短弧插值**（±180° 不再翻个跟头）。
4. 顺带把 `advanceMin` 上限从 6 分钟降到 1.6：超过 1.6 分钟说明快照真的丢了，宁可站住也不外推。

**验收**：录屏同条件重采样，断言"相邻采样的位移单调不回退"，且换分钟前后的位移差 ≤ 中位数的 1.5 倍。

### 1.6 走廊必须画、飞机必须贴着走廊（#6）

**病根 A（有飞机没线）**

```
在飞 109 架：AIRPORT_FEED 68 / INTRA 37 / CROSS 4
默认 lineKinds={cross:true, feed:true, intra:false}   → INTRA 201 条一条不画
```

凡是飞在省内短途走廊上的 37 架，画面上就是"凭空出现的小箭头"。这不是渲染 bug，是**过滤规则没考虑"有人在飞"**。

**病根 B（线是弯的、飞机是直的）**

```
corridors 492 条：path 为空 484 条（只有端点）、3 点 4 条、4 点 2 条、6 点 2 条
```

```js
// NationMap.vue:343
const points = coords.length===2 ? arcPoints(coords[0],coords[1],row.bulge) : coords
```

后端明确约定"两点不传 path，前端用两端点直飞"（`nation.py:708`），前端却按 `bulge` 造了一条二次弧。
492 条里 484 条是这种情况 —— 画的是弧、飞机走的是弦，越放大偏得越明显。

**改法**

1. **几何单一来源**：前端不再造弧，`points = path ?? [from,to]`，画出来就是数据本身。
   （`bulge` 字段保留不动，避免影响其它调用方；只是不再参与绘制。）
2. **在飞必画**：`corridors` 的显示集合 = 三档筛选结果 **∪ 当前在飞班次所在的走廊**。
   这 109 条走廊不受 `lineKinds` / `lineLimit` 约束 —— "有人在上面飞"比"用户想看几条线"优先。
   同时 `lineStats.shown` 要如实反映（图上多少条就写多少条）。
3. **端点必有名字**：`labels` 的提权集合加入"当前在飞班次的 `fromName`/`toName`"，
   与既有"跨省端点提权"同一优先级（rank 0），否则会出现"有飞机、没起降城市"。
4. 悬停/点选行为不变；`soloCorridor` 分支复用 `toLineShape`，自动跟着改。

**验收**：一条用例遍历 `flightDots`，断言每架飞机到其走廊折线的最短距离 < 0.5（SVG 单位），
并断言"在飞班次 `corridor` 全部出现在绘制的 `corridors` 里"。

### 1.7 回波改成"真雷达的长相"（#7）

我按用户的提醒去看了真实拼图（`.run/real_radar.png`，RainViewer 同期瓦片，就是本项目的数据源），
真实回波有四个特征，我们一个都不占：

| 特征 | 真实雷达 | 我们现在 |
|---|---|---|
| 分级关系 | 红核 ⊂ 橙 ⊂ 黄 ⊂ 绿 ⊂ 蓝，**层层嵌套** | 三档**互斥**（87 / 109 / 83 片并排相邻） |
| 填充 | 实心填色，**无描边** | 每档都描一圈高亮边 → 等高线观感 |
| 内部 | 有杂色颗粒（同一片里混着不同强度） | 一片一个纯色 |
| 外形 | 细长带状 + 零散单体，边缘不规则 | 圆润多边形，Chaikin 磨得太"干净" |

**病根**

```python
# radar_public.py:285
cells: Dict[str,List[Tuple[float,float]]] = {'WEAK':[], 'CONVECTIVE':[], 'STRONG':[]}
...
closed_cells = {band:_close_cells(rows) for band,rows in cells.items()}
bands = {band:_rings_of(rows) for band,rows in closed_cells.items()}
```

每个栅格只归一个档，每档各自成环 —— 数学上就不可能嵌套。

**改法**

1. **后端改累计掩膜**：先保留每格 rank，再按阈值取并集 `rank>=1 / >=2 / >=3` 分别成环。
   代码改动极小（`cells` 多存一个 rank，成环前按阈值筛），缓存键升到 `-geo5`。
   嵌套之后外层会更大更整、内层变小，环数预计不增反降。
2. **前端只填不描**：删掉 `.echo-*` 的 `stroke`，改成三档实心填充（含浅色主题一套）；
   `virtualMode` 的"更醒目"改为提高不透明度 + 描一道 0.6 px 暗边，而不是亮边。
3. **加颗粒**：给整个回波组挂一个滤镜 —— `feTurbulence`(fractalNoise, baseFrequency≈0.9) → 去饱和 →
   `feComposite operator="in"` 只留在回波内 → `feMerge` 叠在源图上，透明度 0.12。
   只作用于静态图层（回波一分钟才换一帧），不影响 30 fps 的飞机。
4. **配色对齐 dBZ 色阶**：绿 `#2e9e5b` / 黄 `#e8c33a` / 红 `#d93a2b`，不透明度 0.55 / 0.68 / 0.82；
   浅色主题各降 0.2 并加深一档。三档之外不加新档（后端只有三个阈值，加了就是编数据）。
5. 保留已有的闭运算 + Chaikin，但要**降一轮**：嵌套后外层环更大，两轮 Chaikin 会把"带状"磨成"香肠"。

**载荷风险**：嵌套后外层环的顶点数上升，全国载荷可能从 622 KB 涨到 760–820 KB。
硬门槛 **≤ 820 KB**（现测试线）。超了就按顺序做三件事：
①外层环 0.012° 抽稀；②Chaikin 从 1 轮降到 0 轮（只留闭运算）；③颗粒层只在缩放 ≥1.5 时开启。

**验收**：截图与 `.run/real_radar.png` 并排比对；断言**面积**递减（`sum(STRONG) ≤ sum(CONVECTIVE) ≤ sum(WEAK)`）
与强回波外接框落在中强内 —— 注意**不能**用"环数递减"当判据：累计之后外层会合并成少数大块，
内层反而是许多小核，实测环数是 49 / 80 / 88（弱 < 中 < 强），环数不单调才是嵌套的正常形态。
载荷 ≤ 820 KB。
