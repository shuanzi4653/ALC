## 3. 端侧对拍实验：方法与实测结果

### 3.1 方法

1. `export_forest.py` 把 `models/ml-v2-vis3k.json`（`alc-forest-v1`，100 树，26 维）导出成 C 数组：
   float32、**无递归**（迭代下降）、无动态内存、无栈增长；叶子两个数都存（不省 96 KiB，
   因为 `forest.py` 真的做了两次除法，少存一个会在最后几个 ulp 分叉）。
2. `edge_infer.c` 实现 `edge_predict`，与 `backend-python/ml/forest.py` 逐字等价。
3. `gen_cases.py` 从 `data/training/national/dataset.json`（319 城 × 30 天真实逐小时观测，
   sha256 前 16 位 `64fa1ef2236382cc`）构造用例：扫 227 447 行、可用 225 533 行，
   按能见度分 5 层抽样（配额 120/180/200/200/300），种子 20261113。
   另补一组只用三站（ZYTX/ZYCC/ZYHB）周边的用例，因模型只用这三站训练。
4. `edge_x86_main.c` 用 MSVC 14.44 `/O2` 编成 x86 可执行，读同一批用例输出 p 与耗时。
5. `pair_check.py` 逐条比对 Python 与端侧 C 的输出。

### 3.2 实测结果（2026-11-11 21:55，原始 JSON 已核）

| 指标 | 全国口径 | 三站口径 |
|---|---|---|
| 用例数 | 1000 | 1000 |
| **max\|Δp\|** | **6.952852982e-07** | **5.727492031e-07** |
| mean\|Δp\| | 2.510e-07 | 2.436e-07 |
| 超差组数（容差 1e-4） | **0** | **0** |
| 判决一致（阈值 0.3） | **1000/1000**（728/728） | **1000/1000**（752/752） |
| 端侧单次判决 | **3.93 µs** | **4.18 µs** |
| 云端 Python 单次 | **152.36 µs** | 182.87 µs |
| 校准后 max\|Δp_cal\| | 1.634e-05 | 6.080e-06 |
| p 分布 | p50 0.5479 / max 0.9804 / mean 0.5575 | p50 0.4976 / max 0.9835 |

模型自检串：`model=ml-v2-vis3k fp=7a7fc34a92babc78 trees=100 features=26 nodes=24111 leaves=24211 calib=92 bytes=509106 checks=OK`

### 3.3 口径红线（写材料时必须遵守）

- 上述结果是在 **x86 等价编译目标**（同一份 C 代码，MSVC /O2）上跑出来的。
- **ESP32 尚未烧录。** 只能说"同一份 C 代码在等价编译目标上验证"。
- **不许说"在 ESP32 上实测"**；**不许说"二十毫秒出结果"**（20 ms 是设计余量，实测 3.9 µs）。

### 3.4 实验过程本身抓出的两处真问题（可作技术深度讲）

1. **阈值量化方向必须向下取整。** 云端 float64、端侧 float32，特征值恰好等于分裂阈值时会翻边。
   实测同一批 1000 组：就近取整错 2/1000、向上取整错 2/1000、**向下取整 0/1000 且与 `forest.py` 位级相等**。
   可证：`(thrF, thr]` 区间内没有 float32 可取。
2. **Python 侧读用例必须量化到 float32。** 文本 `9.4` 代表 float32 的 9.3999996185，
   `strtof` 与 `float()` 得到两个不同的数。**首轮因此 40/1000 超差（max 1.109e-02），修完降到 6.95e-07。**
   错在 Python 侧读文件方式，不在 C——写报告时顺序要写清，免得被当成"调容差蒙过去"。
