## §1 F-1 打通气象通道开关（4 小时）

### 1.1 问题回顾

三层叠在一起，缺一层都不行：

```
第 1 层：前端"信息密度"下拉框叫 duty/command/demo —— 这是显示详略，不是权限
第 2 层：真正发出去的 X-ALC-Operator 读 localStorage['alc-operator']，
        值域 observer/duty/admin，但全包 0 处 setItem —— 永远等于默认 duty
第 3 层：后端切天气通道要 admin，前端没有 admin 的写入路径 → 死锁
```

### 1.2 修法（三选一，我推荐方案 A）

#### 方案 A：给页面加一个真的身份切换器（推荐）

**做什么**：在「设置」面板里加一个 `select`，选项直接对应后端枚举，选中就写 `localStorage`。

**为什么推荐**：这是唯一能"演示"的做法。评委看到页面上有个"观察员 / 值班员 / 管理员"的下拉，自己点一下 switch 就切了，**这就是加分项**。

**代码位置**：`src/components/SettingPanel.vue`（或对应设置面板组件）

```vue
<!-- 在设置面板里新增一段 -->
<template>
  <section class="setting-row">
    <label class="setting-label" title="决定你能做哪些写操作；观察员只读">
      操作员角色
    </label>
    <select :value="operator" @change="onOperatorChange">
      <option value="observer">观察员（只读）</option>
      <option value="duty">值班员（可暂停/恢复/处置）</option>
      <option value="admin">管理员（可切换气象通道）</option>
    </select>
    <p class="setting-hint">
      权限说明：切换气象通道需要「管理员」；日常处置「值班员」即可。
    </p>
  </section>
</template>

<script setup>
import { ref, watch } from 'vue'

const OPERATORS = ['observer', 'duty', 'admin']
const operator = ref('duty')

// 与打包后 zo() 保持完全一致的读法
function readOperator() {
  try {
    const v = localStorage.getItem('alc-operator')
    return OPERATORS.includes(v) ? v : 'duty'
  } catch {
    return 'duty'
  }
}

operator.value = readOperator()

function onOperatorChange(e) {
  const v = e.target.value
  if (!OPERATORS.includes(v)) return
  operator.value = v
  try { localStorage.setItem('alc-operator', v) } catch {}
  // 关键：写完之后要让页面重新取一次 weather/mode，
  // 否则按钮的 disabled 状态还是按旧角色算的
  window.dispatchEvent(new CustomEvent('alc-operator-changed', { detail: v }))
}
</script>
```

**别忘了**：`lc-operator` 改了之后，`/api/traffic/weather/mode` 要重新拉一次。否则用户切成 admin 了，页面还以为自己是 duty。

在气象监测页加：

```js
// 监听角色变化，重取通道元数据
onMounted(() => {
  window.addEventListener('alc-operator-changed', refreshMode)
  onUnmounted(() => window.removeEventListener('alc-operator-changed', refreshMode))
})

async function refreshMode() {
  const r = await Bo('/api/traffic/weather/mode')
  weatherModeMeta.value = r   // 重算按钮 disabled
}
```

#### 方案 B：前端枚举改名对齐（最省事，但不好演示）

**做什么**：把"信息密度"下拉框的取值从 `duty/command/demo` 改成 `duty/command/demo` **保持不变**，但另存一个 key，例如 `alc-density`。然后 `alc-operator` 单独维护。

**为什么不推荐**：它解决了"撞车"，但没解决"没有 admin 入口"。用户还是切不了。

#### 方案 C：后端放宽到 duty（最快，但丢分）

**做什么**：把 `weather/mode` 的权限从 `admin` 降到 `duty`。

**为什么不推荐**：你自己写的"本操作需要管理员及以上"就变成了空话。评委问"为什么分级"，你答不上来。**这是拿设计换便利，不值得。**

### 1.3 顺手要修的两处

**① `observedAt` 与 `setItem` 的一致性检查**

打包后代码里：

```js
function zo(){
  try{ let e=localStorage.getItem(`alc-operator`);
       return [`observer`,`duty`,`admin`].includes(e) ? e : `duty` }
  catch{ return `duty` }
}
```

这个函数**每个请求都调一次**，每次都要读 `localStorage`。改成模块级缓存：

```js
let _op = null
function readOperator() {
  if (_op) return _op
  try {
    const v = localStorage.getItem('alc-operator')
    _op = ['observer','duty','admin'].includes(v) ? v : 'duty'
  } catch { _op = 'duty' }
  return _op
}
```

（这不是必须的，但 `localStorage` 是同步 API，每次请求读一次在高频轮询下会卡主线程。）

**② 后端错误消息的措辞**

现在：

```
本操作需要管理员及以上；当前身份：值班员（请求头 duty）
```

这句话对普通用户是**天书**——"请求头 duty"是什么？建议改成：

```
切换气象通道需要「管理员」权限。你当前是「值班员」，
可在右上角「设置 → 操作员角色」中切换。
```

**把修复路径直接写进错误消息**，这是最好的用户引导。

### 1.5 一个必须提醒的点

**切回实测气象也需要 `admin`。** 如果哪天你用 admin 切到了虚拟气象，然后改回 duty，页面上就再也切不回来了。

建议顺手加一条保护：**虚拟气象模式在切换后的 30 分钟内，允许任何人切回实测**（单向回落豁免）。这符合"安全侧默认可恢复"的原则，也是一句很好的答辩话术：

> 进虚拟态需要管理员，但退出虚拟态不需要——我们不允许系统停留在虚拟状态而无人能恢复。

代码大致是：

```python
def require_admin_for_mode_change(target_mode: str, current_mode: str):
    # 切向虚拟：必须 admin
    if target_mode == "virtual":
        return require_role("admin")
    # 切回实测：任意角色都允许（安全侧）
    return require_any_role()
```

## §2 F-2 雾天案例页气象对齐（3 小时）

### 2.1 问题回顾

雾天案例页（`?case=fog-20250105`）发出的请求：

```
/api/traffic/v2/overview?seed=42&scenario=live&case=fog-20250105   ✅ 带 case
/api/traffic/weather?seed=42&scenario=live&minute=60               ❌ 没带 case
```

结果：右边讲 2025-01-05 沈阳大雾（997.8 m），地图画 2026-10-21 的实时天气，底部状态条写「低能见度：本帧无」。

### 2.2 前端修法

**位置**：打包后 `Mt()` 函数（原 `src/stores/weather.ts` 或同类）。

**现在**：

```js
let r = await Bo(`/api/traffic/weather?seed=${x.value.seed}&scenario=${x.value.scenario}&minute=${n}${k.value?`&cityId=`+encodeURIComponent(k.value):``}`);
```

**改成**：

```js
function buildWeatherUrl() {
  const p = new URLSearchParams({
    seed: String(x.value.seed),
    scenario: x.value.scenario,
    minute: String(A.value),
  })
  // 关键：案例回放时，气象也必须取同一个案例
  if (caseId.value) p.set('case', caseId.value)
  if (cityId.value) p.set('cityId', cityId.value)
  return `/api/traffic/weather?${p.toString()}`
}

let r = await Bo(buildWeatherUrl())
```

**`caseId` 从哪来**：

```js
// URL 参数 → store
const params = new URLSearchParams(location.search)
const caseId = ref(params.get('case') || '')
```

**别忘了另一处**（打包后 `Qt()`，快照重放）：

```js
let e = await Bo(`/api/traffic/weather?seed=${D.value}&scenario=${O.value}&minute=${A.value}`);
```

这里同样要补 `case`。

### 2.3 后端修法（这一条更重要）

后端现在**静默忽略** `case` 参数——传了不认、不报错、直接回实时数据。这是最坏的行为：它让前端以为"我传了"。

**改法**：`GET /api/traffic/weather` 的入参 schema 里加 `case`，并且**校验案例是否存在**。

```python
from fastapi import Query, HTTPException

@router.get("/api/traffic/weather")
async def get_weather(
    seed: int = Query(42, ge=0, le=99999),
    scenario: str = Query("live"),
    minute: float = Query(60),
    cityId: str | None = Query(None),
    case: str | None = Query(None),          # ← 新增
):
    if case:
        case_meta = case_registry.get(case)   # 与 /v2/overview 用同一个注册表
        if case_meta is None:
            raise HTTPException(
                status_code=422,
                detail={
                    "retryable": False,
                    "code": "UNKNOWN_CASE",
                    "message": f"未知案例 `{case}`，可用案例见 /api/traffic/cases",
                },
            )
        # 案例回放：气象必须来自该案例的 METAR 序列，不能取实时
        return build_case_weather(case_meta, minute, cityId)
    return build_live_weather(seed, scenario, minute, cityId)
```

**要点**：

1. **`case` 必须走和 `/v2/overview` 完全相同的注册表**，不能有两套
2. **未知 case 必须报错**，不能静默回落——静默回落就是这次 bug 的成因
3. **案例模式下禁止回落实时**：`build_case_weather` 内部如果取不到案例数据，要返回 `available: false`，不能偷偷用实时数据填

### 2.4 第三层修法：加一条口径一致性断言

这是防御性的，但很值。**在页面渲染前，检查"结论的 case"和"气象的 case"是不是同一个**：

```js
const caseMismatch = computed(() => {
  const overviewCase = overview.value?.case?.caseId ?? null
  const weatherCase = weather.value?.case ?? null
  return overviewCase && overviewCase !== weatherCase
})
```

如果 `caseMismatch` 为 true，在页面顶部显示红条：

> ⚠️ 数据口径不一致：结论来自案例 `fog-20250105`，气象图层来自实时数据。请刷新页面或检查接口。

**这条断言的意义**：以后再有人改参数漏了 `case`，页面会自己喊出来，不会像这次一样安静地错。

## §3 F-3 `/health` 去自曝 + 版本号（1.5 小时）

### 3.1 现在长什么样

```json
{"status":"ok","version":"0.11.4-beta","at":"2026-10-21T08:57:49Z","uptimeSeconds":1965.3,
 "checks":{"planStore":{"ok":true,"detail":"store dir not exposed","plans":null},
```

### 3.2 三条自曝，逐条改

#### ① `"llm probe not wired"` —— 最要命

**现状**：`ok: true` 但 `detail` 说"根本没接线"。这是**报了个假绿**。

**改法**：要么真接线，要么老实报 `unknown`。

```python
def check_llm():
    try:
        # 真探一次：用最小 prompt 打一次 LLM，超时 3 秒
        t0 = time.monotonic()
        r = llm_client.probe(timeout=3.0)      # 返回 {"ok": bool, "model": str}
        ms = round((time.monotonic() - t0) * 1000)
        if not r["ok"]:
            return {"ok": False, "detail": "LLM 探针失败", "latencyMs": ms}
        return {"ok": True, "model": r["model"], "latencyMs": ms}
    except Exception as e:
        return {"ok": False, "detail": f"LLM 探针异常：{type(e).__name__}"}
```

**如果这一版的 LLM 确实是异步任务、不适合同步探**，那就诚实地报：

```python
return {"ok": None, "state": "NOT_PROBED", "detail": "LLM 由后台任务调用，不提供同步探针"}
```

**关键区别**：`ok: null` + `state: "NOT_PROBED"` 是诚实的；`ok: true` + `"not wired"` 是骗人的。**评委能接受"没做"，不能接受"假装做了"。**

#### ② `"store dir not exposed"` + `"plans": null`

**改法**：至少报出计划数量和最近写入时间。不需要暴露目录路径。

```python
def check_plan_store():
    try:
        n = plan_store.count()
        last = plan_store.last_write_at()
        return {"ok": n > 0, "plans": n, "lastWriteAt": last.isoformat() if last else None}
    except Exception as e:
        return {"ok": False, "detail": f"计划库读取失败：{type(e).__name__}"}
```

#### ③ `"version": "0.11.4-beta"`

**改法**：改成从构建时注入，别再手写。

```python
# 构建时写进 VERSION 文件
VERSION = (Path(__file__).parent / "VERSION").read_text().strip()
```

CI 或构建脚本里：

```bash
echo "0.11.8" > VERSION
```

**顺便给前端也加一个**：`/api/traffic/version` 现在是 404，加一个最简单的：

```python
@router.get("/api/traffic/version")
async def version():
    return {"version": VERSION, "builtAt": BUILD_TIME, "commit": GIT_SHA_SHORT}
```

这样页脚可以显示 `v0.11.8 · 2026-10-21`，**答辩时评委问"这是哪一版"，页面上直接看得见**。

## §4 F-4 图例文案与字号（2 小时）

### 4.1 状态条补两句

**现在**：

> 雷达：仅层状降水 434.9 km²（15–35 dBZ，可飞越）· 本帧无 ≥35 dBZ 对流，橙色按设计不出现

**问题**：没说在哪儿，也没说占比。用户对着地图找不到。

**改成**：

> 雷达：层状降水 434.9 km²（15–35 dBZ，可飞越）· **回波中心在东北三省以东境外，占本帧 0.25%，当前视野下不明显** · 本帧无 ≥35 dBZ 对流，橙色按设计不出现

**数据怎么来**：`radar.summary.echoFraction`（现在就有，本次实测 `0.002464`）+ `radar.watch.field` 的坐标范围。

```js
function describeRadarLocation(watch) {
  if (!watch?.field?.coordinates?.length) return ''
  const ring = watch.field.coordinates[0][0]
  const lng = ring.reduce((s, p) => s + p[0], 0) / ring.length
  const lat = ring.reduce((s, p) => s + p[1], 0) / ring.length
  // 东北三省主体约 115–135°E, 38–54°N
  const inRegion = lng >= 115 && lng <= 135 && lat >= 38 && lat <= 54
  return inRegion ? '回波在监视区内' : '回波中心在监视区外，当前视野下不明显'
}

const pct = (radar.value?.summary?.echoFraction ?? 0) * 100
// 0.2464 → "0.25%"
```

### 4.2 「实测雷达回波」这个标签要加条件

**问题**：命令行/服务端环境下 `radar.available = false`，标签还写"实测"。

```js
function radarLabel(mode, radarAvailable) {
```

## §5 F-5 `points` 裁剪 + 前端接分页（1 小时）

### 5.1 后端：真的裁掉

**现在**：`/api/traffic/flights?page=1&size=100` 返回 100 条，每条 856 B，其中 `points` 占 395 B（46.3%）。

**为什么没裁**：`slim` 字段硬编码 `true`，但没有任何代码读它。

**改法**：

```python
@router.get("/api/traffic/flights")
async def list_flights(
    page: int = Query(1, ge=1),
    size: int = Query(100, ge=1, le=500),
    slim: bool = Query(True),     # 默认瘦，明确要轨迹才带
):
    items = plan_store.page_flights(page, size)
    if slim:
        items = [strip_points(f) for f in items]     # ← 真的删
    return {
        "page": page, "size": size,
        "total": plan_store.total_flights(),
        "pages": math.ceil(plan_store.total_flights() / size),
        "slim": slim,
        "items": items,
    }

def strip_points(f: dict) -> dict:
    out = dict(f)
    out.pop("points", None)
    out["hasPoints"] = True      # 告诉前端"要轨迹请去打 /flights/points"
    return out
```

**体积预期**：856 B → 约 461 B，**降 46%**。100 条从 90 KB 降到 48 KB。

### 5.2 前端：接上分页接口

**现在**：首页翻页是本地切片（`Ce.value.length / 20`），`Ce` 是本地 1010 条数组。

**为什么这不算错**：1010 条内存里放着，翻页很快。但语义上不好——**"本地有 1010 条"和"服务端有 7760 条"是两件事**。

**改法（可选，但建议）**：列表区改成分页请求。地图仍然只画截断后的 1010 条（这个设计是对的，不用改）。

```js
async function loadFlightPage(page = 1) {
  const r = await Bo(`/api/traffic/flights?page=${page}&size=20`)
  tableRows.value = r.items
  totalPages.value = r.pages
  totalCount.value = r.total        // 7760，显示"共 7760 班，当前第 x/y 页"
}
```

**表格顶部文案**改成：

```
共 7,760 班 · 当前第 1 / 388 页 · 地图仅绘制城际 848 班 + 配送前 162 班
```

这句话解决了"为什么地图上的航班数比总数少"这个必然会被问的问题。

### 5.3 顺手：`fields` 的错误码

```
GET /api/traffic/session?fields=list
→ {"code":"DECISION_REQUEST_FAILED","message":"query.fields：String should match pattern '^(slim|full)$'"}
```

**改**：参数校验类错误不要套 `DECISION_REQUEST_FAILED`。

```python
class InvalidParameter(Exception):
    code = "INVALID_PARAMETER"

@app.exception_handler(RequestValidationError)
async def on_validation_error(request, exc):
    return JSONResponse(
        status_code=422,
        content={
            "retryable": False,
            "code": "INVALID_PARAMETER",
            "message": summarise(exc),      # 保留原文案
        },
    )
```

`operations` / `journal` 的 `sessionId` 缺失同理。

## §9 答辩口径更新（配合修完的版本）

修完之后，这些话术可以正面用：

**问「你的双气象通道怎么验证？」**
> 页面上有个「操作员角色」选择，切成管理员就能切通道。切过去之后系统会自动告诉您：这份计划是按实测生成的，而现在显示的是虚拟回波，两者的绕飞结论不能混着看——并且旁边就有一个「按虚拟通道重新调度」的按钮。**我们做的不是"切换",是"切换之后告诉你口径变了"。**

**问「为什么特意区分实测和模拟？」**
> 因为低空经济最怕的就是拿模拟数据当真实依据去放行。我们的原则是：模拟数据可以用来演示、可以用来做对照实验，但不能参与实际放行判断。所以虚拟气象这个模式，进要管理员，退不需要——**系统不允许停在虚拟状态而没人能恢复。**

**问「你雷达数据是实的吗？」**
> 是实测的，中国气象数据网组网组合反射率，6 分钟一帧。但源站对数据中心 IP 整站封禁，所以我们是让浏览器代取瓦片再回传——服务器仍然是唯一的解码和派生出口，浏览器只负责搬运字节。服务端直连会 403，我们会如实报"雷达不可用"，**不会拿模拟数据顶上**。

**问「雾天案例是怎么复现的？」**
> 2025-01-05 沈阳大雾，ZYTX 实测能见度 997.8 米，哈尔滨 1593 米，长春 2993 米，来自 Iowa State ASOS——和我们训练集同源，且未经插值。结论是三站 METAR 按本系统阈值算出来的，21 条走廊达到禁飞级。**"此刻已在阈值内"和"未来会不会"是两件事，我们按前者处置。**

**问「这一版主要改了什么？」**
> 三件：建场包从 7.5 MB 降到 1.2 MB，靠的是分页截断加 10 分钟缓存；健康检查上线，能报出计划库、气象通道、LLM 三路状态；地图图例从 7 项恢复到 9 项并且每一项可点。
