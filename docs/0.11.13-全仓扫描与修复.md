## 二、修掉的（1 个真缺陷）

### 2.1 「本案例判据」面板从来没加载出来过

**现象**：`?case=fog-20250105` 打开，切到「3 处置」，看不到「本案例判据」那一块。
没有任何提示，页面也不会报错给用户。

**根因**（`OperationsConsole.vue:47`）：

```js
const props = defineProps({ ..., session: Object, ... })
...
watch(() => [caseMode, activeCaseId, session.value?.status], async () => { ... })
//                                          ^^^^^^^^^^^^^ `session` 是 prop，不是 ref
```

`session` 是 **props 上的对象**，没有 `.value`。这一句在 watch 的 getter 里，
getter **在组件挂载时就会求值一次**（收集依赖），于是：

1. 一挂载就抛 `ReferenceError: session is not defined`；
2. Vue 里 watch getter 抛错 = 这个 watch 永不建立；
3. 于是 `casePanels` 永远是 `null`，`v-if="casePanels"` 的那一块永远不渲染。

**为什么一直没被发现**：
- 构建通过（语法完全合法）；
- 435/449 条前端判据全绿（它们不渲染这个组件）；
- `_audit_unbound_names.py` 是 **Python AST** 扫描，`ReferenceError` 不在它射程里（MEMORY ㉓ 记过这条盲区）；
- 报错只出现在浏览器控制台，没人天天开着看。

**修复**：`session.value` → `props.session`（3 处），并写上注释说明为什么闸门看不见它。

**判据（两条，缺一不可）**：
1. `_probe_all_pages.py`：8 个页面逐页点开，**JS 异常 0 条、API 4xx/5xx 0 条**（修复前：气象监测 / 3 处置各 1 条）；
2. `_probe_case_panels_simple.py`：等建场完成后切「3 处置」，`[data-case-panels]` = **1**，
   面板内容实测为「本案例判据 · 历史回放 2025-01-05 沈阳大雾 · 观测已达禁飞级 · 18 条走廊 · 涉及班次 2640 班 · 改航 2632 · 延误 8 · 暴露变化 2406 → 0 架次」。

## 三、补掉的（2 个工具缺口）

### 3.1 新增审计：prop 当 ref 用

上面那个缺陷是「一类病」，不是一次手误 —— 只要有人写 `propName.value` 就会重犯，
而现有全部闸门都看不见。所以补了 `tools/maintenance/_audit_vue_prop_refs.py`：

- 从 `defineProps({...})` 取键名；
- 在 `<script>` 体内找 `键.value`；
- 同名标识符另有 `const/let/var` 定义则排除（那是局部 ref）；
- **带负向自检**（喂一个缺陷样本必须先红，喂一个正确样本必须不报）；
- 已接进 `_gate_toolchain.py`：**29 → 31 项**，`README.md` 的项数同步改。

自检输出：`自检通过：缺陷样本 1 条被抓到，正确样本 0 条`；全仓 19 个 .vue → `ok`。

### 3.2 修好扫描器自己的一个"静默漏扫"

`_probe_all_pages.py` 第一版用 `textContent === '1 态势'` 匹配页签，
实际 DOM 里带空白 → **5 个页签全部 missing**，而脚本照样打印"跑完了"。
这种"扫描器自己没扫到"比漏 bug 更危险（它会让人以为已经扫过）。
改成按去空白后文本匹配，8 个页签全部 `ok`。

## 六、这一轮的方法论

**"扫一遍"要有尺，不能靠读代码时"觉得可疑"。** 这一轮真正抓到 bug 的那把尺，
是"把每个页面都点开、听浏览器报错"——它只花了 70 秒，抓到的是三条静态审计 +
449 条单元判据都看不见的东西。

另外一条：**探针自己也会说谎**。案例面板的验证我前后失败三次（首页 → 2 走廊 →
消息竞争），每次症状都像"功能没修好"，实际是"问错了地方"。所以现在的探针注释里
把这三个坑都写在代码上，免得下一轮再踩。
