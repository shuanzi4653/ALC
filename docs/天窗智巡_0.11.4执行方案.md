### W-13 · 把 `case` 提升为全局运行上下文（4h）

#### 现在是什么

`case` 是三个组件的 props，不是一个系统级状态：

- `POST /traffic/session?scenario=live` —— 建场时**不带 case**
- `GET /v2/overview?case=fog-20250105` —— **带**
- `GET /v2/corridors?limit=40` —— **不带**
- `GET /v2/corridor/{id}` —— **不带**
- `GET /traffic/weather`、`/traffic/operations` —— **不带**

结果：13 个子页里只有 2 页的正文随 case 变化，其余 11 页逐字相同。

#### 改成什么

**一个函数、一个字段、一条断言。**

**① 后端建一个唯一的解析入口**（新增 `backend-python/app/traffic/context.py`）：

```python
from dataclasses import dataclass
from datetime import datetime

@dataclass(frozen=True)
class RunContext:
    case: str | None          # None = 实时
    scenario: str             # live / weather_interrupt / ...
    observed_at: datetime     # 案例时刻 or 实时时刻
    seed: int
    plan_id: str

def resolve_context(request) -> RunContext:
    """所有 traffic 接口只准从这里取上下文，不准各自读 query。"""
    case = request.query_params.get("case") or request.headers.get("X-ALC-Case")
    scenario = request.query_params.get("scenario", "live")
    if case:
        meta = load_case(case)          # data/cases/<case>.json
        return RunContext(case=case, scenario=meta.scenario,
                          observed_at=meta.observed_at,
                          seed=meta.seed, plan_id=meta.plan_id)
    return RunContext(case=None, scenario=scenario,
                      observed_at=latest_observation_time(),
                      seed=int(request.query_params.get("seed", 42)),
                      plan_id=current_plan_id())
```

**② 五个接口全部改成 `ctx = resolve_context(request)`**，禁止再出现 `request.args["case"]` / `params.get("case")`。

**③ 前端把 case 放进全局 store，并在每次 fetch 时自动附加**：

```js
// frontend/src/api/client.js
let _ctx = { case: new URLSearchParams(location.search).get('case') || null,
             scenario: new URLSearchParams(location.search).get('scenario') || 'live' };
export function setContext(patch) { _ctx = { ..._ctx, ...patch }; }   // 切案例时调
export async function api(path, opts) {
  const u = new URL(path, base);
  if (_ctx.case) u.searchParams.set('case', _ctx.case);
  if (_ctx.scenario) u.searchParams.set('scenario', _ctx.scenario);
  return fetch(u, opts);
}
```

**④ 切案例 = 换 URL + 重新建场**（不要"只改文案"）：

```js
async function switchCase(caseId) {
  setContext({ case: caseId });
  history.replaceState(null, '', caseId ? `/?case=${caseId}` : '/');
  await rebuildSession({ case: caseId });   // 关键：必须重建 plan
}
```

#### 为什么

这是"一条链路"与"一个页面"的分水岭。现在评委点第二层就出戏，**根因不是数据错，是上下文没共享**。

#### 怎么算改完（验收）

```bash
BASE=https://tianchuang.shuanzi.site
for p in "/v2/overview" "/v2/corridors?limit=53" "/v2/corridor/CAR-1-01-1-05" "/traffic/sub/observations"; do
  echo -n "$p -> "

    | python -c "import sys,json;d=json.load(sys.stdin);print(d.get('observation',{}).get('observedAt') or d.get('observedAt'))"
done
# 四条输出必须全部 = 2025-01-05T00:00:00Z
```

**界面断言**（人工，2 分钟）：雾天模式下依次进入 ①气象监测 ②走廊剖面 ③预警中心 ④调度台账，**四个页面的观测时刻都必须显示 2025-01-05**。

### W-14 · 雾天案例必须真的改一次计划（6h）

#### 现在是什么

雾天首页与实时首页的页脚**逐字相同**：

```
本轮处置（延迟优先）放行率 98% · 时隙重排 3500 · 改航绕飞 0 · 停止放行 123
```

同屏右栏气象情报还写着"**本帧无高影响天气：36 条观测/情报全部正常**"。
而调度台账里，`沈阳 ↔ 本溪` 的班次状态是"**已到达**"——这条走廊在首页上标着"已达禁飞级"。

#### 改成什么

**案例不是"换一组观测"，是"换一次运行"。**

**① 建场时接受 `case`，并用案例时刻的气象重建一次调度**

```python
# backend-python/app/traffic/session.py
def build_session(ctx: RunContext):
    weather = load_case_weather(ctx) if ctx.case else fetch_live_weather(ctx)
    corridors = evaluate_corridors(weather, ctx)          # 概率档
    obs_level = evaluate_observation(weather, ctx)        # 观测档
    level = stricter(corridors.level, obs_level)          # 取更严（0.11.3 已有）
    plan = dispatch(ctx, corridors, level)                # ← 必须用 level 重新调度
    return Session(plan=plan, corridors=corridors, level=level, ...)
```

**② `dispatch()` 必须真的动状态**：`level == BAN` 的走廊上，所有 `未起飞` 班次走"改航 → 延误 → 关闭"三级，并在 `plan.stats` 里累计。

**③ 首页页脚改成读 `plan.stats`**（现在似乎是读实时全局统计），并且**必须与实时不同**。

**④ 气象情报卡片必须读案例帧**，不能写死"本帧无高影响天气"。

**⑤ 如果时间真的不够**（<4h），走**降级方案**：

在首页横幅加一行明确的边界声明：

> 本案例回放 **观测与判据**，**不重跑调度**；航班状态仍为实时推演。

并把页脚的"本轮处置"整块**隐藏**（而不是显示与实时相同的数字）。宁可少一块，不要留一块错的。

#### 为什么

"按前者处置"这句话是你们今天首页的核心主张。**如果处置没有发生，这句话就是假的。** 而这句话一旦被拆穿，整条"气象 → 决策"的叙事同时失效——那正是 25 分创新性 + 20 分 AI 应用的立论基础。

#### 怎么算改完（验收）

```bash
# 1) 雾天与实时的处置统计必须不同
diff <(curl -s "$BASE/api/traffic/v2/overview?case=fog-20250105" | jq '.stats') \
     <(curl -s "$BASE/api/traffic/v2/overview?scenario=live"     | jq '.stats')
# 必须有差异，且 fog 的 rerouted > 0

# 2) 禁飞走廊上的班次不得是"已到达"
curl -s "$BASE/api/traffic/v2/corridor/CAR-1-01-1-05?case=fog-20250105" | jq '.verdict'   # BAN
# 再到台账筛该走廊，状态只能出现 已关闭/改航/延误，不能出现 已到达
```

**界面断言**：雾天页脚的"改航绕飞"必须 **> 0**；"停止放行"必须 **≠ 123**。

### W-16 · 口径总账重写（3h）

#### 现在是什么

「口径与来源」是全系统的"定义源头"，但它自己有三处与实现不符：

| 行 | 字典写的 | 系统实际 |
|---|---|---|
| 插值不确定度 σ | `σ = 0.05 + 0.02 × 最近站距(km)` | **留一站交叉验证残差 RMS × (1+站距/120)，上限 0.15**（实测 0.0262） |
| 待处置走廊 | `不可飞概率 ≥ 50%` | 雾天模式实测 **40 条**，而同一页结论说概率 **31%**（不可能有 40 条过 50%） |
| 模型覆盖 | 分母"全部城际走廊" | 实际分母是**取到的 40 条**，不是 53 |

**这三行都是"字典说 A、系统做 B"。** 评委只要拿字典对一遍页面，就能得出"他们说一套做一套"——比任何技术缺陷都伤。

#### 改成什么

**逐行替换**（照抄即可）：

| 指标 | 定义 | 分子 | 分母 | 来源 |
|---|---|---|---|---|
| 待处置走廊 | **观测档或概率档任一达到"注意级"的城际走廊数** | 达到注意级及以上的走廊 | 全部城际走廊（当前 53 条） | `kpis[pending]` |
| 禁飞级走廊 | **观测档或概率档任一达到"禁飞级"的城际走廊数** | ≥禁飞级的走廊 | 全部城际走廊（当前 53 条） | `kpis[high]` |
| 模型覆盖 | 拿到概率输出的走廊占比 | 有概率的走廊（=53） | 全部城际走廊（=53） | `kpis[ai]` |
| 插值不确定度 σ | **σ = LOOCV 残差 RMS × (1 + 最近站距/120 km)，上限 0.15** | — | — | `_idw()` |
| 可飞性带段数 | 沿走廊每 5 km 一段 | 采样段数 | ⌈长度 ÷ 5⌉ | `corridors[].samples` |

**再加一条"定义与实现同源"的硬约束**：

> 这一页的每一个数字，都必须由接口直接给出；页面上**不允许出现任何手写常数**。
> 实现方式：`/api/traffic/v2/glossary` 返回 `[{key, definition, numerator, denominator, source, updatedAt}]`，页面只渲染，不硬编码。

**另一个必须删的句子**（它现在等于自曝）：

> 延期后的风险未重算（**本版本没有逐时概率**）

走廊剖面明明画着 0–6 h 逐时概率（`hourly[]` 7 个点）。这句话是假的，而且它堵死了"延误也是降险手段"这条最有力的结论（见 W-17）。

#### 为什么

**这一页是你们"诚实"人设的地基。** 地基上有一行错的，上面所有的"边界声明"都会被打折。

#### 怎么算改完（验收）

- 全站 grep：`（当前 40 条）`、`0.05 + 0.02`、`本版本没有逐时概率` 均应 **0 处**
- 页面上的 σ 显示值必须等于 `/v2/corridor/{id}` 返回的 `sigmaMean` 按同一公式格式化后的值（允许 ±1 位小数）

### W-17 · 反事实对照组重新定义（8h）— 本次最重要的一张

#### 现在是什么

雾天反事实页同时写着：

> **模型改判 0 架次**
>
> 关掉 AI：**3016** 架次暴露；开启 AI：**0** 架次

而且它的实现是：B 组在 `observed_ban` 时把 `DIRECT` 从可执行动作里移除。

**评委一句"那你 3016 是怎么救的"，答案只能是"我把'直接飞'这个选项删了"**——这跟 AI 无关。

#### 改成什么

**换对照，不换页面。** A 组要变成"低空运行的真实基线"，而不是"一个瞎了眼的规则引擎"。

| 组 | 现在的定义 | **改成** | 它代表 |
|---|---|---|---|
| A | 关掉 AI（规则全权，**且看不见观测**） | **现行做法**：只按**当前观测**处置，不做任何未来外推 | 值班员抬头看天 |
| B | 开启 AI | **本系统**：按**未来 0–6 h 逐时概率**提前处置 | 你们的贡献 |

**核心公式**（用你们已有的 `hourly[]`）：

```python
for flight in flights:                      # 每个班次
    arrive_t = flight.depart_t + flight.duration
    hours = [h for h in range(0, 7)
             if flight.depart_t <= h*60 <= arrive_t]     # 飞越期间覆盖的小时
    p_A = observed_ban(corridor, now)                     # A：只看此刻
    p_B = max(corridor.hourly[h].p for h in hours)        # B：看飞越期间最差
    exposure_A += p_A > 0
    exposure_B += p_B >= THRESHOLD
```

**关键改动：把"延误"当成一个真正可用的动作，并重算延误后的风险。**

```python
def decide(flight, corridor, now, cost):
    actions = []
    actions.append(("DIRECT", expected_loss(corridor.p_over(flight.window))))
    for d in (30, 60, 90):
        p_after = corridor.p_over(shift(flight.window, d))    # ← 用 hourly 重算
        actions.append((f"DELAY_{d}", cost.delay(d) + expected_loss(p_after)))
    actions.append(("REROUTE", cost.reroute + expected_loss(alternatives(flight))))
    actions.append(("CANCEL", cost.cancel))
    return min(actions, key=lambda a: a[1])
```

**② 0 米高度的两种情况，分开处理**

| 情况 | 处理 |
|---|---|
| 推演未启动（T+0 初始态） | 卡片状态写 **「待起飞 · 推演未推进」**，高度显示 `—`，不显示 `0 m`、不显示"飞行中" |
| 推演中 | 高度必须有值；若为空，显示 `—` 并标 `DATA_MISSING` |

```js
// 状态与数值必须自洽，加一层运行期断言
invariant(!(phase === 'CRUISE' && altM < 1), `班次 ${id} 状态为飞行中但高度 ${altM}m`);
```

同理：`地速 0 km/h` + `爬升` 不能同时出现。

**③ 空态页填到"有信息"**

| 页面 | 现在 | 改成 |
|---|---|---|
| 预警与处置（实时无天气） | 4 个卡片 + 空白 | 加一块 **「本窗口无气象成因事件」** + 三个可点的下钻：`查看 361 个排程冲突` / `切到雾天案例看处置` / `查看判据阈值` |
| 分歧台账（空） | "尚无裁决记录"×2 | 保留一句空态 + 显示 **「本会话可裁决的走廊 0 条；切到雾天案例有 21 条可裁决」** 并给跳转 |
| 运行日志（1 条） | 9 个刻度全 0 | 记录少于 10 条时，**隐藏时间轴**，只显示列表 |

#### 为什么

三处都是"评委第一眼就看到"的位置。0 米高度是**唯一一个会被当成"数据造假"的显示错误**（飞机悬在 0 米）。

#### 怎么算改完

- 投影模式：<16px 元素 = 0
- 全站 grep：`飞行中.*0 m AGL` 组合 = 0（用断言，不靠肉眼）
- 三个空态页在 1366 宽下，空白面积 ≤ 屏高 30%
