## 二、两条 P0

### F-1 路由「只写不读」—— 四个键名写错（已修）

复测报告定位了两个根因。**第二个根因不成立**：`applyHash()` 已经在读
`location.hash`，且 `onMounted` 里是「先 applyHash 再注册监听」（0.11.17 已修对）。
真正的原因只有一个是静态可证的：

```js
// 修前：SECTION_HASHES 里四个键与 SECTION_NAMES 对不上
intel / model / caliber / divergence
// 实际 section 名
briefing / card / reference / ledger
```

`sectionHash()` 是 `SECTION_HASHES[section] || home` —— **查不到就静默回落到首页**。

**实测对账**（负向验证）：

| | 旧表 | 新表 |
|---|---|---|
| 查不到的 section | briefing / reference / card / ledger | 无 |
| 不同 hash 数 | **9 / 13** | **13 / 13** |

报告写的「13 个页面只有 9 个不同 hash」被逐字复现。

判据 `frontend/tests/sectionHashes.test.mjs`（5 条）：13 个可导航页都有 hash、
hash 互不相同、每个 hash 都能读回同一个 section、**映射表里不许有 section 名以外的键**。

### F-11 路由读入口（**已修，根因是打包产物里的变量绑定**）

上一版我判「内容是对的，只有地址栏不对，P3 停」。**方向反了：地址栏对、内容是错的。**
原因是我用 `body.textContent` 判"走廊剖面在不在"，而页面用 `v-show` 切页 —— **所有 section 的 DOM 一直在**，
判据永远通过。换 `innerText` 立刻暴露（1544 字，与复测报告测的 1545 字逐字吻合）。

根因是一条链：源码写 `location.hash`，**产物里被编译成 `Me.hash`**，而 `Me` 在别的作用域是数组
（`let Me=[{key:'',label:'全部'}]`）⇒ `Me.hash` 恒 `undefined` ⇒

| 现象 | 机制 |
|---|---|
| 直达回首页 | `sectionFromHash(undefined)` → `'home'` |
| F5 回首页 | 同上 |
| 手动改 hash 无效 | 仍读 `Me.hash` |
| 未知 hash 不纠正 | `String(undefined\|\|'')` → `''`，被判成"空、正常" |

**四个现象一个原因。** 修法：全局对象写全 `window.location.hash`。
产物证据：`index-CVpcEAuL.js`（坏，`Me.hash` 5 次）→ `index-CPcL_Dsq.js`（好，`window.location.hash` 7 次、裸的 0 次）。

⚠️ **上一版为什么"改了没生效"**：源码改对了，但**没有重新构建前端**（只部署了 jar）。
新工序：**改完前端必须 grep 产物确认那段代码在**，不能只看源码。

实测（干净 profile、无 `?ws`、等足建场）：直达 / 刷新 / 站内点击 三种入口均落 `corridor-*`，
`#/nope` → 地址栏纠正为 `#/situation/home`。**4/4 PASS。**

## 八、全量复扫（2026-10-25，**不升版本号**，补丁随 0.11.18 发布）

按「全局检查前后端 + 特别查探针/不显示异常的报错/漏洞」的要求，扫了 6 个维度。

| 维度 | 怎么查 | 结果 |
|---|---|---|
| **后端静默失败** | 扫所有 `except` 中「既不打日志又返回兜底值」的块 | 仅 **1 处**：`weather/om_forecast.py` 网络失败静默 `return None` → **已补 `logger.warning`**（不改返回值，调用方对 `None` 的处理是对的） |
| **假探针** | 逐个读 `/health`、`/traffic/health` 的三个 check 实现 | **无假探针**（planStore 真数文件、llm 真读 `LAST_CALL`）。但 `_check_weather` **恒 `ok: True`** —— 「没人用」和「取不到」都表现为 0 帧，无法区分 → **已加 `judgesWeather: false` + detail**，明说它不判定气象健康 |
| **写端点权限** | 14 个 POST 逐个查 `_require` | **无漏洞**。`operations/disposal` 刻意只要求身份（注释写明"这一层是可追溯不是鉴权"）；`weather/mode` **有** `_require`（按方向分：进虚拟要 admin、回实测放开）——我的首轮 8 行检测窗口漏看了它 |
| **参数校验（注入/资源）** | `fields` / `seed` / `minute` / `bufferM` / `regionId` | `fields: Query('slim', pattern='^(slim|full)$')` —— **实测乱传 `fields=xyz` 返回 422**，不存在"任意值触发 24 MB 投影"的路径 |
| **页面静默异常** | **新写探针** `_probe_silent_undefined.py`：13 页 × 2 种模式（实时 / 雾案例），扫可见文本里的 `undefined` / `NaN` / `[object Object]` | **26 页全干净**（这是 N-2「1010 行 undefined」那类问题的通用网） |
| **前端吞错 / 定时器** | 扫空 `catch`、`setInterval` 与 `clearInterval` 配对 | 仅 2 处 `localStorage.setItem` 空 catch（隐私模式下必须吞，合理）；5 个 `setInterval` **全部在 `onUnmounted` / `onBeforeUnmount` 清理** |

**结论：未发现需要修的缺陷。** 本轮只做了两处「静默 → 可见」的可观测性补强，外加一个新探针。
按用户要求**不改版本号**，补丁随 `0.11.18-beta` 一起发布（`py-scanfix.tar.gz`）。
