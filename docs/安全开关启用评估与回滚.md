## 0. 一句话

应用自己是 `security.enabled=false`（`anyRequest().permitAll()`）。
**2026-10-14 起 nginx 会话门已被拆除**（用户要求「删掉登录界面，不用登录直接进界面」），
于是**当前不存在任何信任边界**：拿到站点链接的人即可调用全部写接口。

> 🔴 **登录门拆除对本文件的影响（先读这个框，再读下面任何一节）**
>
> **作废清单**（这些句子描述的是拆门前的世界）：
>
> | 位置 | 原表述 | 现状 |
> |---|---|---|
> | 本节旧句 | 「唯一信任边界是 nginx 会话门 / 拿到 `aic_session` 就拿到全部写权限」 | 那条门不存在了；现在是**没有**边界 |
> | §2.2 | `LoginOverlay.vue` 调 `POST /api/auth/login` | 该组件**已从仓库删除** |
> | §2.3 | 「无 `aic_session` 时先返 **302 → /login**」 | 不再 302，直接放行 |
> | §2.4-④ | `LoginOverlay` 因此永不出现 | 没有登录浮层了 |
> | §2.5 | 「nginx 层：会话门、登录页……照旧」 | 这两样都没有了 |
> | §3-A | `--user <账号>:<口令> https://$H/sz-auth` | `/sz-auth` 已删除，无标的 |
> | §5 | 两层表（nginx 会话门 + Java 角色） | **只剩 Java 那一层**，另加下面两道新防线 |
>
> **取代它的两道防线（重要：这不是"更安全了"）**
>
> ① nginx `limit_req`（**已上线**）：只覆盖点名的端点，每源 IP 20 r/m，超出返回 429；
> ② **按工作区每日配额 —— 尚未实现**（原计划的工作项）。在它落地之前，
> 公网任何人对 `POST /api/agent/ask`（**烧 DeepSeek 额度**）与
> `POST /api/monitor/run-now`（**改写系统状态**）只有限速这一道软约束。
>
> **对「要不要开 `security.enabled`」的重新定位**：开关机制没变，但它要求调用方持有
> **Java 侧的登录态与角色**；而 Java 侧的登录入口要由前端登录界面发起 —— **那个界面已经删了**。
> ⇒ **在当前形态下直接打开它，会让前端全部写操作变成 401/403，且没有任何界面可以登录。**
> ⇒ 前置条件已从「先建账号」变成「**先决定是否恢复某种登录形态**」。
>
> 因此：**不要按 §6 的顺序直接执行**。§1 与 §4 作为机制说明与回滚手册仍然成立。

## 1. 开关的机制与前提（先读这一节，否则会踩硬失败）

### 1.1 现状（实测，2026-10-14）

| 项 | 值 | 出处 |
|---|---|---|
| 生效配置 | `security.enabled: false`（**字面量**，不是 `${...}` 占位符） | 服务器 `/opt/apps/AIC-tianchuang/config/application.yml` 第 77–85 行 |
| 账号键 | `viewer-user` / `viewer-password` / `operator-*` / `admin-*` **六个全为空串** | 同上第 80–85 行 |
| `.env` 里的 SECURITY/账号键 | **一条都没有** | `grep -nE 'SECURITY\|VIEWER\|OPERATOR\|ADMIN' .env .env.secrets` → 空 |
| 互斥链 | `permitAllChain` 生效（`havingValue="false", matchIfMissing=true`） | `backend-java/.../config/SecurityConfig.java:33-39` |

### 1.2 怎么开：**改环境变量，不改 yml**

Spring Boot 的属性优先级里 **OS 环境变量 > 配置数据文件**，且支持 relaxed binding：

```
SECURITY_ENABLED  →  security.enabled
SECURITY_VIEWER_USER → security.viewer-user
```

systemd 的两个单元本来就 `EnvironmentFile=` 了 `.env`（并可选加载 `.env.secrets`），
所以只要往里面写 `KEY=VALUE` 就生效，**零代码改动、不改 yml、不用重新构建 JAR**。

### 1.3 ⚠️ 三条硬前提

1. **必须先有账号再打开关。** `SecurityConfig.userDetailsService()` 在
   `enabled=true && allow-demo-user=false && 账号列表为空` 时
   **抛 `IllegalStateException` → 应用启动失败**（`SecurityConfig.java:92-94`）。
   这是**硬失败**（好事：不是静默降级），但排查时会先看到"服务起不来"。
   ⇒ 顺序：**写账号 → 再打开关 → 再重启**。
2. **`.env` 会被重装覆盖，`.env.secrets` 不会。** `install-remote.sh` 用仓库模板
   **整体覆盖** `.env`。把开关放 `.env` ⇒ 下次重装被**静默抹回 false**（方向安全，
   且 nginx 会话门仍在，但那是"配置自己变回去了"，正是本项目最不愿意出现的一类错）。
   ⇒ 本方案的开关与账号**一起放 `.env.secrets`**（600，不被覆盖），
   并用 `verify-remote.sh` 的 J 项持续守住权限。
3. **别用固定演示账号。** `viewer/viewer-demo` 只在本机演示（`security.enabled=false`）下存在；
   打开关时必须 `SECURITY_ALLOW_DEMO_USER=false` 并配真实账号。

### 1.4 开关打开后，Java 侧链的样子

```java
// SecurityConfig.securedChain —— 按声明顺序求值，**首个命中生效**
.requestMatchers("/", "/index.html", "/assets/**", "/favicon.ico",
                 "/api/health/**", "/api/auth/**", "/actuator/health/**").permitAll()
.requestMatchers(HttpMethod.GET,  "/api/internal/qweather/**").permitAll()   // 控制器内自限回环
.requestMatchers(HttpMethod.GET,  "/api/**").hasAnyRole("VIEWER","OPERATOR","ADMIN")
.requestMatchers("/ws/**").authenticated()
.requestMatchers(HttpMethod.POST, "/api/monitor/**", "/api/sim/**").hasAnyRole("OPERATOR","ADMIN")
.requestMatchers(HttpMethod.POST, "/api/**").hasRole("ADMIN")                 // ← 写操作的兜底
.anyRequest().denyAll()
```
CSRF：**从关闭变开启**（`CookieCsrfTokenRepository.withHttpOnlyFalse()`），仅 `/api/auth/login` 豁免。
未登录 → `401 {"code":"AUTH_REQUIRED","message":"请先登录","retryable":false}`；
角色不足 → `403 {"code":"ACCESS_DENIED","message":"当前账号无权执行该操作","retryable":false}`。

### 2.3 「会从 200 变 401/403」的完整清单

- **401（未登录 / 会话失效）**：开启后所有 `/api/**`（除 1.4 里 permitAll 的那几类）与 `/ws/**`。
  *但在浏览器里你通常看不到 401* —— nginx 会话门在更外层，无 `aic_session` 时先返 **302 → /login**。
  401 只在「有 nginx 会话、但 Java 侧没登录态」时出现（例如重开后 Java 内存态丢失、或直接打 28082）。
- **403（角色不足）**：§2.2 里标 ❌ 的 6 个写动作，非 ADMIN 账号。
- **不变的 200**：所有 GET 读接口、`/api/health/**`、`/api/auth/**`、`/healthz`、静态资源。

### 2.4 四个意外发现（做清单时才挖出来的）

① **`/api/sim/**` 是死路径。** 全仓 grep：该前缀**只**出现在 `SecurityConfig.java:56` 与旧文档/旧报告里，
   当前**没有任何控制器映射它**（现行对应物是 `POST /api/scenario/switch`，且前端不调用）。
   ⇒ 那条 `hasAnyRole("OPERATOR","ADMIN")` 规则**目前没有标的**。
   ⇒ 验收时若按"非授权角色调 `/api/sim/**` 应被拒"，实测会得到 **404**（路径不存在），
   **不是 403** —— 一条 404 无法证明"鉴权生效"。真正能证明的判据见 §3-B。

② **`operator` 档在当前前端上等于 `viewer`。** OPERATOR 只解锁
   `POST /api/monitor/**` 与（死掉的）`/api/sim/**`，两者前端都没有入口。
   ⇒ 真要三档，得**改规则**（例：把 `/api/traffic/operations/**` 降到 OPERATOR），
   或**给前端加角色隐藏**。现状下**只应发 ADMIN 账号**（可选再发一个只读 VIEWER 用于演示）。

③ **前端没有按角色隐藏控件。** 全仓 grep 无 `role` / `permission` 判断。
   ⇒ 非 ADMIN 登录后按钮**照样显示**，点了才 403 弹错。这是"看得见但用不了"，
   与项目一贯的「有内容 ≠ 够得着」是同一条纪律的反面。

④ **`/api/auth/status` 的语义会变。** `enabled=false` 时它**恒**返回 `authenticated=true`
   （`AuthController.status()` 第 36-37 行的短路），前端的 `LoginOverlay` 因此永不出现；
   开启后才是真值。⇒ **前端无需改动**（`api.js:169` 已经按 `!auth.enabled || auth.authenticated` 分支），
   但这也是一个"开关一开，界面行为跟着变"的点，验收时要在浏览器里真的看一眼。

⑤ **CSRF 前提已成立（这条是"不做会全 403"的坑）。** 开启后 CSRF 生效，
   所有非 GET 必须回送 `X-XSRF-TOKEN`。已核实：`frontend/src/api.js:30-33` 会从
   `XSRF-TOKEN` Cookie 取值并加头；`AuthController.status()` 会主动 `csrf.getToken()`
   把该 Cookie 逼出来（否则首次 POST 必然 403，且看起来像"权限配错了"）。

### 2.5 明确**不受影响**的

- nginx 层：会话门、登录页、`/healthz`、gzip、`limit_req`、WebSocket 透传 —— 全部照旧。
- 巡检/冒烟探针：走 `/healthz`（nginx 自带）与 `/api/health/**`（permitAll），**不受影响**。
- Python 侧（28083）：只被 Java 内网调用，且 `/api/internal/qweather/**` 仍 permitAll。

## 3. ② 验收清单（每条都写「红了会长什么样」）

> 约定：`H=tianchuang.shuanzi.site`。所有判据**只认状态码/字段值，不认命令退出码**。

**A. 前端主流程可用（2026-10-14 拆门后：**无 Cookie、无口令**）**
```
curl -s -o /dev/null -w '%{http_code}\n' https://$H/                                       # 期望 200（拆门前是 302 → /login）
curl -s https://$H/api/dashboard | head -c 120                                             # 期望 JSON，非 {"code":"AUTH_REQUIRED"}
curl -s https://$H/api/health/ready                                                        # 期望 READY
```
> ⚠️ 一旦开启 `security.enabled`，这三条会**同时变红**：`/` 仍可能是 200（静态资源由 nginx
> 直接给），但 `/api/dashboard` 变 401 —— 而**前端已经没有登录界面**，用户无法自救。
> 这正是 §0 警告框说的事：拆门之后，这个开关不再是一个"随时可以打开"的开关。
浏览器侧：进站看到大屏、地图有数据、WebSocket 显示已连接、**不出现登录遮罩**。
*红了长什么样*：大屏永远停在「正在提交调度请求」+ 控制台一串 401 → 说明 Java 侧没登录态
（多半是只做了 nginx 会话、没做 `/api/auth/login`）。

**B. 非授权角色调写接口被拒**（**不要用 `/api/sim/**`，它 404**）
```
# 用 VIEWER 账号登录 Java 拿 JSESSIONID/CSRF，再打一个**存在**的写端点：
curl -s -w ' [%{http_code}]\n' -X POST -H 'Content-Type: application/json' \
     -H "X-XSRF-TOKEN: $XSRF" -b jar.txt --data '{}' \
     https://$H/api/traffic/command                                        # 期望 403 ACCESS_DENIED
# 反向自证（同一请求、ADMIN 账号）：期望 400/200（业务校验），**不是 403**
```
*红了长什么样*：VIEWER 拿到 200 ⇒ 鉴权没生效（比报错更糟）；ADMIN 也拿到 403 ⇒ 角色名或 CSRF 配错。

**C. `/healthz` 与 `/api/health` 仍免鉴权、探针不受影响**
```
curl -s -o /dev/null -w '%{http_code}\n' https://$H/healthz            # 期望 200（无 Cookie）
curl -s -o /dev/null -w '%{http_code}\n' https://$H/api/health/live   # 期望 200（无 Cookie）
```
*红了长什么样*：变 302 → 前端会被踢去登录页，巡检脚本会全线报红（**这是最容易误判成"服务挂了"的一条**）。

**D. 控制台/管理功能仍可用**（ADMIN 账号，浏览器）
确认处置、执行处置、记笔记/导出回执、气象口径切换、查证并研判 —— 五个动作各点一次，都要成功。
*红了长什么样*：按钮点了弹「当前账号无权执行该操作」 ⇒ 规则把写操作收得比预期更紧。

**E. 未登录一律进不了**
```
curl -s -o /dev/null -w '%{http_code}\n' https://$H/api/dashboard      # 期望 302（nginx 会话门）
curl -s -o /dev/null -w '%{http_code}\n' https://$H/ws/                # 期望 302
```

**F. 401/403 的形状（供前端与脚本识别）**
```
401 → {"code":"AUTH_REQUIRED","message":"请先登录","retryable":false}
403 → {"code":"ACCESS_DENIED","message":"当前账号无权执行该操作","retryable":false}
```

**G. 回滚验收**：执行 §4 的 `off` 之后，**A/B 里的读接口立即恢复 200，写接口不再 403**
（用一个非 ADMIN 账号重打 §3-B 的那条命令，期望不再是 403）。

## 4. ③ 一键回滚

**脚本**：`.run/cloud/security-toggle-remote.sh`（在服务器上执行；本地位于 `.run/cloud/`）

```bash
# 只读现状（不重启、不改任何文件）
ssh -i ~/.ssh/hongsight.pem ubuntu@62.234.154.34 'bash -s' -- status < .run/cloud/security-toggle-remote.sh

# 生成三档账号（自动生成强口令，写到 /root/.AIC-tianchuang-app-accounts.txt 600，只回显长度与摘要）
... -- init

# 打开关（先校验账号齐备 → 备份 .env.secrets → 写 SECURITY_ENABLED=true → restart → 等就绪 → 自检）
... -- on

# 一键回滚
... -- off
```

**回滚耗时**：`restart` 约 **8–15 s**（Java 常驻 ~10 s 到 `/api/health/live` 200）。
**回滚后**：Java 立刻回到 `permitAllChain`（全放行），前端无需任何操作即可继续用
（nginx 会话门仍在，所以公网侧**不会**变成裸奔）。

**失败分支（脚本设计）**

| 情况 | 脚本行为 |
|---|---|
| `on` 时账号不齐 | **拒绝执行**并提示先跑 `-- init`（避免 IllegatateStateException 起不来） |
| `restart` 后 30 s 内 `/api/health/live` 不是 200 | **自动回滚**（`SECURITY_ENABLED=false` + restart）并退出码 2 |
| 回滚后仍不 200 | 打印 `journalctl -u AIC-tianchuang -n 60` 的尾部提示，退出码 3 |
| `.env.secrets` 不存在 | 先创建（600 ubuntu:ubuntu），再写 |
| 任何写操作前 | `cp -a .env.secrets .env.secrets.bak-<ts>`（幂等可回退） |

**判据**：`status` 子命令要能**自证**当前生效值 —— 不能只读 `.env.secrets`（那是"我写的"），
要读**进程实际环境**或 Java 的 `/api/auth/status` 的 `enabled` 字段（那是"它认的"）。
