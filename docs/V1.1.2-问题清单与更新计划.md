# V1.1.2 问题清单与更新计划

编制时间：2026-11-14 17:30｜基线：`cb20f7a`（VERSION 1.1.1）
范围：全国四级（态势 / 气象监测 / 走廊 / 推演 / 台账 / 日志 / 口径）中"同一结论多处显示"的口径不一致问题。
原则：本轮**不改阈值、不改算法、不动 2640→0 与 0.1% 这套结论**；只让同一件事在全站只有一个来源。

---

## 一、归因：不是一个 bug，是四类结构问题

用户 2026-11-14 报的两处（推演页右上角恒写"直飞放行"、判据 4/4 通过却标"暂不放行"），追下去不是孤例。全站扫描后，同类问题归为四类：

| 类别 | 定义 | 后果 | 已确认处数 |
| --- | --- | --- | --- |
| A. 同结论双路径 | 同一裁决由两个接口各算一次，其中一个少传输入 | 两处数字打架，且错的一侧看不出错 | 4 处 |
| B. 阈值前端复制 | 后端常量的值被抄进前端做分组、筛选、文案 | 后端调阈值，前端不跟随 | 5 处 |
| C. 快照与实时并置 | 一个面板冻结在"选中那一刻"，另一个跟着时钟走 | 屏幕内自相矛盾，且未标时基 | 2 处 |
| D. 状态徽标与实际行为不符 | 界面宣称"已完成/已就绪"，实际未执行 | 与"雷达槽未取得"同类，属于**说法错**而非数字错 | 2 处 |

A 类是本次报告的主因；B、C、D 三类是同一毛病的不同表现：**界面上的一个词，背后没有唯一的来源**。

## 二、P0（影响结论正确性，必须随 1.1.2 修完）

### P0-1　取证链路少传三个输入，裁决系统性偏松

- 位置：`backend-python/traffic/nation.py:1397`
- 现状：`flight_objects([corridor], minute, table, weather)` 只传 4 个参数；
  列表侧 `nation.py:998` 与整页载荷 `nation.py:1072` 都传了 `_model_probs()` 与 `blocked_ids`。
- 缺的三个输入及后果：
  1. `model_probs` → `pModel=None` → `nation_ops.py:118` 的 `p_model >= MODEL_HOLD(0.60)` 门槛失效；
  2. `blocked_ids` → `nation_ops.py:218` 的"航路压强回波且无小绕"封禁失效；
  3. 接口 `evidence(flight_id, minute)` 无 `virtual` 形参 → 虚拟气象演示时取证仍按实况重算。
- 实测（云端，2026-11-14）：虚拟模式下 `NC-0169#0` 列表为"绕飞放行"，取证返回 `RELEASE / 直飞放行`；
  `NC-0193#-1` 列表为"停飞（无可用绕飞方案）"，取证同样返回 `RELEASE`。
- 修法：三处 `flight_objects` 调用统一走一个包装函数（见 P0-2），`evidence()` 增加 `virtual` 形参并透传。
- 验收：对同一 `(flightId, minute, virtual)`，取证的 `decision`/`decisionLabel` 必须与列表逐字段相等；
  构造 `pModel≥0.60`、命中 `blocked_ids`、`virtual=1` 三种样本各一条断言。

### P0-2　推演板与列表各读一套裁决

- 位置：`frontend/src/components/traffic/NationDeduce.vue:27`（板头标签）、`:105`（第 3 段"裁决"）
- 现状：两处都读 `data.flight.decisionLabel`（取证接口），而左侧列表 `CorridorBrowser.vue:134/150`
  读的是 `/nation/flights`（列表接口）。P0-1 未修时，两侧必然分叉；修了 P0-1 也只是"碰巧相等"。
- 修法：裁决类字段（`decision`、`decisionLabel`、`riskLevel`、`riskP`）**只认 `props.flight`**（列表侧）；
  `data` 仅提供证据细节（观测、判据、期望损失、结论句）。若 `data.flight.decision !== props.flight.decision`，
  界面显式标"取证快照与当前帧不一致"，而不是静默取一边。
- 验收：新增测试——把两侧 decision 人为设成不同值，板头必须显示 `props.flight` 的值并出现不一致提示。

### P0-3　判据少一条"模型低能见概率"，于是"4/4 通过"与"暂不放行"同时成立

- 位置：`backend-python/traffic/nation.py:1516`（`if flight.get('pModel') is not None` 条件追加）
- 现状：P0-1 使 `pModel` 为 `None`，第 5 条判据根本不生成，页脚如实写"4/4 通过"；
  而列表侧 HOLD 恰恰来自模型门槛（`MODEL_HOLD=0.60`）。用户看到的"明明可飞却停飞"即此。
- 修法：判据列表固定五行，模型概率取不到时也要出现，标 `ABSENT` 并注明"本帧未取到模型概率，该条不参与裁决"——
  与回波缺失（`nation.py:1504`）的处理保持一致。
- 验收：`criteria.length >= 4` 且当 `pModel != null` 时必含 `key='pmodel'`；`pModel` 缺失时该行 `source='ABSENT'`。

### P0-4　虚拟气象只覆盖两个接口，其余页面各说各话

- 位置：`main.py:497`、`main.py:510` 支持 `virtual`；`evidence`、`zones`、`pulse`、`counterfactual` 均无
- 现状与影响：
  - `NationBriefing.vue:59`（调度台账自取）`?level=nation&minute=…`，**无 virtual**，且 `level` 写死全国；
  - `NationPanel.vue:226`（取证）无 virtual；
  - 结果：开"虚拟气象"后，首页显示大面积停飞，台账与取证仍按实况，一屏两套数。
- 修法：把 `virtual` 与 `level/id` 提为"所有取数入口的公共参数"，由前端统一注入（一处封装），
  后端各接口统一声明；未支持的接口显式返回 `virtualUnsupported: true`，前端据此在页脚标注"本页不随虚拟气象变化"。
- 验收：虚拟模式下 `/nation`、`/nation/flights`、`/nation/evidence`、台账自取四处的 `hold` 计数相等；
  不支持的页面必须出现显式提示，不得静默使用实况。

### P0-5　"反事实/对照"跑在旧会话引擎上，与全国层同名不同源

- 位置：`frontend/src/components/traffic/CounterfactualPanel.vue:95`
  （`/api/traffic/v2/counterfactual?seed=42&scenario=live&policy=…`）
- 现状：该接口的服务端实现属旧轨（`traffic/v2.py` 会话/走廊引擎），数据来自初赛三站口径与案例重放；
  而推演第 4 段"反事实"读的是全国取证载荷。两个都叫"反事实"，一个 7336/7760 案例口径，一个 106 架在飞单帧口径。
- 修法（二选一，建议 a）：
  a. 页面顶部固定标注"数据来源：案例重放（2025-01-05 沈阳大雾 / 7760 班），与首页全国帧不是同一套"，
     并在页脚给出与全国口径的换算关系说明；
  b. 把该页改为全国口径（工作量大，且会与文档第 5 章的案例叙述冲突）。
- 验收：页面上同时可见"来源"与"时间基准"两行；文档 5.2 的两套口径声明与页面一致。

## 三、P1（影响可读性与可维护性，1.1.2 一并处理）

### P1-1　"直飞放行"兜底：缺字段时默认成最松的结论

- 位置：`CorridorBrowser.vue:206`（`r.decisionLabel || (r.hold ? '延期' : '直飞放行')`）、
  `CorridorBrowser.vue:243`（人工裁决把 `auto` 记成同样的兜底值）
- 风险：缺字段时静默显示"直飞放行"，且 `auto` 会作为"算法原判"写进本地裁决记录与日志——
  错的不是显示，是**留痕**。
- 修法：兜底值改为"未判定"（`UNKNOWN`），并在日志里写"算法原判缺失"，不猜。

### P1-2　推演板是"选中那一刻"的快照，播放中不重算且不标时基

- 位置：`NationDeduce.vue:220-258`（`key()` 在播放时固定为 `id|run`）；板头无分钟标注
- 现状：时钟在走、列表在更新，板子停在选中时那一分钟；用户会读成"同一时刻两种结论"。
- 修法：板头加"结论取 T+xx 分（快照）"；播放跨越阈值时给"已与当前帧不一致，点此重算"的入口。

### P1-3　同一段里依据与裁决混源

- 位置：`NationDeduce.vue:105`（裁决取 `data`）、`:106`（依据取 `props.flight.drivers`）
- 现状：可能出现"裁决：直飞放行"下面列着"模型低能见度概率 62%"。
- 修法：随 P0-2 一起统一取 `props.flight`；`data` 只提供证据行的数值与出处。

### P1-4　阈值在前端复制了五处

| 位置 | 复制值 | 对应后端常量 |
| --- | --- | --- |
| `CorridorBrowser.vue:173` | `riskP >= 0.35` | `RISK_WATCH` |
| `NationBriefing.vue:138/186` | `pModel >= 0.35` | `MODEL_WATCH` |
| `NationPanel.vue:689` | `0.15 / 0.35 / 0.60` 三档 | 0.15 **后端没有这个值**，属自造 |
| `runtime.js:1935/1960` | 文本写死 0.75 / 0.60 / 0.35 | `RISK_HOLD` / `MODEL_HOLD` / `MODEL_WATCH` |
| `NationDeduce.vue:147` | 代价系数 0.6/小时 | `W_HOUR` |

- 修法：新增 `/api/traffic/v2/constants` 一次性下发阈值与代价系数，前端启动时取一次并缓存；
  所有分组、筛选、文案、图例读同一份。`NationPanel:689` 的 0.15 需先确定语义（是否并入 `MODEL_WATCH`）再落。
- 验收：新增守卫测试——前端源码不得再出现裸的 `0.75`/`0.60`/`0.35` 常量（白名单除外）。

### P1-5　"大模型取证"页只有一个"就绪"徽标，没有调用模型

- 位置：`NationPanel.vue:1206`（`大模型就绪 · deepseek-chat`）；该页数据来自 `/nation/evidence`，
  服务端只回 `llm.configured/status`，**不产生任何模型输出**
- 现状：真实的 AI 输出只出现在两处——走廊页"生成一句解读"（`CorridorPanel.vue:44` → `/v2/explain`）
  与旧会话取证（`OperationsConsole.vue:228` → `/traffic/explain`）。报告与 PPT 宣称的"证据检索 + 结论成句"，
  在新界面里**不可见**。
- 修法：在取证页把"证据检索"与"结论成句"接上（复用 `/v2/explain` 的数字守卫与降级逻辑，按班次改造），
  并把四种结局（采用/否决/不可用/未配置）显示在同一屏；做不到就在徽标上写"仅状态，未调用"。
- 说明：这一条与 D 类同源——**不要用一个"就绪"的徽标替代"已经跑了"的证据**。

### P1-6　调度台账写死全国，切层级不跟随

- 位置：`NationBriefing.vue:59`（`level=nation` 固定）
- 现状：从首页下钻到沈阳市，再点"调度台账"，页面仍是全国 106 架；面包屑与数据不一致。
- 修法：台账自取改为跟随 `store.scope`，与 `/nation` 同一组 `level/id/virtual` 参数。

## 四、P2（记录在案，1.1.2 可只做说明不做改造）

### P2-1　网关 30 秒读超时短于冷启动重建

- 现象：2026-11-14 17:07–17:10，公网 `GET /api/traffic/v2/nation?level=nation&minute=60` 连续三次
  在 **30.2 s** 返回 500；Java 日志 `java.net.http.HttpTimeoutException: request timed out`；
  同一时刻直连 Python `127.0.0.1:28083` 同一路径 **0.1 s** 返回 568 KB。
- 影响：冷启动后第一条请求稳定失败一次，前端 90 s 超时救不回来（超时发生在网关）。
- 修法：网关读超时抬到 90 s 与前端对齐，或首次请求走"预热 + 202 + 轮询"。**本轮只记录，不扩面。**

### P2-2　走廊行与班次是 1:N 的兜底

- 位置：`CorridorBrowser.vue:123`（`byCorr.set(f.corridor, f)`，后者覆盖前者）
- 现状：当前 106 架 / 106 走廊，恰好 1:1，不会触发；一旦调整 `headway` 参数，同一走廊同刻两班时，
  列表会取"最后一架"而非"最差一架"，标签随之漂移。
- 修法：按严重度取最差（`HOLD > DETOUR > RELEASE`），并在行内标"该走廊 N 架在飞"。

### P2-3　日志页两本账

- 位置：`OperationsConsole.vue:275-292`
- 现状：有 `sessionId` 时优先读旧会话账，否则读 `/nation/journal`。全国模式下无会话，行为正确；
  但案例模式下会出现"首页全国口径、日志案例口径"。
- 修法：页头标注"本页读数来自案例会话（初赛口径）"，不做数据合并。

## 六、可自动化的验收判据（1.1.2 必须新增）

1. `evidence` 与 `flights` 同参同结果：`decision`、`decisionLabel`、`riskLevel`、`riskP` 四项逐字段相等（含 `pModel≥0.60`、`blocked_ids`、`virtual=1` 三种构造）。
2. `criteria` 固定五行，缺模型概率时出现 `ABSENT` 行，且页脚不再出现"4/4 通过"这种与裁决矛盾的计数。
3. 虚拟模式下四处 `hold` 计数一致：`/nation`、`/nation/flights`、`/nation/evidence`、台账自取。
4. 兜底值守卫：`decisionLabel` 缺失时返回"未判定"，源码中不得再出现 `|| '直飞放行'`。
5. 阈值守卫：前端源码不得出现裸 `0.75`/`0.60`/`0.35`（白名单：图表刻度、样式）。
6. 一致性提示：两侧 decision 不等时，界面必须出现"取证快照与当前帧不一致"。
