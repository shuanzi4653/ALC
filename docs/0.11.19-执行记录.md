## 二、W-1 是怎么修的（方案低估的那一层）

方案写「复用天气端点里已有的取帧函数」。核实后的实情是：

- `history` 7 行 = 基准**前** 6 小时，末行 `00:00Z`（= minute 0）
- `frames` 7 帧 = 基准**后** 6 小时，`00:00Z ~ 06:00Z`
- `corridor()` 取的是 `history[-1]` ⇒ **恒 00:00Z**，所以 minute 怎么传都不动

所以改的不是"加一个参数"，是**观测取数的入口**：

1. `cases.frame_at_minute(case_id, minute)` —— 取该时刻**最近**的逐时帧（不插值：插出来的中间值没有对应报文，进判据就是"这个数没有出处"）
2. `_histories_at_minute()` —— 把帧观测**替换进 history 末行**，前 6 行留着当 past（只换末行 = "历史照旧，但此刻的实测是这一帧"；整段换掉会让 past 也变成未来）
3. **`epoch` / `timeUtc` 必须一起换** —— `vector_for()` 读 `row['epoch']` 取小时正弦，只换 visM 不换时间戳，特征里的小时还是旧时刻的
4. `field()` / `corridors()` / `corridor()` / `overview()` 全部透传 `minute`
5. **`_case_field_cache` 的键加上 minute 这一维** —— 只按 `case_id` 存会静默让两个时刻共享同一份观测（M10 那个坑的同一种形态）

前端：`CorridorPanel` / `SituationBrief` 各加 `minute` prop + 300 ms 防抖重取（拖滑块会连发几十次，后端建场槽位只有 2 个）。

## 三、本轮我自己引入并修掉的一个 500

**W-5 改完后 `GET /v2/overview?scenario=live`（不带 case）返回 500。**

```
UnboundLocalError: cannot access local variable '_window' where it is not associated with a value
```

原因：我把 `_window = _window_phrase(...)` 插在了「有 case」那个分支里，而 `scenario=live` 走另一个分支 ⇒ 变量未定义。

**抓到它的是 8 页扫描**：它报告 `API 2x /v2/overview` 是 4xx/5xx。修法是把这行提到 `items` 之后**无条件**计算（`_window_phrase(None, ...)` 本来就返回「未来 3 小时内」，实时通道就是未来 3 小时）。

修完三种情况全 200：`scenario=live` / `case=…&scenario=live` / `case=…&minute=360`。

> 这条值得记一笔：**改文案看起来最安全，但"变量在哪个分支里定义"是它唯一会炸的地方**。而 8 页扫描（只看 4xx/5xx）正好能抓。

## 五、两处需要知道的取舍

1. **反事实（`counterfactual`）也加了 `minute` 参数，但前端暂不传** —— 它比较的是"裁决规则"，固定基准帧才可比；答辩的数字（2613→0、改判 3044）不受影响。接口支持以后要传。
2. **`minute=480` 时夹到 06:00Z** —— 案例 `frames` 只到 06:00，480 分钟没有对应帧。所以 W-3 把滑块上限收到 360（实时通道仍是 480）。返回值里带 `frameLagMinutes`，以后要显示"最近帧相差多久"可以直接用。
