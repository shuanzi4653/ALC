## 1. G-1（P0，3h）：雾天案例页把雾画出来

### 1.1 现在是什么样

- 接口已经诚实：`lowVisibility.included = false`，`reason: CASE_OBSERVATION_ONLY`，并明确写「图上按站点画的是**影响范围示意**」
- 接口同时给了 4 条可直接画的站：`stationVisibility[]`，每条有 `lat` / `lon` / `visM` / `visLevel`
- 前端只读了 `lowVisibility.regions`（空数组），所以**什么都没画**
- 实测：开关「低能见度（雾）」图层，地图区像素变化 **60 px**（等于没画）

### 1.2 改成什么

**目标：案例模式下，在地图上画 4 个"影响范围示意圆"，半径和颜色由能见度决定，并明确标注这是示意不是边界。**

#### 规则表（照抄实现）

| `visLevel` | 能见度 | 圆半径 | 填充 / 描边 | 图例语义 |
|---|---|---|---|---|
| `BAN` | < 1000 m | **40 km** | 填充 `rgba(120,60,160,0.28)`，描边 `#8b5cf6` 1.5px 实线 | 「禁飞级低能见度（示意）」 |
| `CAUTION` | 1000–5000 m | **24 km** | 填充 `rgba(120,60,160,0.14)`，描边 `#8b5cf6` 1px **虚线** | 「需注意低能见度（示意）」 |
| 其他 | ≥ 5000 m | 不画 | — | — |

#### 圆心标注

每个圆中心加一个点 + 两行小字：

```
ZYTX · 沈阳
998 m · 禁飞级（示意）
```

字号 10px，颜色 `#e9d5ff`，点半径 3px。

#### 措辞（必须原样出现在图层说明里）

> 「按 4 个机场站的实测能见度画的影响范围示意，半径 40 / 24 km 是声明常量，**不是实测雾区边界**。本案例无城市格点场，因此不产出雾区面。」

#### 关键约束

1. **只在案例模式（`case` 存在）下走这条路。** 实时模式仍然读 `lowVisibility.regions`（那是真的面），不要混。
2. **不要动 `included:false` 的语义。** 后端说"没有面"是对的，前端是"按站点补一个示意"，两者不冲突。
3. **图例文案要跟着变。** 案例下把「低能见度（雾）」改成「低能见度（雾·示意）」，靠 `Ms()` 那套动态改名机制扩一个入口就行。

### 1.3 代码落点（按行为找，别死找函数名）

- **数据入口**：气象帧对象里新增读取 `frame.stationVisibility`（`Array<{station, visM, visLevel, lat, lon, observedAt}>`）
- **几何构造**：在现有图层构造函数（就是画 `lowVisibility.regions` 那个）前面加一个分支：

```js
function fogCirclesFromStations(frame) {
  const st = frame?.stationVisibility
  if (!Array.isArray(st) || !st.length) return null   // 没有就走原来的 regions
  const LEVEL = {
    BAN:     { r: 40000, fill: 'rgba(120,60,160,0.28)', dash: null },
    CAUTION: { r: 24000, fill: 'rgba(120,60,160,0.14)', dash: [4, 3] },
  }
  const features = []
  for (const s of st) {
    const cfg = LEVEL[s.visLevel]
    if (!cfg) continue
    const ring = circlePolygon([s.lon, s.lat], cfg.r, 64)   // 生成 64 边形，别用真圆
    features.push({ type: 'Feature', properties: { tier: s.visLevel, station: s.station,
      label: `${s.station} · ${Math.round(s.visM)} m`, ... }, geometry: ring })
  }
  return features.length ? { type: 'FeatureCollection', features } : null
}
```

- **渲染**：复用现有的 fill + line 两套样式（跟 `lowVisibility.regions` 的渲染同一个函数），只是数据源换成上面这个
- **图层开关**：挂到现有的 `fog` 图层 key 上，不要新建 key（图例已经 9 项了，别再加）

### 1.4 验收（4 条，缺一不算完）

1. 打开 `?case=fog-20250105`，地图上能数到 **4 个圆**，其中沈阳那个最大、颜色最深
2. 关掉「低能见度（雾·示意）」图层，**地图区像素变化 > 3,000 px**（用本文附录脚本量，低于 3,000 就是没画出来）
3. 圆圈中心标签显示 `ZYTX · 998 m`
4. 图层说明里能找到「**不是实测雾区边界**」这 8 个字

### 1.5 风险

| 风险 | 处理 |
|---|---|
| 40 km 圆把走廊盖住，看不清航线 | 圆用半透明填充、**不加描边光晕**；圆的 z-index 放在航线**下面** |
| 评委问"这圆怎么来的" | 图例说明 + 站点标签已经写了，照着念 |
| 实时模式下误用这条路 | 分支条件写成 `frame.case && frame.stationVisibility?.length`，双保险 |

## 2. G-2（P0，2h）：虚拟通道下接口别自己打自己脸

### 2.1 现在是什么样

同一条响应里：

```
weatherMode               = virtual
radar.mode                = virtual
radar.watch.source        = SYNTHETIC_RADAR_CREF    ← 诚实
radar.summary.channel     = CMA_RADAR_TILES         ← 自称气象局实测
radar.summary.note        = 「本通道几何为实测雷达反射率经阈值分类与配准后生成」  ← 自称实测
radar.summary.slot        = 2026-10-21T11:00:00Z    ← 昨天
radar.summary.slotAgeMinutes = 0.0                  ← 硬算的
```

### 2.2 改成什么

**原则：凡是"这条数据是什么"的描述性字段，都必须从当前通道派生，不能写死。**

#### 改动 A：`summary.channel` 跟着通道走

| `weatherMode` | `summary.channel` |
|---|---|
| `measured` | `CMA_RADAR_TILES`（保持原样） |
| `virtual` | `SYNTHETIC_RADAR_CREF` |

#### 改动 B：`summary.note` 跟着通道走

- measured：`「本通道几何为实测雷达反射率经阈值分类与配准后生成，与合成气象场分开标注。」`（原句不动）
- virtual：`「本通道几何为程序生成的模拟回波，用于演示与压力测试，**不是观测数据**，不参与任何实测结论。」`

#### 改动 C：`slotAgeMinutes` 在虚拟通道下置 `null`

虚拟数据没有"时次年龄"这个概念。写 `null` 比写 `0.0` 诚实。

前端遇到 `null` 时显示「—」，不要显示 "0 分钟"。

#### 改动 D：`summary.slot` 在虚拟通道下加前缀

`"SYNTHETIC@2026-10-21T11:00:00Z"` —— 一眼能看出不是实测时次。

### 2.3 代码落点

`summary` 的构造处（就是拼 `channel` / `note` / `slot` / `slotAgeMinutes` 那个字典）。现在大概是：

```python
summary = {
    "channel": "CMA_RADAR_TILES",
    "note": "本通道几何为实测雷达反射率经阈值分类与配准后生成，与合成气象场分开标注。",
    "slot": slot,
    "slotAgeMinutes": age_minutes,
    ...
}
```

改成：

```python
if mode == "virtual":
    summary = {
        "channel": "SYNTHETIC_RADAR_CREF",
        "note": "本通道几何为程序生成的模拟回波，用于演示与压力测试，不是观测数据，不参与任何实测结论。",
        "slot": f"SYNTHETIC@{slot}",
        "slotAgeMinutes": None,
        ...
    }
else:
    summary = { ... 原样 ... }
```

**注意**：`radar.regions` / `radar.watch` 里的 `source` 已经是对的（`SYNTHETIC_RADAR_CREF`），别动。

### 2.4 验收（3 条）

1. `mode=virtual` 时 `GET /api/traffic/weather` 的 `radar.summary.channel` 必须是 `SYNTHETIC_RADAR_CREF`
2. 同一响应里 `radar.watch.source` 与 `radar.summary.channel` **必须是同一个值**（这条最关键，一查就穿的就是它俩不一致）
3. `mode=measured` 时这两个字段必须**完全没变**（跟 0.11.10 逐字节对比）

### 2.5 风险

`radar.summary.channel` 可能被前端某处拿去做判断（比如判断要不要显示雷达图层）。改之前先 grep 一遍 `channel`，确认没有 `if channel === 'CMA_RADAR_TILES'` 这种硬编码逻辑。**有的话先改成按 `weatherMode` 判断，再改字段值。**

## 3. G-3（P0，0.5h）：把气象页那句导语改对

### 3.1 现在是什么样

同一时刻（`mode=virtual`）两页的原文：

- 首页：「当前为模拟气象通道：**走廊概率仍按三站 METAR 实测计算**，与地图上的虚拟回波不是同一份气象。」
- 气象页：「通道是「虚拟气象」：本页天气场与**走廊概率都走模拟通道**，不是实测，仅供演示。」

**首页那句是对的，气象页那句是错的。**

### 3.2 改成什么

气象页导语改成三段式（照抄）：

> 「通道是「虚拟气象」：**地图上的雷达回波与天气场走模拟通道（程序生成，不是观测）**；**走廊的不可飞概率仍按沈阳 / 长春 / 哈尔滨三站 METAR 实测推算**，不受本开关影响。
> 两者来源不同 —— 回波不冒充观测，走廊概率也不看模式值。仅供演示。」

实时通道的导语保持现在的写法（它本来就是对的）：

> 「通道是「实测气象」：走廊的不可飞概率由沈阳 / 长春 / 哈尔滨三站 METAR 实测推算；而本页这张天气场（风场点与派生风险区）来自 Open-Meteo 模式估算 —— 两者来源不同：走廊概率不看模式值，天气场也不冒充观测。」

### 3.3 一句话原则（写进代码注释，以后别再犯）

> **走廊概率永远走 METAR，天气场永远走 Open-Meteo，切换的只有雷达回波。** 凡是要描述"哪份数据走哪条路"的文案，必须按这三句拆开写，不许合并成一个"都"。

### 3.4 验收（2 条）

1. `mode=virtual` 时，气象页导语里**不能出现"走廊概率都走模拟通道"**这种合并说法
2. 气象页导语与首页结论条对"走廊概率来源"的说法**必须一致**（都写 METAR）

## 4. G-4（P1，2h）：避让几何跟着通道重算

### 4.1 现在是什么样

虚拟通道下，同一屏里：

| 位置 | 数字 |
|---|---|
| ≥45 dBZ 对流内核（禁止进入） | **941.4 km²**（2 个单体） |
| 35–45 dBZ 对流回波（须绕飞） | **45,376.7 km²**（7 个单体） |
| 15–35 dBZ 层状降水（可飞越） | **176,411.4 km²**（2 个单体） |
| **本计划的避让几何：并集** | **0 km²（内核 0 · 谨慎 0 · 层状 275.4）** |

`275.4` 是**实测通道**的数。

### 4.2 根因

避让几何（`avoidanceGeometry` 或等价结构）在建场时算好并缓存，**切换通道没有触发重算**。而分档统计是每帧现算的，所以两边不同步。

### 4.3 改成什么

**两条路，选一条。优先选 A。**

#### 方案 A（推荐，2h）：切通道后让避让几何失效

1. `POST /api/traffic/weather/mode` 成功后，**清掉当前工作区的避让几何缓存**（和依赖它的预序列化 session 缓存）
2. 前端切通道成功后，**不要只刷新天气，要重新拉一次 session**（现在的逻辑只刷 `Mt()` 即天气，没刷 session）
3. 页面在 session 重建期间显示一条小提示：「气象通道已切换，正在按新通道重算避让几何（约 20 秒）」

好处：几何永远是对的，而且复用已有的建场链路，不写新算法。
代价：切完要等 20 秒。

#### 方案 B（备选，3h）：虚拟通道下直接不显示避让几何

如果 A 来不及，就先在虚拟通道下把「本计划的避让几何」这一行**隐藏**，改成一句：

> 「虚拟通道不参与避让几何计算（避让几何基于实测通道）。要演示避让效果，请切回实测通道。」

好处：0 风险，绝不矛盾。
代价：虚拟通道的演示价值大幅下降（没有绕飞效果可看）。

### 4.4 验收（3 条）

1. 虚拟通道下，「避让几何」的内核值 **> 0**（因为分档里有 941.4 km² 内核）
2. 避让几何的层状值 **不等于** 275.4（那是实测的数）
3. 切回实测后，避让几何**回到** 275.4 那一套（不能把虚拟的数留在实测里）

## 7. G-7（P2，1h）：冷启动别用大遮罩挡地图

### 7.2 改成什么

**遮罩 → 顶部细进度条（高 3px）+ 一行小字，地图和 KPI 照常显示。**

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 62%
```

```python
"""用法：改 CASE_URL 和 LAYER_TEXT，跑一次，看输出的地图区变化像素。
   判定线：> 3000 才算画出来了；< 200 等于没画。"""
from PIL import Image, ImageChops
import json, time
from walk import ev, nav, txt, shot, pump, send, sid

CASE_URL   = 'https://tianchuang.shuanzi.site/?case=fog-20250105'
LAYER_TEXT = '低能见度'

def click_at(x, y):
    for t in ('mousePressed', 'mouseReleased'):
        send('Input.dispatchMouseEvent', {'type': t, 'x': x, 'y': y,
                                          'button': 'left', 'clickCount': 1}, sid=sid)

nav(CASE_URL, 9.0); pump(16)

btns = ev("""(()=>{const o=[];document.querySelectorAll('button,span,div,label,li').forEach(e=>{
  const t=(e.innerText||'').trim(); if(!t||t.length>12)return;
  const r=e.getBoundingClientRect();
  if(r.width>0&&r.height>0&&r.height<44&&getComputedStyle(e).cursor==='pointer')
    o.push({t,x:Math.round(r.x),y:Math.round(r.y),w:Math.round(r.width),h:Math.round(r.height)})});
  return o})()""")

target = next((b for b in btns if LAYER_TEXT in b['t']), None)
assert target, f'找不到图层按钮：{LAYER_TEXT}'

shot('vf_on')
click_at(target['x'] + target['w'] // 2, target['y'] + target['h'] // 2)
pump(2.5)
shot('vf_off')

a = Image.open('shots/vf_on.png').convert('RGB')
b = Image.open('shots/vf_off.png').convert('RGB')
d = ImageChops.difference(a, b).convert('L')
w, h = d.size

def count(y0, y1):
    c = d.crop((0, y0, w, y1))
    return sum(1 for v in c.getdata() if v > 18)

print(f'图例行(430-460) = {count(430, 460)}')
print(f'地图区(480-880) = {count(480, 880)}   ← 判定这一行')
print(f'底栏(880-1000)  = {count(880, 1000)}')
```

## 14. 附：本轮测试口径备忘（下次别再踩）

| 坑 | 说明 |
|---|---|
| **工作区 ≠ 账号** | 页面用自动生成的 `alc_ws`（本轮 `d6667f1097854e518153829d`），不是 `M6699`。用账号工作区调接口改状态，页面看不到。**改状态必须在页面里改。** |
| **建场响应结构变了** | 从 `{phase, session:{...}}` 改成扁平：`status`（`READY`）+ 顶层 `sessionId` / `flights` / `flightStats` / `stats` / `mapFlights` / `fields`。按 `phase` 轮询的旧脚本会永远等不到。 |
| **判"图层有没有画"只能靠像素差分** | 图层开关是自定义 `div`，DOM 里查不到对应要素。唯一靠得住的是"关掉之后地图区变了多少像素"。 |

| **限流** | 连续打 `POST /api/traffic/weather/mode` 会 429。间隔 ≥1.5 s。 |
| **`flights?page=` 的 409** | 是限流/冷启动瞬时态，等 5 秒复测即 200。判断限流前先复测一次。 |
