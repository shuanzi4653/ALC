## 零、先说「真实气象为啥暴橙」—— 不是 bug，是风

查了实时通道的实际输入（`/traffic/weather?scenario=live`，2026-10-27 15:30Z）：

| 项 | 值 |
|---|---|
| 数据源 | `OPEN_METEO` / `MODEL_ESTIMATE`（公开模式估算，不是 METAR 实测） |
| 沈阳 | 6.0 ℃ · 湿度 23% · **风速 4.4 m/s · 阵风 12.8 m/s** · weatherCode 0（晴） |
| 走廊概率 | 53 条里 **4.4% – 29.8%**：可飞 20 · 需谨慎 20 · **不可飞 13** |

判据是"能见度 <1000 m **或阵风 >10 m/s** 为停飞档"。
**阵风 12.8 m/s 已经在 10 m/s 线上**，所以晴天也会有一批走廊判到停飞/谨慎档 ——
这是"风"的问题，不是"雾"的问题，也不是模拟数据串进了实时通道。

真正难看的是**画法**：原来把 `p` 直接喂给色带（0 绿 → .5 黄 → .8 橙 → 1 红），
于是 30% 也画成橙；再加上 13 条"不可飞"走廊照样画粗带子，屏幕就成了"到处都不能飞"。

## 一、C-1 走廊带与航迹分档

用户定的口径（原文）：

> 谨慎航线在态势上显示就行了，禁飞线不显示，正常飞行的蓝线就正常显示就行了，
> 绕行的还是按照原来的设定即可。

### 改了什么

| 对象 | 原来 | 现在 |
|---|---|---|
| 走廊可飞性带 | `p` 直接映射色带，不可飞也画 | **蓝＝可飞 / 琥珀＝需谨慎 / 不可飞不画** |
| Top N 选取 | 前 3 条，不管结论 | 先滤掉不可飞，再取前 3（多取 8 条再筛） |
| 配送无人机航迹 | 浅橙 `#FFD085`（橙＝警示色，一屏几十架就像到处告警） | 淡紫蓝 `#B9B2E8`（仍与飞行汽车可区分，但不抢警示语义） |
| 绕行航迹 | 与正常同宽同透明度 | **颜色不变**（按用户要求），宽度 ×0.62、透明度 .5 |

判据：色带不再读 `p` 做插值，改读后端结论 `tier`（`CLEAR` / `CAUTION`）——
一条走廊一个结论，颜色才和结论条对得上。**"不能飞"由风险区色块与事件图层表达**，
走廊带只回答"这条路现在什么样"。

### 图例同步

两处图例都加了第一句：

> 走廊带：蓝＝可飞 / 橙＝需谨慎（不可飞不画） · 航迹：青＝飞行汽车 / 淡紫＝无人机 / 橙＝绕行

## 二、T-1 左栏美化（含「没点击的项没有变色」的真因）

### 真因

不是设计问题，是**样式被历史规则压住**：

```css
/* TrafficWorkbench.vue:1061（老规则） */
.operations-nav button{ border:0!important; background:transparent!important; … }
```

所有按钮的 `background` 被强制成透明。新写的 `.nav-group{background:…}` 没有
`!important`，同权重、但对方的 `!important` 更高 —— 于是"未选中项"永远是透明的。
**这类问题不会报错、也不会让测试变红，只能靠"量计算样式"发现。**

### 现在的样子

- 组：卡片（极淡白底 + 描边 + 圆角），hover 变青，选中＝蓝渐变 + 左侧 3 px 亮条；
- 子视图：时间线（竖线 + 圆点），选中圆点实心发亮；
- 底部区域/投影/演示/设置：等宽胶囊，选中态有底；
- 收起态：卡片收成方块，只留编号。

判据（实测计算样式）：

```
未选中项底色: rgba(255, 255, 255, 0.035)     ← 原来是 rgba(0,0,0,0)
选中项底色  : linear-gradient(90deg, rgba(32,104,136…
```

## 三、S-2 推演按钮：「下一步」与「展开/收拢」拆开

原来是一个按钮两用：走到第 7 步才变成「展开全部」——
"我点一下会发生什么"取决于我走到第几步，这不是一个按钮该有的行为。

现在三个并列：`上一步` / `下一步` / `展开全部`（展开后变 `收拢`）。

实测：

| 状态 | 按钮 |
|---|---|
| 第 1 步 | 上一步(禁用) · 下一步 · 展开全部 |
| 第 2 步 | 上一步 · 下一步 · 展开全部 |
| 展开后 | 上一步 · 下一步(禁用) · **收拢** |

## 四、R-1 分歧台账并入推演（第 8 步）

步骤条从 7 步变 8 步：数据 · 插值 · 概率 · 判据 · 裁决 · 对照 · 七帧 · **复核**。

第 8 步内嵌原「分歧台账」，并**按当前走廊过滤**（`focusCorridor`）——
它要回答的是"这条走廊被改判过几次"，不是"全库有多少条"。
`sections.ts` 里 `ledger` 仍在 `HIDDEN_SECTIONS`：导航无入口，深链仍可达。

空态分了两种说法（这是"空台账"最容易被误读的地方）：

- 全库无记录：`台账是空的 —— 这是真实状态，不是加载失败。`
- 本走廊无记录：`本走廊还没有人工复核记录。` + `全库共 N 条，但都不在本走廊。`

## 五、L-2 口径与来源：框没框全

真因不是 `overflow` 没写，而是 `table{width:100%}` 让表格**永远不超过容器**：
七列被压扁、`code` 里的长路径换行成三四行，看起来像"框没框全"。

改法：`table{min-width:1080px}` + `code{white-space:nowrap}` + 滚动条可见。
宁可有横向滚动条，也不要把一列压成竖条。

## 六、W-1 城市气象条（右下角空白 → 自动滚动）

### 数据

新增 `GET /traffic/weather/cities`（36 城）：

- 源：Open-Meteo `current`（温度 / 天气代码 / 风 / 湿度 / 体感）；
- **一次请求取全部城市**（多坐标逗号分隔）—— 20 个城市不是一个 20 次请求的问题；
- 缓存 10 分钟；取不到返回 `available:false` + 原因，不编造；
- 页面上明写：**不参与走廊判据**（判据只看站点实测与概率模型）。

### 界面

首屏右栏底部一块「城市气象」：36 城 ×2 遍，CSS 无缝纵向滚动（64 s 一轮），
hover 暂停，`prefers-reduced-motion` 下不动。
每行：图标 · 城市 · 天气现象 · 气温；`title` 里给体感 / 风 / 湿度。

### 踩到的坑：**跨层第五次缺失**

前端调 `/api/traffic/weather/cities` → 404，返回体是 Spring 的
`{"status":404,"error":"Not Found","path":"…"}`。
真因：`/api` 走 Java，而 Java 对"比 `{resource}` 白名单多一段"的路径必须**显式声明**。
这是同一形状的第五次（前四次：`weather/mode`、`operations/dispose`、`radar/tiles`、`weather/observations`）。

界面上表现为"这一块不出现"——不报错、不红测试。
补上 `DecisionController` 的一个方法后，跨层审计 `_audit_gateway_routes.py` 回到
`unmatched calls: 0 / undecidable: 0`。

## 八、「松原—哈尔滨、吉林—长泰之间那条线是什么」

那是**一班的计划航迹**，不是新加的东西。

标注格式是 `<航班号> · <巡航高度>`：

| 前缀 | 含义 |
|---|---|
| `CAR-…` | 飞行汽车（青色航迹） |
| `DEL-…` | 配送无人机（淡紫航迹，高度常是 19–160 m） |

你截图里那两处，一条是 `DEL-3-06-04-0-70 · 19 m`（无人机 19 m 高度），
另一条是飞行汽车的航迹。它们连在两个城市之间，因为**航线本来就是城市对之间的直线**。

之所以会让人问"这是什么"，是因为**图例里从来没说过航迹的颜色**。
这一轮补上了：`航迹：青＝飞行汽车 / 淡紫＝无人机 / 橙＝绕行`。
