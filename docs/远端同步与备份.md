# 远端同步与双备份（GitHub + Gitee）

> 自 2026-11-09 起，本项目采用**双远端**：GitHub 为主、Gitee 为二次备份。
> 任何一次提交/发版，**两个远端都必须更新**。

## 1. 远端

| 名称 | 地址 | 角色 |
|---|---|---|
| `origin` | `https://github.com/shuanzi4653/ALC` | 主仓库（公开，材料核查入口指向这里） |
| `gitee` | `git@gitee.com:shuanzi4653/aic-tianchuang.git` | 二次备份（公开） |

> 命名说明：GitHub 仓库名 `ALC` 是历史遗留（项目正名为 **AIC**）；Gitee 侧直接用正名 `aic-tianchuang`。

## 2. 自动同步（提交即推）

已启用仓库级钩子：`core.hooksPath = .githooks` → `.githooks/post-commit`。

- 每次 `git commit` 成功后，钩子**依次推送 `origin` 与 `gitee`**；失败自动重试一次（本机 schannel / 代理偶发 502）。
- 钩子**永不阻断提交**（退出码恒 0），结果写在 `.run/git-sync.log`。
- 临时关闭：`set AIC_SKIP_SYNC=1`（单次）或 `git config --unset core.hooksPath`（长期）。
- 被 `.gitignore` 排除的目录（`.run/`、`.workbuddy/`、`node_modules/`、`.venv/`）**不会**进入远端。

查看同步结果：

```bash
tail -n 30 .run/git-sync.log
```

## 3. 手动同步（发版或批量改动后）

双击根目录 `sync.bat`，或：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-remotes.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-remotes.ps1 -Message "发版：V1.1.0"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-remotes.ps1 -NoCommit   # 只推已有提交
```

脚本行为：有改动先 `git add -A` + `git commit`（默认消息带当前 `VERSION`）→ 依次推两个远端 → 任一失败退出码 1。

## 4. 发版流程里的位置

发版链不变，只在末尾补一步：

1. `.run\build_manual.ps1` 构建（**不要**直接 `mvnw package`）
2. `tools/deploy/_deploy_release.py --py-tree` 部署
3. 云端 `bin/verify-remote.sh`（判据 PASS 37 / FAIL 0）
4. **`sync.bat` 双远端同步**（或依赖 post-commit 钩子自动推）

## 5. 首次配置（换机时照抄）

```bash
# 1) 克隆主仓库（本机 schannel 会断，必须指定 openssl 后端）
git -c http.sslBackend=openssl clone https://github.com/shuanzi4653/ALC.git
cd ALC && git config http.sslBackend openssl

# 2) 身份（不设 name 的话提交作者会显示 unknown，公开后不可逆）
git config user.name  "shuanzi4653"
git config user.email "1292153064@qq.com"

# 3) 双远端
git remote add gitee git@gitee.com:shuanzi4653/aic-tianchuang.git

# 4) Gitee SSH（密钥已在 ~/.ssh/gitee_ed25519，公钥需在 Gitee「设置 → SSH 公钥」里）
ssh -T git@gitee.com

# 5) 启用钩子
git config core.hooksPath .githooks
```

## 6. 纪律

- **两个远端必须同代次**：只推了 GitHub 就发版，等于备份失效。发版后看一次 `.run/git-sync.log`。
- **Gitee 推送走 SSH**（`git@gitee.com`），不再用 HTTPS 口令；密钥 `~/.ssh/gitee_ed25519` 只在本机。
- **`.gitignore` 是唯一的排除判据**：凭据（`SHUANZI_SITE_CREDENTIALS.md`、`config/application.yml`、`*.pem`、`secrets.db`）不得入库；`docs/代码注释归档-V1.0.0.md` 按约定只在本地。
- Gitee 公开仓库会同步暴露提交历史，**提交信息里不写内部路径、口令、服务器 IP**。
