## 2. 传模型文件之后会发生什么

本地把 `models/ml-v3-national-vis.json` 就位后实测同一接口（这是「传完文件」的等状态）：

```
nationalModel.available = true      version v3.20261110      test.auc 0.9488
fallback.probSource     = MODEL
flights[*].probSource   = MODEL（全量）
liveCoverage            = {cities: 319, medianP: 0.0668, maxP: 0.9781}
counterfactual.modelAxis = {applicable: true, changedCount: 30}
  withModel    : hold 30 / detour 1 / release  93
  withoutModel : hold  0 / detour 1 / release 123
班次 pModel : n=124, p25 0.043, 中位 0.202, p75 0.643, max 0.997
本帧 HOLD   : 30 / 在飞 124
```

**这是本版最重要的一条副作用：传完文件，首页「停飞」从 0 变成 30，放行从 123 掉到 93。**

- 好处：AI 那 20 分终于有东西，且「不用模型全放行 → 用模型拦下 30 架」是全系统最有说服力的一屏
- 风险：材料里「放行率 100%」「停飞 0」直接与屏幕打架

必须准备的一句解释（来自 `fallback.note`）：端点两城概率按独立事件合并，取**任一端点**超阈；ml-v3 是「前瞻 1 小时」不是当前实况。所以天气好的时候也会拦下一批「一小时后可能掉到 3 km 以下」的航段。

## 7. 一条方法论

这次两份外部文档的错误，全都属于同一类：**把「看起来像」当成了「实测是」**。

- 文件在不在 → 看了一眼目录名就下结论，没 ssh
- AUC 为 null → 看见 null 就归因「文件没传」，没打开文件看字段
- 507 全过 → 数了通过的用例，没数**没被收集的文件**

所以本版的验收标准全部写成**可直接执行的断言**（字段路径 + 期望值），而不是「传完就好了」。方案里每一个数字后面都能追到一条命令。
