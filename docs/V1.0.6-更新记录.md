## 6. 全国化口径统一（同轮追加，2026-11-12）

### 6.1 为什么单开一节

V1.0.5 把旧的三省运行图从界面撤了，但**裁决层的说法还是三省的**：口径页的②层写着"东北运行网 · 36 城 53 + 216 条"，顶栏还挂着"东北三省 · 全域"的城市下拉，净空卡的说明写着"与东北 69 站点法定管制区分开计数"。这些字都不是错在数字上，而是错在**指向**：判定早就跑在全国 492 条航线、319 座城市上了，界面却把它说成某个区域的运行网。评审看到"36 城"和"319 市"并排，第一个问题一定是"到底覆盖多少"。

所以这一轮只做一件事：**把"基于三省"的全部表述改成"面向全国 / 大区 / 省 / 市"**，并补上能让这句话被当场验证的内容。

### 6.5 三处遗留缺口：补齐（同日追加）

上一版留了三条，都是"页面在、数据不通"。这一轮只补通路，不新开页、不加功能：

**① 分级切片只到「全国 + 六大区」→ 现在跟随作用域。**
同一张表三个层级通用：全国看六大区、大区看区内各省、省（或市）看本省各市；列随层级换
（省层没有"停飞 / 低能见"这两个字段，市块只统计本市航线与在飞，如实显示"—"）。
实现上只多做一件事：当前作用域不是全国时，按同一入口多取一份 `level=…&id=…` 的载荷，
**不在前端把省的数字加出来**。①层仍固定取全国（它讲的就是全国聚合），两层各说各的层级。

**② 分歧台账永远空 → 并入本机人工裁决。**
服务端那本账只记预警中心的处置，全国层没有对应写入点，所以永远 0 行。而人真正做过的事在
`alc.review.v1`（走廊页「人工裁决」）——日志页早就并进表了，台账页没有。现在两边并进同一张表：
判定口径不变（与算法原判一致 = 采纳，不一致 = 否决），靠"操作人"区分来源；导出 CSV 一起可导。

**③ 反事实页默认等旧计划建场（首次 40–90 秒）→ 默认走全国层当前帧。**
后端补了一条轴：`counterfactual.modelAxis`（含模型 / 不含模型）。摘掉模型只会影响
"p ≥ MODEL_HOLD 触发的停飞"这一类，规则分与绕飞几何两边完全相同 —— 所以差异只可能来自模型，
正是这一页要回答的问题。实测本帧 106 架在飞、32 架是模型单独拦下的，首屏 1 s 出数。
案例重放（`?case=…`）原样保留，并顺手修掉一个真 bug：以前只认 `BUILDING`，
拿到 `BUSY` 就停在"对照不可用"，用户只能手点重试；现在两者都纳入轮询。

顺带修掉四处表述：面板与页头各写一遍「反事实对照」（标题叠两次）、全国层结论句缺主语
（"用 停飞，换掉 32 架次"）、台账页脚在表非空时仍印"尚无裁决记录"、浅色主题下提示条与
`cf-scope` 低对比（1.84:1）。

**仍然没做的**：人工裁决只写浏览器本地，没有落服务端台账（要加表与写接口，属新功能）；
反事实的两条轴（回波 / 模型）不合并成一个"总改判数"，因为同一架可能同时出现在两边。
