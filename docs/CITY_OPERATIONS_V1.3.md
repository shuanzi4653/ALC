# 0.9.6（Beta） 运行说明：时间、空域、资源、气象与调度

本文件说明 0.9.6（Beta） 的运行语义与数据边界。参数均为**本项目模拟运行策略**，不是现实空域许可，也不是已验证的机型能力。

## 1. 时间合同

计划创建时固定基准 `baseTime = 2026-09-14T10:00:00Z`，界面统一按 `Asia/Shanghai` 显示。

| 字段 | 含义 | 展示规则 |
| --- | --- | --- |
| `requestedDepartureAt` | 申请起飞 | 始终显示 |
| `plannedReleaseAt` | 本版本排程允许的时隙 | 未分配为空，不显示为 `00:00` |
| `actualReleaseAt` | 推演中实际签发放行 | 未来为空，显示“未发生” |
| `actualTakeoffAt` | 实际进入起飞阶段 | 进程单展开区 |
| `estimatedArrivalAt` | 按当前有效航迹计算 | 始终显示 |
| `actualArrivalAt` | 到达事件已发生的时间 | 未发生为空 |
| `planRevision` | 班次所属排程版本 | `traffic-plan-v1.3` |

主界面时间形态为 `09-14 18:05:00 · T+00:05:00`。相对分钟只用于算法内部与推演轴。

回看过去时只展示该时刻之前发生的事件，不会泄露未来的“实际时间”。

## 2. 城市中心与起降点

- 目录文件：`backend-python/data/traffic/city-centers.json`（schemaVersion 1.3，EPSG:4326）。
- 每城记录 `id`、名称、省份、是否省会、`centerType`、来源、复核日期与质量状态。
- 已删除城际端点统一向西南偏移 2690.72 米的逻辑；边界校验失败的城市只记录 `OUTSIDE_PROVINCE_REVIEW_REQUIRED`，**不吸附、不静默改写坐标**。
- 中心枢纽 `CITY-{id}` 与城市中心同一坐标，`offsetFromCenterM` 为 0，表示“中心点即可用的模拟起降点”，而不是隐藏在建筑里。
- 特殊点显式记录：
  - 延边州（`2-09`）：按**州府城区代表点**取点，未使用自治州几何质心。
  - 大兴安岭地区（`3-13`）：行政驻地在内蒙古境内，本省边界内无可覆盖驻地，按三省运行边界选定**服务枢纽代表点**并保留差异说明；未移动省界。

本轮核查结果：36/36 通过本省边界校验，最大枢纽偏移 0 米。逐城记录见 `docs/evaluation-v1.3/city-coordinate-audit.json`。

## 3. 高度合同与已声明高度层

- 垂直基准：`altitudeAGL = altitudeMSL - groundElevationMSL`。当前本地无 DEM，`groundElevationMSL` 为 `null`，因此航迹高度一律标注为 **AGL 模拟相对高度**。
- 机型参数：`backend-python/data/traffic/aircraft-profiles.json`

| 项目 | 配送无人机 | 飞行汽车 |
| --- | --- | --- |
| 已声明巡航层 | 80 / 160 米 AGL | 350 / 500 米 AGL |
| 巡航上限 | 200 米 AGL | 600 米 AGL |
| 起降段 | 可低于巡航下界，但必须位于检查过的进离场空间内 | 同左 |

- 冲突处理顺序：**先换用另一个已声明高度层**，再预约定时时隙，最后地面等待。绝不逐点叠加高度。
  - `DIRECTION_LAYER` 主用已声明层：对向方向取已声明层集合的两端；走廊序号奇偶轮换。
  - `ALTERNATE_DECLARED_LAYER` 备用已声明层。
  - `NO_DECLARED_LAYER_AVAILABLE` 无可用层：延后、重新选路或关闭。
- 本轮观测：飞行汽车最高 500 米、配送最高 160 米，均在机型上限内；无班次因叠加高度而越限。

## 4. 起降与交叉资源日历

`ResourceCalendar` 是以**追加写入**的预约日志，记录每个资源在时间窗内的占用：

- 资源：城市枢纽、配送节点（商家/收货）、交叉区。
- 交叉区以 15 公里网格为单元，容量 2 架、窗口 1.5 分钟。
- 容量与时间窗同时校验；`reserve_all` 采用全有或全无，避免半预约。
- 本轮观测：456 个起降资源、32 个交叉区、255 次交叉区预约。

地面等待优先于空中悬停。恢复暂停班次时会重新检查原时隙、天气快照、枢纽容量与冲突；任一失效则进入重排，不直接放行。

## 5. 气象来源

Python 是唯一的归一化入口（`traffic/weather_sources.py`），两条来源共用一套观测结构：

| 来源 | 实现 | 数据性质 |
| --- | --- | --- |
| Open-Meteo | 直接请求公开接口，一次批量提交多坐标 | **模型估算**，不是测站实况 |
| 和风天气 | 经 Java 内部原始接口 `/api/internal/qweather/current`，凭据只留在 Java | 供应商当前产品，**未验证等同测站观测** |

- 单位归一化：和风 km/h → m/s、km → m；Open-Meteo 直接请求 `wind_speed_unit=ms`。
- 城市中心与天气网格点分别保存，网格位置不会覆盖城市坐标。
- 和风的雷暴值由天气代码与云量推导，作为 `thunderEstimate` 单独标注，**不注入风险引擎**；快照中 `thunderProbability` 为 `null`。
- 不可用时保留上一份快照并标注数据年龄，不会静默替换为随机天气；切换到合成场景会显式改变 `provider` 与 `dataType`。
- 选择方式：`ALC_TRAFFIC_WEATHER_PROVIDER=qweather` 时优先和风，失败则降级到 Open-Meteo 并写入 `PROVIDER_FALLBACK_OPEN_METEO` 标记。
- 覆盖边界：仅城际端点与采样城市有天气值，**航路内部未全程采样**；不使用省级测站代替 36 城城区观测。

## 7. 调度台账

- 班组班次条 `frontend/src/components/traffic/FlightStrip.vue`：标识、路由、时间、空间、约束、操作六个区域。
- 放行队列 `frontend/src/components/traffic/DispatchBoard.vue`：
  - 默认关注**未来 30 分钟**，可切换 60 分钟或全部班次。
  - 展开为完整台账后按**待放行 / 运行中 / 受限异常 / 已完成**分组，支持类型与关闭原因筛选、每页 20 张分页。
  - 与地图选中双向联动：定位、跟随、暂停/申请恢复。
- 被建筑、天气、容量或冲突关闭的班次不会通过操作进程单绕过校验。

## 8. 配送业务

- 每城 12 个可配置业务节点（商家/收货），6 条配送走廊，服务半径 6000 米并与省界取交集；无可靠城区边界，故标注为**模拟服务区**。
- 订单状态：待备货 → 待分配 → 待起飞 → 配送中 → 已送达；异常另有等待、取消。
- 载具状态独立维护：可用、装载、飞行、返航、充电、停用。订单与载具不共用状态字段。
- 电量模型：`每公里 3.5% + 每爬升 100 米 1.2%×2`，返航需保留 25% 余量；电量不足以返航则订单取消，理由为 `ENERGY_INSUFFICIENT_FOR_RETURN`。
- 电量为**模型估计**，保存参数与余量，不冒充实测续航。

本轮观测（种子 42 / 合成流动气象）：2592 单，已送达 2499，取消 93，送达率 0.9641，平均地面等待 2.77 分钟。
