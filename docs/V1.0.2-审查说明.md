## 一、这是个什么系统

低空交通（飞行汽车 / 城际无人机）的**协同运行管理系统**。四件事：

1. **航线网**：全国 319 城 / 30 个省级单元 / 492 条航线，四级下钻（全国 → 大区 → 省 → 市）；
2. **运行处置**：每架在飞都是独立班次对象，有编号、申请-计划-实际三个时刻、放行许可、高度剖面、风险概率与裁决依据；
3. **气象保障**：319 城逐市实况（双源）+ 雷达回波 + 走廊逐公里剖面，回波压线时自动改航；
4. **空域净空**：287 个机场的限制区几何（规则化生成），标出 113 条穿越航线，可切「可申请穿越 / 一律禁飞」。

技术栈：Vue 3 + Vite（前端 5180）、FastAPI（算法服务 8600）、Spring Boot（网关 8085）。

## 三、这一版改了什么（V1.0.1 → V1.0.2）

主线是把「**八个入口各说各话**」改成「**一套作用域，八个视角**」，再把这版新加的三维与配色做扎实。

### 3.1 信息架构（11 条外部反馈全部落地）

| 原来 | 现在 |
| --- | --- |
| 首页是东北、总览是东北，只有点「运行总览」才看到全国 | 八个入口默认都是全国；东北原图仍可在「运行总览」切回，作用域在页面之间共享 |
| 切页面后作用域被重置回全国 | 切页面保留「我在哪个省/市」，面包屑一路跟着 |
| 走廊剖面只做了东北 | 全国 492 条航线都支持逐公里剖面 |
| 气象监测不同步当前层级 | 气象跟着作用域走：全国看重点城，进省看本省各市 |
| 民航情报响应慢、对象写的是机场 | 改名「运行情报」，分「班次情报 / 空域情报」两个 tab，首屏不再等机场表 |
| 处置页不跟随国区省市 | 事件按（城市, 省）聚合，随作用域变化 |
| 台账 / 情报 / 取证三个入口同一张表、同一个标题 | 按用途分开：台账按起飞时刻、情报按风险降序、取证叫「选取证对象」 |
| 推演页没有个性化 | 顶部加选区行：选城市（120 项，省会与机场城市排前）+ 选班次，选完即驱动实况→判据→裁决 |

### 3.2 新增能力

| 能力 | 说明 |
| --- | --- |
| **三维（四级）** | maplibre + 真实高程瓦片，全国/大区/省/市都能立体；带能力探测与帧率看门狗（见 §6.1） |
| **双受众视角** | 同一套几何两种读法：运行视角（航线为主）/ 空域视角（净空圈为主） |
| **深浅色** | 顶栏一键切，地图、三维、图表全部跟随，记在 localStorage |
| **飞行汽车是活的** | 沿航向按速度连续移动，进站淡出、离站淡入；点它画出航线（已飞实线 / 未飞虚线）与起终点 |
| **走廊剖面扩到全国** | 每约 6 km 采样一次，判强回波 / 对流 / 弱回波，合并成段 |
| **多源气象** | open-meteo 主 + wttr 补前 80 关键城，带数据时效与过期快照标记 |
| **空域净空** | 287 机场限制区（规则化 DERIVED）/ 113 条穿越航线 / 覆盖 0.37% 陆域 |

### 3.3 修掉的主要缺陷（附根因，方便你判断修没修干净）

- 推演页整页空白：提示条的 `v-if` 插进了条件链中间，把整块内容排除掉了；
- 事件处置台的 tab 永远不熄灭：入口标签表里漏了 `alerts` 这一项；
- 地图「红色小方框」伪影：强回波最小环在国家级缩放下不足 2×4 像素，描边被画成空心框；
- 同屏两个时间基准（09:00 与 22:24）：后端 UTC、前端本地，现已统一北京时间；
- 后端随机崩溃（exit 139）：`pulse` / `evidence` 没走同一把锁，与主请求并发进 shapely；
- 气象接口限流打满：429 不重试直接落盘 + 退回快照，TTL 30 分钟；
- 全国页误挂东北的建场进度条、雷达瓦片一次拉 140+ 张、台账横向溢出；
- `/api/traffic/v2/nation/zones` 一直 404：Python 侧 200，但 **Java 网关只透传显式声明过的路径**，两段路径接不住。

细节见 [`docs/V1.0.2-发布说明.md`](V1.0.2-发布说明.md)。

## 四、跑起来（三步）

前置：Windows 10/11、Python 3.12+（64 位）、Node.js 20+、JDK 17 或 21（**须含 `javac`**）。

```powershell
# 1) Python 虚拟环境（路径必须是 backend-python/.venv，启动器硬编码）
cd backend-python
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt

# 2) 前端依赖
cd ..\frontend
npm ci

# 3) 回根目录，一键启动（起 Python + Java + 前端）
cd ..
.\start.bat
```

**首次装依赖必须联网**；之后日常运行不用再拉包，但城市底图与雷达瓦片仍需联网。

先跑一次环境自检更省事：双击 **`check-env.bat`**（检查运行时、依赖与端口占用，直接告诉你能不能启动）。

浏览器打开 `http://127.0.0.1:5180`，进首页就是全国态势。

## 五、请重点看这几块（高价值找茬区）

按「容易出问题、又不容易被发现」排序：

**1. 飞行汽车与点选（本版新功能，最可能出问题）**

- 打开页面后，地图上的小三角是否**在移动**？停一会儿再点「暂停」，它是否立刻停住？
- 点任意一架，是否**只画出它这一条**航线（已飞实线、未飞虚线）并标出起点与终点城市名？
  （全国层的三角只有 6 px，点不中属正常——可以先去「处置 · 调度台账」点一行选中，再看地图）
- 起终点离得很近时，两个地名会不会叠在一起？（同城接驳航线应该只标一个点）
- 点选后地图会**自动放大**到这条航线；点「复位」是否能回到全国？
- 让时间轴跑几分钟，是否有飞机**淡出消失**、同时有新飞机出现？
- 切到「走廊」再切回来：作用域应保留，**选中态会清空**（换页重新取数，这是有意的）。

**2. 作用域一致性（这版改动最大）**

- 首页下钻到某个省 → 切到「气象」「处置」「推演」「日志」→ 作用域是否还是那个省？面包屑对不对？
- 在省里点「返回上一级」，是否回到正确父级，而不是直接跳全国？
- 全国 → 大区 → 省 → 市 逐级下钻再逐级返回，地图视野、选中态、跟随态是否残留？

**3. 数字自洽**

- 顶部总数、六个大区卡片、省块、市块，四级的「航线 / 在飞 / 停飞」是否互相矛盾？
- 台账里的在飞数，和顶部「在飞」是否一致？右栏气象城数和「气象实况 N 城」是否一致？
- 大区卡片之和**故意大于**全国总数（跨省航线两端各计一次），悬停有说明——这是口径不是 bug。

**4. 深浅色**

- 切到浅色再看这四张图：全国图、省层、三维、走廊剖面——有没有「白字压白底」「深色块没换掉」？
- 切完刷新页面，主题是否记住？
- 浅色下地图的城市点、航线、绕飞段是否还看得清？

**5. 三维与降级**

- 点「三维」是否真的立起来（可旋转、有俯仰）？省/市层是否能看到地形起伏？
- 如果你的机器没开硬件加速（或远程桌面里），点「三维」会不会自动退回「倾斜」并给出原因？（这是**设计行为**，见 §6.1）
- 三维里点一架飞机，是否也画出同一条航线并拉近？

**6. 时间轴与时刻**

- 拖滑块，飞机位置是否连续、不闪跳？跨零点时时刻是否还说得通？
- 同屏所有时刻是否都是**北京时间**（曾经出现过 UTC 与本地混排）？
- 切换倍速（15/60/300）再暂停，画面是否停在同一时刻？

**7. 空态与失败态**

- 断网（或禁掉 open-meteo 域名）后刷新：气象那块是否给出可读提示（「补数中」「旧数据」），而不是空白或 0/0？
- 点一个**该时刻不在飞**的班次，是否如实说「不在飞」而不是编一条？
- 取一个没有证据链的班次点「取证」，是否说明原因而不是转圈？

**8. 窄屏**

- 1366×768（答辩投影最常见）：工具栏是否折行挡住地图？右栏是否被压到看不清？
- 点选一架飞机后，详情卡会不会把地图挤成一条缝？（这版限高了，请重点验）
- 窗口拉到 1920 以上时，地图两侧是否出现大片空白？

## 六、已知限制（这些**不用报**）

**6.1 三维是「有条件启用」**
软件渲染（没开硬件加速、远程桌面、部分虚拟机）下，这一版会**主动不建三维**，直接退回倾斜视图并写明原因。
这是 V1.0.1 两次把浏览器主线程拖死的直接对策（卡死的是浏览器 GPU，不是服务器）。
判定方式是 `getContext('webgl', {failIfMajorPerformanceCaveat: true})` 拿不到上下文，比字符串匹配权威。
另外：全国层不挂地形（只有省/市层挂 DEM），全国层起柱会变成一片棋盘，已撤掉。

**6.2 全国层不画航线、不显示地名**
492 条线在国家级缩放下平均只有 20–40 px，画出来就是一张蜘蛛网；这一层要回答的是「哪些城市进了网络」。
所以全国层只有城市点与在飞班次，**点选一架才会出现地名**。下钻到大区/省/市才画航线与方向箭头。

**6.3 交通数据是模拟（SIM）**，不是真实航班。只有气象、雷达、机场情报来自公开实况源。

**6.4 大模型取证在未配 api-key 时只走规则链**，界面会标 `NOT_CONFIGURED`。这是设计，不是失败。

**6.5 气象备源只补 80 个城市**（省会 + 机场城市）。主源被限流时，其余城市没有实况是预期行为，界面会写「补数中」。

**6.6 台湾、西藏、香港、澳门不纳入通航**，地图仍完整绘制（含南海诸岛与九段线小图）。这是需求，不是遗漏。

**6.7 东北两套数各自成立，不要互相对照**
V1.0.0 那套东北网是 36 城；全国网的东北大区是 **31 城**——因为通航范围按 50 km 缓冲带做了保守裁剪，退出 5 城。
36 与 31 都对，是两个不同口径，互相比会得出错误结论。

**6.8 ml-v3 的三条限制**（主动交代，别当新 bug 报）：
① 输入与标签同源（都用 open-meteo 模式能见度），指标衡量的是「模式能见度的演变可不可预测」，不等于实测命中率；
② `precision 0.259`——4 次报警有 3 次是假的，低 TS 主要来自**误报多**而非漏报多（recall 0.959）；
③ 模型是 **logistic（28 维线性）**，`kind:"logistic"`，不是东北那套森林。

**6.9 飞行汽车的位置是「按航向外推」**
1 秒 = 1 分钟推进，最多超前 6 分钟（再多就不是数据了，交给后端快照接管）。
所以暂停时的位置与「整分钟的班次快照」可能有几十秒的差——这是有意的平滑，不是算错。

**6.10 本版不做的事**（范围外，不用报）
移动端适配（只按桌面 1366 以上设计）、账号与权限体系、真实航班数据接入、建筑体量建模。

## 七、怎么报 bug

提到 https://github.com/shuanzi4653/ALC/issues ，按这个格式写，我修得快：

```
标题：[页面] 一句话症状

环境：Windows 11 / Edge 版本 / 窗口分辨率 / 是否开了 DevTools
页面：#/situation/national 的「态势」视图
时刻：时间轴 09:00（滑块 60）
层级：全国 / 华东 / 江苏省 / 南京市
步骤：
  1. 点「情报」→ 再点「态势」
  2. 点任意一架飞机
  3. ……
期望：……
实际：……（截图）
控制台：有报错就把那几行贴上来（F12 → Console）
```

**四条提高命中率**：

- 写明**时间轴时刻**。这系统里大量东西随分钟变，「复现不了」十有八九是时刻不同。
- 写明**当前层级**。同一个按钮在不同层级行为不同。
- 写明**深浅色**。这版有两套主题，白字压白底只在浅色下出现。
- **截图带上顶部那一行总计和右栏**，我能立刻判断是数据算错还是只是显示错。

## 八、口径纪律（报 bug 前先看这一条）

数字分四类，混着看会误判：

| 标签 | 含义 | 例子 |
| --- | --- | --- |
| `SIM` | 本系统模拟生成 | 航线、班次、时刻、在飞数 |
| `PUBLIC` | 公开源实况 | 逐市气温/风速/能见度（open-meteo、wttr.in）、雷达回波（RainViewer）、机场 METAR |
| `DERIVED` | 本系统按规则算出 | 概率、绕飞改航、雾区面、净空圈 |
| `OFFICIAL` | 法规/管制口径 | 净空规则、通航范围裁剪 |

**净空圈是规则化生成的**（DERIVED，界面上写明「规则化生成，非官方公布」），不是机场公布的官方图。
**通航范围裁剪（50 km 缓冲带）是本项目的保守执行口径**：《无人驾驶航空器飞行管理暂行条例》只写「一定范围」，**没有写公里数**。如果你看到「法律规定 50 km」这种表述，那是错的，欢迎指出来。
