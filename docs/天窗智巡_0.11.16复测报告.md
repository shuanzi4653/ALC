## 1. 评委到底怎么打分

这一节回答你的问题："我不知道评委到底怎么想。"

我把这类竞赛（AI 算法精英大赛 · 行业赛道）的评审行为拆成三层。理解这三层，比逐条对细则更有用。

### 1.1 第一层：不是逐项加分，是先定档再摊分

评委每天看 20–40 个项目。他对你的项目**不会从 0 分开始逐项累加**，而是先形成一句内心判断——"这是个什么水平的项目"——然后把这个印象按权重摊到六个细则上。

定档发生在**前 90 秒**。

前 90 秒他看到的是：一张信息很密的地图、三排小按钮、一条写着"不可飞概率 37%，8 条走廊处于禁飞级"的横幅、四个数字。**没有任何一个字告诉他：这是什么系统、给谁用、解决什么问题。**

这不是致命伤（地图本身有说服力），但它把定档交给了他自己的猜测。他一猜，你就从"有主见的项目"变成"看起来挺复杂但说不清的项目"。

### 1.2 第二层：三类硬伤是降档，不是扣分

| 硬伤 | 评委会想什么 | 后果 |
|---|---|---|
| **不可信**<br>同屏数字打架、日志里 undefined | "数据是编的 / 这不是成品" | 应用成效整项归零，创新性连坐（创新建立在数据上） |
| **看不懂**<br>30 秒说不清在干什么、找不到核心功能 | "技术可能做了，但我识别不出来" | 创新性按"常规实现"给分，哪怕技术真新 |
| **演示崩**<br>点了没反应、白屏、卡住 | "连演示都不稳，怎么上线" | 实施分降档，且情绪污染后面所有项 |

你现在三类都占了一点：

- **不可信**：4 处同屏矛盾 + 日志里的 `undefined` + 人物 `absent`
- **看不懂**：首屏无标题无定位、13 页无地址、字号最大 20px
- **演示崩**：按"演示"按钮，12 秒内界面没有任何变化（详见 U-5）

第三条在答辩现场是最危险的。因为**你会去按它**——按钮就叫"演示"。

### 1.3 第三层：只有三种东西能加分

反过来，能让评委往上抬档的，只有三类：

1. **可核对的诚实**：主动写清口径、局限、失效条件，而且能被核对。
2. **可比较的增量**：用 AI 和不用，差多少，有具体数字。
3. **可复现的证据**：数字能点进去看到来源。

对照一下你的现状：

| 能力 | 现状 | 说明 |
|---|---|---|
| 可核对的诚实 | **超配** | 口径总账把阈值 0.25/0.15、分母 53、数据源接口全写出来了。这在竞赛里是稀缺品，多数队伍不敢写 |
| 可比较的增量 | **0** | 反事实页写着"AI 改判 0 架次" |
| 可复现的证据 | **被毁** | 口径总账做得太好，评委拿去核对，一核对发现卡片 22、分子 0、明细 0 |

**结论：你的技术分不低，是"可信度"和"可识别度"把分压住了。**

这句话决定了执行方案的排序——优先修什么，不是看哪个技术难，而是看哪个在拆你的可信度。

### 1.4 评委眼里你现在的人设

如果让我用一句话概括评委看完之后的印象：

> "这帮学生工程能力不错，做了个挺完整的东西，口径写得很规范。但好像有些数字自己没对齐，而且……他们到底想让我看哪儿？"

这个人设对应 **66 分左右**。要往 83 走，不需要新功能，需要做两件事：**把矛盾清零**，**让第一眼有焦点**。

| 时间 | 动作 | 看到什么 | 情绪 |
|---|---|---|---|
| 0:00–0:30 | 打开首页 | 3.1 s 出图。三排导航、一条被截断的横幅、4 个数字、一张地图 | 中性。**问题：没有标题，不知道自己在看哪一部分** |

| 1:30–2:30 | 点"处置这 22 条" | 跳到走廊列表，53 条，8 条不可飞 | 加分。路径顺 |
| 2:30–3:30 | 点第一条不可飞 | 能见度满足、阵风满足、云底满足，结论"不可飞" | **停住。凭什么？页面上一个字没有** |

## 3. 数据层：四处自相矛盾

### P-1（最严重）同一份快照，走廊页判 8 条不可飞，复盘页说 AI 改判 0 架次

**现象**

同一份计划、同一时刻，两页给出相反结论：

- 走廊剖面：`不可飞 8 条 / 需谨慎 14 条 / 可飞 31 条`，最高 37%
- 复盘对照："计划 8538d9cf… · 参评 7336 / 7760 架次 · **AI 改判 0 架次**"
- 复盘对照："关掉 AI：**626** 架次暴露在禁飞级走廊上；开启 AI：**626** 架次。"
- 复盘对照："本快照下两组都没有穿越禁飞级走廊的班次：模型给出的最高走廊不可飞概率 37%，三站观测也均未达禁飞阈值，因此没有任何一班被判为'必须改航或取消'。"

**根因（已定位到常量）**

`/api/traffic/v2/counterfactual` 的 `note` 字段原文：

> 「暴露」的判据 = 走廊概率 **≥80%** 或 走廊中点最近站的观测已达禁飞级（0.11.3 起）

而走廊判定用的是 `kpiDetail.probabilityThreshold = 0.25`、`probabilityWatchThreshold = 0.15`。

于是同一个系统里同时存在 **三套阈值**：

| 用途 | 阈值 | 出处 |
|---|---|---|
| 走廊判"不可飞" | **0.25** | `kpiDetail.probabilityThreshold` / `P_PROB_BLOCK` |
| 走廊判"需谨慎" | **0.15** | `kpiDetail.probabilityWatchThreshold` / `P_PROB_WATCH` |
| 反事实"暴露"与改判 | **0.80** | `counterfactual.note`（0.11.3 起硬编码） |

实测 53 条走廊里 `p ≥ 0.80` 的有 **0 条**（最高 0.3701），所以反事实层永远算出 0 改判。**这不是数据巧合，是结构必然。**

**代价量化**

抽样 1006 班中，落在 8 条"不可飞"走廊上的有 **64 班**（6.4%，折算全量约 494 班），其中状态 CLOSED 的 11 班，气象原因（阻断/绕飞）仅 **3 班**。系统判了"这 8 条走廊现在不可飞"，处置层一条都没动。

**为什么这条最贵**

"用 AI 和不用，差多少"是这个项目对 25 分创新性最直接的答卷。现在这张答卷上写着 **差值 = 0**。评委不需要懂代码，按顺序点两页就能看到。

### P-2 「待处置走廊 22 条」与口径表自己写的分子（0 条）直接打架

**现象**

| 位置 | 数值 |
|---|---|
| 首屏 KPI 卡片 | 待处置走廊 **22 条**（雾案例 53 条） |
| 检验 → 口径与来源 → 口径总账 | "待处置走廊（观测判据命中）"，分子 = "观测判据命中的走廊"，来源 `kpiDetail.observations` |
| 接口 `kpiDetail.observations` | **0** |
| 走廊页 53 条 `verdictObservation` | 53/53 全部"可飞" |

22 的真实来源是 `p ≥ 0.15` 的走廊数（8 条不可飞 + 14 条需谨慎），**跟"观测判据命中"没有任何关系**。雾案例更极端：待处置 **53 条 = 全部走廊**，而观测命中只有 18 条。

**为什么会被抓**

评委看 KPI 卡片不懂业务，但一定会点"这东西怎么算的"。口径总账把定义、分子、分母、来源全写出来，看起来很专业——**专业到评委可以直接拿它来核对**。一核对，三个数字互相打脸。

上一版的问题是"口径表定义 p≥0.8，页面数字不符合"；这一版把定义改了，但**改的是文案，没改分子**。矛盾从"定义 vs 数字"变成"文案 vs 文案"。

### P-3 走廊详情：三条判据全部"满足"，结论仍写"不可飞"，一个字的解释都没有

**现象**（长春 ↔ 哈尔滨，`CAR-2-01-3-01`）

- 顶部：`不可飞概率 37% · 不可飞 · 插值不确定度 σ≈0.15 · 最近站距 18.1 km`
- 判据（3 条）：
  - 能见度 **≥ 9.7 km**（阈值 < 1000 m）→ **满足**
  - 阵风 **8.23 m/s**（阈值 > 10 m/s）→ **满足**
  - 云底高 **5000 m**（阈值 < 300 m）→ **满足**

三条全满足，结论不可飞。**判据面板上没有出现过"概率档阈值 0.25"这几个字**（它只出现在复盘页的说明段里）。

**为什么会被抓**

这正是评委最爱问的那句话："你凭什么说不飞？"页面把三条硬指标摆在最显眼的位置，每条后面写着绿色的"满足"，然后标题写着"不可飞"。评委第一反应是"系统坏了"，第二反应是"这数据是编的"。

上一版是"结论引错了证据"（拿 9656 m 说禁飞级），这一版变成"判据自己证明可飞，结论还是不可飞"。同一个病，更深一层：**判据区和结论区没有共享同一套推理**。

### P-4 `undefined` 泄漏到回执和审计日志，处置人写成 `absent`

**现象**

在处置台点"确认"后，页面回执与运行日志同时落成：

```
对象：undefined:WEATHER_BLOCKED:true
时刻：2026/10/24 11:15:41（T+0 分）
动作：确认事件
人物：absent
明细：已确认（事件 undefined:WEATHER_BLOCKED:true）
计划：4b82ee831aed
```

运行日志明细里同样是：`2026/10/24 11:15:41 事件处置 0.0 — 确认事件 已确认（事件 undefined:WEATHER_BLOCKED:true）`

**两个独立缺陷叠在一起**

1. **事件 id 取错字段**：拼接 `event.id` 时对象上没有该字段 → `undefined`，界面直接输出，无兜底。
2. **操作者身份没传**：`localStorage['alc-operator'] = 'admin'`，设置面板下拉也显示"管理员"，但请求没带 `X-ALC-Operator`，后端记为 `absent`。同一次测试里用 `fetch` 打 `weather/mode`，后端回的是"你当前是「观察员」"——**角色在刷新后就失效了**。

**为什么会被抓**

这个项目反复强调"人在环上、可追溯、否决必须填理由"。台账里"人物：absent"等于自己承认**没有人**。再配上 `undefined`，评委对"工程质量"的印象一次性扣到底——这属于 15 分实施分里的硬伤，和算法好坏无关。

### P-5 配送无人机（占业务 89%）T+1:00 起全程在空 0 架

**现象**

`mapFlights` 的组成确实改了（0.11.14 是车 698 + 机 24，现在车 164 + 机 288），但按推演时刻实际统计"在空"：

| 推演时刻 | 在空 | 飞行汽车 | 配送无人机 |
|---|---|---|---|
| T+00:00 | 25 | 12 | **13** |
| T+01:00 | 40 | 40 | **0** |
| T+02:00 | 53 | 53 | **0** |
| T+04:00 | 49 | 49 | **0** |
| T+06:00 | 56 | 56 | **0** |
| T+07:50 | 21 | 21 | **0** |

全量业务量：配送 6912 / 7760 = **89%**，飞行汽车 848 = 11%。

**根因**

`flightStats.mapSampling` 写着"每 30 分钟分桶：飞行汽车每桶 20 条、配送无人机每桶 18 条"。抽样按**起飞分钟**分桶取前 N 条，而配送班次航程短、落地快，被选中的 18 条在桶首就飞完了 → 到该桶中后段，在空的配送无人机就是 0。

**为什么会被抓**

评委打开"配送无人机"图层，地图上没有一架。左侧写着"配送无人机 0"，而项目讲的是"低空物流 + 飞行汽车双业态"。这不是"看不出来"，是"看出来是空的"。

## 4. 界面层：让评委第一眼抓不到重点的六件事

这一节是 v2 新增。所有数字都是实测（1680×1050 基准视口，Chrome devtools 量出来的，不是目测）。

### 先说结论：排版本身没坏

我测了 1920×1080、1440×900、1366×768、1280×800 四种分辨率：

| 分辨率 | 元素溢出视口 | 文字互相重叠 | 横向滚动条 | 页面高度 |
|---|---|---|---|---|
| 1920×1080 | 0 | 0 | 无 | = 视口 |
| 1440×900 | 0 | 0 | 无 | = 视口 |

## 5. 次级问题

### 数据层

**M-1 城市观测分档与判据阈值符号冲突**

气象监测页 36 个地级市全部标"正常"，其中：

- 绥化、鹤岗：**阵风 15 m/s** → "正常"
- 吉林、辽源：**天气现象 = 雷暴** → "正常"

而走廊判据是"阵风 > 10 m/s 即停飞"。同一个页面体系里，15 m/s 标正常、10 m/s 判停飞。

**M-2 回放页同屏混着实时处置数字**

雾案例回放页页脚写"回放不重跑调度 · 无处置数字"，但左侧同一屏仍有"运行事件 5 个 · 停止放行 119 班"、"在空 40 架"、"四态合计 1006 班"。既然声明了不重跑，就不该把实时数字摆在旁边。

**M-3 结论句把 37% 说成"处于禁飞级"**

"未来 3 小时内，长春 ↔ 哈尔滨不可飞概率 37%，8 条走廊处于禁飞级"。37% 与"禁飞级"并列：如果禁飞级 = p≥0.8，这句自相矛盾；如果禁飞级 = p≥0.25，"禁飞级"这个词被稀释成"四分之一可能"。两种读法都不利。

**M-4 0.25 的阈值与模型校准水平不匹配**

检验页自己披露的低能见度（禁飞级）目标：`POD 0.465 / FAR 0.636 / TS 0.257`。误报率 63.6% 的模型，用 0.25 的概率阈值直接判"不可飞"，等于把 2/3 的误报变成停飞建议。模型卡没给"0.25 阈值处的精确率/召回率"，评委问"为什么是 0.25"时没有数字可答。

**M-5 53 条走廊能见度仍无区分度**

全部显示"≥9.7 km"（三站 METAR 均为 `6+`，取 9656.1 m 下界，1/d² 插值后是常数）。已加"≥"和下界说明，比上版诚实，但一条走廊一条走廊看全是 9.7 km，仍像"没算"。

**M-6 localStorage 脏值**

`alc.traffic.density = "undefined"`（字符串）。界面回落到"值班员"没崩，但脏值会一直跟着这个浏览器，换版本也不会自愈。同一存储里 `alc-operator=admin` 却是"刷新即失效"（见 P-4）。
