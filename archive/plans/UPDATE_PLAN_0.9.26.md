## 1. 老师意见的代码级归因（诊断文档结论 + 本次复核）

### 1.1 A3｜操作记录恒空 —— 本次**已代码复核确认**

```
backend-python/traffic/operations.py  command()
  if action not in ('SUSPEND','RESUME'): raise ValueError('未知操作')
```

- 该文件的 `REASONS` / `ACTIONS` 两个字典是**计划关闭原因**与**间隔动作**，**不是**日志动作集合 ——
  日志动作集合确实只有 `SUSPEND` / `RESUME` 两值。
- → 值班员不手动暂停过班次（默认状态），这一页恒为空。**诊断文档的归因成立。**
- 空态文案把用户推向"调度台账" = 亲口承认此页无价值。
- 附加问题：顶栏「导出本地记录」导出的是整份会话 JSON，**不是**操作记录。

### 1.2 A2｜种子暴露 —— 本次**已定位**

`frontend/src/components/TrafficWorkbench.vue:301`：

```html
<label>随机种子 <input aria-label="模拟随机种子" type="number" min="0" max="99999" v-model="seed"></label>
… <span class="traffic-session">{{sessionLabel}} · {{ready?'种子 '+session.seed:'等待计算'}} …</span>
```

- 位置就是「运行设置」—— 看起来很重要的位置。
- **但种子的真实作用必须保留**：`service.py::_fingerprint()` 与评测/对照/回归都靠它逐字节复现。
- → 结论与诊断文档一致：**不是"种子没用"，是"它不该出现在业务主界面上"**。

### 1.3 A4｜地图与预警中心矛盾 —— 三层根因

| 层 | 事实 | 后果 |
|---|---|---|
| 图层空 | 0.9.20 起点观测**只在极端**时（阵风 ≥17 m/s、能见度 <1 km、小时雨量 ≥8 mm）生成 6 km 禁止内核；轻度不利天气只记录不生成几何 | 「极端气象风险区」图层长期为空是**设计使然**，但观众读成"天气很好" |
| 口径异源 | 预警中心红卡 = **业务事件**（`runtime.js::closureReasons`，按 `routeId + reason + 是否关闭` 合并）；地图 = **气象几何** | 两个数各自都对，却没有一个出口能把"停在这条走廊的这批班次"画出来 |
| 归因错位 | `README.md` §0.9.14 实测：`closed=123`、`closedByWeather=0`；关闭原因只有**超出推演时段 88** 与**资源或耗时不足 35** | "一地红色停止放行"**绝大多数不是天气造成的**，但页面导语写着"气象类事件优先重排时隙……仅当两者都不可行时才停止放行"→ 被读成"天气导致停飞" |

> 这三层是**同一个现象的三个独立成因**，修一层不会让另两层消失。P0-2 必须三层同时处理。

### 1.4 A1｜情报页缺"厚"维度

现有五块：挑选班次（≤12 条）· 放行许可（单班等宽报文）· 观测报文（逐城 METAR 式）·
危险天气情报（`WSIM` 头，显式声明"不是任何气象中心发布的 SIGMET"）· 改航依据（逐班复诵）。

- `clear` / `unknown` 场景或气象源不可用时，观测数组直接为空 → **整页近乎空白**。
- 即便 `live` 场景，全部内容都是**派生 + 演示**性质，没有一块是行业里站得住的业务情报
  （无起降点运行情报、无空域状态通报、无时隙与资源态势、无趋势预报）。

### 1.5 A5｜"放不了我就说掉价" —— 这是**验收口径**，不是一条改进项

诊断文档把它正确地读成了「宁缺毋滥」原则。本轮把它落成两条硬判据：

1. **演示动线走完，任何一屏不得为空或停在提示语上**（P2-6 演示模式 + 逐页空态复查）；
2. **撑不满的内容宁可不做** —— 不新增占位面板，宁可少一个页面。

`docs/paper-innovations.md` 已登记 **8 项创新点**，其中 4 项判为「强」：

| # | 创新点 | 类型 | 已实测的反面案例 |
|---|---|---|---|
| 1 | 谐波云团轮廓生成器（含曲率预算） | 算法·参数化几何 | 用顶点索引驱动 → 最大外角 **122°**；Nyquist 通过而曲率超限（**47.85°**） |
| 2 | 同源同心风险分层构造 | 算法·拓扑约束 | `difference` 布尔差集必产生零宽薄片 |
| 3 | 避让包络凸包精确剪枝 | 算法·计算几何 | O(n) 全采样 **97** → O(h) **5**（**19.4×** 样本减少），且**精确非近似**（缺失面积 0） |
| 4 | 渲染与规划共用单一运动源 | 架构·一致性 | 图与规划器不一致从"需要审计"变成"类型上不可能" |

**本次复算确认**（`_bench_innovations.py`，1.5 s）：

```
① regions at t=120 min = 3；caution ∩ core 重叠 3.494e-07 m²（≈0）；sliver 0
② same-source 0 sliver vs difference 0
③ 97 → 5（19.4x fewer samples）；missing area vs full hull 0（精确）
④ drawn regions inside planner envelope 18/18；centre_at deterministic True
```

> ⚠️ **一处必须如实处理的数字**：同一节的计时显示
> `full sampling 25.40 ms` vs `shipped pruned path 34.52 ms` → **ratio 0.74×（剪枝版更慢）**。
> 这是**诚实记录**：第 3 项创新点的优势是**样本复杂度（O(n)→O(h)）**，在这个小规模上墙钟被常数项吃掉。
> **引用时必须写规模**，不得把"19.4×"说成"快 19 倍"。这条正是 `changelog/` 的引用纪律。

## 4. 为什么把算法放主轴：与诊断文档结论的关系（需你确认）

诊断文档 §八 的结论是：

> 「软件当前的瓶颈**不在算法，而在表达**。」

**我同意它的事实判断，但不完全同意它的行动结论**，理由：

| # | 理由 |
|---|---|
| 1 | 诊断文档的 16 项改进里**算法类只有 1 项**（P2-1）。照单执行 → 界面焕然一新，算法仍是"藏在文档里的功劳"。 |
| 2 | 创新性 25 + AI 技术应用 20 = **45 分**，是全表最大的两块。这两块的判分对象**就是算法**。 |
| 3 | 附件1 二、（二）**强制**要求标注"核心创新层级"并与主流方案定性对比 —— 这是**形式审查**项，不做直接被拦。诊断文档未覆盖此项。 |
| 4 | "表达"与"算法"在这套系统里**不是两件事**：气象态势页、可解释性面板、结论下钻，**表达的对象正是算法**。把它们做成"纯界面工程"会丢掉算法的因果链。 |

**因此本版的处置是**：把诊断文档中**以算法为对象的**那几项（P1-4 气象态势页、P1-3 下钻、P2-5 可解释性、P2-1 对照、P1-2 AI 可见化）从"界面项"**升格为"算法项"**，
用 §2.3 的四条判据验收；其余（P0-1/2/3/4、P1-1/5/6、P2-2/3/4/6）按原样做。

> **这是本版最需要你确认的一处判断**（见 §7 问题 1）。
