# 凭据说明 —— 交付包里少了什么、为什么、怎么补

这个包是为了「换一台电脑把系统跑起来」而准备的，**不是**可以直接公开的仓库。
打包时按本仓库自己的口径（`.gitignore`）移除了三类凭据文件。
它们不影响启动，但会影响一部分联网功能的完整度。逐条说明如下。

---

## 一、移除了哪些文件

| 被移除的文件 | 它是什么 | 为什么必须移除 |
|---|---|---|
| `config/alc_secret.key` | Fernet 对称密钥 | 与 `backend-python/data/secrets.db` **配对**：一个存密钥、一个存用它加密的密文。只给其一无意义，给全了等于交出明文凭据 |
| `backend-python/data/secrets.db` | 加密后的凭据库 | 同上。里面是和风 / 中国气象数据网的账号密码 |
| `config/qweather/qweather_private_key.pem` | 和风 Ed25519 私钥 | 用它对每个和风请求签 JWT。`.gitignore:47` 明确忽略、`git` 从未跟踪 —— 按本仓库自己的定义它就是凭据 |

另外移除了 `backend-python/_sim_bench.py`。**它不是凭据**，原因不同：它是整个后端里唯一
`import tools.*` 的文件，而 `tools/` 不在本包内（体积 2 MB、偏开发侧）。留着它只会
在有人碰它的时候炸一个 `ImportError`，属于**删除后不影响任何运行链路的死文件**。

---

## 二、缺失后会发生什么（已核对代码，不是推测）

### 1. `config/alc_secret.key` + `secrets.db` —— 无影响

`secret_store.resolve_key()` 在找不到密钥时会**自动新建**一个
（返回值 `FILE_CREATED`，并打一条警告），源码链路不依赖这个库。
和风/气象凭据在 Python 侧是通过 `python -m traffic.secret_store set <KEY>` 写入的；
本包走的是 Java 侧的和风链路，不经过它。

### 2. `config/qweather/qweather_private_key.pem` —— 降级，但不崩

`MonitorService` 第 164–180 行：和风调用抛异常后会被 `catch`，改走
`python.currentWeather()`（即 open-meteo 公开源），并写入：

```
run.effectiveSource = "live-public"
run.degraded        = true
run.degradeReason   = "QWEATHER_UNAVAILABLE_PUBLIC_SOURCE_USED"
```

界面上会**如实标注本轮为降级**，气象数据仍然有（来自公开源），只是来源不同。
两个源都失败时才会报 `ExternalDataUnavailableException` ——
**不会用编造的数据顶替**，这是本系统的既定纪律。

## 三、如果你想补回来

### 补和风私钥（推荐，能让气象走首选源）

1. 到和风天气控制台重新生成一对 Ed25519 密钥（或向项目维护者索取）。
2. 把私钥存成 `config/qweather/qweather_private_key.pem`，**PKCS#8 格式**：
   ```
   -----BEGIN PRIVATE KEY-----
   <base64>
   -----END PRIVATE KEY-----
   ```
3. 确认 `config/application.yml` 里的 `qweather` 四项与控制台一致：
   `api-host` / `kid` / `iss` / `sub`，以及 `private-key-path` 指向上面这个文件。
4. 重启 Java 服务，日志里出现「和风 Ed25519 私钥加载成功」即为生效。

> 注意：改完 `config/application.yml`（**UTF-8，不要用记事本存成 ANSI**）后必须重启服务。

### 补 Python 侧凭据（仅当你要用 CMA 雷达的需登录通道）

```powershell
cd backend-python
.\.venv\Scripts\python.exe -m traffic.secret_store set cma.api_user_id
.\.venv\Scripts\python.exe -m traffic.secret_store set cma.api_password
```

首次执行会自动创建 `config/alc_secret.key` 与 `data/secrets.db`。

> **本包实际用不到这一步。** 运行时的实测雷达走的是
> `traffic/cma_tiles.py`（公开瓦片，无需账号，代码里 `credentialed: False`），
> 需登录的 `cma_radar.py` 不在当前调用链上。

## 四、`config/application.yml` 里现在有什么

本包**保留**了 `config/application.yml` 原样，其中包含：

- `qweather` 四项（`api-host` / `kid` / `iss` / `sub`）—— 这些是**标识符，不是密钥**，
  单独拿到无法签发 JWT（没有私钥就不能签名）。
- `deepseek.api-key` —— 一个真实的 API Key，会产生计费调用。

> **请知悉**：这份 `application.yml` 属于「借你试用」的性质。
> 如果之后要公开仓库、上传比赛材料或对外分发，请先把 `deepseek.api-key` 换掉或清空，
> 并从 `config/application.example.yml` 重新生成本地配置。
> 清空后系统照常启动，只是智能研判会降级为本地规则基线。
