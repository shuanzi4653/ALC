## 一、需求与它撞上的两道墙

需求原文：在 `C:\Users\12921\Desktop\ALC\TianChuang` 做一个**完整独立**的启动器文件夹，
收件人双击即可打开**云端**的完整项目，**不得再访问本地文件/服务**。

设计前先确认了两件事，两件都改变了方案：

### 墙 1：`auth_basic` 在 server 级，连静态资源一起挡

`.run/cloud/AIC-tianchuang.site` 里 `auth_basic` 写在 `server {}` 下，`location` 未覆盖它。
后果：浏览器访问 `http://62.234.154.34:28081/` 时，**在 Vue 代码加载之前**就先收到 401
认证框。所以"打开网页"这一步本身就要求浏览器持有口令。

### 墙 2：URL 内嵌凭据已被现代浏览器弃用（因此 `.url` 快捷方式方案作废）

曾计划发一个内嵌 `http://aic:口令@62.234.154.34:28081/` 的 `.url` 快捷方式，做到"双击零交互"。
**实测否掉了**：

- Chrome 59+ 起地址栏不再显示用户信息；
- Chrome 65+ / Firefox / Safari 进一步**禁止带用户名口令的顶层导航**；
- 绕开需要 `--disable-blink-features="BlockCredentialedSubresources"` 之类启动开关。

失效的形态恰好是本项目最忌讳的那类：**看起来应该能用，实际会弹认证框**。

### 并因此发现：应用侧登录不是闸门

`config/application.example.yml` 是 `security.enabled: false` + `allow-demo-user: true`；
`AuthController.status()` 的实现是

```java
boolean signedIn = !securityEnabled || (authentication != null && ...);
```

即 `security.enabled=false` 时**恒返回 `authenticated=true`**；前端 `api.js` 见
`!auth.enabled || auth.authenticated` 也会**跳过 `LoginOverlay`**。
⇒ 曾考虑的"放行静态资源、改在页面内登录"方案等于**没有任何防护**，已否决。

## 二、结论：两条约束不能同时满足，必须让用户选

只要 Basic Auth 还在，**必须有人把口令喂给浏览器一次**（脚本无法代喂）。所以
「双击零交互」与「不许明码」二者只能取其一。三个候选：

1. 明文随包（`访问口令.txt`）+ 首次粘贴；
2. **不落盘、私下告知**（首次手输一次）；
3. 去掉 Basic Auth、写端点单独设防（页面公开可看）。

**用户选定 ②**（口令不随包、不落盘，由提供者私下告知）。

### 用户随后追加「不许别人保存口令内容」—— 窗口模式因此**反转**

② 的第一版把"首次输一遍"交给浏览器密码管理器长期记住，所以启动器当时**必须用
普通窗口**打开。用户随后明确要求**口令不许在别人机器上被保存**，这条直接否掉了
"交给密码管理器"：

| | 第一版（已作废） | 现行 |
|---|---|---|
| 窗口 | **普通窗口**（就是为了能保存密码） | **隐私窗口**：Edge `--inprivate` / Chrome `--incognito` / Firefox `-private-window` |
| 输口令次数 | 一次，之后浏览器自动填 | **每次都要输** |
| 口令在本机的留存 | 浏览器密码库（长期） | 关窗即失效 |

> 硬约束（现行）：启动器**默认用隐私窗口**打开；找不到能强制隐私窗口的浏览器时，
> **如实打印"本次没能强制"**，而不是假装做到了。

**代价被明确接受**：每次使用都要重新输一次口令 —— 这是"不留痕"换来的成本，
不是缺陷。**本文第一版的结论与现行相反，改设计时勿照抄。**

### 「不许保存」能到什么程度（别写成"已禁止"）

隐私窗口 + 明确告知，能让口令**不被浏览器留存**；但它拦不住一个**刻意**把口令
抄下来的人。那是纪律问题，不是技术手段能穷尽的。所以启动器与 readme 一律写
**「请不要保存」**，不写**「已禁止保存」** —— 后者是一句写在屏幕上的假话，
正是本项目最忌讳的"把未验证写成已通过"。

## 三、启动器设计与它的判据

文件：`TianChuang/启动天窗智巡.bat`（纯 ASCII+CRLF，无 `chcp`，只负责调 ps1 与暂停）、
`TianChuang/launcher.ps1`（UTF-8 **带 BOM**，中文输出）、`TianChuang/readme.txt`。
三个文件必须同目录；`.bat` 用 `%~dp0` 定位 ps1，**ps1 内部不引用任何本机路径**。

### 探测优先、按结果分流

| 探测结果 | 含义 | 启动器行为 | 退出码 |
|---|---|---|---|
| TCP 连不上 | 包到不了机器 | **不打开浏览器**，打印三条排查方向 | 3 |
| TCP 通 + `/` 探测 = 401 | 可达且 Basic Auth 在 | 用**隐私窗口**打开 + 告知"口令不要保存、关窗即失效" | 0 |
| TCP 通 + `/` 探测 = 200 | 可达但认证已被摘掉 | 打开浏览器 + 告知"未开启访问验证" | 0 |
| TCP 通 + 其它状态码 | 可疑 | 照常打开 + 打印状态码供反馈 | 0 |

**为什么认证探测用 `/` 而不是 `/healthz`**（这条踩过）：nginx 的
`location = /healthz { return 200 ...; }` 跑在 **rewrite 阶段**，早于 access 阶段，
所以 `/healthz` **永远 200、永不要求认证** —— 拿它判断"站点有没有访问验证"会
**恒得出「没有开启访问验证」**，然后用户照样被弹口令框。写在屏幕上的假话。
`/` 未认证时 401（已实测），才是正确判据。**认证探针与存活探针因此是两个路径。**

**为什么用 TCP 连接而不是 HTTP 状态码当"活没活"的主判据**：TCP 绕开 HTTP 栈、代理与
状态码语义，只回答"包能不能到达"。这与本项目既有教训同向 —— 拿应用层状态码判死活，
会把"服务不在"和"路由不对"混成同一现象（`MEMORY.md` §十⑯）。

**不假装成功**：连不上时不打开浏览器、不返回 0。当前云端是"已安装、未启用"，
所以**今天运行必然是退出码 3** —— 这是正确行为，不是故障。

### 实跑过的三个分支（不是"能解析"就算数）

`.run/_test_launcher_branches.py`（一次性）用 127.0.0.1 上的一次性 HTTP 服务真跑：

- 401 → 命中"请不要保存"文案，**且已作废的"保存/密码管理器"字样不再出现**，exit 0
- 200 → 命中"未开启访问验证"，exit 0
- 真实 `62.234.154.34:28081` → **exit 3** + 防火墙排查文案，且不打开浏览器

第 1 条的"且不再出现"是**正向对照**：只断言新文案存在，会被一份**同时说两句话**的
输出蒙过去，而残留的那半句才是读者会照做的那半句。判据函数因此带一个 **7 例自检**：
接受正确文案、拒绝 3 种已作废写法、**且不把"请不要写进密码管理器"这种否定式提及误判为违规**
（前两版把裸词 `密码管理器` 当违规词，那是一条等着咬正确答案的假阳性）。

两个坑记在这里，因为它们都会伪装成"被测对象坏了"：

1. 用 `-Command` + 调用运算符跑脚本时，脚本内 `exit 3` 只结束**脚本**，
   会话仍以 0 退出 ⇒ 退出码判据必须走 `-File`（`.bat` 的真实路径）。
   第一次跑就因此报了一个不存在的失败。
2. 控制台代码页 936，直接收管道字节会是 GBK ⇒ 断言中文前先在子进程里
   把输出编码钉成 UTF-8，否则"中文断言失败"可能只是解码猜错了。
3. 测试用的脚本副本**必须保留 BOM**，否则副本自身会乱码，量的就不是原件了。

## 四、文件夹校验器与它的非自证参照物

`tools/maintenance/_normalise_launcher_folder.py`（闸门式工具，0 干净／1 有发现／2 无法测量）：

- 编码：`.bat` 纯 ASCII+CRLF+无 BOM；`.ps1`/`.txt` UTF-8 **带 BOM**+CRLF。
  **Write 工具只写 LF**，所以必须有一次字节级回转（M 级：改完必回读复验）。
- **禁止本地引用**：`127.0.0.1`/`localhost`/`C:\`/`.venv`/`node_modules`/`backend-*`/
  `frontend`/`.run` 出现在 ps1 代码里即 FAIL —— 这是"不得访问本地"这条需求唯一可量化的判据。
- **`chcp` 判据只搜代码行**：第一版搜全文，于是被注释里那句"不要在这里写 chcp"
  误报。加豁免＝必须有**双向负向对照**（真调用必被抓／注释里的不算），
  否则"检查不再咬"与"什么都没发现"在日志里长得一样（M74）。
- **交叉对照（M75）**：启动器的 `$SiteHost:$SitePort` 必须与
  `.run/cloud/AIC-tianchuang.site` 的 `listen` 端口一致，且该 `host:port` 出现在
  `docs/云端部署与运维说明.md` 里。文件夹内部自洽说明不了"它指向的是不是真的云端"。
- 另跑 `_scan_secrets.py --root TianChuang`：**secrets=0 markers=0**（文件夹内零凭据）。
